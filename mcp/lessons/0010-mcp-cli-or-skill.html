MCP, CLI, or Skill

When a capability could be a server, a command, or a skill, the choice has real costs in context, security, reuse, and effort. This lesson gives a decision method, and says plainly where it is the author's judgment.

An honest starting point

No official source compares the three. The MCP docs say when to connect a server, and the Claude Code docs describe skills and their context cost. Neither says which to pick. The framework below is the author's judgment, built from the cited facts about each option. Treat it as a checklist to argue with, not a rule.

The Claude Code docs give the context figures: skill descriptions are always in the listing, bodies load on use, and tool definitions can be deferred through tool search to keep MCP context low.12

Five questions, in order

Ask them about one capability at a time. The first "yes" usually settles it.

  1. Is it know-how rather than an action? A checklist, a house style, a multi-step procedure with judgement. Write a skill. The body costs nothing until it is needed.
  2. Is it one local, deterministic command that you already run by hand? Expose a CLI. Add a skill that documents when to use it, if the agent needs guidance.
  3. Does more than one kind of host need it, or does it sit behind a remote service with real authentication? Build an MCP server. This is where the protocol's shared auth and reuse pay off.
  4. Must the model call it many times with typed, validated inputs and outputs? Build an MCP tool with a schema. A CLI with JSON output is the cheaper alternative if the host always has a shell.
  5. Must it run where there is no shell? A chat app or a sandboxed host cannot run your CLI, so use an MCP server.

When not to build a server If the only user is you, in one editor, with a shell, a CLI is almost always cheaper. A server is a process to start, secure, version, and update. Build it when the reuse, the auth, or the lack of a shell justifies that cost.

Check yourself

A team wants its release checklist, with judgement about exceptions, available to its assistant. Which fits best?

Checklists with judgement are know-how, which a skill carries. A skill's body loads only when it is used, so it costs little until needed.2

Which fact is the strongest reason to build an MCP server rather than a CLI?

Reuse across hosts and remote authentication are where the protocol's shared design pays off. Speed and output format are not the reasons.3

When is a CLI usually the cheaper choice?

A CLI avoids running and securing a server process. It fits a single user with a shell. The other three cases favour MCP or a skill.
