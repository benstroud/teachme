Lesson 3 of 10MCP v2

Authoring a Server

Build one server with McpServer, register a tool with a schema, and serve it over stdio. Everything later in the set adds to this file.

The shape of a server

A v2 server is an McpServer with capabilities registered on it, and a transport that carries its messages. For a local server, the transport is stdio: the client starts the server as a child process and talks to it over its standard input and output.1

import { McpServer } from "@modelcontextprotocol/server";
import { serveStdio } from "@modelcontextprotocol/server/stdio";

const server = new McpServer({ name: "notes-server", version: "1.0.0" });
// ...server.registerTool(...), registerResource(...), registerPrompt(...)

serveStdio(() => server);

The lab's src/server.ts builds the full version. Its entry point creates a new server per connection through a factory, so each client gets its own instance.

Register a tool

A tool has a name, a description, an input schema, and an async callback. The v2 API takes a zod schema through z.object. The raw-shape form is deprecated.2

server.registerTool(
  "add_numbers",
  {
    title: "Add numbers",
    description: "Add two numbers and return the sum.",
    inputSchema: z.object({ a: z.number(), b: z.number() }),
    outputSchema: z.object({ sum: z.number() }),
    annotations: { readOnlyHint: true },
  },
  async ({ a, b }) => {
    const sum = a + b;
    return {
      content: [{ type: "text", text: String(sum) }],
      structuredContent: { sum },
    };
  },
);
Two returns, one call The result has content for any client that reads text, and structuredContent for clients that read the typed object. The lab's stdio test checks structuredContent equals { sum: 5 }. The spec says structured content SHOULD also be serialized as a text block for compatibility.3

Check what the server offers

A client asks for the list with tools/list. The lab's stdio test lists three tools and reads back their annotations. The output includes the fields the spec defines: name, title, description, inputSchema, outputSchema and annotations.3

Check yourself

In a local v2 server, what carries the messages between client and server?

For a local server the transport is stdio. The client launches the server process and exchanges JSON-RPC messages over its standard streams.1

Why does the lab's serveStdio call take a factory rather than a server?

The factory is called for each connection, so each client gets its own server instance. The SDK's type is McpServerFactory.1

Which input-schema form does the v2 SDK mark as deprecated?

The raw-shape form is deprecated in favour of z.object(...), according to the SDK's type definitions.2
