Lesson 2 of 10MCP v2

v1 and v2 Compared

"v2" names the TypeScript SDK and the revision it implements, 2026-07-28. The biggest change is that the connection no longer starts with a handshake. Read the wire to see it.

Three names that get mixed up

NameWhat it is
The 2025 revisionThe protocol revision dated 2025-11-25. The previous one, called "2025" in these lessons.
The 2026-07-28 revisionThe current protocol revision. Dated, not numbered. There is no protocol "v2" version string.
SDK v1 and SDK v2Two TypeScript SDK lines. v1 is one package, @modelcontextprotocol/sdk (1.32.2 at authoring). v2 is split into @modelcontextprotocol/server and @modelcontextprotocol/client (2.4.0 at authoring).

The SDK package README says the v2 SDK is the stable line and implements the 2026-07-28 spec. The protocol versioning page confirms that revisions are identified by date.12

What changed on the wire

The 2025 revision starts each session with an initialize exchange, then a notification. The 2026-07-28 revision removes that handshake. Each request declares its version and capabilities in _meta.3 These are real messages captured by the lab's tracer (code/src/trace.ts):

-> {"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"trace-client","version":"1.0.0"}},"jsonrpc":"2.0","id":0}
<- {"jsonrpc":"2.0","id":0,"result":{"protocolVersion":"2025-11-25","capabilities":{...},"serverInfo":{"name":"notes-server","version":"1.0.0"}}}
-> {"jsonrpc":"2.0","method":"notifications/initialized"}
-> {"method":"tools/call","params":{"name":"add_numbers","arguments":{"a":1,"b":1}},"jsonrpc":"2.0","id":1}
-> {"method":"tools/call","params":{"name":"add_numbers","arguments":{"a":1,"b":1},"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientInfo":{"name":"trace-client","version":"1.0.0"},"io.modelcontextprotocol/clientCapabilities":{}}},"jsonrpc":"2.0","id":0}
<- {"jsonrpc":"2.0","id":0,"result":{"_meta":{"io.modelcontextprotocol/serverInfo":{"name":"notes-server","version":"1.0.0"}},"content":[{"type":"text","text":"2"}],"structuredContent":{"sum":2},"resultType":"complete"}}

The first trace has three messages before the work. The second starts straight at the work. Each result in the second trace carries resultType, which the spec says all results gain in this revision. Clients must treat a result without it from an older server as "complete".3

Run both traces yourself

  1. In code/, run npm install, then npm run build.
  2. Run node dist/trace.js legacy, then node dist/trace.js pin.
  3. Find the initialize line in the first output and the _meta object in the second. Predict what changes if you call three tools instead of one, then check.

Other changes in the 2026-07-28 revision

  • Discovery: server/discover is added, and servers must implement it. Clients may call it, but are not required to.3
  • Input requests: server-initiated requests (roots, sampling, elicitation) are replaced by a multi-round-trip pattern, input_required. Lesson 7 covers it.3
  • Transport: Streamable HTTP keeps one POST endpoint. The GET stream, Mcp-Session-Id sessions, and SSE resumability are removed.3
  • Removed: ping, logging/setLevel, and roots-list-changed notifications.3
  • Errors: renumbered. The changelog names UnsupportedProtocolVersion as moving from -32004 to -32022.3

Connection modes on a v2 client

The v2 client has three modes, and the default is not the modern one. It is worth knowing which one you are in:4

ModeBehaviour
legacy (default)Runs the plain 2025 sequence, with no probe and no new headers
autoProbes with server/discover first. Falls back to initialize when the server is legacy
{ pin: "2026-07-28" }Modern revision only. Any other revision fails loudly

Deprecated, not yet removed

The deprecation registry lists sampling, roots, logging, dynamic client registration, and the HTTP+SSE transport. It says no feature has been removed under its policy yet, and gives earliest-removal rules, not schedules.5 Lesson 7 covers sampling and elicitation.

Migration checklist (v1 SDK to v2)

  1. Replace @modelcontextprotocol/sdk with the server or client package, and import from the subpaths for stdio (/stdio).
  2. Move raw-shape inputSchema objects to z.object(...). The raw form is deprecated in v2.
  3. Decide the connection mode explicitly. Do not rely on the default if you need the modern revision.
  4. Check every result handler for resultType, and remove any code that calls ping or logging/setLevel.
  5. Run an interop test against an older peer. The lab's v1-lab/test/interop.test.js is an example of both directions.

Check yourself

What does the 2026-07-28 revision use in place of the initialize handshake?

The spec removes the handshake. Each request declares its protocol version and capabilities in _meta, as the trace shows.3

Which package is the v2 TypeScript server built on?

The v2 SDK splits into server and client packages. @modelcontextprotocol/sdk is the v1 single package.2

What is the default connection mode of the v2 client?

The client's versionNegotiation option defaults to legacy. Opt into auto or a pin for the modern revision.4
