Resources and Prompts

Tools are for the model to call. Resources are context the application chooses to include. Prompts are templates the user picks. The same data can be any of the three, so pick by who should decide.

Who decides

The spec defines the three primitives by their controller, not by their content:1

  • Tools are model-controlled. The model can discover and invoke them automatically.
  • Resources are application-driven. The host decides how to incorporate them, through a UI selection or automatic inclusion.
  • Prompts are user-controlled. The user selects them, often as a slash command.

If you expose a note as a resource, the application shows it to the model when it judges the note relevant. If you expose it as a tool, the model decides to fetch it. Pick by the decision you want to keep.

A resource template

A template addresses a family of resources by URI. The lab's notes://{id} returns one note for each id:

server.registerResource(
  "note",
  new ResourceTemplate("notes://{id}", { list: undefined }),
  { title: "Note", description: "One note by id", mimeType: "text/plain" },
  async (uri, { id }) => {
    const note = store.get(String(id));
    if (!note) throw new Error(`No note with id ${String(id)}`);
    return { contents: [{ uri: uri.href, mimeType: "text/plain", text: `${note.title}\n${note.body}` }] };
  },
);

The stdio test reads notes://n1 and checks that the text begins with Shopping. The client never called a tool; it asked for a resource by URI.

A prompt

A prompt has arguments and returns messages. The user supplies the arguments; the server fills the template:

server.registerPrompt(
  "summarize_note",
  { description: "Ask the model to summarize one note", argsSchema: z.object({ id: z.string() }) },
  async ({ id }) => {
    const note = store.get(id);
    const text = note ? `Summarize this note:\n${note.title}\n${note.body}` : `No note ${id}.`;
    return { messages: [{ role: "user", content: { type: "text", text } }] };
  },
);

The lab test a prompt is fetched with its arguments filled in asks for n2 and checks that the message mentions Ideas.

Injection risk in prompts and resources Anything a server returns can end up in the model's context. The spec says implementations MUST carefully validate prompt inputs and outputs to prevent injection attacks.2 A note body that says "ignore your instructions" is data, and the host should treat it that way. Lesson 9 covers this.
