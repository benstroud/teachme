Lesson 6 of 10MCP v2

Consuming a Server

A client connects, lists what the server offers, calls it, and checks every result. Learn the four calls, the connection mode you choose, and how to read a failed result.

Connect

A client needs a transport for the server it starts. For a local server that is StdioClientTransport, from the client package's /stdio subpath. Choose the connection mode in the client's options, since the default is the 2025 sequence:1

import { Client } from "@modelcontextprotocol/client";
import { StdioClientTransport } from "@modelcontextprotocol/client/stdio";

const client = new Client(
  { name: "notes-app", version: "1.0.0" },
  { versionNegotiation: { mode: "auto" } },
);
await client.connect(
  new StdioClientTransport({ command: process.execPath, args: ["dist/server.js"] }),
);

The lab's stdio.test.ts uses this exact pattern, in a helper called connect().

Read the result, not only the promise

A promise that resolves does not mean the tool succeeded. A tool execution error resolves with isError: true. Your code must check it:2

const result = await client.callTool({ name: "delete_note", arguments: { id: "missing" } });
if (result.isError) {
  // The message is for the model or for a human: show it, do not retry blindly.
  const text = (result.content[0] as { text: string }).text;
  throw new Error(`delete_note failed: ${text}`);
}
Check structured output A successful call returns structuredContent for the typed value. The lab's test asserts { sum: 5 } rather than parsing text, which is more robust. If the server's output schema changes, that test fails, which is the behaviour you want.

Check yourself

A tool call's promise resolves, and the result has isError: true. What happened?

Tool execution errors are normal results with isError: true, so the model can read the message and correct its call.2

Which client option selects the modern 2026-07-28 revision and fails loudly for any other?

The pin mode runs the modern revision and rejects anything else. auto probes and falls back, and legacy is the default.1

Which call gets a prompt with its arguments filled in?

getPrompt fills the template with the arguments you pass and returns the messages.
