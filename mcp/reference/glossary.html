MCP v2 Glossary

The canonical terms for this workspace. Use them in code comments and reviews so they match the specification.

Roles and revisions

Host
The AI application that coordinates one or more MCP clients. Lesson 1.
Client
A component that keeps one connection to one MCP server and obtains context from it. Lessons 1, 6.
Server
A program that provides context to MCP clients through tools, resources, and prompts. Lessons 1, 3.
Protocol revision
A dated version of the specification, such as 2025-11-25 or 2026-07-28. There is no protocol version named "v2". Lesson 2.
v2 SDK
The TypeScript SDK line 2.x, split into @modelcontextprotocol/server and @modelcontextprotocol/client. It implements the 2026-07-28 revision. Lesson 2.

Primitives

Tool
A function the model can discover and call, with an input schema, an optional output schema, and annotations. Model-controlled. Lessons 3, 4.
Resource
Read-only context addressed by URI, including templates such as notes://{id}. Application-driven. Lesson 5.
Prompt
A parameterised message template the user selects. User-controlled. Lesson 5.
Annotations
Hints about a tool, such as readOnlyHint and destructiveHint. Clients MUST treat them as untrusted unless the server is trusted. Lessons 4, 9.
Tool execution error
A normal result with isError: true, which the model can read and act on. Distinct from a protocol error. Lesson 4.

Messages and connections

JSON-RPC
The message format under MCP: requests with methods, and results or errors back. Lesson 1.
_meta
The per-request object where the 2026-07-28 revision carries the protocol version, client info, and capabilities. Lesson 2.
resultType
A field on every result in 2026-07-28. Values include complete and input_required. Lessons 2, 7.
legacy (connection mode)
The client default: the 2025 handshake with initialize and notifications/initialized. Lesson 2.
pin (connection mode)
The client option { pin: "2026-07-28" }, which speaks only the modern revision and fails for any other. Lesson 6.
stdio
The transport where the client starts the server as a child process and exchanges newline-delimited JSON over its standard streams. Lessons 3, 8.
Streamable HTTP
The remote transport: one POST endpoint, with the Accept and MCP-Protocol-Version headers. Lesson 8.

Input, consent, and security

input_required
A result that asks the client for input. The client answers and retries with inputResponses. Replaces server-initiated requests in 2026-07-28. Lesson 7.
Elicitation
A request for user input, in form mode (structured, not for secrets) or URL mode (out-of-band, required for sensitive data). Lesson 7.
Sampling
A server request for a model completion through the client. Deprecated in 2026-07-28. Lesson 7.
Protected Resource Metadata
The RFC 9728 document an HTTP MCP server MUST implement, so clients can find its authorization server. Lesson 8.
Origin validation
Checking the Origin header against allowed hosts before serving a request, to block DNS rebinding. Lesson 8.
Token passthrough
Accepting or forwarding a token that was not issued for the server. The spec says servers MUST NOT accept such tokens. Lesson 9.
