References & Borrowing

Let functions use a value without taking it — the two reference rules keep it safe.

The mental model in one sentence

A reference (&) lets code use a value without owning it; creating one is borrowing, and the two reference rules keep every reference valid.1

Borrowing instead of moving

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1);   // borrow s1, don't move it
    println!("'{s1}' is {len} chars"); // s1 still usable!
}

fn calculate_length(s: &String) -> usize { s.len() }

The & makes a reference; the parameter type &String borrows. Because the reference doesn't own the value, nothing is dropped when the function returns — and the original stays usable.1

The two reference rules

  1. At any given time, you can have either one mutable reference or any number of immutable references.
  2. References must always be valid — never dangling.1
let mut s = String::from("hi");
let r1 = &s; let r2 = &s;      // many immutable — OK
let r3 = &mut s;               // OK if r1/r2 no longer used
println!("{r3}");

Trying to use &mut s while immutable references are still live triggers a borrow error — the compiler shields you from data races.

A mutable reference lets you change

fn change(s: &mut String) { s.push_str(", world"); }

You must take &mut to modify a borrowed value; a plain &String is read-only.

No dangling references

Rust refuses to return a reference to a value that dies inside the function:1

fn dangle() -> &String {   // error: nothing to borrow from
    let s = String::from("hi");
    &s                     // s is dropped here
}

The fix is to return the owned String instead of a reference.

Slices: borrowed sequences

A slice is a reference to a contiguous part of a collection — &str for strings, &[T] for arrays. It borrows, doesn't own, so it never outlives the data it points into.

Key idea If passing a value into a function and wanting it back afterwards is tedious (Lesson 3), the answer is a reference: borrow it, let the function look, and the owner keeps it. Just honor the two rules.
