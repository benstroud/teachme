Variables, Types & Control Flow

Immutability by default, shadowing, and expressions — Rust's liberal-but-controlled grammar.

The mental model in one sentence

Rust favors clarity and safety: variables are immutable by default, types are explicit, and most constructs are expressions that produce values.1

immutable vs mut vs shadowing

let x = 5;            // immutable — cannot reassign
let mut y = 5;        // mutable
y = 6;                // OK

let spaces = "   ";         // &str
let spaces = spaces.len();  // shadow: now usize — type can change
  • Reassigning an immutable produces error E0384; add mut to opt in.1
  • Shadowing re-binds a name with a new let; unlike mut, it can change the type.1
  • const is a compile-time constant with an explicit type, never reassigned.

Annotate types where the compiler can't infer a default: let x: u64 = 5;.

Control flow as expressions

let kind = if x > 0 { "positive" } else { "non-positive" };

loop { break; }                      // infinite loop with break
while y > 0 { y -= 1; }
for n in 1..=5 { println!("{n}"); }  // range, inclusive when '..='

In Rust, if is an expression — both branches must yield the same type, and the value flows into the binding.2

Functions

fn main() {
    let total = add(2, 3);
}

fn add(a: i32, b: i32) -> i32 {   // return type after ->
    a + b                        // last expression is the return value
}

The last expression (no semicolon) is returned implicitly — a Rust idiom you'll see constantly.2

Key idea The mut vs let-shadowing distinction is a classic interview trap: mut cannot change a variable's type; shadowing can, because it's a brand-new binding.
