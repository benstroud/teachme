Putting It Together

A small, real program that uses ownership, structs, enums, collections, errors, and a test.

The mental model in one sentence

Everything you've learned composes: define data with structs and enums, collect it, model failure with Result, and prove behavior with a test.

A tiny library

use std::collections::HashMap;

struct Cart {
    items: HashMap<String, u32>,   // item name -> quantity
}

#[derive(Debug)]
enum CartError { Empty }

impl Cart {
    fn new() -> Cart { Cart { items: HashMap::new() } }

    fn add(&mut self, name: &str, qty: u32) {
        let entry = self.items.entry(String::from(name)).or_insert(0);
        *entry += qty;
    }

    fn total_items(&self) -> u32 {
        self.items.values().sum()
    }

    fn biggest(&self) -> Result<&str, CartError> {
        let mut best: Option<(&String, &u32)> = None;
        for (name, qty) in &self.items {
            if best.map_or(true, |(_, b)| qty > b) {
                best = Some((name, qty));
            }
        }
        best.map(|(n, _)| n.as_str()).ok_or(CartError::Empty)
    }
}
  • Field shorthand, entry(...).or_insert(0) to accumulate counts.
  • map_or handles None without a new match.
  • Returns Result to model the "no items" error rather than panic.

A test

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn adds_and_totals() {
        let mut cart = Cart::new();
        cart.add("apple", 2);
        cart.add("pear", 1);
        assert_eq!(cart.total_items(), 3);
    }

    #[test]
    fn empty_cart_is_an_error() {
        let cart = Cart::new();
        assert!(matches!(cart.biggest(), Err(CartError::Empty)));
    }
}
cargo test   // runs the tests

#[test] marks test fns, assert_eq!/assert! check outcomes, and cargo test runs them.

The senior recap

  • Shape data with structs (records) and enums (one-of) + match.
  • Own data by default; borrow (&) or pass &mut when you don't need to own.
  • Handle failures with Result and ?; reserve panic! for true bugs.
  • Make it generic with traits; tie references with lifetimes.
  • Let the compiler teach you — every error names the rule you tripped.
Key idea Rust rewards a small set of mental tools, reused relentlessly. When stuck, trace who owns each value and which operation is borrowing vs moving — ownership answers most design questions.
