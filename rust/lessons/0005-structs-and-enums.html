Structs & Enums

Named bundles of data, and types that model "one of a set" — the two main ways to shape data.

The mental model in one sentence

A struct groups named, typed fields into a record; an enum says a value is one of a set of variants (which can each carry data).12

Structs: defining and building

struct User {
    active: bool,
    username: String,
    email: String,
}

let user1 = User {
    active: true,
    username: String::from("ada"),
    email: String::from("ada@x.dev"),
};
user1.email       // dot notation reads a field
// the whole instance must be mut to change a field

Structs own their data — they use String, not &str, unless you add lifetimes.1

Methods with impl

impl User {
    fn greeting(&self) -> String {
        format!("Hi, {}", self.username)
    }
}
println!("{}", user1.greeting());

Methods live in an impl block and take &self for the instance.1

Enums: one of a set

enum IpAddrKind { V4, V6 }

enum Status {
    Active,
    Disabled,
    Pending(String),   // a variant can carry data
}

let s = Status::Pending(String::from("review"));

Variants are namespaced with :: and are all the same enum type, so a function takes any variant.2

match: exhaustive control flow

fn label(status: &Status) -> &'static str {
    match status {
        Status::Active   => "live",
        Status::Disabled => "off",
        Status::Pending(_) => "awaiting",
    }
}

match can't return without covering every variant — the compiler forces completeness. Use _ as a catch-all if you only care about some cases.2

Option: null, made safe

let a = Some(5);      // Option<i32>
let b: Option<i32> = None;

match b {
    Some(v) => println!("{v}"),
    None    => println!("nothing"),
}

Option<T> is distinct from T — the compiler won't let you use it as a definite value until you handle both variants.2

Key idea Structs are for "contains all of these"; enums are for "is exactly one of these." Paired with match, enums give you compile-time-checked handling of every case — no missing-branch surprises.
