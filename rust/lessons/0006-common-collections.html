Common Collections

Vec, String, HashMap — the standard containers you reach for daily.

The mental model in one sentence

Rust's standard collections store data on the heap and follow the same ownership rules you already know — a vector drops its elements when it goes out of scope.1

Vec<T>: a growable list

let v = vec![1, 2, 3];            // Vec<i32>, inferred
let mut w = Vec::new();
w.push(5);                        // mut needed to push

let third: &i32 = &v[2];          // index → panics if out of bounds
let maybe: Option<&i32> = v.get(2); // get → safe, returns Option

for i in &v { println!("{i}"); }  // iterate by reference
for i in &mut w { *i += 10; }     // mutate through ref

Use v.get(i) when the index might be invalid; use &v[i] when it's guaranteed — indexing a non-existent element panics.1

Storing different types

A Vec holds one type. To store mixed values, wrap them in an enum whose variants hold the different types:1

enum Cell { Int(i32), Float(f64), Text(String) }
let row = vec![Cell::Int(3), Cell::Text(String::from("blue"))];

String: growable UTF-8 text

let mut s = String::from("hello");
s.push_str(", world");
let len = s.len();                 // bytes, not characters
let first = &s[0..4];              // slicing by byte range

String and the borrowed &str are different types; String::from creates an owner.2

HashMap<K, V>: key-value pairs

use std::collections::HashMap;

let mut scores = HashMap::new();
scores.insert(String::from("Blue"), 10);
let v = scores.get(&"Blue");          // Option<&i32>
for (key, value) in &scores { println!("{key}: {value}"); }

get returns an Option; insert needs the map to be mut.

Key idea The collections are generic (Vec<T>, HashMap<K,V>) and obey the move/copy/borrow rules you've learned — remember that pushing a String into a vector moves it.
