Ownership & Move Semantics

The idea that makes Rust unique: every value has exactly one owner, and moving transfers it.

The mental model in one sentence

Ownership is a set of compiler-checked rules: each value has one owner, only one owner at a time, and when the owner goes out of scope the value is dropped.1

The three ownership rules

  1. Each value in Rust has an owner.
  2. There can be only one owner at a time.
  3. When the owner goes out of scope, the value is dropped (freed).1

Stack vs heap

The stack holds fixed-size values in LIFO order; the heap holds data whose size isn't known at compile time, reached through a pointer. String is growable and heap-allocated.1

let s1 = String::from("hello");   // s1 owns a heap String
let s2 = s1;                      // ownership MOVES to s2
// println!("{s1}");               // error: value borrowed after move

After the move, s1 is invalid — exactly one owner prevents two frees of the same memory.

Copy vs move

Simple types stored entirely on the stack copy on assignment instead of moving, so both variables stay usable:2

let a = 5; let b = a;   // i32 is Copy — a and b both valid

Copy types: integers, bool, float, char, and tuples of those. Heap types like String are not Copy. When you want both, call .clone() to deep-copy explicitly.

Ownership transfer through functions

fn main() {
    let s = String::from("hi");
    takes_ownership(s);   // s moves in, unusable after
    let x = 5;
    makes_copy(x);        // x is Copy — still usable
}

fn takes_ownership(some: String) { println!("{some}"); }

When a heap value is passed to a function, it moves; returning a value moves ownership back out. This "too much ceremony" is what references (Lesson 4) solve.2

Key idea Move is not a copy — it's a transfer of ownership. The compiler rejects any use of the old binding afterward. This single rule eliminates double-free and use-after-free bugs at compile time.
