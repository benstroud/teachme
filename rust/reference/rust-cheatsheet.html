Rust Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. Hello, Rust

cargo new hello && cd hello   # creates src/main.rs + Cargo.toml
cargo run                     # build and run
cargo build                   # build only (debug)
cargo test                    # run tests

// src/main.rs
fn main() {
    println!("Hello, world!");
}

cargo is the build tool and package manager; println! is a macro (hence the !).1

2. Variables & expressions

let x = 5;              // immutable by default
let mut y = 5;          // mutable
const MAX: u32 = 100;   // const, type required

// shadowing — new let, can change type
let spaces = "   ";
let spaces = spaces.len();        // now usize

let z = if x > 0 { 1 } else { 0 };   // if is an expression
  • Integers: i8..i128, u8..u128; default i32. f32/f64, bool, char.2
  • Reassigning an immutable yields error E0384; shadowing with let can retype.

3. Ownership & move

let s1 = String::from("hello");
let s2 = s1;            // s1 MOVES into s2 — s1 unusable
// println!("{s1}");     // error: value borrowed after move

let a = 5; let b = a;   // i32 is Copy — both usable
  • Three rules: each value has one owner; one owner at a time; drop when owner goes out of scope.3
  • Heap values (String) move; Copy types (int/bool/float/char) copy.
  • Need both copies? Use .clone().

4. References & borrowing

fn len(s: &String) -> usize { s.len() }   // borrow, not own
fn change(s: &mut String) { s.push_str("!"); }

let r1 = &s; let r2 = &s;      // many immutable  — OK
let r3 = &mut s;               // one mutable     — OK
// mixing them after use ends is fine; overlapping is not
  • Rules: one mutable ref OR any number of immutable refs; references must be valid (never dangling).4
  • Slices: &str, &[T] — borrowed views without owning.

5. Structs, enums, match

struct User { active: bool, username: String }

impl User {
    fn new(name: String) -> User {
        User { active: true, username: name }
    }
}

enum Status { Active, Disabled, Pending(String) }   // variant can hold data

let u = User { active: true, username: String::from("ada") };
match &u.username {
    Status // (enum shown elsewhere)
}
enum Coin { Penny, Quarter }
fn value(c: Coin) -> u8 {
    match c { Coin::Penny => 1, Coin::Quarter => 25 }   // exhaustive match
}
  • Enums model "one of a set"; variants namespaced Type::Variant.56
  • match must cover every variant — the compiler enforces exhaustiveness.
  • Option<T> = Some(T) or None; distinct from T; use match or methods to get the inner value.6

6. Collections

let v = vec![1, 2, 3];           // Vec<i32>
let mut v = Vec::new(); v.push(5);
let n: &i32 = &v[2];             // panics if out of bounds
let n2: Option<&i32> = v.get(2); // safe; Option
for i in &v { println!("{i}"); }

// String: growable UTF-8 text
let mut s = String::new();
s.push_str("hi");

// HashMap
use std::collections::HashMap;
let mut scores = HashMap::new();
scores.insert(String::from("Blue"), 10);
scores.get(&"Blue")              // Option

Vectors hold one type; store mixed values via an enum variant instead.7

7. Error handling

use std::fs::File;
fn open() -> Result<File, std::io::Error> {
    let f = File::open("x.txt")?;   // returns Err early, or the value
    Ok(f)
}
// unwrap: extract value or panic
let f = File::open("x.txt").expect("file missing");
  • Recoverable = Result<T,E>; unrecoverable = panic!.8
  • ? propagates errors; unwrap/expect panic instead.

8. Generics, traits, lifetimes

fn largest<T>(list: &[T]) -> &T { ... }      // generic over T

trait Shape { fn area(&self) -> f64; }        // interface
impl Shape for Circle { fn area(&self) -> f64 { ... } }

// lifetime: ties an output reference to an input
fn first_word<'a>(s: &'a str) -> &'a str { ... }
  • Generics: abstract stand-in for a type, so code runs on many types.9
  • Traits: shared behavior (like an interface); examples Copy, Clone, Debug, Display.
  • Lifetimes ('a) let the compiler prove references stay valid.

9. Design checklist

  • Prefer ownership by default — use owned String/Vec in structs; borrow (&) in function params when you don't need ownership.
  • One mutable or many immutable references — never overlap &mut with &.
  • Model optionality with Option, errors with Result; avoid unwrap in library paths.
  • Use match for exhaustive handling of enums.
  • Read the compiler — errors like E0502 (borrow), E0384 (immutable) point exactly at the fix.
