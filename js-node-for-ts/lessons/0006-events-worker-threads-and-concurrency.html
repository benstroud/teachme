Events, Worker Threads & Concurrency

Decouple with node:events and offload CPU work with node:worker_threads.

Why you need a third way

Node's event loop is excellent at I/O concurrency, but CPU-heavy tasks (crypto, image processing, heavy math) will block the loop. Two native modules cover the gaps: node:events for decoupled in-app messaging, and node:worker_threads for true multi-threaded CPU work.1

Type-safe event emitters

The EventEmitter pattern is everywhere in Node. In TypeScript you can bind the event names to their payload types with a generic map, so emitting the wrong shape is a compile error:

import { EventEmitter } from "node:events";

interface AppEvents {
  userLogin: (username: string, timestamp: number) => void;
  error: (err: Error) => void;
}

class TypedEmitter extends EventEmitter {
  on<K extends keyof AppEvents>(eventName: K, listener: AppEvents[K]): this {
    return super.on(eventName, listener);
  }
  emit<K extends keyof AppEvents>(eventName: K, ...args: Parameters<AppEvents[K]>): boolean {
    return super.emit(eventName, ...args);
  }
}

const bus = new TypedEmitter();
bus.on("userLogin", (user, time) => {
  console.log(`User ${user} logged in at ${time}`);
});
bus.emit("userLogin", "alice", Date.now());

This reuses the <K extends keyof AppEvents> generic trick from the TypeScript course: the emitter enforces exactly the events you declared, with exactly the payload type each expects.

Offloading CPU work to worker threads

When a computation risks blocking the loop, move it to a separate thread with worker_threads. The main thread spawns a Worker; the worker posts results back over parentPort:

import { Worker, isMainThread, parentPort, workerData } from "node:worker_threads";

if (isMainThread) {
  function runComputeTask(data: number): Promise<number> {
    return new Promise((resolve, reject) => {
      const worker = new Worker(import.meta.filename, { workerData: data });
      worker.on("message", resolve);
      worker.on("error", reject);
    });
  }
  runComputeTask(100).then((res) => console.log("Computation result:", res));
} else {
  // Worker thread execution
  const result = (workerData as number) * 2;
  parentPort?.postMessage(result);
}
Key idea The event loop runs I/O concurrently on one thread; worker threads give you real parallel CPU execution on additional OS threads. Reach for them when the loop is the bottleneck, not for regular I/O (which the loop already handles well).
