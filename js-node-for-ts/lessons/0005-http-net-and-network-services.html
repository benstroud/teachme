HTTP Servers, Sockets & Fetch

Native servers with node:http, TCP with node:net, and the global fetch client.

A server without a framework

You do not need Express to serve HTTP in Node.js. The standard node:http module builds high-performance servers with explicit request/response handling — full control, no framework opaqueness:1

import http from "node:http";

interface HealthResponse { status: string; uptime: number; }

const server = http.createServer((req, res) => {
  if (req.method === "GET" && req.url === "/health") {
    const payload: HealthResponse = { status: "healthy", uptime: process.uptime() };
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify(payload));
  } else {
    res.writeHead(404, { "Content-Type": "text/plain" });
    res.end("Not Found");
  }
});

server.listen(8080, "127.0.0.1", () => {
  console.log("Server listening on http://127.0.0.1:8080");
});

The request req and response res are streams — that's why they compose with the pipeline lesson you just finished.

Outbound requests with the global fetch

Modern Node.js ships the standard global fetch API, so HTTP clients need no third-party dependency. Typed and native:

async function fetchGitHubUser(username: string): Promise<{ login: string; public_repos: number }> {
  const response = await fetch(`https://api.github.com/users/${username}`, {
    headers: { "User-Agent": "NodeJS-Client" }
  });
  if (!response.ok) {
    throw new Error(`GitHub API error: ${response.statusText}`);
  }
  return response.json() as Promise<{ login: string; public_repos: number }>;
}
Key idea node:http builds servers; global fetch builds clients; node:net gives raw TCP when you need a protocol below HTTP. All native, all typed.
