JS Core, Prototypes & Object Model

The runtime TypeScript erases: prototypal inheritance, closures, and dynamic objects.

TypeScript is erased; JavaScript runs objects

You use types, classes, interfaces, and generics every day. At runtime, though, TypeScript is compiled away. JavaScript executes entirely through prototypal inheritance and a dynamic object model. Mastering that runtime foundation is what makes your Node.js backend behavior predictable.1

Prototypal inheritance vs. class sugar

ES6 class is syntactic sugar over prototype chains. Every object has an internal link ([[Prototype]], read via Object.getPrototypeOf() or __proto__) pointing at another object. Looking up a property walks the chain until found or until null:

// Base prototype object
const loggerPrototype = {
  log(message) {
    console.log(`[LOG]: ${message}`);
  }
};

// Create an object LINKED to that prototype
const service = Object.create(loggerPrototype);
service.name = "AuthService";

service.name;        // "AuthService"  (own property)
service.log("Active"); // "[LOG]: Active" (inherited up the chain)

A class compiles down to a constructor function whose instances link to the class's prototype — the same mechanism, nicer syntax. Structural typing at compile time; prototypes at runtime.

Closures and scope

Functions capture their lexical scope even after the outer function returns. This is the backbone of data encapsulation and factory functions in Node.js:

function createCounter(initial = 0) {
  let count = initial;             // private via closure — no object needed
  return {
    increment() { return ++count; }
  };
}

const counter = createCounter(10);
counter.increment(); // 11
counter.increment(); // 12  — count persists inside the closure
Key idea Types check which values can flow where, at compile time. Prototypes and closures determine how objects and state actually behave, at runtime. Both matter; never confuse them.
