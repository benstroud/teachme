Streams, Buffers & Binary Data

Process large data in chunks with node:stream and handle raw bytes with node:buffer.

Don't load everything into RAM

Loading a large file entirely into memory exhausts RAM and pressures the garbage collector. Node streams process data chunk by chunk, keeping memory use low and constant. For a TypeScript developer, typing stream events and pipelines makes data transformations safe.1

Buffers: raw bytes outside the heap

A Buffer is a fixed-size chunk of memory allocated outside the V8 heap, used for binary data (file I/O, network packets, cryptography). It is bytes, not text — don't treat it as a UTF-8 string:

import { Buffer } from "node:buffer";

const buf = Buffer.from("Hello Node.js Streams", "utf-8");
console.log(buf.length);        // byte length (not character count)
console.log(buf.toString("hex")); // hex representation of the bytes

Compose pipelines instead of listener soup

Manual .on("data")/.on("error") wiring is leak-prone and hard to read. node:stream/promises exports pipeline, which composes a read→transform→write chain with automatic cleanup and error propagation:

import fs from "node:fs";
import zlib from "node:zlib";
import { pipeline } from "node:stream/promises";

async function compressFile(inputPath: string, outputPath: string): Promise<void> {
  try {
    await pipeline(
      fs.createReadStream(inputPath),
      zlib.createGzip(),
      fs.createWriteStream(outputPath)
    );
    console.log("File compression completed successfully.");
  } catch (error) {
    console.error("Pipeline compression failed:", error);
    throw error;
  }
}
Key idea Why streams? Constant, low memory usage for arbitrarily large data — the whole point of a streaming pipeline is that you never hold more than a chunk at a time.
