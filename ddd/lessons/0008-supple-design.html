Lesson 8 of 10Domain-Driven Design

Supple Design

A supple design is one that developers can use, combine, and change without fear. Its interfaces say what they do, its functions have no hidden side effects, and its rules are stated so they can be checked.

What supple means

Part III's chapter Supple Design describes code that is easy to work with, not just correct. The book's aim is for developers to be able to combine the model's parts in ways the original authors did not plan, and trust the result. A rigid design breaks when it is combined. A supple one bends without splitting.1

Habits that make a design supple

HabitWhat it looks like
Intention-revealing interfacesA method is named for what it means, such as reopen(), not for how it changes a field
Side-effect-free functionsA query returns a value and changes nothing, so it can be called freely
AssertionsRules are stated as conditions the code checks, such as "a paid invoice cannot be edited"
Closure of operationsAn operation on a value returns the same kind of value, so it can be chained
Declarative designCode states what must be true, and leaves the how to the building block

Before and after

// Hard to use: the name hides the effect, and the caller must know the field
invoice.setStatus("OPEN");

// Intention-revealing: the name says what the business means
invoice.reopen();

// A side-effect-free query can be called anywhere
invoice.isOverdue(today);
Closure of operation A common example is numeric addition: adding two numbers gives a number, so you can combine any number of additions. A money operation that returns a money value does the same for the domain.

Your task (one attempt)

  1. Find one method in your code whose name describes how it works, not what it means. Propose a name that reveals intent.
  2. Find one function that both returns a value and changes state. Split it into a query and a command, and say which call sites change.
  3. Choose one rule and write it as an assertion. Say where it is checked, and what the caller sees if it fails.

Check yourself

Which name is an intention-revealing interface?

reopen() says what the business means. The other names describe the mechanism or a field, which hides the intent.

Why is a side-effect-free function easier to combine?

A query that changes nothing can be called in any order and any number of times, which is part of what makes a design supple.

What is the main purpose of an assertion in a supple design?

An assertion states a rule as a checkable condition. It makes the rule visible in the code and fails when it is broken.
