Ubiquitous Language

The team uses one language for the domain, in conversation, in documents, and in the code. Where the words disagree, the model is wrong, and the disagreement is the thing to fix.

What the term means

Evans calls the shared vocabulary of the team the ubiquitous language. It is ubiquitous because it appears everywhere the model does: in the code's class and method names, in the meeting room, in the requirements, and in the tests. Fowler describes it as a common, rigorous language built between developers and users, based on the domain model used in the software.21

The rigour matters. Fowler notes that software does not cope well with ambiguity, so the terms must be precise enough for the code to use them.2

Where it lives

PlaceWhat the language looks like
ConversationA domain expert says "a claim is reopened", and the developer uses the same phrase
Codeclaim.reopen(), not claim.setStatus("OPEN")
DocumentsRequirements and tests name the same concepts the code does
DiagramsBoxes carry the domain's names, not the team's internal shorthand

Experts object, developers listen

Fowler quotes Evans on a practical rule: domain experts should object to terms or structures that are awkward or inadequate to convey their understanding.2 If an expert hears a developer say "entity record" and winces, the code has drifted from the business. The objection is useful data, not a style complaint.

Watch for translation When a developer says "the user" but the expert says "the applicant", every conversation has a silent translation step. Translation is where meanings get lost. Pick the expert's word and use it everywhere.

Your task (one attempt)

  1. Take the five nouns from lesson 1. For each, find where it appears in some code you have written, such as a class name, a variable, or a column.
  2. Mark every place where the code uses a different word for the same idea. Write down which word the business would use.
  3. Rename one of them in the code, or write a short note proposing the rename. Predict which conversations get easier, and which get harder.

Check yourself

What does "ubiquitous" mean in the ubiquitous language?

The language is ubiquitous because it is used in conversation, documents, diagrams, and code alike. It is not a shared standard across projects.1

A domain expert says "the applicant". The code says user. What is the most useful next step?
