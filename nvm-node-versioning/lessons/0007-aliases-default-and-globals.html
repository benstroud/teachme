Aliases, Default & Globals

Named pointers, the default shell version, and why globals do not follow you.

The mental model in one sentence

Aliases are named pointers to versions; default decides what a fresh shell gets, and global npm packages are per-version — so switching versions can "lose" your CLIs unless you migrate them.1

Pointers and defaults

nvm alias default 20      # new shells start on 20.x
nvm alias work 20.11.1    # a named pointer you can nvm use work
nvm unalias work
nvm ls                    # shows installed versions + aliases

Globals do not follow you

# install a version and carry over its globals from another version
nvm install 20 --reinstall-packages-from=18

# or reinstall a CLI explicitly after switching
npm install -g typescript ts-node

Because each version has its own global node_modules, a CLI installed under 18 is not present under 20 until you reinstall or migrate it.1

Key idea Prefer project-local tooling (npx, devDependencies) over global installs. Globals are exactly the thing that makes your environment harder to reproduce.1
