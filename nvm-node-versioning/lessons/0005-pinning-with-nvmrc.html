Lesson 5 of 10nvm · Node Version Management

Pinning with .nvmrc

Name the runtime in the repo, switch to it, and declare intent with engines.

The mental model in one sentence

A project pins its runtime with an .nvmrc file; nvm use reads that file, and --install-if-missing installs the version if you do not have it yet.1

Pin, then use

# in the project root
echo "20" > .nvmrc          # a major, or an exact version like 20.11.1

nvm use                    # read .nvmrc and switch
nvm use --install-if-missing   # install it first if absent

cat .nvmrc                 # commit this file

Commit .nvmrc so every checkout names the same runtime. Pair it with engines in package.json to declare intent even to tools that do not read .nvmrc.2

Auto-switching (optional)

You can add a shell hook that runs nvm use when you cd into a directory containing .nvmrc. It is convenient, but keep it out of CI and scripts, where explicit switching is clearer.1

Key idea Pin a major (e.g. 20) for apps that want the latest patch of a line; pin an exact version when you need byte-for-byte reproduction. State which policy your team uses.1

Check yourself

2. nvm use --install-if-missing…
