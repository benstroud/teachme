Lesson 9 of 10nvm · Node Version Management

Alternatives & Edge Cases

fnm, Volta, nvm-windows, asdf — and the shell, Docker, and Apple Silicon traps.

The mental model in one sentence

nvm is the classic choice, but it is not the only one — and its shell-function design has real edge cases (non-interactive shells, Docker, Apple Silicon) you should know before standardizing.1

The alternatives

ToolDistinguishing trait
nvmSourced shell function; POSIX shells.1
nvm-windowsSeparate Windows implementation.2
fnmFast, cross-platform manager.3
VoltaPins toolchains per project, shell-agnostic.4
asdfMulti-language version manager.5

Edge cases that bite

  • Non-interactive shells (cron, some IDEs) do not source rc files, so nvm is missing.1
  • Docker: images often pin Node in the base image; you do not need nvm there.
  • Apple Silicon: pre-16 Node may need x86_64/Rosetta; the nvm README documents the workaround.1
Key idea Standardize on one manager per team and write it in onboarding. Mixing nvm and Volta on the same machine is a reliable way to get "wrong version" bugs.4
