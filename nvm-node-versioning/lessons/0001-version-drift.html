Lesson 1 of 10nvm · Node Version Management

Version Drift

Why one global Node fails, and why pinning is a reproducibility practice.

The mental model in one sentence

One global Node install cannot serve projects that need different majors — without explicit version pinning, "what runs" silently drifts between your laptop, a teammate, and CI.1

The failure modes

SymptomUnderlying cause
Old project fails after an upgradeGlobal Node moved to a new major.2
CI green, local red (or vice versa)Different Node versions in each environment.
Native module build errorsCompiled for a different Node ABI.
"Works on my machine"The runtime was never pinned.3

The fix is a practice, not a command

  • Declare the expected runtime in the project (engines, .nvmrc).3
  • Switch per project with a version manager instead of one global install.1
  • Make CI use the same version the project declares.
Key idea Version drift is a reproducibility bug. The moment two developers or a CI runner disagree on the runtime, every other guarantee is conditional.1
