Glossary

Advanced TypeScript — the canonical vocabulary. Adhered to in every lesson.

The Set Model

Type (as a set)
A type is the set of all values that belong to it. Reasoning about types as sets is the foundation of everything else here.
string = the set of every possible string value.
Literal type
A type whose set contains exactly one value.
"on" is a set of size 1; it is a subset of string.
Assignability
"B is assignable to A" means a B value is accepted where an A is expected. Equivalent to B ⊆ A — B's set is a subset of A's.
Subtype / supertype
B is a subtype of A when B ⊆ A (B is narrower). A is then the supertype (wider). Subtypes are assignable to supertypes.
Structural typing
TypeScript decides assignability by an object's shape (its members), not by its declared name. An object with all the required members fits.
Union A | B
Set union (∪) — a value in A or B. Wider than either part.
Intersection A & B
Set intersection (∩) — a value in A and B. For object types, this combines members (narrower).
never
The empty set (∅). No value has this type. It is the subtype of every type and the absorbing element of unions (T | never = T).
unknown
The universal set — contains every value. The supertype of every type. You must narrow it before use. The type-safe top type.
any
An escape hatch that disables type checking. Assignable to and from everything. Not a set — a hole in the type system. Avoid in senior code.

Narrowing & Control Flow

Narrowing
Using a runtime check to shrink a type's set within a branch — ruling out members that the check excludes.
Inside if (typeof x === "number"), string | number ⟶ number.
Control-flow analysis
TypeScript's engine that tracks the most specific type at every point along every code path (branches, loops, assignments, early returns).
Type guard
Any expression TypeScript recognizes as narrowing: typeof, instanceof, in, equality, truthiness.
Type predicate
A user-defined guard: a function whose return type is arg is T. Callers narrow on a true result. TS trusts the body — it does not verify it.
function isFish(p: Fish | Bird): p is Fish
Discriminant / Discriminated union
A union whose members share a common literal property (the discriminant), letting a switch narrow each case cleanly.
{ kind: "circle" } | { kind: "square" } — kind is the discriminant.
Exhaustiveness check
Assigning the value to never in a default branch so that an unhandled union member becomes a compile error. Relies on never being the empty set.
The null trap
A JS quirk: typeof null === "object". Use x != null (loose !=) to exclude both null and undefined.

Generics

Generic
A function, type, or class parameterized by one or more types. Think: a function whose arguments are sets, returning a set.
Type parameter
The variable in angle brackets (<T>) standing for a type the caller supplies or the compiler infers.
Type-argument inference
The compiler deducing a type parameter from the values passed, so you rarely write <T> explicitly.
Constraint (extends)
An upper bound on a type parameter. T extends X means T's set ⊆ X's set — the same subset meaning as in conditional types. Not class inheritance.
keyof T
The union of T's property-name literals. keyof {a:1; b:2} = "a" | "b".
Indexed access type T[K]
The type of property K on T. Tracks the exact value type, e.g. {a:number}["a"] = number.

Variance

Variance
How the subset relation ⊆ between types is transformed when they're wrapped in a compound type (array, function parameter, function return). Either preserved, flipped, dropped, or both-ways.
Covariant
Preserves the direction: if Cat ⊆ Animal then the wrapped type does too. Holds for output positions — function return types and readonly arrays.
() => Cat is assignable to () => Animal.
Contravariant
Flips the direction. Holds for input positions — function parameters (under strictFunctionTypes). A function taking the wider type is assignable where a narrower-parameter type is expected.
(a: Animal) => void is assignable to (c: Cat) => void.
Invariant
Neither direction is safe. The logically-correct variance for a read-write slot (e.g. a mutable array, which is both read and written).
Bivariant
Both directions accepted — deliberately unsound, kept for ergonomics. TS uses it for method parameters and treats mutable arrays as covariant for the same reason.
"Demand less, deliver more"
The function-assignability rule: A is assignable to B when A's parameters are wider (contravariant) and its return is narrower (covariant).

Conditional Types & infer

Conditional type
A type-level ternary: T extends U ? X : Y. The extends test is the subset check (T ⊆ U) — the true branch is taken when it holds.
"hi" extends string ? 1 : 0 = 1.
Distributive conditional type
When the checked type is a bare type parameter given a union, the conditional runs once per member and unions the results.
ToArray<A | B> = ToArray<A> | ToArray<B>.
Disabling distribution
Wrap both sides in a one-tuple — [T] extends [U] — to test the union as a single whole.
infer
A placeholder declared inside the extends clause that pattern-matches a type and binds a captured part to a name, usable in the true branch.
T extends (...a:any[]) => infer R ? R : never captures the return type (= ReturnType).
never as the else-branch
The idiomatic "no match" result: ∅ means "no values," and it absorbs cleanly under distribution (T | never = T). Prefer it over any/unknown.

Mapped Types & Key Remapping

Mapped type
A type that iterates over the keys of another type (keyof T) and rebuilds an object, transforming each property. Shape: { [K in keyof T]: … }.
{ [K in keyof T]: T[K] } reproduces T; add ?, readonly, or a new value type to transform it.
The two type variables in a mapped type
Inside { [K in keyof T]: V }, K is the key (a literal type), and you can also capture the value with [P in keyof T] then use T[P] (indexed access). A mapped type is a block transform: same keys, new values.
Homomorphic
A mapped type that writes keyof T directly over an original type — it preserves its modifiers (readonly, optional ?) unless you strip them. That's why Partial<T> and Readonly<T> keep the shape of T.
Key remapping (as)
Rename keys with [K in keyof T as NewKey]: …. Since TS 4.1; combined with never in the key position to drop keys, or with template literals to rename.
{ [K in keyof T as `get${Capitalize<K>}`]: () => T[K] } turns name into getName(): string.
Utility functions built from mapped types
Partial (all keys optional), Required (all required), Readonly (all readonly), Pick / Omit (subset of keys), Record (uniform keys→value).

Template Literal Types

Template literal type
A string-literal type built with backtick syntax and ${…} substitutions whose result is a set of strings — the cross product of each placeholder's literal values. `img-${number}` = the type of every "img-<N>" string.
Type of the result
If all placeholders are literal (or already narrowed by infer / never), the result is a finite literal type. If a placeholder is a wide type like number or string, the result is a wider inferred type (e.g. `${number}` is `${number}`, a distinct non-literal type).
Pattern matching with infer + template literals
Use a template literal in the extends clause with infer placeholders to describe a string's shape: T extends `get${infer R}` ? R : never. This is how you parse URLs, ids, and paths at the type level.
Capitalization helpers
Built-in string-transformation utilities: Uppercase, Lowercase, Capitalize, Uncapitalize.
Key relationship to mapped types
Template literals + as key remapping rename properties; template literals + infer pattern-match on string content. Together: transform keys or values, or both.

Recursive Type-Level Programming

Recursive type
A type (often a conditional or mapped type) that references itself to process a structure step by step — unwrapping Promise<Promise<…>>, or a tuple type down to its base case. The machine at work: extends as a test, infer as destructuring, and the type name as the recursive call.
Base case
The terminating branch that does not recurse (empty tuple, non-promise, []). Every recursive type needs one, mirroring value-level recursion. It usually resolves to never, [], or the unchanged type.
Tail recursion optimization (TS ≥ 4.5)
When the recursive call is in tail position (the last operation, usually the true branch of a conditional), TypeScript can reuse the stack — letting you recurse over arbitrarily long unions/tuples without hitting the depth limit. Put the recursion last.
Depth limit
TS enforces a recursion-depth cap (default roughly 50 levels before 4.5, up to ~10000 with tail-call optimization). Hit it and you get a "type instantiation depth exceeded" error — the type-level stack overflow.
type recursion vs. interface recursion
interface Node { children: Node[] } is recursive data — fine.
Recursive type-conditional computation (like Awaited) is type-level programming, the thing this course means by "recursion."

Type-Safe API Design

Branded type / nominal fake
A structural type plus a unique marker that only you can produce, so two otherwise-identical shapes (e.g. two strings, a userId vs an email) are not interchangeable. type UserId = string & { __brand: "UserId" } — a nominal-style type you shape via a constructor function.
Builder pattern
A fluent API where each method call returns a new type that exposes only the next valid methods. By returning progressively narrower types, TypeScript makes state-machine violations a compile error.
Overloads (and their ordering)
Multiple signatures for one function name. TS picks the first matching overload, so order the most specific first. A string | number overload after a "exact"-literal overload lets a literal get the strict path.
Literal types in parameters
Accepting a union of literals ("small" | "large") instead of string forces the caller to pick an allowed value — autocomplete offers them, and typos become errors.
Function overloading as a narrowing tool
Overloads let you express return type depends on input argument: a (x: number) => number and (x: string) => string pair give the caller a precisely-typed result per input, without losing the wide fallback.
