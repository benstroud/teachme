Lesson 05 · Type-level programming

Conditional Types & infer

A type that decides — and a way to reach inside another type and pull a piece out.

★ Mission link: this is where you cross from using types to computing with them. Every reusable utility worth its name (ReturnType, Awaited, your own) is a conditional type with an infer. Builds on Lesson 03 (extends = ⊆), Lesson 01 (never = ∅), and Lesson 04 (param vs. return positions).

The ternary, lifted to types

You know the value-level ternary. A conditional type is the same shape, one level up — and the test extends is the exact ⊆ (subset) reading from Lesson 03, not class inheritance:1

type IsString<T> = T extends string ? "yes" : "no";

type A = IsString<"hi">;   // "yes"  — "hi" ⊆ string
type B = IsString<number>; // "no"   — number ⊄ string

Read it aloud: "if T's set fits inside string's set, then …, else …." That's all a conditional type is.

Distribution: it loops over unions for free

The one rule that surprises everyone: when the checked type is a bare type parameter and you hand it a union, the conditional distributes — it runs once per member and unions the results.2

type ToArray<T> = T extends any ? T[] : never;

type R = ToArray<string | number>;
// NOT (string | number)[] — it distributes:
// = ToArray<string> | ToArray<number> = string[] | number[]

To stop distribution, wrap both sides in a one-tuple [T] extends [U] — now the union is tested as a single whole:2

type ToArray<T> = [T] extends [any] ? T[] : never;
type R = ToArray<string | number>;  // (string | number)[]
Why this matters: distribution is how a single conditional transforms every member of a union at once — the workhorse of type utilities. But it's also a silent footgun: forget the brackets and your "whole-union" test secretly runs per-member. Knowing when to add [ ] is a senior tell.

infer: pattern-match and capture

Inside the extends clause you can declare a placeholder with infer — "match this shape, and bind this part to a name I can use in the true branch."3 This is how you reach into a type:

// Pull the element type out of an array
type ElementOf<T> = T extends (infer U)[] ? U : never;
type E = ElementOf<boolean[]>;   // boolean

// The real ReturnType — capture the return position
type MyReturn<T> = T extends (...a: any[]) => infer R ? R : never;
type N = MyReturn<() => number>;  // number

Notice the fallback is never — the empty set from Lesson 01. "No match" should produce "no values," and T | never collapses to T, so a never branch vanishes cleanly under distribution. That's why it's the idiomatic else-branch, not any or unknown.

Variance, made concrete: swap the return for a parameter — T extends (a: infer P) => any ? P : never — and you've built Parameters. The two infer positions are exactly the covariant (return) and contravariant (parameter) slots from Lesson 04. Same machine, opposite variance.
