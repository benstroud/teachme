Lesson 02 · Foundations

Narrowing & Control-Flow Analysis

Watch TypeScript shrink a set, line by line, as it reads your code.

★ Mission link: narrowing is how you make a type-safe API feel safe — the compiler proves which branch you're in. It's also the #1 source of "why is this still string | undefined?" errors. Builds directly on Lesson 01.

The idea: narrowing = shrinking the set

From Lesson 01, a union like string | number is the union of two sets. Narrowing is what happens when TypeScript uses your runtime checks to rule out members and leave a smaller set in a given branch.1 The engine that does this — tracking the type at every point along every code path — is called control-flow analysis.

function pad(p: number | string) {
  if (typeof p === "number") {
    // here the set is narrowed to ⟶ number
    return " ".repeat(p);
  }
  // the number was ruled out, so here ⟶ string
  return p.toUpperCase();
}

Senior gotcha — the null trap: typeof null === "object" in JavaScript. So if (typeof x === "object") does not remove null from string[] | null.1 Reach for x != null (loose != catches both null and undefined) before treating something as present.

Type predicates: teach the compiler your own guard

A function returning arg is Type is a type predicate (user-defined type guard). It exports a narrowing decision so callers narrow automatically:2

function isFish(pet: Fish | Bird): pet is Fish {
  return (pet as Fish).swim !== undefined;
}
if (isFish(pet)) pet.swim();   // pet ⟶ Fish
else           pet.fly();    // pet ⟶ Bird
Power tool, sharp edge: a predicate is an assertion you are trusted on — TypeScript does not verify the body matches the claim. A wrong predicate silently lies to every caller. Use them, but keep the body honest.

The senior pattern: discriminated unions + exhaustiveness

Give each member of a union a shared literal property (the discriminant). Switching on it narrows cleanly — and a never in the default turns a missed case into a compile error.3 This is where Lesson 01's "never = empty set" earns its keep:

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number };

function area(s: Shape) {
  switch (s.kind) {
    case "circle": return Math.PI * s.radius ** 2;
    case "square": return s.side ** 2;
    default:
      const _exhaustive: never = s; // add a 3rd shape ⟶ this line errors
      return _exhaustive;
  }
}

Add a "triangle" later and forget to handle it? s in the default is no longer never — it's {kind:"triangle";…} — and the assignment fails to compile. The type system forces you to update every consumer. That's senior-grade safety.
