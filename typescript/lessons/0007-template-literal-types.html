Lesson 07 · Type-level programming

Template Literal Types

A string's shape at the type level — combine them with infer and mapped types to parse and rewrite strings.

★ Mission link: template literals turn string values into a set of strings the compiler understands. With them you can type route paths, event names, ids, and API keys such that only well-formed strings compile — and, combined with as key remapping, rewrite object types by their keys. Builds on Lesson 05 (infer for pattern capture) and Lesson 06 (as key remapping).

Backtick syntax, set-of-strings semantics

A template literal type writes ${…} placeholders. The result is the set of every string you could form — the cross product of each placeholder's literal values.1

type Level = "info" | "warn" | "error";
type LogKey = `event.${Level}`;
// "event.info" | "event.warn" | "event.error"

const k: LogKey = "event.warn";   // ok
const bad: LogKey = "event.trace"; // error: "trace" is not in Level

Read it as: "a LogKey is the string "event." followed by one of the level strings."The set grows as a cross product — two placeholders with 3 and 4 values each give 3 × 4 = 12 possible strings.

Wide types stay wide

If a placeholder is a wide type like number or string, the result is not a finite literal union — it's a distinct, precise type that describes the shape. You can't enumerate a number, so `img-${number}` is its own type, assignable to string but narrower than it:2

type AssetId = `img-${number}`;
let a: AssetId;
a = "img-42";     // ok
a = "img-x";     // error
const s: string = a;  // ok — every AssetId is a string

Pattern matching: infer inside the literal

The real power pairs a template literal with infer in an extends clause. This parses a string's shape at the type level — the type-level equivalent of a regex capture group.3

// strip a "get" prefix, capture the rest
type StripGet<T> = T extends `get${infer R}` ? R : never;
type A = StripGet<"getUser">;  // "User"
type B = StripGet<"nope">;    // never — didn't match

// decompose a dotted path "orders.eu.placed" into its parts via recursion (Lesson 08)
type Head<T> = T extends `${infer H}.${infer _}` ? H : T;
type H = Head<"orders.eu">; // "orders"
Why this matters: the `${infer H}.${infer _}` pattern — capture some, skip a separator, capture the rest — is the basis of parsing delimited strings, and it recurses (Lesson 08) to walk a full path. This is how you type data-driven, string-shaped domain values without casting.

Capitalization helpers

Four built-in transformation utilities give you string casing:4

type Cap = Capitalize<"name">;     // "Name"
type Up   = Uppercase<"name">;  // "NAME"
type Lo   = Lowercase<"NAME">;  // "name"
type Unc  = Uncapitalize<"Name">; // "name"

Putting it together with mapped types

Now the payoff from Lesson 06: use a template literal inside the as clause to rename every key. This is the "getter factory" — derive an API from a data shape:

type User = { name: string; age: number };

type Getters<T> = {
  [K in keyof T as `get${Capitalize<K>}`]: () => T[K]
};

type G = Getters<User>;
// { getName(): string; getAge(): number }

The mapped type drives the keys and the value types; the template literal + Capitalize rename them; T[K] keeps the value type honest. One data shape, one derived API type, zero duplicated declarations.

The mental stack: a template literal is strings; a mapped type is objects; infer is pattern capture. Combine them the way this lesson did and you can rewrite keys, parse IDs, and type event names — the building blocks of a self-consistent, string-driven type API.
