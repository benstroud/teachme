Generics From First Principles

A generic is a function whose arguments are types, not values.

★ Mission link: generics are the unit of every reusable utility and every type-safe API you'll design. They're also the gateway to type-level programming — conditional and mapped types are just generics that compute. Builds on Lesson 01.

The idea: a function over types

You already think of a normal function as taking a value and returning a value. A generic takes a type and returns a type. The <Type> in angle brackets is a type parameter — a variable that stands for a set you'll fill in later.1

function identity<Type>(arg: Type): Type {
  return arg;
}

Why this beats any

The whole point: a generic preserves the relationship between input and output. any throws that relationship away.1

function bad(arg: any): any {}        // in: number → out: ??? (anything)
function good<T>(arg: T): T {}        // in: number → out: number (linked)

const a = bad(42);   // a: any  — type info destroyed
const b = good(42);  // b: 42   — type info threaded through

any collapses the set to "I give up." A generic keeps the caller's set intact all the way out.

Inference: you rarely write <T>

The compiler reads the argument and figures out the type parameter for you.1 Passing it explicitly is the exception, not the rule:

identity<string>("hi");  // explicit — rarely needed
identity("hi");          // inferred — T = "hi". the normal way

Constraints: extends is Lesson 01's subset

An unconstrained T could be any set, so you can't touch its members. A constraint shrinks the allowed sets. And here's the payoff from Lesson 01: T extends X means exactly "T's set is a subset of X's set."2

function logLen<T extends { length: number }>(arg: T): T {
  console.log(arg.length);  // safe: every allowed T has .length
  return arg;
}
logLen("abc");       // ✅ string ⊆ {length:number}
logLen([1, 2]);      // ✅ arrays have length
logLen(3);           // ❌ number ⊄ {length:number}
The mental hook: wherever you later see extends — in constraints, and soon in conditional types (T extends U ? … : …) — read it as "is a subset of", not the class-inheritance "extends" from other languages. Same keyword, set-theory meaning.

One parameter constraining another: keyof

Type parameters can reference each other. keyof T is the union of T's keys; constraining K extends keyof T makes a property getter that can't reach for a missing key:3

function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const x = { a: 1, b: "hi" };
getProp(x, "a");  // returns number — exact, not a union
getProp(x, "z");  // ❌ "z" is not in keyof T

Note T[K] — an indexed access type. The return type tracks the exact property. This precise input→output linkage is what makes a generic utility delightful to use.
