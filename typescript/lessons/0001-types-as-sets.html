Lesson 01 · Foundations

Types as Sets

The one mental model that makes assignability, never, unions, and half your error messages obvious.

★ Mission link: this is the bedrock under type-level programming and reading any error. Every advanced trick later is set arithmetic in disguise.

The idea

Stop thinking of a type as a "kind of thing." Think of it as a set of values — the collection of every value allowed to inhabit it.1

  • string is the (infinite) set of all strings.
  • boolean is the set { true, false } — just two values.
  • "on" is a literal type: a set of size one.

Once types are sets, the relationships between them are just set relationships.

Assignability = subset

The rule that governs every error TS2322: Type 'X' is not assignable to type 'Y':

// "B is assignable to A"  ⟺  B ⊆ A  (B's set fits inside A's)
const mode: string = "on";   // ✅ {"on"} ⊆ string
const only: "on" = mode;       // ❌ string ⊄ {"on"} — string is too wide

A narrower set flows into a wider one, never the reverse. This is the whole game.2 When you read an assignability error, ask: which set is bigger, and which way is the value flowing?

Union and intersection are set operations

A | B
= A ∪ B
wider (either)
A & B
= A ∩ B
narrower (both)

A | B is the union — a value in A or B, so it is wider. A & B is the intersection — a value in A and B.

The senior gotcha: for object types, intersection combines members ({a:1} & {b:2} needs both a and b), while union restricts you to the shared members. People expect the opposite. Sets explain why: an object with more required keys describes fewer possible objects.

The two edges: never and unknown

If types are sets, two sets sit at the extremes:3

  • never = the empty set ∅. No value is a never. That's why T | never is just T, and why string & number is never (no value is both a string and a number — the overlap is empty).
  • unknown = the universal set. Every value fits, so you must narrow it before you can use it. The type-safe top of the hierarchy.

any is not a set — it switches checking off. A hole in the type system. Senior code avoids it.
