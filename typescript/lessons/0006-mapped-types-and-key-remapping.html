Mapped Types & Key Remapping

Iterate over keyof T to rebuild an object type — and rename or drop keys with as.

★ Mission link: mapped types are how you transform a shape instead of redeclaring it. Partial, Readonly, Pick, Omit are all mapped types — and so are the getter/mutable variants you'll write for others. Builds on Lesson 03 (keyof and indexed access) and Lesson 05 (conditionals inside a map).

The shape: { [K in keyof T]: … }

A mapped type is a block transform. It says: "for every key K in T's keys, produce a property, and here's its type." Same keys, new values.1

type Config = { host: string; port: number };
// make a copy
type Copy<T> = { [K in keyof T]: T[K] };
type C = Copy<Config>;  // { host: string; port: number }

// the real Partial: every key optional
type Partial<T> = { [K in keyof T]?: T[K] };

// the real Readonly: every property readonly
type Readonly<T> = { readonly [K in keyof T]: T[K] };

Read aloud: "iterate K over keyof T; the value at K is T[K], marked optional / readonly / etc."The ? and readonly are modifiers you place in the key position — the same key spelling, a different shape.

When a mapped type is homomorphic

If the mapped type writes keyof T where T is an original type variable (like Partial<T> and Readonly<T> above), it's homomorphic: it automatically preserves any readonly or ? modifiers on the source, so the transform is additive rather than destructive.2

type Node = { readonly id: string; label?: string };
// homomorphic: Partial keeps the readonly on id, makes the rest optional
type P = Partial<Node>;  // { readonly id?: string; label?: string }

// to STRIP modifiers, add a - prefix: -readonly, and -?
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
type M = Mutable<Node>;  // { id: string; label?: string } — readonly gone

Two type variables: K for the key, T[K] for the value

Inside the map you have both the key and the value at your fingertips. This is where utilities get interesting — transform a value type without touching the keys:

// wrap every value in an array
type ToArrays<T> = { [K in keyof T]: T[K][] };
type A = ToArrays<{ x: number; y: string }>; // { x: number[]; y: string[] }

// the real Record: map a fixed set of keys to a uniform value type
type Record<K extends string, V> = { [P in K]: V };
type Routes = Record<"home" | "login" | "admin", string>;
// { home: string; login: string; admin: string }

Key remapping with as (TS ≥ 4.1)

Add as NewKey after keyof T to rename keys. Combine with a conditional to drop keys (return never in the key position).3 This is the piece that, with template-literal types (Lesson 07), turns one object type into a whole new one:

// drop any key whose value is a function — keep only data keys
type DataKeysOnly<T> = {
  [K in keyof T as T[K] extends (...args: any[]) => any ? never : K]: T[K]
};

// rename: prefix every key with "get" — full form in Lesson 07
type Rename<T> = { [K in keyof T as K]: T[K] }; // identity — placeholder
Why this matters: the as clause is the tipping point between "reproduce the shape" and "derive a new shape." Dropping keys via never is how Omit<T, K> and Exclude work. It's the construct that makes "one source of truth for a type, many derived views" possible.

Pick, Omit, Exclude — the ones you'll actually use

UtilityWhat it keeps
Pick<T, K>only keys K
Omit<T, K>all keys except K
Exclude<T, K>union members not in K

All three are implemented as conditional + mapped types. Once you can write { [K in keyof T]: T[K] }, you own the family — they stop being magic and start being five lines you could reconstruct from memory in an interview.
