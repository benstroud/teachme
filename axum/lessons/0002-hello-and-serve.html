Hello, Axum

One route, one handler, one call to axum::serve. Every later lesson changes one of these three pieces.

Create the project

cargo new hello-axum
cd hello-axum
cargo add axum
cargo add tokio --features full

tokio with the full feature provides the runtime and the #[tokio::main] macro. The Axum docs say #[tokio::main] needs the macros and rt-multi-thread features, or full, which covers both.1

The program

This is the hello-world example from the crate docs, with the address set to the loopback interface.1 The lab version is code/examples/l02_hello.rs.

use axum::{routing::get, Router};

#[tokio::main]
async fn main() {
    // Build the application with a single route.
    let app = Router::new().route("/", get(|| async { "Hello, World!" }));

    // Bind a TCP listener, then hand it and the router to axum::serve.
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000")
        .await
        .unwrap();
    println!("listening on {}", listener.local_addr().unwrap());
    axum::serve(listener, app).await.unwrap();
}

Read it line by line

  • Router::new().route("/", get(...)) adds one route. get(...) says the route answers only GET.
  • The closure || async { "Hello, World!" } is a handler. It takes no extractors and returns a &str, which Axum turns into a text/plain response.2
  • TcpListener::bind is Tokio. It opens the port. Axum does not bind sockets for you.
  • axum::serve(listener, app) runs the server until it stops. It accepts a listener and a Router with no unbound state.3
A rule you will hit later axum::serve needs a Router whose state type is (). A router that still needs shared state does not compile here. Lesson 6 shows the fix, with_state. The lab probe that proves this is recorded in the notes file.

Your task (one attempt)

  1. Run the lab example: cargo run --example l02_hello from the code/ folder.
  2. In another terminal, run curl -i http://127.0.0.1:3000/. Expect a 200 OK status line, a content-type: text/plain; charset=utf-8 header, and the body Hello, World!.
  3. Change the body text, run again, and confirm the change in the response.
  4. Try curl -i -X POST http://127.0.0.1:3000/. Predict the status before you run it. Lesson 3 explains the answer.

Check yourself

What does axum::serve need as its first argument?

The listener comes from Tokio, bound to an address. axum::serve runs the router on it.3

Why does main carry #[tokio::main]?

Axum serving is async. The runtime is Tokio, and the macro starts it around your main.1

What must the router's state type be for axum::serve to accept it?

A Router with unbound state does not compile under axum::serve. Lesson 6 covers binding state with with_state.3
