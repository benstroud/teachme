Testing Without a Socket

A Router is a Tower service. You can send it a request in memory, check the response, and never open a port. Use a real socket only for the one thing a socket test proves.

Build the router in a function

The Axum testing example builds the router in a function, so tests and the real program share the same code.1 The lab does the same with app(state) in every example. Nothing in main is special, so a test that calls app() is testing the real thing.

One request: oneshot

ServiceExt::oneshot sends one request and returns the response. You need the tower crate with its util feature, and http-body-util to read the body:1

use axum::{body::Body, http::Request};
use http_body_util::BodyExt;
use tower::ServiceExt;

#[tokio::test]
async fn health_with_oneshot() {
    let response = app(AppState::default())
        .oneshot(Request::builder().uri("/health").body(Body::empty()).unwrap())
        .await
        .unwrap();
    assert_eq!(response.status(), StatusCode::OK);

    let bytes = response.into_body().collect().await.unwrap().to_bytes();
    assert_eq!(&bytes[..], b"ok");
}

The lab test health_with_oneshot is exactly this. Converting the body with collect().await.to_bytes() is the step most people look up.

Several requests: ready and call

To send more than one request to the same service, turn the router into a service with a fixed body type, then call it in a loop:

let mut service = app(AppState::default()).into_service::<Body>();

for _ in 0..2 {
    let req = Request::builder()
        .method("POST")
        .uri("/count")
        .body(Body::empty())
        .unwrap();
    let response = service.ready().await.unwrap().call(req).await.unwrap();
    assert_eq!(response.status(), StatusCode::OK);
}
The annotation you may need Without into_service::<Body>(), the compiler cannot infer the body type, and ready() fails with E0283, "type annotations needed". The lab probe reproduced that error. Pinning the body type fixes it.

ready() waits until the service can accept a request, and call() sends it. Both come from Tower's Service trait, which is why the test imports tower::Service.2 The lab test stateful_sequence_with_ready_and_call uses this pattern to show state changing between calls.

A real socket, once

Sometimes a test should prove that the server actually listens and shuts down. The lab test real_socket_round_trip binds port 0, which asks the operating system for a free port, starts the server with graceful shutdown, sends one raw HTTP request, and stops the server:2

let listener = tokio::net::TcpListener::bind("127.0.0.1:0").await.unwrap();
let addr = listener.local_addr().unwrap();
let (shutdown_tx, shutdown_rx) = tokio::sync::oneshot::channel::<()>();
let server = tokio::spawn(async move {
    axum::serve(listener, app(AppState::default()))
        .with_graceful_shutdown(async {
            let _ = shutdown_rx.await;
        })
        .await
        .unwrap();
});
// ...connect to addr, send a request, read the reply...
shutdown_tx.send(()).unwrap();
server.await.unwrap();

This test is slower and needs an operating system port, so use oneshot for everything else. Keep one socket test per server, to check the wiring.

Check yourself

Why does the lab build the router in an app() function?

The testing example builds the router in a function so tests call the same code that main serves.1

Why does a loop of ready().call() need into_service::<Body>()?

Without the pinned body type the compiler reports E0283. The probe in the lab showed exactly that error.2

What is the main cost of a real-socket test, compared with oneshot?

A socket test binds a port and runs a real server. That proves the wiring, but it costs time and a port. Most checks belong in oneshot.
