Shipping

Read configuration from the environment, log with tracing, and stop cleanly on Ctrl+C. Then check the list of things the lab deliberately leaves out.

Configuration from the environment

A deployed service takes its settings from environment variables, not from edits to the source. The lab reads PORT and falls back to 3000 when it is missing or not a number:

let port: u16 = env::var("PORT")
    .ok()
    .and_then(|p| p.parse().ok())
    .unwrap_or(3000);
let addr = SocketAddr::from(([127, 0, 0, 1], port));

The lab test port_defaults_when_env_is_missing_or_invalid tests the same parsing as a pure function. Keeping parsing out of main makes it testable without touching the process environment.

Logging with tracing

The lab sets up tracing with an environment filter. If RUST_LOG is not set, the default is debug for the crate and for tower_http:

tracing_subscriber::registry()
    .with(
        tracing_subscriber::EnvFilter::try_from_default_env().unwrap_or_else(|_| {
            format!("{}=debug,tower_http=debug", env!("CARGO_CRATE_NAME")).into()
        }),
    )
    .with(tracing_subscriber::fmt::layer())
    .init();

The router gets TraceLayer::new_for_http() from lesson 8, so each request is logged through the same subscriber. Run the binary with RUST_LOG=info and you get the lines the lab produced during verification:

INFO l10_shipping: listening on 127.0.0.1:3917
INFO l10_shipping: shutdown signal received, finishing in-flight requests
INFO l10_shipping: server stopped cleanly

Stopping cleanly

Attach a shutdown future with with_graceful_shutdown. When that future completes, axum::serve stops and returns. The lab's future waits for Ctrl+C:

async fn shutdown_signal() {
    tokio::signal::ctrl_c()
        .await
        .expect("failed to install Ctrl+C handler");
    tracing::info!("shutdown signal received, finishing in-flight requests");
}

axum::serve(listener, app())
    .with_graceful_shutdown(shutdown_signal())
    .await
    .unwrap();
tracing::info!("server stopped cleanly");

The last log line prints only because serve returned. The lab verified that: sending SIGINT to the running binary produced the three lines above and exited.

Your task (one attempt)

  1. From the code/ folder, run PORT=3917 RUST_LOG=info cargo run --example l10_shipping.
  2. In another terminal, run curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3917/health. Expect 200, and a request line in the server log.

  4. Run it again with RUST_LOG=warn. Predict what disappears from the log, then check.

Before you ship: the lab left these out

The lab is a teaching program. Each item below is a decision a real deployment has to make, and the lab does not make it:

  • Bind address. The lab binds to 127.0.0.1, which is only reachable from the same machine. A service behind a proxy or inside a container usually binds to 0.0.0.0. Decide it, and make it configuration.
  • CORS. CorsLayer::permissive() allows every origin. Replace it with the origins your frontend actually uses.
  • Body size. The docs set a default limit of 2 MB for Bytes, String, Json, and Form bodies.2 Decide whether that is right for each endpoint. The lab does not test it yet.
  • Timeouts. A slow client or a slow dependency can hold a connection open. Add a timeout layer from tower-http. It is not in the lab.
  • Secrets. Read them from the environment, and never log them. The require_token check in lesson 8 is a placeholder, not an authentication scheme.
  • A health check. The /health route in the lab is the minimum a load balancer needs.

Where to go next

The Axum repository's examples/ directory has about 56 examples. Useful ones after this set are graceful-shutdown, testing, tracing-aka-logging, error-handling, jwt, and the database examples, which need a persistence set first.3

Check yourself

What makes axum::serve return in the lab after Ctrl+C?

The shutdown future resolves on Ctrl+C. Then serve returns, and the final log line runs. The lab verified the sequence by sending SIGINT.1

Where do PORT and RUST_LOG come from in the lab?

The lab reads both from the environment at startup. RUST_LOG is read by the EnvFilter, and PORT by env::var.

Why is CorsLayer::permissive() a problem in a production API?

A permissive CORS policy lets any website's frontend call your API from a browser. The lab uses it for convenience, and production should list the origins it needs.
