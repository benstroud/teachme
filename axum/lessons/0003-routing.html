Routing

Routes match a path first, then a method. Learn the three decisions the router makes, and the 0.8 path syntax that breaks old code.

Methods on one path

A route takes a path and a method router. Chain the methods you accept on the same path:1

Router::new().route("/users", get(list_users).post(create_user))

Here GET /users reaches list_users and POST /users reaches create_user. The lab program does exactly this in l03_routing.rs.

Path parameters use braces

In Axum 0.8, a path parameter is written {id}. The docs say a wildcard that matches several segments is written {*rest}.2

.route("/users/{id}", get(show_user))

async fn show_user(Path(id): Path<u32>) -> String {
    format!("user {id}")
}
The old syntax now panics Axum 0.7 used /:id. In 0.8 that form is rejected when the route is built. A probe in the lab confirmed the message: Path segments must not start with :. For capture groups, use {capture}. If you copy an older tutorial, change every :name to {name}.3

The parameter is extracted with Path, covered in lesson 4. A value that does not parse, such as /users/abc for a u32, returns 400 Bad Request. The lab test non_numeric_id_is_400 checks it.

Nesting a router under a prefix

nest mounts a whole router under a path. Inside the nested router the prefix is stripped, so its routes are written without it:4

fn api() -> Router {
    Router::new()
        .route("/users", get(list_users).post(create_user))
        .route("/users/{id}", get(show_user))
}

pub fn app() -> Router {
    Router::new()
        .route("/health", get(health))
        .nest("/api", api())
}

Now /api/users/42 reaches show_user. merge is the sibling operation: it combines two routers at the same level, and the docs say it panics if both routers define a fallback.4

Three things that are not routing

The router makes three decisions, and each has a different response. The lab's app() adds a fallback, so the three cases are visible:

RequestWhat happensStatus
GET /healthPath and method match. Handler runs.200
POST /healthPath matches, method does not. Fallback does not run.405 Method Not Allowed
GET /nopeNo route matches the path. Fallback runs.404, from the fallback

The fallback is for unmatched paths. The docs say it does not run for a method mismatch, and the lab test wrong_method_is_405_not_the_fallback confirms that.4

Check yourself

In the lab app, what does POST /health return?

The path matches but the method does not. The fallback runs only when no route matches the path.4

What does {id} replace in Axum 0.8 path syntax?

The 0.8 changelog changed capture syntax from /:single to /{single}. The old form panics when the route is built.3

When does a router's fallback handler run?

The fallback handles unmatched paths. It does not run for a method mismatch, and it does not run because a handler chose to return 404.4
