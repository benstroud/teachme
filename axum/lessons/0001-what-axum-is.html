What Axum Is

A web framework that turns plain async Rust functions into HTTP endpoints, with the routing, extraction, and middleware pieces already typed for you.

The one-sentence model

An Axum application is a Router that maps method and path pairs to handlers. Each handler is an async fn that asks for the request data it needs through extractors, and returns something that can become an HTTP response.1

request
  → Router (matches method + path)
    → middleware (optional layers, wrap the handler)
      → handler (async fn with extractors as arguments)
        → return value (anything that implements IntoResponse)
→ response

Where Axum sits

Axum is built on Tower. The Axum error-handling docs describe it as built on tower::Service, and middleware in Axum is Tower middleware.2 The network side runs on Tokio, and axum::serve takes a Tokio listener.1 You will meet three libraries in this set: Axum for routing and extraction, Tower for the service and layer model, and Tokio for the runtime that drives it.

Why Tower matters Tower's Service trait is a function from a request to a future of a response. Because an Axum Router is a Service, you can test it by calling it directly, with no network port. Lesson 9 uses that.

What you will not write by hand

You do not parse the URL, read the body, or set Content-Type yourself for the common cases. Extractors do that work. You declare the types you want, and Axum either produces them or returns an error response before your handler runs.3 Lesson 4 shows that behaviour, including the status codes.

The Rust you need first

Handlers are generic over their extractors and return types, and errors are Result values. The Rust set covers these: error handling with Result and ?, traits and generics, and borrowing. If the phrase "trait bound not satisfied" is unfamiliar, read the generics lesson first.

Version and toolchain

This set teaches Axum 0.8. Its path syntax changed from /:id to /{id}, and the old form now panics. The changelog for 0.8.0 lists the change.4 The docs describe version 0.8.9, which needs Rust 1.80 or newer.4

Check yourself

Which library is Axum built on for its service and middleware model?

Axum's error-handling docs describe it as built on tower::Service, and its middleware is Tower middleware.2

What can a handler return?

The handler docs say a handler returns something that can be converted into a response. IntoResponse is that conversion.3

Where does middleware run relative to the handler it wraps?

Middleware is a Tower layer: it can act before the handler, after it, or both, and it can refuse the request entirely.1
