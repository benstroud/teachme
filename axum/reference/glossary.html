Axum 0.8 Glossary

The canonical terms for this workspace. Lessons link here. Use these words in code comments and reviews so they match the docs.

Routing and handlers

Router
The value that maps method and path pairs to handlers. A Router<S> is parameterised by its state type S. Only Router<()>, with no unbound state, can be passed to axum::serve. Lessons 2, 3, 6.
Handler
An async fn (or closure) that takes zero or more extractors and returns something that implements IntoResponse. At most 16 arguments. Lessons 2, 4.
Path parameter
A segment captured from the URL, written {id} in Axum 0.8. The old :id form panics. Read it with Path. Lesson 3.
nest
A router method that mounts another router under a path prefix. Inside the nested router, the prefix is stripped from the path. Lesson 3.
Fallback
The handler that runs when no route matches the path. It does not run for a method mismatch, which returns 405. Lesson 3.

Requests and responses

Extractor
A type that reads a value from the request, used as a handler argument. Extractors run left to right. The body-consuming extractor must be the last argument. Lesson 4.
Rejection
The error an extractor returns when its input is wrong, such as 400 for a bad path value or 422 for JSON with the wrong shape. The handler is not called. Lesson 4.
IntoResponse
The trait that turns a handler's return value into an HTTP response. Implemented by strings, status codes, Json, tuples with a status first, and Result when both arms implement it. Lessons 5, 7.

State

State
Shared data bound to a router with with_state and read by handlers through the State<T> extractor. Each clone of the state shares any Arc inside it. Lesson 6.
FromRef
The trait that lets a handler ask for a part of the state, such as State<Arc<Mutex<_>>>, instead of the whole state. Implement it on the state type for each part. Lesson 6.

Middleware and services

Service (Tower)
The Tower trait for a function from a request to a future of a response. A Router is a Service, which is why it can be tested without a socket. Lessons 1, 9.
Infallible
The error type Axum requires its services to use. Errors must therefore become responses inside the handler, rather than escape the service. Lesson 7.
layer
A Router method that wraps every route added before the call with a Tower layer or middleware. Repeated layer calls mean the last one is outermost. Lesson 8.
route_layer
A method that attaches a layer to one route, which runs only when that route matches. Lesson 8.
from_fn
The function that turns an async function taking a request and a Next into a middleware layer. Next must be the last argument. Lesson 8.

Testing and shipping

oneshot
The ServiceExt method that sends one request to a service and returns its response, with no network port involved. Lesson 9.
Graceful shutdown
Stopping axum::serve when a future given to with_graceful_shutdown completes, so that serve returns and the program can log and exit. Lesson 10.
