Events and Channels

Commands answer a question. Events announce a change. Channels stream ordered updates to one caller. Pick the one that matches the shape of the data.

Three shapes of communication

You needUseWhy
Ask for data and get one answerCommandRequest and response, the lessons 4–5 pattern.
Announce something that any listener may react toEventOne-way and fire-and-forget. The sender does not wait for a reply.1
Stream many ordered updates to one caller, such as progressChannelBuilt for fast, ordered streaming from Rust to JavaScript.2

Events: Rust to JavaScript

From Rust, emit an event by name. Use emit_to to target one window. Import the Emitter trait first:2

use tauri::{AppHandle, Emitter};

#[tauri::command]
fn start_download(app: AppHandle, url: String) {
    app.emit("download-started", &url).unwrap();
}

// Only the window labelled "login" receives this:
// app.emit_to("login", "login-result", result).unwrap();

In JavaScript, listen registers a handler. It returns a promise that resolves to an unlisten function, so await it before you call the function:2

import { listen } from '@tauri-apps/api/event';

const unlisten = await listen<string>('download-started', (event) => {
  console.log('started:', event.payload);
});

// Later, when no longer interested:
unlisten();

Events also flow the other way. The frontend can emit with emit from the same module, and Rust can listen with app.listen after importing Listener.2

Payloads and limits

An event payload must implement Serialize and Clone, and it travels as JSON. The docs add two limits: events are not type-safe, and the event system is not suited to sending large amounts of data.2

A common mistake Developers often reach for events for everything, because they are the easiest to write. Use them for notifications: "the file changed", "the user signed out". For a stream of 10,000 progress updates, use a channel.

Channels: an ordered stream to one caller

A channel is a command parameter typed Channel<T>. Rust sends values into it, and the JavaScript caller creates the channel and handles each message:2

use tauri::ipc::Channel;

#[tauri::command]
fn download(url: String, on_event: Channel<u32>) {
    on_event.send(0).unwrap();
    on_event.send(50).unwrap();
    on_event.send(100).unwrap();
}
import { invoke, Channel } from '@tauri-apps/api/core';

const onEvent = new Channel<number>();
onEvent.onmessage = (percent) => {
  console.log('progress', percent);
};

await invoke('download', { url, onEvent });

The docs' example sends a richer enum of download events. A number is enough to learn the pattern. The channel fits progress and output streams because it preserves order and is designed for this traffic.2
