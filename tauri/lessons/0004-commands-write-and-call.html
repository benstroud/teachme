Commands: Write One and Call It

A command is a Rust function the frontend may call. Three steps make one: annotate it, register it, invoke it.

Step 1: write the function in Rust

Mark an ordinary function with #[tauri::command]. Here is a small one in src-tauri/src/lib.rs:1

#[tauri::command]
fn greet(name: &str) -> String {
    format!("Hello, {name}! Welcome to Tauri.")
}

Note the signature. The argument is a borrowed &str, and the return value is an owned String. Those are Rust ownership choices from the Rust set's borrowing lesson. Lesson 5 explains why the choice changes for async commands.

Step 2: register it on the builder

A command does nothing until you list it in the builder's handler. Use generate_handler! with every command name inside it:1

tauri::Builder::default()
    .invoke_handler(tauri::generate_handler![greet])
    // ...the rest of the builder chain from your template
Two rules from the docs First, call invoke_handler only once. The docs say that only the last call is used, so put every command in one generate_handler! list.1 Second, command names must be unique across the app.

Commands in other modules

A command in lib.rs must not be pub. Once you move commands into their own module, the function must be pub, and you list it by its module path:1

// src-tauri/src/commands.rs
#[tauri::command]
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

// src-tauri/src/lib.rs
.invoke_handler(tauri::generate_handler![commands::greet])

Step 3: call it from the frontend

Import invoke from the core API module and call the command by its name. Arguments travel as a JSON object:1

import { invoke } from '@tauri-apps/api/core';

const message = await invoke('greet', { name: 'Ben' });
console.log(message); // "Hello, Ben! Welcome to Tauri."

The docs note that the same call works from a global script through window.__TAURI__.core.invoke, when the app enables that option.1 Most TypeScript projects use the import.

Argument names: the casing rule

By default, Rust snake_case argument names become camelCase keys in JavaScript. The docs use this example: a Rust argument invoke_message: String is sent as invokeMessage.1

#[tauri::command]
fn save_note(note_title: String) { /* ... */ }

// JavaScript sends:
invoke('save_note', { noteTitle: 'Groceries' });

To keep the snake_case keys on the JavaScript side, set the attribute: #[tauri::command(rename_all = "snake_case")].1

Check yourself

If invoke_handler is called twice on the builder, which commands does Tauri use?

The docs say only the last call is used, so every command must appear in one generate_handler! list.1

A Rust argument named note_title is passed from JavaScript under which key by default?

The default is camelCase on the JavaScript side. Add rename_all = "snake_case" to keep the snake_case key.1

Which statement about a command defined directly in lib.rs is correct?

The command docs say a command in lib.rs must not be pub. Commands in a separate module are the opposite: they must be pub.1
