Scaffolding and Project Anatomy

Generate a project, run it, and learn which file controls what before you change any code.

What you need installed

Tauri needs system build dependencies, Rust, and, if your frontend is JavaScript-based, Node.js LTS. The per-OS list is in the official prerequisites.1 On Windows you need Microsoft C++ Build Tools and the WebView2 runtime. On macOS you need Xcode or the command-line tools (xcode-select --install). On Linux you need the WebKit and build packages for your distribution.1

Toolchain check Run rustc --version. The plugin crates in lesson 9 require Rust 1.90 or newer, and the plugin pages say so. If you are on an older toolchain, run rustup update stable before lesson 9. The authoring machine had 1.84.1.

Create a project

The docs recommend the interactive scaffolder. The npm form is one of several equivalent entry points.2

npm create tauri-app@latest
cd your-app-name
npm install
npm run tauri dev

npm run tauri dev starts the frontend dev server and opens the app window. Changes to the frontend reload without a rebuild. Changes to the Rust side recompile and restart.

Read the project tree

A new project looks roughly like this. The frontend folder names depend on the template you pick at scaffold time (for example, src/main.js or src/main.ts).3

your-app/
├── package.json
├── index.html
├── src/                    ← frontend
│   └── main.js  (or main.ts)
└── src-tauri/              ← Rust core
    ├── Cargo.toml          ← Rust dependencies (crates)
    ├── Cargo.lock
    ├── build.rs
    ├── tauri.conf.json     ← app identifier, windows, build settings
    ├── capabilities/
    │   └── default.json    ← which permissions each window has
    ├── icons/
    └── src/
        ├── main.rs         ← thin entry point
        └── lib.rs          ← put your app code here

Two conventions matter from the start. The docs say to keep src/main.rs thin and put app code in lib.rs.3 And the capabilities/ folder is where the permissions for each window are declared.3 Lesson 8 covers that folder in depth.

The config file that matters first

tauri.conf.json holds the app's name, its reverse-domain identifier, the build settings, and the windows the app opens. The configuration reference lists these top-level keys: productName, version, identifier, build, app, bundle, and plugins.4

{
  "productName": "your-app",
  "version": "0.1.0",
  "identifier": "com.example.yourapp",
  "build": {
    "devUrl": "http://localhost:3000",
    "frontendDist": "../dist"
  },
  "app": {
    "windows": [
      { "title": "Your App", "width": 800, "height": 600, "label": "main" }
    ]
  }
}
Watch the identifier The reference says identifier is required and reverse-domain. The value com.tauri.dev is rejected by tauri build. Pick your own domain-style name now, because changing it later affects app data locations and updates.4

The values in your generated file may differ from this sample (for example, the dev server port). Trust the file in your project over the sample here.

Your task (one attempt)

  1. Scaffold a project with npm create tauri-app@latest. Name it tauri-hello.
  2. Run npm install, then npm run tauri dev. Confirm a window opens.
  3. Stop the dev process. Open src-tauri/tauri.conf.json and change the window title.
  4. Run npm run tauri dev again. Confirm the new title appears.

If the Rust build fails with a version error, run rustup update stable and retry.

Check yourself

Which file holds the app identifier and the window settings?

tauri.conf.json holds the identifier, build settings, and windows. package.json is for npm, Cargo.lock pins Rust versions, and build.rs is a build script.4

The project docs suggest where to put most of your Rust application code?

The structure docs say to keep main.rs thin and put app code in lib.rs.3

What is the capabilities/ folder for?

Capability files declare the permissions granted to windows. Lesson 8 is entirely about them.3
