What Tauri Is

Two programs in one app: a Rust core that owns the operating system, and a webview that renders the interface you write in HTML, CSS, and TypeScript.

The mental model in one sentence

A Tauri app is a Rust core process with full access to the operating system, plus one or more webview processes that render your frontend, and the two talk through a message boundary.1

Who does what

  • The core process is the only component with full access to the operating system. It creates windows, tray menus, and notifications, routes all communication between processes, and should hold global state.2
  • The webview process renders the user interface. The core doesn't render the actual user interface itself; it spins up WebView processes.2

In practice this means the frontend is ordinary web code (HTML, CSS, and TypeScript, or a framework of your choice), and everything privileged, such as reading files or talking to the OS, is written in Rust and reached through an explicit interface.

Which web engine runs your UI

Tauri does not ship its own browser engine. It uses the one the operating system already provides: Microsoft Edge WebView2 on Windows, WKWebView on macOS, and webkitgtk on Linux. These libraries are dynamically linked at runtime and are not included in your executable.2

Why this matters The same HTML can render slightly differently on each platform, because each uses a different engine. Test on every OS you ship to. Your TypeScript is not compiled to a single browser, it is run by whichever webview the user already has.

Why the binary can be small

The docs say a minimal Tauri app can be less than 600 KB, and give the reason directly: they are very small because they use the OS's webview.31 Your real app will be bigger. The number is a floor for a trivial app, not a promise about yours.

Where Tauri sits in your toolkit

Tauri is a framework for building desktop applications, not a web server or a general Rust library. Your Rust code lives in a src-tauri/ folder, and your frontend lives beside it. The Rust side is the part this set spends most of its time on, because the boundary between the two sides is where Tauri's design decisions show up.

Prerequisites for this set

You will write small Rust programs. The Rust set covers the fundamentals used here, especially ownership, error handling with Result, and borrowing.

Key idea Tauri does not put a browser inside your app. It asks the operating system for the browser it already has, and keeps the powerful parts in Rust behind an interface you define.

Check yourself

Where does a Tauri app's HTML, CSS, and TypeScript interface actually run?

The core process does not draw the interface. It starts webview processes, and those use the OS's engine: WebView2, WKWebView, or webkitgtk.2

Which job belongs to the Rust core process rather than the webview?

The core is the only component with full access to the OS. It creates windows and tray menus and routes all inter-process messages.2

Why is a minimal Tauri app so small?

The architecture docs state it directly: Tauri apps are small because they use the OS's webview. The docs' figure of under 600 KB applies to a minimal app.3
