Build, Sign, and Ship

A build produces an installer. Shipping it to real users means signing it, and, for updates, signing those too. Each platform asks for something different.

Build the app

The distribute page's build command is npm run tauri build. The same build can also be run with cargo tauri build, or with your package manager's equivalent.1 If you want to split the steps, the docs show compiling first and bundling second:1

npm run tauri build -- --no-bundle
npm run tauri bundle -- --bundles app,dmg

What each OS produces

PlatformFormats named on the distribute page
LinuxDebian package, Snap, AppImage, Flatpak, RPM, AUR
macOSApp Store, DMG, App Bundle
WindowsMicrosoft Store, Windows Installer

The bundle settings live under bundle in tauri.conf.json. The reference lists bundle.active, which defaults to false, and bundle.targets, which defaults to all. Platform-specific keys sit under the platform name, for example macOS.dmg and windows.nsis.2 Check the file your project generated before you rely on those defaults.

Identifier check The build fails with the placeholder identifier com.tauri.dev. Set your own reverse-domain identifier from lesson 2 before you build for distribution.2

Code signing

The distribute page states that most platforms require code signing. On macOS, you name a signing identity in bundle under macOS as signingIdentity, or set the APPLE_SIGNING_IDENTITY environment variable.1 Two practical limits the macOS guide states: ad-hoc signing with "-" does not stop macOS from asking the user for approval, and a free Apple account cannot notarize.3

Distributing outside the App Store also requires notarization. The docs give two credential routes: App Store Connect API keys (APPLE_API_ISSUER, APPLE_API_KEY, APPLE_API_KEY_PATH) or an Apple ID (APPLE_ID, APPLE_PASSWORD, APPLE_TEAM_ID).3 In CI, the certificate is provided with APPLE_CERTIFICATE and APPLE_CERTIFICATE_PASSWORD.3

The updater

Automatic updates use the updater plugin. The updater docs state that its signature check cannot be disabled. An update must be signed by a key your app trusts, so a compromised update server cannot push code on its own.4

  1. Install and register. Run npm run tauri add updater. The docs register the plugin on desktop only, inside setup, behind a #[cfg(desktop)] guard.4
  2. Generate keys. Run npm run tauri signer generate -- -w ~/.tauri/myapp.key. Keep the private key out of the repository.4
  3. Provide the private key at build time through the TAURI_SIGNING_PRIVATE_KEY environment variable. The docs say .env files do not work for this.4
  4. Configure the updater. Set bundle.createUpdaterArtifacts to true, and under plugins.updater give the pubkey and the endpoints.4
"bundle": { "createUpdaterArtifacts": true },
"plugins": {
  "updater": {
    "pubkey": "<the public key content, not a file path>",
    "endpoints": [
      "https://releases.example.com/{{target}}/{{arch}}/{{current_version}}"
    ]
  }
}
Two traps The pubkey value is the key content, not the path to a key file. And the endpoint URL uses template variables such as {{target}}, {{arch}}, and {{current_version}}, which the updater fills in.4

Before you ship: a checklist

  • The identifier is your own reverse-domain name, not com.tauri.dev.
  • Every capability grants only what each window needs. Lesson 8 is the review.
  • No command reads or writes a path without a check in Rust. Lesson 5 is the review.
  • Signing identities and notarization credentials are in environment variables, not in the repository.
  • The updater private key is stored outside the repository, and the public key is in the config.
  • You have run the bundle on each OS you plan to ship to. The same HTML renders through a different engine on each.

Your task (one attempt)

  1. Set your own identifier in tauri.conf.json, then run npm run tauri build for your OS. Note the bundle output folder the build prints.
  2. Open one installer or bundle and confirm the app name and icon look right.
  3. Optional: generate an updater key pair with npm run tauri signer generate -- -w ~/.tauri/tauri-hello.key. Do not commit the key, and do not publish it.

Check yourself

Which bundle format does the distribute page name for macOS?

The distribute page lists DMG, App Store, and App Bundle for macOS. AppImage and Flatpak are Linux formats, and Windows Installer is a Windows format.1

Which statement about updater signatures is correct?

The updater docs say the signature check cannot be disabled. An update must be signed by a trusted key.4

Where is TAURI_SIGNING_PRIVATE_KEY supplied for an updater build?

The docs say to set it as an environment variable at build time, and that .env files do not work for it.4

Primary source (read this next)

Read Distribute, then Sign for macOS if you ship to Apple users, and the Updater page before you enable automatic updates.
