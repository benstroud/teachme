Plugins: Dialog, File System, Store

Plugins add ready-made, permission-gated powers. Learn the install pattern once, then reuse it for every official plugin.

What a plugin is

An official plugin is two halves: a Rust crate that runs in the core process, and a JavaScript package that the frontend imports. The Rust crate is named tauri-plugin-<name>. The JavaScript package is named @tauri-apps/plugin-<name>. The plugin's powers are gated by permissions, exactly as lesson 8 described, so a plugin you install does nothing for a window until a capability grants it.1

Toolchain requirement The dialog, file system, and store plugin pages each state a Rust version of at least 1.90. If rustc --version shows an older version, run rustup update stable first.234

The install pattern

From the src-tauri folder, add the Rust crate. From the project root, add the JavaScript package. The docs also show an automatic route that does both in one step:2

# Rust side, inside src-tauri/
cargo add tauri-plugin-dialog

# JavaScript side, at the project root
npm install @tauri-apps/plugin-dialog

# Or do both in one step, from the project root
npm run tauri add dialog

Register it on the builder

The Rust side must be registered in the builder, in lib.rs. The dialog and file system plugins use an init() function, and the store plugin uses a builder:234

tauri::Builder::default()
    .plugin(tauri_plugin_dialog::init())
    .plugin(tauri_plugin_fs::init())
    .plugin(tauri_plugin_store::Builder::new().build())

Grant its permissions

Installing the plugin is not enough. Add the permissions the plugin's page lists to your capability file. The file system docs use fs:default as the baseline, and the store docs use store:default.34 The dialog page does not show a literal snippet in the form these notes captured, so copy the identifiers directly from its permissions section rather than guessing.2

Remember the scope The file system docs warn that enabling a permission such as fs:allow-exists by itself does not allow access to any path. A scope is also required (lesson 8).3

Your task (one attempt)

  1. Run rustc --version. If it is below 1.90, run rustup update stable.
  2. In tauri-hello, run npm run tauri add dialog. Then open src-tauri/src/lib.rs and find the registration. Note what changed in the capability file, if anything.
  3. Open the dialog plugin page and add the permission identifiers it lists to your capability.
  4. Add a button that uses the dialog plugin's JavaScript API, described on the same page, to show a message box. Confirm the box appears.
  5. Stretch, optional: repeat with the store plugin, storing a counter that survives an app restart.

Check yourself

Which command adds the dialog plugin's Rust crate?

The Rust crate is tauri-plugin-dialog, added with cargo add inside src-tauri. The JavaScript package is @tauri-apps/plugin-dialog, added with npm.2

What is true of fs:allow-exists on its own, according to the file system docs?

The docs warn that enabling the permission alone grants no path access. The scope decides where.3

What minimum Rust version do the dialog, file system, and store plugin pages state?

Each plugin page states a Rust version of at least 1.90. Run rustup update stable if you are older.2
