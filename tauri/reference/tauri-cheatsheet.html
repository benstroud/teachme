Commands (Rust to JS)

#[tauri::command]
fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

// Register in lib.rs. Call invoke_handler ONCE; only the last call is used.
tauri::Builder::default()
    .invoke_handler(tauri::generate_handler![greet])
import { invoke } from '@tauri-apps/api/core';

const msg = await invoke('greet', { name: 'Ben' }); // rust snake_case → JS camelCase
RuleDetail
Argument keyscamelCase by default; #[tauri::command(rename_all = "snake_case")] keeps snake_case
ErrorsErr rejects the promise; the error type must implement Serialize
AsyncUse owned arguments (String), not &str or State<'_, T>
Sync off-thread#[tauri::command(async)] on a non-async function
lib.rs vs moduleIn lib.rs, not pub; in a module, pub and listed by path
AccessCommands are callable from all windows by default; restrict in build.rs

Managed state

use std::sync::Mutex;
use tauri::State;

tauri::Builder::default()
    .setup(|app| {
        app.manage(Mutex::new(AppState::default()));
        Ok(())
    })

#[tauri::command]
fn increase(state: State<'_, Mutex<AppState>>) -> u32 {
    let mut s = state.lock().unwrap();
    s.counter += 1;
    s.counter
}

// Outside a command (needs use tauri::Manager):
let state = app.state::<Mutex<AppState>>();

Mismatch: wrong State type compiles, then fails at runtime with a state-not-managed error.

Events and channels

NeedRustJavaScript
Emit to all listenersapp.emit("name", &payload) (import Emitter)emit('name', payload) from @tauri-apps/api/event
Emit to one windowapp.emit_to("label", "name", payload)—
Listenapp.listen("name", |event| …) (import Listener)const un = await listen<T>('name', e => e.payload); call un() to stop
Stream to one callerCommand takes Channel<T>; send(value)new Channel<T>(); set onmessage; pass in invoke args

Payloads implement Serialize and Clone. Events are not type-safe and not suited to large data.

Capabilities and scopes

// src-tauri/capabilities/default.json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "main-capability",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "core:path:default",
    "core:window:allow-set-title",
    "fs:default"
  ]
}
// tauri.conf.json: enable explicitly (otherwise every file in the folder is used)
"app": { "security": { "capabilities": ["main-capability"] } }
ConceptRule
Permission format<name>:default or <name>:<command>, e.g. fs:allow-mkdir
WindowsMatch by window label, never by title
ScopeNarrows where a permitted action applies; deny supersedes allow
fs:allow-exists aloneGrants no path access; add a scope
Remote URLsOff by default; a capability's remote key opts in
CSPEnforced only when set in the configuration file
