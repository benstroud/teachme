Tauri 2 Glossary

The canonical terms for this workspace. Lessons link here. Use these words in your own notes and code comments so they match the docs.

Architecture

Tauri
A framework for desktop applications in which a Rust core process owns the operating system and a webview renders the frontend you write in HTML, CSS, and TypeScript. Avoid: "Electron-like" as a shorthand, because the engines differ.
Core process
The Rust process that is the only component with full access to the operating system. It creates windows and tray menus, routes all IPC, and should hold global state. Lessons 1, 3.
WebView process
A process started by the core to render the user interface, using the operating system's web engine. Avoid: "renderer", which is a different term in other frameworks.
IPC (inter-process communication)
The asynchronous message passing between the webview and the core. Every request goes through the core. Arguments and return values must serialize to JSON. Lesson 3.

Calling and communicating

Command
A Rust function marked #[tauri::command] and registered with generate_handler!, which the frontend may call by name. A command is a request that returns one answer. Lessons 4, 5.
invoke
The frontend function, from @tauri-apps/api/core, that calls a command. It works like the browser's fetch API and returns a promise. Lesson 4.
Event
A one-way, fire-and-forget message that either side can emit. Its payload must implement Serialize and Clone. Use events for notifications, not for large streams. Lesson 7.
Channel
A typed Channel<T> passed to a command as an argument, for ordered streaming from Rust to one JavaScript caller, such as progress updates. Lesson 7.
Managed state
A value registered with app.manage, borrowed by commands through State<'_, T> or fetched with Manager::state. A type mismatch is a runtime error. Lesson 6.

Security

Capability
A JSON file in src-tauri/capabilities/ that names the windows it applies to and the permissions they receive. Only enabled capabilities are used in the build. Lesson 8.
Permission
A named grant for a core or plugin API, written as <name>:default or <name>:<command>, such as fs:default. Granting a permission does not, by itself, grant access to any path. Lessons 8, 9.
Scope
A granular allow or deny rule that narrows where or on what a permitted command may act. Deny always supersedes allow. Scopes are plugin-specific TOML. Lesson 8.
Window label
The identifier of a window, such as main. Capabilities match windows by label, not title, and the security boundary depends on labels. Lesson 8.
CSP (Content Security Policy)
A policy that limits what a page may load and run. Tauri restricts it and enables the protection only when the policy is set in the configuration file. Lesson 8.

Building and shipping

Plugin
An official extension made of a Rust crate named tauri-plugin-<name> and a JavaScript package named @tauri-apps/plugin-<name>. Its APIs are gated by permissions. Lesson 9.
Identifier
The required reverse-domain name of the app in tauri.conf.json, such as com.example.app. The placeholder com.tauri.dev is rejected by tauri build. Lessons 2, 10.
Bundle
An installer or package produced by tauri build, in a format for one OS, such as a DMG on macOS or a Debian package on Linux. Lesson 10.
Updater signature
A signature that the updater verifies before installing an update, against a public key in the configuration. The check cannot be disabled. Lesson 10.
