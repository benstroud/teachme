Tailscale SSH

Keyless SSH driven by identity and policy — no authorized_keys to manage.

The mental model in one sentence

Tailscale SSH removes key management: you SSH to a machine over the tailnet and Tailscale authenticates you by identity and enforces access with the tailnet policy — no authorized_keys to copy around.1

Turning it on

# advertise that this host accepts Tailscale SSH
tailscale up --ssh        # (or: tailscale set --ssh)

# from a client, connect by name
ssh user@my-server

Access is then governed by the ssh section of the tailnet policy: who (user/tag) may connect as which OS user, optionally with a time window.1

Check mode and fit

Good fitNot a good fit
Single-user machines and serversMulti-user machines with differing access1
Hosts that should not allow outbound SSHHosts you do not fully trust

Check mode can require SSO approval on every connection (e.g. checkPeriod: always) for stronger control.1

Key idea Because there is no client key file, any OS user on the client can attempt a connection — but the server-side policy decides what actually succeeds. Policy, not a key on disk, is the control.1

Check yourself

1. Tailscale SSH authenticates you using…

2. Access to a Tailscale SSH host is enforced…

3. Check mode on Tailscale SSH can require…
