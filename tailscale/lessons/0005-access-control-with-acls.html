Access Control with ACLs

The policy file that decides who may reach what — deny-by-default and directional.

The mental model in one sentence

Access is governed by a declarative policy file (huJSON): each rule says a source may reach a destination on given ports — and Tailscale is deny-by-default once you define rules.1

An ACL rule

{
  "acls": [
    { "action": "accept",
      "src": ["tag:laptop"],
      "dst": ["tag:server:22,443"] }
  ]
}

Read it as: devices with tag:laptop may connect to devices with tag:server on ports 22 and 443.1

Four properties to remember

PropertyMeaning
Deny-by-defaultNo explicit allow means no access.
DirectionalAllowing A to B does not allow B to A.1
Locally enforcedA device enforces incoming connections itself.1
Affects tailnet traffic onlyLocal-network access is untouched.1
Key idea The default when you define no acls section is allow-all; an empty acls object denies all. Knowing that default is the difference between "works everywhere" and "locked down".1
