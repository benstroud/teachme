Operating & Automating a Tailnet

Diagnosing paths, keeping connectors alive, and joining nodes unattended.

The mental model in one sentence

Running a tailnet well means three habits: diagnose the path (direct vs relayed), manage key expiry so servers do not drop off, and automate joins with auth keys and tags.1

Diagnose

tailscale status        # peers + direct/relayed
tailscale netcheck      # NAT type, UDP, nearest DERP

If a peer is relayed when you expect direct, it is usually NAT or a blocked UDP port — netcheck points you at the cause.1

Reliability: key expiry

Device keys expire by default. For servers and connectors (subnet routers, exit nodes) that is dangerous: when a connector key expires its routes stay but become unreachable — a fail-close policy that avoids leaking traffic. Disable expiry on always-on nodes, and run connectors in pairs for high availability.2

Key idea A tailnet that "just works" is one where connectors never expire, automation uses tagged auth keys, and short-lived runners clean up after themselves.3
