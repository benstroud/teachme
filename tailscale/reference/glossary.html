Tailscale Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

Core model

Tailscale
A mesh VPN built on WireGuard that connects your devices into a private network using identity, with zero-config traversal of NAT and firewalls.1
WireGuard
The modern, fast, secure VPN protocol Tailscale is built on.1
mesh VPN
Every device connects directly to every other device, rather than all traffic funneling through one gateway.1
overlay network
A virtual network layered on top of the real internet/private networks.
tailnet
Your private Tailscale network — the set of devices and users that share access.1
node / device
A machine (or user) joined to the tailnet.
coordination server
Tailscale's control plane that distributes keys and policy; it does not carry your data.2
DERP relay
Tailscale's encrypted fallback relay used when a direct connection cannot be established.2

Addressing & DNS

tailnet IP
A device's address inside the tailnet, drawn from the 100.64.0.0/10 CGNAT range.3
MagicDNS
Automatic DNS so you can reach devices by name instead of IP.4
FQDN / ts.net
Machine name + tailnet DNS name (ending in .ts.net); shared devices require the full name.4
search domain
Added by MagicDNS so typing the machine name alone resolves.4

Access control

ACL
A rule in the tailnet policy file allowing a source to reach a destination on given ports.5
policy file (huJSON)
The declarative file defining acls, tags, and related settings.6
deny-by-default
Without an explicit allow, communication is blocked when ACLs are defined.5
directional
Allowing A to reach B does not allow B to reach A.5
locally enforced
Each device enforces incoming connections from the distributed rules.5
tag
A label on a device used in ACLs (e.g. tag:server) for policy by role, not person.5
autogroup
A built-in group (e.g. all members) for shorthand in policies.5

Extending the network

subnet router
A node that advertises a LAN CIDR so the tailnet can reach that subnet.7
exit node
A node you route all your internet traffic through.8
SNAT / masquerading
Rewriting source addresses for traffic through a subnet router (default on; can be disabled on Linux).7
return route
The route (for 100.64.0.0/10) devices need when SNAT is disabled.7

Services & servers

Tailscale SSH
Keyless SSH authenticated by identity and access policy, enforced on the server.9
check mode
A Tailscale SSH setting that requires SSO approval before a session.9
Serve
Expose a local service to your tailnet over HTTPS.10
Funnel
Expose a service to the public internet.11

Automation & ops

auth key
A pre-authorized key that joins a device to the tailnet without interactive login.12
ephemeral node
A node that is automatically removed shortly after it goes offline.13
key expiry
Device keys expire by default; disabled for servers, it matters for reliability.
fail-close
If a connector's key expires, its advertised routes stay but become unreachable (no leak).7
