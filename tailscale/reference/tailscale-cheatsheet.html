Tailscale Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The model

mesh VPN on WireGuard  •  identity-based  •  zero-config
tailnet = your private network of devices
data is peer-to-peer; the control plane is not in the path
  • Connections work across NAT/firewalls without port forwarding.1
  • Falls back to an encrypted DERP relay when direct fails.2

2. Your first node

tailscale up            # join / authenticate
tailscale status        # peers + direct/relayed
tailscale ip -4         # tailnet IP (100.64.0.0/10)
tailscale ping NAME     # path to a peer
  • Tailnet addresses come from 100.64.0.0/10.3
  • status shows each path as direct or relayed.2

3. Identity & tags

user      -> a person from your identity provider
device    -> a machine joined under a user
tag:role  -> replaces user ownership for servers
  • Identity, not network location, is the boundary.1
  • Disable key expiry on always-on servers/connectors.

4. MagicDNS

FQDN = machine name + tailnet name (ends .ts.net)
ping monitoring  ==  ping monitoring.yak-bebop.ts.net
  • Search domains let you type the machine name alone.4
  • Devices shared with you need the full domain name.4

5. Access control (ACLs)

{ "acls": [ { "action": "accept",
    "src": ["tag:laptop"],
    "dst": ["tag:server:22,443"] } ] }
  • Deny-by-default, directional, locally enforced.5
  • No acls section = allow all; empty acls = deny all.5

6. Subnet routers

tailscale up --advertise-routes=10.0.0.0/24
# then enable/approve the route in the admin console
tailscale up --snat-subnet-routes=false   # Linux, keep source IPs
  • Extends the tailnet to LANs you cannot install on.6
  • Without SNAT, add a return route for 100.64.0.0/10.6

7. Exit nodes

tailscale up --advertise-exit-node       # on the node
tailscale up --exit-node=my-server       # route ALL internet traffic
tailscale up --exit-node=my-server --exit-node-allow-lan-access
  • Routes the default route, not one subnet.7
  • Useful on untrusted Wi-Fi; changes your public IP.

8. Tailscale SSH

tailscale up --ssh          # advertise SSH on a host
ssh user@my-server          # auth by identity + policy
  • No key files; enforced server-side by policy.8
  • Assumes port 22; check mode can require SSO approval.8

9. Serve & Funnel

tailscale serve --bg 3000     # tailnet only, HTTPS
tailscale funnel --bg 3000    # public internet
tailscale serve status
  • Serve is private to the tailnet.9 Funnel is public.10
  • Tailscale issues the HTTPS cert for the name.11

10. Ops & automation checklist

tailscale netcheck      # NAT type, UDP, nearest DERP
  • Disable key expiry on connectors (fail-close on expiry).6
  • Join unattended with auth keys; tag by role.12
  • Use ephemeral nodes for short-lived runners.13
