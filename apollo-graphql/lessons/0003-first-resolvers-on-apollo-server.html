First Resolvers on Apollo Server

A schema plus a map of functions, and Apollo Server turns them into a running endpoint you can query.

The mental model in one sentence

Apollo Server takes your typeDefs (the SDL) and a resolvers map (functions that return each field's value) and serves them over HTTP as a GraphQL endpoint.1

Install and the minimal server

The current package is @apollo/server (v4+), with graphql as a peer dependency — this replaced the older apollo-server v3 package.1

npm i @apollo/server graphql

import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';

const typeDefs = `#graphql
  type Book {
    id: ID!
    title: String!
    author: String!
  }

  type Query {
    books: [Book!]!
  }
`;

const books = [
  { id: '1', title: 'The Awakening', author: 'Kate Chopin' },
  { id: '2', title: 'City of Glass', author: 'Paul Auster' },
];

const resolvers = {
  Query: {
    books: () => books,
  },
};

const server = new ApolloServer({ typeDefs, resolvers });
const { url } = await startStandaloneServer(server, { listen: { port: 4000 } });
console.log('GraphQL ready at', url);

How the pieces fit

  • typeDefs = your schema, written in SDL inside a #graphql template literal.1
  • resolvers = a plain object keyed by type, then by field. Each entry is a function returning that field's value.
  • The Query.books resolver returns an array of Book objects; Apollo Server then applies field resolvers (or defaults) to shape the response.
  • startStandaloneServer boots a standalone HTTP server with no web framework; expressMiddleware is the alternative when you need Express.1
Key idea A resolver is just a function. It can be async, call a database, call another service, or return a static array — Apollo Server only cares that it returns a value matching the field's type.

Run it and query it

A readable step: start the server, open the Explorer landing page it prints, run { books { id title author } }, and watch the returned JSON mirror your selection exactly. Then add a field to your query (try author only) and see the response change shape while the resolver stays untouched.
