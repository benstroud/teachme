Arguments, Input Types & Mutations

Data enters through arguments and changes through mutations — shaped by input types so the boundary stays typed and stable.

The mental model in one sentence

Fields take arguments (grouped into input types), and writes go through type Mutation — whose resolvers run serially and return a payload the client can read back.1

Arguments on a query

type Query {
  book(id: ID!): Book
  books(filter: BookFilter): [Book!]!
}

type Mutation {
  createBook(input: CreateBookInput!): CreateBookPayload!
}

input BookFilter { minPrice: Float, published: Boolean }
input CreateBookInput { title: String!, authorId: ID!, price: Float }
const resolvers = {
  Query: {
    book: (_parent, { id }) => db.loadBook(id),
    books: (_parent, { filter }) => db.queryBooks(filter),
  },
  Mutation: {
    createBook: async (_parent, { input }, ctx) => {
      const book = await db.createBook(input, ctx.user.id);
      return { code: 'OK', book };
    },
  },
};
// client: mutation CreateBook($input: CreateBookInput!) { createBook(input: $input) { code book { id title } } }

Design decisions that matter

  • Arguments live on the field. A nested field can take arguments too (e.g. author { books(first: 5) }). Its resolver uses both parent and args.
  • Group related arguments into an input type rather than a dozen flat arguments — it stays extensible and readable.1
  • Return a payload, not a bare scalar. A createBook that returns just Book breaks the moment you need to also report code or warnings. A payload type grows without breaking clients.2
Key idea Mutations are where state changes must be explicit. Return enough (the object plus a result code) so clients can react; treat errors as structured data when practical rather than only as transport failures.

Single responsibility on write paths

Keep the resolver thin: it validates against the schema (done for you), checks authorization (later lessons), calls one service function, and shapes the payload. No business logic in the resolver itself; you want it to read as a coordination call, not a program.2
