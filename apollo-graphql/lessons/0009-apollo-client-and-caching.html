Apollo Client and Caching

A browser-side data layer: run operations, and normalize results so the same entity is stored once and shared everywhere.

The mental model in one sentence

Apollo Client (web, v4) wraps your view layer in a provider, exposes hooks like useQuery/useMutation, and keeps a normalized cache — each entity stored once by __typename + id, then reused across queries.1

Wire it up

import { ApolloClient, InMemoryCache, gql } from '@apollo/client';
import { ApolloProvider, useQuery } from '@apollo/client';

const client = new ApolloClient({
  uri: '/graphql',
  cache: new InMemoryCache(),
});

// wrap the app: <ApolloProvider client={client}>...</ApolloProvider>

const BOOK = gql`query Book($id: ID!) { book(id: $id) { id title author { id name } } }`;

function BookCard({ id }) {
  const { loading, error, data } = useQuery(BOOK, { variables: { id } });
  if (loading) return <p>loading…</p>;
  if (error) return <p>{error.message}</p>;
  return <p>{data.book.title} by {data.book.author.name}</p>;
}
  • ApolloProvider gives the component tree access to the configured client.1
  • useQuery returns loading/error/data; useMutation returns a function you call to fire a write.
  • Operations are written with the gql template tag so the client can parse and cache them.

What normalized caching means

Query A fetches book { id title author { id name } } and query B fetches book { id title price }. Because the cache keys objects by __typename + id, the Book is stored once: A's cache write fills title/author, B's fills price. Reading A again returns the merged entity, and the same Book anywhere else on screen is the same cached object.2

Key idea This is a different cache from the server's. The server caches to avoid work per client; the client cache avoids re-fetching and keeps one screen consistent — so the schema must expose stable ids on the objects you want merged.

Server vs client responsibilities

LayerWhat it is for
Apollo ServerExecutes operations against data, returns the exact selection. No knowledge of the UI's cache.
Apollo ClientRuns operations, caches normalized results, and keeps the UI in sync as data changes.

This division is why authors/books need ids returned to the client: normalization only kicks in when the cache can identify each entity.
