Integrating a Data Layer

The schema promises a shape; the data layer holds the truth. A thin loader/service boundary maps one to the other so resolvers stay thin.

The mental model in one sentence

Resolvers are coordinators: they translate schema fields to calls on a service/loader layer, never reach into SQL/HTTP themselves — so your GraphQL layer and your storage stay decoupled.1

The seam between schema and data

// userLoader.ts  — the only place that knows about the table/client
const db = postgresClient;   // Prisma, pg, whatever the project uses

export function loadBook(id) {
  return db.book.findUnique({ where: { id } });
}
export function queryBooks(filter) {
  return db.book.findMany({
    where: { price: { gte: filter?.minPrice }, published: filter?.published },
  });
}

// resolvers.ts  — thin, only maps fields to loader calls
const resolvers = {
  Query: {
    book: (_p, { id }) => loadBook(id),
    books: (_p, { filter }) => queryBooks(filter),
  },
};

The resolver returns rows that already map 1:1 to schema fields, so the default resolver fills most of the response. You write an explicit field resolver only for computed fields or joins the row does not already carry.

Three integration shapes

SourcePattern
Database (Prisma, pg, DynamoDB)A query/loader module the resolvers call; rows usually map cleanly to schema types.
Another service (HTTP)A thin client that fetches the external resource; the resolver awaits it and returns mapped data.
Computed/derived fieldsExplicit field resolvers on the type (e.g. price from priceInCents).

Rules of thumb

  • Keep the loader layer the only place that knows storage. If your ORM changes, resolvers don't.1
  • Return domain-shaped objects. Prefer rows that already carry the field names your schema expects, so the default resolver does the work for free.
  • Watch the per-item joins. A Book.author resolver that queries per book is where the N+1 problem sneaks in — that is resolved next lesson.
  • Put shared deps on context. The DB client and loaders live in contextValue, constructed per request (see the context lesson).
Key idea The schema is your contract, the data layer is your storage, and resolvers are the thin translators between them. Resist writing SQL inside a resolver — that couples today's query to tomorrow's schema changes.
