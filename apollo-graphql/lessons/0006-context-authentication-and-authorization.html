Context, Authentication & Authorization

Prove who the caller is once per request (context), then enforce what they may do field by field (authorization).

The mental model in one sentence

The context function runs once per request and builds contextValue — the same object injected into every resolver, which is where you put the verified user, the DB client, loaders, and tracing.1

Building contextValue

import { startStandaloneServer } from '@apollo/server/standalone';

const { url } = await startStandaloneServer(server, {
  context: async ({ req }) => ({
    user: await authenticate(req.headers.authorization),
    db: dbClient,
    loaders: makeLoaders(),
  }),
});
  • context receives the incoming request and returns your per-request object.1
  • Read the Authorization header, verify the token once, and resolve it to a user — then every resolver gets it from contextValue.
  • Put a verified user in context, never a raw password or secret.

Authorization belongs in the resolvers

import { GraphQLError } from 'graphql';

function requireRole(ctx, role) {
  if (ctx.user?.role !== role) {
    throw new GraphQLError('Not allowed', { extensions: { code: 'FORBIDDEN' } });
  }
}

const resolvers = {
  Mutation: {
    deleteBook: (_parent, { id }, ctx) => {
      requireRole(ctx, 'ADMIN');
      return db.deleteBook(id);
    },
  },
  Book: {
    price: async (book, _args, ctx) => {
      if (!ctx.user) throw new GraphQLError('Login required', { extensions: { code: 'UNAUTHENTICATED' } });
      return book.price;
    },
  },
};

Throw a GraphQLError to surface a structured error; Apollo Server places it in the response's errors array with your extensions intact.2

Key idea Authentication is "who are you?" — done in context, once. Authorization is "may you do this?" — done per field/type in resolvers (or via a directive that wraps them). Keep the two clearly separate in your head and your code.

A few practical rules

  • A small require* helper (or a directive) keeps checks consistent instead of copy-pasted per resolver.
  • Distinguish UNAUTHENTICATED (not logged in) from FORBIDDEN (logged in but not allowed).2
  • For web-framework integrations (Express), req may carry the parsed request; the same token logic applies. Flag: the exact context signature differs between startStandaloneServer and expressMiddleware — confirm against the installed version.
