Apollo GraphQL Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

The schema language

GraphQL
A query language and a runtime contract for APIs. Clients send a selection of the fields they want; the server returns exactly that shape.1
SDL (Schema Definition Language)
The textual syntax used to describe a GraphQL schema: types, fields, scalars, nullability, lists, enums, inputs, interfaces, unions.2
scalar
A leaf type with no sub-fields. GraphQL ships five: Int, Float, String, Boolean, ID. Custom scalars (e.g. a DateTime) can be added.2
object type
A type made of named, typed fields, e.g. type Book { title: String }. Every field ultimately resolves to scalars or other objects.
field
A named member of an object type carrying a type and (optionally) arguments. Clients select fields to include in the response.
nullability / !
The non-null marker. title: String may be null; title: String! must never be null. If a non-null resolver throws, the error propagates to the nearest nullable parent field.2
list [T]
A field whose value is a list of type T. Combinations like [Book!]! (non-null list of non-null books) encode strictness.
enum
A named set of allowed string values, e.g. enum OrderStatus { CREATED FULFILLED }. Validated by both server (schema) and client (operation).2
input type
A same-shape-as-an-object type used for arguments, marked with the reserved input keyword. Can hold scalars, enums, other inputs, and lists — but not interfaces or unions directly.2
interface
A contract of shared fields that concrete object types must implement, enabling a field to return any implementing type. Clients select with ... on Type inline fragments.2
union
A type listing possible object types with no shared required fields; the response must disambiguate with __typename/inline fragments.
operation
A named (or anonymous) request: query, mutation, or subscription. Queries may run in parallel; mutations run serially.2

The runtime (Apollo Server)

@apollo/server
The current Apollo Server package (v4+). Replaced the older apollo-server v3 package; graphql is a peer dependency.3
typeDefs
Your schema, written in SDL as a string or template literal, passed to new ApolloServer({ typeDefs, resolvers }).3
resolver
A function that returns the value for a schema field. Signature: (parent, args, contextValue, info). Root Query/Mutation fields have no parent.4
resolver chain
The way execution walks an operation: it calls the root field resolver, then for each nested field calls that field's resolver with the parent's returned value, and so on, depth-first.
default resolver
The fallback Apollo Server uses when a field has no resolver: it reads parent[fieldName]. This is why a resolver can return a plain object.4
parent / root value
The object the parent resolver returned, given to the child resolver as its first argument (parent). For root fields it is undefined.4
args
The second resolver argument: the operation's arguments, validated and coerced against the schema.
startStandaloneServer
A helper from @apollo/server/standalone that starts Apollo Server on its own HTTP server, with no web framework required.3
GraphQLError
The error class thrown in resolvers; carries a message, extensions, and an optional HTTP status code. It is how you surface typed, structured errors.5

Context & data

contextValue
The third resolver argument: an object shared across every resolver for a single request. Built by the context function; the natural home for the current user, the DB client, loaders, and tracing.6
context function
A per-request function passed to Apollo Server (e.g. context: async ({ req }) => ({ ... })) whose return value becomes contextValue.6
N+1 problem
Executing one query for the list item plus one query per item (N), causing N+1 total queries to the data source for a single operation.
DataLoader
A small batching/caching utility (dataloader npm package) that coalesces many load() calls in one tick into a single batch, and caches results within the instance's lifetime — which must be one request.7

Client & federation

@apollo/client
Apollo's client library (web, v4): sends operations, manages caching, and exposes hooks like useQuery/useMutation to view layers.8
ApolloProvider
The React context provider that makes a configured ApolloClient available to the component tree.8
InMemoryCache
Apollo Client's normalizing cache. It stores each object once, keyed by __typename + id, so returning the same entity is deduplicated and shared across queries.9
supergraph
The single, composed GraphQL schema that clients query in a federated architecture.10
subgraph
A single GraphQL service (e.g. an Apollo Server) that contributes part of the supergraph. Built with buildSubgraphSchema from @apollo/subgraph.10
entity
A type defined with @key(fields: ...): an identity that multiple subgraphs can contribute fields to, matched across subgraphs.11
__resolveReference
The subgraph resolver, returned from a type's resolver row, that loads an entity from just its key fields when another subgraph references it.11
Apollo Router
The graph gateway that serves the supergraph to clients and routes each request across the subgraphs that can answer it.10
