SQS Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The message model

A message on a queue looks like this (what your producer sends and what your consumer receives):

{
  "MessageId":    "9b...",
  "ReceiptHandle": "AQEBaZ...==",
  "MessageBody":  "{\"orderId\":\"ord_1001\",\"total\":129.99}",
  "MessageAttributes": {
    "eventType": { "DataType": "String", "StringValue": "Order Placed" },
    "priority":  { "DataType": "Number", "StringValue": "5" }
  },
  "Attributes": {
    "SentTimestamp":     "1757145600000",
    "ApproximateReceiveCount": "1",
    "ApproximateFirstReceiveTimestamp": "1757145610000"
  }
}
FieldMeaning
MessageBodyYour payload (up to 256 KiB). SQS treats it as opaque text — JSON in, JSON out.
MessageIdSQS-assigned unique id. Reuse it as the idempotency key.
ReceiptHandleRequired to DeleteMessage or ChangeMessageVisibility. Expires — not a durable ref.
MessageAttributesUp to 10 structured fields (String / Number / Binary) sent with the body.
AttributesSQS-set metadata: sent time, receive count, first-receive time.

2. Producer (TypeScript sketch)

import { SQSClient, SendMessageCommand } from "@aws-sdk/client-sqs";

const sqs = new SQSClient({});

await sqs.send(new SendMessageCommand({
  QueueUrl:    "https://sqs.us-east-1.amazonaws.com/123/orders",
  MessageBody: JSON.stringify({ orderId: "ord_1001", total: 129.99 }),
  MessageAttributes: {
    eventType: { DataType: "String", StringValue: "Order Placed" }
  },
  // For FIFO queues only:
  // MessageGroupId: "ord_1001",
  // MessageDeduplicationId: "ord_1001",
}));
  • QueueUrl is the address; you can also use QueueName via GetQueueUrl.
  • For FIFO queues, the queue name must end with .fifo; both FIFO-only fields are required.

3. Consumer — Lambda with event source mapping

import { SQSBatchResponse, SQSEvent, SQSHandler, SQSRecord } from "aws-lambda";

export const handler: SQSHandler = async (event: SQSEvent): Promise<SQSBatchResponse> => {
  const failures: { itemIdentifier: string }[] = [];

  for (const record of event.Records) {
    try {
      const order = JSON.parse(record.body);
      await processOrder(order, record.messageId);
    } catch (err) {
      failures.push({ itemIdentifier: record.messageId });
    }
  }

  // Returning this tells SQS: delete the successful ones,
  // leave the failed ones in the queue (their visibility will expire and retry).
  return { batchItemFailures: failures };
};
  • ESM polls the queue (long polling by default since 2022), batches up to batchSize (default 10) or waits up to batchWindow (default 0).
  • Returning batchItemFailures with itemIdentifier values is the partial batch response. SQS only retries those.
  • Tip: the same handler code works whether or not you return batchItemFailures — the response is opt-in.13

4. Standard vs FIFO

DeliveryAt-least-onceExactly-once
OrderBest-effortStrict per MessageGroupId
Throughput (default)Nearly unlimited300 msg/s (3,000 with batching)
Throughput (high-throughput mode)n/a3,000 msg/s (with batching)
DedupNone5-minute dedup window via MessageDeduplicationId

Default to standard. Reach for FIFO when you can name a specific business reason you need order and dedup.

5. Polling

  • Short polling (default): immediate response, samples subset of servers; more empty receives at low load.
  • Long polling: WaitTimeSeconds 1–20; SQS holds the request open until a message arrives or wait expires. Reduces cost and empty responses.
  • For a Lambda ESM, long polling is enabled automatically — no extra config needed.

6. Visibility timeout

  • Default 30s; range 0–12 hours. Set per queue or per message.
  • Clock starts when a message is received.
  • If you don't delete (or the consumer crashes), the message becomes visible again after the timeout and gets retried.
  • For long tasks, call ChangeMessageVisibility periodically to keep extending.
  • Set this higher than your P99 handler duration. Lower it for fast-failing jobs.

7. Dead-letter queue

  • Configure a redrive policy on the source queue: maxReceiveCount (default 10).
  • DLQ must be same account + region as the source.
  • FIFO sources can use FIFO DLQs.
  • DLQ messages keep the original body and a few extra attributes (DeadLetterQueueSourceArn, ApproximateReceiveCount).
  • Use DLQ redrive to move messages back to the source after a fix.
  • Alarm on ApproximateNumberOfMessagesVisible on the DLQ.

8. Choosing: SQS vs SNS vs EventBridge

Behavior neededReach for
Single consumer group pulls durable work at its own paceSQS
Strict order per entity + dedupSQS FIFO with MessageGroupId
Tell-everyone fan-out, push to many subscribersSNS
Route events to many targets by content filterEventBridge bus
Each event must reach every subscriber reliablySNS → SQS per subscriber
Buffer before a slow consumer; backpressureSQS

9. Design checklist

  • Idempotent handlers — dedupe on messageId or a business id from the body. Treat every retry as if it could be a duplicate.
  • Visibility timeout > P99 handler duration, with headroom.
  • DLQ on every queue with a redrive policy. Alert on its depth.
  • Long polling for any custom consumer; ESM gets it for free.
  • Don't store big payloads in the body; use S3 + a reference, or the Extended Client Library.
  • Use FIFO groups correctly: one group per logical entity, not one for the whole queue.
  • Partial batch response for Lambda — return only the failed message ids.
  • Monitor: ApproximateNumberOfMessagesVisible, ApproximateNumberOfMessagesNotVisible, ApproximateAgeOfOldestMessage.
