SQS Core Concepts

Queue, message, polling — the vocabulary you will reuse for the rest of the course.

The mental model in one sentence

A queue is a named, durable inbox. Producers SendMessage into it; consumers ReceiveMessage from it; consumers DeleteMessage when they're done with each message. SQS stores the messages redundantly across Availability Zones so that no single server going down loses work.1

The two queue types

SQS has exactly two kinds of queue, and you choose one when you create it:

TypeWhen to pick it
Standard queueDefault choice. At-least-once delivery, best-effort order, virtually unlimited throughput. Pick this unless you have a specific reason not to.
FIFO queueWhen order within a logical group matters and duplicates are unacceptable. Lower throughput cap (300/s default; 3,000/s with batching; up to 3,000/s without batching in high-throughput mode). Queue name must end with .fifo.2
Key idea Most production queues are standard. Reach for FIFO when you can name a business reason for order and dedup — not "it would feel safer."

The message

Every message on an SQS queue carries:

  • MessageBody — your payload, up to 256 KiB. SQS treats it as opaque text. JSON in, JSON out.
  • MessageId — a SQS-assigned unique id. Use it as your idempotency key.
  • ReceiptHandle — a per-receive token you must present to DeleteMessage or ChangeMessageVisibility. It expires; it is not a durable reference.
  • MessageAttributes — up to 10 small structured fields (String / Number / Binary) sent alongside the body.
  • Attributes — SQS-set metadata like SentTimestamp and ApproximateReceiveCount.3

The producer side: SendMessage

TypeScript with the v3 SDK looks like this:

import { SQSClient, SendMessageCommand } from "@aws-sdk/client-sqs";

const sqs = new SQSClient({});

await sqs.send(new SendMessageCommand({
  QueueUrl:    "https://sqs.us-east-1.amazonaws.com/123456789012/orders",
  MessageBody: JSON.stringify({ orderId: "ord_1001", total: 129.99 }),
  MessageAttributes: {
    eventType: { DataType: "String", StringValue: "Order Placed" }
  },
  // For FIFO queues only:
  // MessageGroupId:        "ord_1001",
  // MessageDeduplicationId: "ord_1001",
}));

Three things to know:

  • QueueUrl identifies the queue. You can also look it up by name via GetQueueUrl.
  • MessageBody is a string. JSON-stringify objects before sending.
  • For FIFO queues, MessageGroupId is required; MessageDeduplicationId is optional but strongly recommended.

The consumer side: ReceiveMessage and DeleteMessage

The classical two-step dance, used by anything that polls the queue directly:

import { SQSClient, ReceiveMessageCommand, DeleteMessageCommand } from "@aws-sdk/client-sqs";

const sqs = new SQSClient({});

const { Messages } = await sqs.send(new ReceiveMessageCommand({
  QueueUrl:           "https://sqs.us-east-1.amazonaws.com/123/orders",
  MaxNumberOfMessages: 1,
  WaitTimeSeconds:    20,            // long polling
  VisibilityTimeout:  60,
  MessageAttributeNames: ["All"],
}));

for (const msg of Messages ?? []) {
  await handle(JSON.parse(msg.Body!));
  await sqs.send(new DeleteMessageCommand({
    QueueUrl:      "https://sqs.us-east-1.amazonaws.com/123/orders",
    ReceiptHandle: msg.ReceiptHandle!,
  }));
}

Two crucial details:

  • Long polling: WaitTimeSeconds: 20 makes SQS hold the request open until a message arrives or 20s elapses. Cheaper than short polling and recommended everywhere.4
  • Delete with ReceiptHandle: the ReceiptHandle is the only thing that authorizes the delete. If you lose it, the message becomes visible again when the visibility timeout expires (more on that in lesson 5).
Engineer's note If you ever write a custom consumer instead of a Lambda event source mapping, long polling is the single biggest cost lever you have.

Queue URL and ARN

Every queue has both. The URL is what you put in QueueUrl on the API calls. The ARN is what IAM policies reference:

URL : https://sqs.us-east-1.amazonaws.com/123456789012/orders
ARN : arn:aws:sqs:us-east-1:123456789012:orders

A FIFO queue's URL and ARN both carry the .fifo suffix.

The minimal vocabulary

Lock these in before the next lesson:

  • Queue — the named durable inbox.
  • Standard queue — at-least-once, best-effort order, default.
  • FIFO queue — exactly-once, strict order per group, .fifo suffix.
  • Message — body + id + receipt handle + optional attributes.
  • SendMessage / ReceiveMessage / DeleteMessage — the three verbs.
  • ReceiptHandle — the per-receive token; expires.
