Why Batching

The fix for N+1 is to turn many small per-item calls into one batched call — DataLoader is a batching and caching utility built for exactly that.

The mental model in one sentence

DataLoader is a small utility for the data-fetching layer that provides batching (coalesce many individual loads into one batch) and caching (memoize the result of each key) over your data source.1

Batching, precisely

You create a loader with a batch function — it accepts an array of keys and returns an array of values. Individual load(key) calls that happen during a single frame (one tick of the event loop) are coalesced into one call to that batch function with all the requested keys.1

const userLoader = new DataLoader(keys => myBatchGetUsers(keys));

const one = await userLoader.load('u1');
const two = await userLoader.load('u2');
const three = await userLoader.load('u3');
// all three loads in one tick → ONE myBatchGetUsers(['u1','u2','u3'])

And caching, also called memoization

Each loader instance keeps its own cache. Once a key resolves it is stored, so loading the same object twice in a request fetches it once and reuses it — preventing duplicate queries even when the same entity appears many times in the response.1

Key idea Batching fixes the N+1 count; caching fixes the duplicates. They work together: batching merges concurrent loads, caching makes repeated loads free. This is why Apollo recommends DataLoader for the N+1 problem.2

Why per-request

Every loader instance is a unique cache. In a web server you should generally create instances per request, because different users are allowed to see different things — a global cache would hand one user's data to another.1 The next lessons build on this scope decision.
