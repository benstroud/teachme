The Cache & Per-Request Scope

Batching fixes the query count; the cache prevents repeats. But the cache is only safe if it lives for exactly one request.

The mental model in one sentence

Each DataLoader instance is a unique memoization cache scoped to that instance — and since different users may see different things, in a web server you create instances per request.1

The memoization cache

Once a key resolves on a loader, its value is cached and reused for later load(key) calls on that instance. This deduplicates: if the same entity appears several times in one response, it is fetched once and the others are served from cache — exactly the "avoids loading the same object twice during a single request" behavior Apollo calls out.12

Per-request instances

// WRONG: shared across all requests
const userLoader = new DataLoader(batchUsers); // global

// RIGHT: created fresh for each request
const resolvers = {
  Query: { users: (_p, _a, ctx) => ctx.loaders.users.load('list') },
};

A global loader is a global cache: request A could read values cached for request B's user. Fresh instance per request keeps the cache from leaking identity or stale data across users.1

Key idea Scope the cache to the request and nothing wider. If you need cross-request caching, use a real shared cache with explicit invalidation; the memoization cache is for request-scoped deduplication, not for global TTL caching.

Prime, clear, and control

You can seed values with prime(key, value), drop one with clear(key), or reset the whole cache with clearAll() — each a way to influence the cache you control per instance.1
