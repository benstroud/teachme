Cache Keys & Priming

Keys are identity for the cache — use cacheKeyFn for composite keys, prime to seed known values, and clear deliberately.

The mental model in one sentence

Every load(key) is stored under a cache key; you can customize that with cacheKeyFn, seed values with prime, and evict with clear/clearAll.1

Composite keys and cacheKeyFn

When a loader's logical key is more than one field (e.g. { locale, id } or a date + id), the cache needs to tell them apart. Use cacheKeyFn to produce the cache key from the requested key:1

new DataLoader(
  async (keys: ReadonlyArray<{ locale: string; id: string }>) =>
    batchGetComposite(keys as { locale: string; id: string }[]),
  {
    cacheKeyFn: (key) => `${key.locale}:${key.id}`,
  },
);
  • cacheKeyFn transforms the key before it is used for the cache and for uniqueness within a batch.1
  • Without it, an object key is compared by reference, which would defeat batching/caching for composite inputs.
Key idea The cache key must be stable and collision-free for your keys. A serialized form (like locale:id) is the common recipe; make sure it cannot collide between distinct logical keys.

Prime known values

const loader = new DataLoader(batchUsers);
loader.prime('u1', alreadyLoadedUser);   // seed a value from elsewhere
await loader.load('u1');                  // served from the cache, no batch

prime(key, value) places a value in the cache without a batch call — handy when a value was already fetched (e.g. from a parent) and you want later resolves to reuse it.1

Clear to control the cache

clear(key) removes one cached value; clearAll() resets the whole instance (including the pending batch queue). Use these when a mutation makes a cached value stale within the request and you want it re-fetched.1
