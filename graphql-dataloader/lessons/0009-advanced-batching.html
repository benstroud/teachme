Advanced Batching

One-to-many relationships, two-stage (nested) batches, and cap on batch size — the moves that keep deep queries to a handful of queries.

The mental model in one sentence

Beyond simple by-id loads, you batch children by their owner, chain a second loader through a first result (two-stage batching), and use maxBatchSize to keep any single batch from getting absurdly large.1

One-to-many: batch posts by owner

async function batchPostsByOwner(keys: ReadonlyArray<string>) {
  const rows = await db.posts.whereIn('ownerId', keys as string[]);
  const groups = new Map<string, Post[]>();
  for (const p of rows) {
    if (!groups.has(p.ownerId)) groups.set(p.ownerId, []);
    groups.get(p.ownerId)!.push(p);
  }
  return keys.map(ownerId => groups.get(ownerId) ?? []); // list per owner
}

Each key still gets a value (an array — empty if none), so alignment holds and one query serves every "posts of this user" field in the request.1

Two-stage (nested) batching

Sometimes a loader needs another loader's output: load posts by owner, collect the unique authorIds, then load authors. Because the second stage's loads all happen together in the same downstream tick, they too form a single batch:

async function batchPostAuthors(keys) {
  const postsByOwner = await ownerPostsLoader.loadMany(keys);
  const authorIds = [...new Set(postsByOwner.flat().map(p => p.authorId))];
  const authors = await userLoader.loadMany(authorIds);   // one batch
  const byId = new Map(authors.map(a => [a?.id, a]));
  return (postsByOwner as Post[][]).map(list => list.map(p => byId.get(p.authorId)));
}

Deep nesting still resolves in a few batches because each level's loads are collected before fetching the next.1

Key idea New batches form when a loader is awaited: the awaiting resolver's downstream loads pile up in one tick. Compose loader-wrapping-loaders, but keep each stage fetching once.

Cap the batch with maxBatchSize

new DataLoader(batchFn, { maxBatchSize: 100 });

maxBatchSize splits a very large batch into groups of at most that many keys, avoiding an oversized single query while still batching within each group.1
