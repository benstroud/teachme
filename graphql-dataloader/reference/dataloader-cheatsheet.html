DataLoader Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The core

npm install dataloader

import DataLoader from 'dataloader';

// batchLoadFn: keys in, values out — ALIGNED BY INDEX
const userLoader = new DataLoader(async (keys: ReadonlyArray<string>) => {
  const rows = await db.users.whereIn('id', keys as string[]);
  const byId = new Map(rows.map(r => [r.id, r]));
  return keys.map(id => byId.get(id) ?? null);   // same order as keys
});

const u = await userLoader.load('u1');          // batched across one tick
  • Batching: loads in one event-loop tick coalesce into one batch call.1
  • Caching: each instance memoizes; the same key loads once per request.1
  • Per-request instance: build loaders in the context function, not globally.1

2. In Apollo Server + TypeScript

import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';

type ContextValue = { loaders: { users: DataLoader<string, User> } };

const server = new ApolloServer<ContextValue>({ typeDefs, resolvers });

const { url } = await startStandaloneServer(server, {
  context: async ({ req }) => ({
    loaders: { users: new DataLoader(batchUsers) },  // fresh per request
  }),
});

// field resolver uses the loader on contextValue
type User = { id: string; posts?: unknown };
const resolvers = {
  User: { async user(parent:any,_a:any,ctx:ContextValue){ /* loader */ } },
};

Put loaders on contextValue so every resolver for the request shares the same cache.2

3. Batch function rules

  • Return an Array the same length as the keys, each value at the same index.1
  • Prefer a Map/dictionary keyed by the row's id, then keys.map(key => byId.get(key)).
async function batchAuthors(ids) {
  const rows = await db.authors.whereIn('id', ids);
  const byId = new Map(rows.map(r => [r.id, r]));
  return ids.map(id => byId.get(id) ?? null);
}

4. Cache keys & priming

// normalize / stringify composite keys
new DataLoader(batchFn, {
  cacheKeyFn: (key) => `${key.t}:${key.id}`,
  maxBatchSize: 100,     // cap batch size
});
loader.prime('u1', cachedUser);   // seed a known value
loader.clear('u1');               // drop one cached value
loader.clearAll();                // drop all (and the batch queue)

5. Errors & missing values

  • Missing rows: return null (or undefined) for that index — do not skip it.1
  • Per-key failures: return an Error instance at that index; the batch resolves and that key rejects.1
  • Throwing from the batch function rejects every load in that batch.
  • A rejected load() is cached as an error, but only until it is cleared — treat errors as values you handle.

6. N+1 → batched

// BEFORE: posts resolver queries per post-author
// AFTER:
const resolvers = {
  User: { posts: (user, _a, ctx) => ctx.loaders.userPosts.load(user.id) },
};
// ctx.loaders.userPosts batches by user.id in one tick → one grouped query

The N+1 problem is per-item resolution; DataLoader turns it into one grouped batch.3

7. Checklist

  • Create loaders per request (contextValue), never globally.1
  • Batch function returns values aligned by index; use a Map and remap by keys.
  • Return null for missing, Error for per-key failures.
  • Use cacheKeyFn for composite keys; prime for known values.
  • Cap giants queries with maxBatchSize and split batches consciously.
  • Verify with a query/query-count log, not by reading code.
  • Skip DataLoader for one-off root lookups and for data you already have.
