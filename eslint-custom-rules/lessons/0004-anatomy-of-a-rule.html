Anatomy of a Rule

meta describes, create observes, report speaks.

Every rule is the same three parts

// rules/no-todo.js  (CommonJS)
"use strict";

module.exports = {
  meta: {
    type: "suggestion",
    docs: {
      description: "Disallow TODO comments in shipped code.",
      url: "https://example.com/rules/no-todo",
    },
    schema: [],                     // no options accepted
    messages: {
      todo: "Remove this TODO before shipping.",
    },
  },

  create(context) {
    const sourceCode = context.sourceCode;

    return {
      Program() {
        for (const comment of sourceCode.getAllComments()) {
          if (/^\s*todo\b/i.test(comment.value)) {
            context.report({ loc: comment.loc, messageId: "todo" });
          }
        }
      },
    };
  },
};

meta describes the rule, create subscribes to nodes, and context.report emits a problem. That is the entire contract, and the official tutorial builds exactly this shape from an empty file.12

meta: the fields that change behaviour

FieldWhy it matters
type"problem", "suggestion", or "layout"; filters with --fix-type.1
docs.descriptionHuman summary; docs.url is what editors link to.1
schemaValidates options; omit or [] to accept none.1
messagesNamed message templates, addressed by messageId.1
fixableRequired to return a fix ("code" or "whitespace").1
hasSuggestionsRequired to return suggest entries.1

Omit fixable and hasSuggestions unless you use them — declaring them falsely is also an error, because ESLint validates that the rule behaved as advertised.1

create: a map of visitors

create(context) {
  let depth = 0;                      // fresh per file: create runs once per file

  return {
    FunctionDeclaration() { depth += 1; },
    "FunctionDeclaration:exit"() { depth -= 1; },
    CallExpression(node) {
      if (depth > 2 && node.callee.name === "eval") {
        context.report({ node, messageId: "tooDeep" });
      }
    },
  };
}

Keys are node types or selectors; values run when traversal reaches them. :exit fires on the way back up, which is how you maintain a stack. Because a fresh create call happens per file, closure state cannot leak between files. The node type names themselves come from ESTree.13

Report with message IDs, not strings

messages: {
  tooDeep: "Do not call eval() more than two functions deep.",
  todo: "{{tag}} left in shipped code.",
},

// later
context.report({
  node,
  messageId: "todo",
  data: { tag: "TODO" },
});

Placeholders in {{double_braces}} are filled from data. Using messageId keeps every wording in one place and lets tooling treat messages as data rather than prose.1

Key idea A rule should be a pure observer: same AST plus same options produces the same reports. No network, no filesystem, no module-level mutable state.1
