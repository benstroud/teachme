Autofix and Suggestions

Fix what is mechanical; suggest what needs a decision.

A fix is a description, not an edit

module.exports = {
  meta: {
    type: "suggestion",
    fixable: "code",                       // mandatory
    schema: [],
    messages: { strict: "Use the strict equality operator." },
  },

  create(context) {
    const sourceCode = context.sourceCode;

    return {
      BinaryExpression(node) {
        if (node.operator !== "==" && node.operator !== "!=") { return; }

        context.report({
          node,
          messageId: "strict",
          fix(fixer) {
            const operator = sourceCode.getTokenAfter(node.left);
            return fixer.replaceText(operator, node.operator + "=");
          },
        });
      },
    };
  },
};

You never mutate the file. You return a fixing object — a range plus replacement text — and ESLint decides whether and when to apply it. The tutorial's worked example does exactly this with fixer.replaceText.13

The fixer API

MethodEffect
insertTextBefore(nodeOrToken, text)Insert just before the range.1
insertTextAfter(nodeOrToken, text)Insert just after the range.1
replaceText(nodeOrToken, text)Swap the whole range.1
remove(nodeOrToken)Delete the whole range.1
…Range(range, text)Same operations against explicit [start, end) offsets.1

A fix() may return one fixing object, an array, any iterable, or a generator — but the ranges must not overlap. Overlap means ESLint cannot know which text wins.1

Why fixes are deferred

  • Fixes from different rules can collide, so ESLint applies only non-overlapping ones per pass.1
  • After applying, ESLint re-runs every rule on the new text and repeats, up to 10 passes, until nothing more is fixable.1
  • Therefore a fixer does not need to chase another rule's style: guess a quote style, and the style rule will correct it on the next pass.1

Best practices: never change runtime behaviour, keep the range as small as possible, and emit one fix per message.1

When there is no single right answer: suggestions

meta: {
  hasSuggestions: true,                    // mandatory
  messages: {
    escape: "Unnecessary escape character.",
    removeSlash: "Remove the backslash.",
    doubleSlash: "Keep a literal backslash instead.",
  },
},

context.report({
  node,
  messageId: "escape",
  suggest: [
    { messageId: "removeSlash",  fix: (fixer) => fixer.removeRange(range) },
    { messageId: "doubleSlash",  fix: (fixer) => fixer.insertTextBeforeRange(range, '\\') },
  ],
});

Suggestions appear in editors for a human to choose. They are applied as stand-alone changes, do not trigger multipass fixing, and are dropped entirely if their fix returns null or empty.1

Ask the agent Add a fix to your debugger rule: remove the statement, plus its semicolon if it has one. Then run --fix-dry-run to inspect the diff without touching disk.

The CLI switches

npx eslint . --fix                     # apply fixes, write files
npx eslint . --fix-dry-run             # show what would change
npx eslint . --fix-type problem        # only fix rules typed "problem"
npx eslint . --fix-type layout,suggestion

--fix-type takes the same vocabulary as meta.type, plus directive for disabling-comment fixes.2
