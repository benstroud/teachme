Scope, Performance & Rollout

Resolve names properly, stay fast, and land the rule without a revolt.

Text matching breaks on names

import { log } from "./logger.js";

function outer() {
  const log = () => {};
  log();            // a different `log`
}

A rule that greps for log() cannot tell these apart. The linter can: it builds scopes and resolves each identifier to the binding it actually refers to.1

const sourceCode = context.sourceCode;
const scope = sourceCode.getScope(node);

In ESLint v9 the old context.getScope() was removed; sourceCode.getScope(node) is the supported way to ask "what scope is this node in?".1

Variables and references

create(context) {
  const sourceCode = context.sourceCode;

  return {
    "Program:exit"(node) {
      const scope = sourceCode.getScope(node);

      for (const variable of scope.variables) {
        const used = variable.references.some((ref) => ref.isRead());
        if (used) { continue; }

        context.report({
          node: variable.identifiers[0],
          messageId: "unused",
          data: { name: variable.name },
        });
      }
    },
  };
}

Each Variable carries its defs (where it was declared) and references (every read and write in the module). Reference#isRead() distinguishes consuming a value from assigning one.1

Scopes come in kinds — global, module, function, block, class, catch, switch, and more — so a complete rule walks child scopes rather than only the top one.1

When your rule creates a use

sourceCode.markVariableAsUsed("myCustomVar", node);

If a rule makes a variable genuinely used in a way ESLint cannot see — a template, a generated reference — mark it, or no-unused-vars will keep complaining about a variable your rule just consumed.1

Performance is a correctness feature

  • Let selectors do the filtering. "CallExpression[callee.name='eval']" visits a handful of nodes; a Program listener that loops every node visits all of them.2
  • Do work on exit, not on every child. Accumulate during traversal, decide in :exit.2
  • Cache per file. create() runs once per file, so anything derived from sourceCode can be computed once and closed over.1
  • Avoid quadratic token scans. Repeated getTokenBefore inside a loop over nodes is the usual culprit.

Rollout checklist

npx eslint --print-config src/app.js | grep acme   # is it on, with which options?
npx eslint . --max-warnings 0                      # no new debt slips in
npx eslint . --fix-dry-run                         # preview autofixes in CI
  1. Land the rule as "warn", with tests in CI, and measure the count.3
  2. Fix or explicitly suppress the backlog; set reportUnusedDisableDirectives so suppressions do not rot.4
  3. Promote to "error" only when the count is zero.3
  4. Document the rule at meta.docs.url so the editor link explains the fix, not just the complaint.1
Key idea A rule nobody can act on is noise. Ship the rule, the test, the docs link, and the migration path together.1
