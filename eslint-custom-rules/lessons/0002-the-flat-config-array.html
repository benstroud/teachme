The Flat Config Array

One exported array, scoped objects, last write wins.

One file, an array of objects

A flat config file default-exports an array of config objects. ESLint reads the array top to bottom and applies every object whose files patterns match the file being linted.1

// eslint.config.js  (ESM)
import js from "@eslint/js";

export default [
  js.configs.recommended,                 // an object: shared baseline
  {
    files: ["src/**/*.js"],
    languageOptions: {
      ecmaVersion: 2024,
      sourceType: "module",
    },
    rules: {
      "no-console": "warn",
    },
  },
  {
    files: ["**/*.test.js"],
    rules: { "no-console": "off" },
  },
  {
    ignores: ["dist/**", "coverage/**"],  // global ignore: no other keys
  },
];

That is the whole mental model: an ordered list of scoped objects. There are no magic sections, no overrides nesting, no implicit inheritance chain.1

The keys that matter

KeyWhat it does
filesLimits the object to matching paths; omit it to apply everywhere.1
ignoresExcludes paths — but only globally when it is the object's only key.1
languageOptionsecmaVersion, sourceType, globals, and an optional parser.1
linterOptionsLinter behaviour such as noInlineConfig and unused-directive reporting.2
pluginsAn object map of name to plugin object — not an array of strings.1
rulesRule IDs to severities (and options).2
settingsShared data for rules that want cross-rule configuration.1

Order is semantics

Later objects win. In the example above, no-console is a warning for src/**/*.js and off for test files, purely because the test object comes after the source object. There is no "merge conflict" — it is a last-write-wins cascade over matching objects.1

{
  files: ["**/*.ts"],
  rules: { "no-console": "error" },
},
{
  files: ["**/*.test.ts"],
  rules: { "no-console": "off" },   // wins for test files
},

How ESLint finds the file

ESLint starts at the file being linted and searches upward for a config, which is what makes per-package configs work in a monorepo. If several exist, the order of precedence is eslint.config.js, .mjs, .cjs, .ts, .mts, .cts.1

npx eslint --config some-other-file.js "**/*.js"   # skip the search
npx eslint --no-config-lookup .                    # use no config at all
