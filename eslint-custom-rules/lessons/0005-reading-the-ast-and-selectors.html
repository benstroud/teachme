Reading the AST & Selectors

Stop matching text. Start querying shapes.

The shapes you will meet most

Node typeInteresting fields
Programbody — the top-level statements.1
VariableDeclarationkind ("const", "let", "var"), declarations.1
VariableDeclaratorid (the pattern), init (may be null).1
CallExpressioncallee, arguments, optional.1

Read the shape, not the text. console.log(x) is a CallExpression whose callee is a MemberExpression with object.name === "console" and property.name === "log".1

Selectors: write the shape as a query

// calls to require()
"CallExpression[callee.name='require']"

// console.log / console.warn, but not console["log"]
"MemberExpression[object.name='console'][computed=false]"

// functions taking more than three parameters
"FunctionDeclaration[params.length>3]"

// any call that appears directly inside an if body
"IfStatement > BlockStatement CallExpression"

// identifiers that look like event handlers
"Identifier[name=/^on[A-Z]/]"

// arrows or function expressions, either one
":matches(ArrowFunctionExpression, FunctionExpression)"

// on the way back up the tree
"CallExpression:exit"

That grammar comes from esquery: node types, attribute predicates, regex values, comparisons, child (>) and descendant (space) combinators, :not, :matches/:is, and the positional pseudo-classes.2

Two rules of the road

  • Specificity decides order. If several selectors match the same node, listeners run from least to most specific — more attributes and pseudo-classes means later. Ties break alphabetically.2
  • :exit is for unwinding. Enter the node to push state, exit it to pop. Anything that needs "after the children" — scope exits, trailing comments, block boundaries — belongs there.2

Key idea Discover node shapes empirically, not from memory: paste the code into ESLint Code Explorer, click the syntax you care about, and read the node type off the tree.4

Check yourself

1. CallExpression[callee.name='require'] matches…

2. A listener keyed "CallExpression:exit" runs…

3. sourceCode.getText(node) returns…

Ask the agent Take a rule you use and rewrite its visitor key as a selector. Confirm in Code Explorer that the selector highlights the same code the rule complains about.
