Testing with RuleTester

A rule you cannot test is a rule you cannot leave on.

The whole test file

// strict-equality.test.js  (CommonJS)
const { RuleTester } = require("eslint");
const rule = require("./rules/strict-equality");

const ruleTester = new RuleTester({
  languageOptions: { ecmaVersion: 2022, sourceType: "module" },
});

ruleTester.run("strict-equality", rule, {
  valid: [
    { code: "if (a === b) {}" },
    { code: "if (a !== b) {}" },
  ],
  invalid: [
    {
      code: "if (a == b) {}",
      output: "if (a === b) {}",           // asserts the autofix
      errors: [{ messageId: "strict", type: "BinaryExpression" }],
    },
  ],
});

console.log("All tests passed!");

RuleTester ships with ESLint — no test framework required, though it composes with one. run() throws if any case fails, and it insists on at least one valid and one invalid case.1

What a case can assert

FieldMeaning
codeThe source to lint (required).1
optionsThe rule's options array, exactly as in config.2
filenameVirtual path, for rules that branch on filename.2
errorsA count, or an array of expected problem shapes.2
outputThe exact code after autofixing; null means "no fix".1
suggestionsExpected suggestions, with their own output.2
errors: [
  { messageId: "banned", data: { name: "eval" }, type: "CallExpression", line: 1 },
]

Assert messageId rather than the rendered message: the id is the contract, the wording is presentation.1

Test the silence, not just the noise

False positives are what get a rule deleted from a codebase. For every invalid case, ask what near-miss should stay quiet and write it as a valid case.2

valid: [
  { code: "eval('safe');", options: [{ forbidden: [] }] },   // option disables it
  { code: "obj.eval('safe');" },                             // not a bare identifier
  { code: "const eval2 = () => {}; eval2();" },              // similar name
],
Key idea A rule is only as good as its valid cases. The invalid cases prove it fires; the valid cases prove it is safe to leave on.2
Ask the agent Write three valid cases for the rule you built in lesson 7 that must produce zero problems. Run node --test or plain node your.test.js until all pass.
