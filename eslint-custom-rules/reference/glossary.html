ReferenceESLint · Custom Rules

Glossary

The vocabulary used throughout this workspace. When a lesson and this page disagree, this page is the one to fix.

Foundations

TermMeaning
LintTo analyse source code for suspicious patterns without running it.1
Static analysisReasoning about a program from its text and structure, not its execution.1
ASTAbstract syntax tree: a tree of typed nodes representing the program's structure.2
ESTreeThe node-type specification ESLint follows (CallExpression, VariableDeclarator, …).2
espreeESLint's default parser: source text in, ESTree AST plus tokens and comments out.1
TokenA lexical unit (identifier, punctuator, literal) with a range; fixers work on nodes and tokens.3

Configuration

TermMeaning
Flat configThe current system: an exported array of config objects, default from v9.3
Config objectOne element of that array, optionally scoped by files.3
CascadeObjects are applied in order; later matching objects override earlier settings.3
Global ignoreAn object whose only key is ignores; it excludes files everywhere.3
languageOptionsParser-facing settings: ecmaVersion, sourceType, globals, parser.3
linterOptionsLinter behaviour: noInlineConfig, reportUnusedDisableDirectives.1
Severityoff/0, warn/1, error/2; controls reporting and exit code.1
OptionsThe array elements after the severity; delivered to the rule as context.options.3
Rule IDrule-name for core rules, namespace/rule-name for plugin rules.3
Directive commentAn inline eslint-disable/eslint-enable or rule-setting comment.1
SuppressionA directive that hides a known problem; track it or it rots.1

Authoring

TermMeaning
RuleAn object with meta and create that inspects nodes and reports problems.4
metaRule metadata: type, docs, schema, messages, fixable, hasSuggestions.4
VisitorA function in the object returned by create, keyed by node type or selector.4
SelectorAn esquery query used as a visitor key, e.g. "CallExpression[callee.name='eval']".5
contextThe rule's environment: options, filename, sourceCode, report.4
reportcontext.report({ node, messageId, data, fix, suggest }) — emits a problem.4
messageIdA key into meta.messages; preferred over inline message strings.4
Placeholder{{name}} inside a message, filled from the report's data.4
Fixablemeta.fixable: "code" | "whitespace"; mandatory before returning a fix.4
Fixing object{ range, text } produced by a fixer call.4
Multipass fixESLint applies non-overlapping fixes, then re-runs rules, up to ten passes.4
SuggestionA fix offered for a human to choose; requires meta.hasSuggestions.4
SchemaJSON Schema for rule options; positional array or a single object schema.4
defaultOptionsDefaults merged recursively underneath user-supplied options.4
PluginAn object with meta, rules and configs that ships rules together.6
NamespaceThe key a plugin is registered under in plugins; prefixes its rule IDs.6

Analysis & tooling

TermMeaning
ScopeA region owning declarations: global, module, function, block, class, catch, switch…4
VariableA binding in a scope, with defs and references.4
ReferenceA read or write of a variable; isRead() tells them apart.4
RuleTesterBuilt-in harness: run(name, rule, { valid, invalid }).7
Code ExplorerOfficial tool for inspecting the AST and tokens of a snippet.8
--print-configCLI flag that prints the fully resolved config for one file.9
FormatterPluggable output renderer; it never changes which problems exist.9
