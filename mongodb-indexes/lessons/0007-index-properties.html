Lesson 7 of 9MongoDB Indexes

Index Properties

Unique, TTL, partial, sparse, hidden — the options that turn a plain index into a constraint or a lifecycle tool.

The mental model in one sentence

Beyond ordering, indexes can carry properties: unique to enforce constraints, expireAfterSeconds (TTL) to auto-delete, and partial/sparse/hidden to scope or test coverage.

Unique: enforce no duplicates

db.users.createIndex({ email: 1 }, { unique: true })
  • Ensures no two documents share the indexed value(s).1
  • A compound unique index enforces uniqueness of the combination.
  • A missing field counts as a null key — so with a unique index, only one document may be missing that field.1

TTL: let time expire data

db.eventlog.createIndex({ createdAt: 1 }, { expireAfterSeconds: 3600 })
  • A single-field index on a date (or array of dates); MongoDB auto-deletes documents once they're older than expireAfterSeconds.2
  • Great for sessions, logs, and temp data. Deletion is a background task; on a replica set it runs only on the primary.2
  • TTL is single-field only — compounds ignore expireAfterSeconds, and _id can't be a TTL index.2

Partial & sparse: index a subset

db.orders.createIndex(
  { status: 1 },
  { partialFilterExpression: { status: { $exists: true } } })
  • Partial indexes only docs matching a filter — smaller, cheaper to write.3
  • Sparse indexes only docs that have the field (older, simpler analog).

Hidden: rehearse a drop

A hidden index is invisible to the query planner, so you can observe how your app behaves without it — before actually dropping it.3

Key idea Reach for unique to enforce integrity and TTL to bound data lifetime — both are free-ish index properties that replace app-side bookkeeping with a database guarantee.
