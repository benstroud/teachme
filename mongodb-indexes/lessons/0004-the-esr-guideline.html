The ESR Guideline

Equality, Sort, Range — the recipe that tells you which field order a compound index needs.

The mental model in one sentence

To build an efficient compound index, order the fields Equality fields first, then Sort, then Range — matching how the query uses each field.1

The three roles

  • Equality — the query matches a value exactly ({ region: "EU" }). Most selective to place first.
  • Sort — the field that orders results (.sort({ placed: 1 })).
  • Range — a comparison like { total: { $gt: 100 } }. Also $ne, $nin, $regex.1

Why this order

Once a range boundary is used, index traversal stops being a clean point-lookup and the ordering after it is broken for further fields. So you consolidate equalities first, then use the index's order to satisfy the sort (avoiding an in-memory SORT), and let the range filter run last over an already-narrowed set.1

Worked example

db.movies.find(
  { directors: "David Lynch", runtime: { $lt: 130 } }
).sort({ year: 1 })

Break it down:

  • Equality: directors
  • Sort: year
  • Range: runtime ($lt)

So the optimal compound index is:

db.movies.createIndex({ directors: 1, year: 1, runtime: 1 })  // E S R

Equality fields may appear in any order among themselves, but all must precede sort and range.1

The one judgment call: S before R

Put sort before range when avoiding an in-memory sort is critical (the common case). If the range is very selective, you can put it before sort (ERS) and accept an in-memory sort over the few survivors.1

Key idea For each query, sort its fields into Equality / Sort / Range buckets, then build the index in that order. If you only remember one rule from this course, remember ESR.
