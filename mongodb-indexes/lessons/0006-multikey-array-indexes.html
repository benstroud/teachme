Multikey (Array) Indexes

Index an array field and MongoDB automatically creates one index entry per element.

The mental model in one sentence

Indexing an array field makes it a multikey index: MongoDB stores one entry per distinct element, all pointing back to the same document.1

It's automatic

db.movies.createIndex({ genres: 1 })   // genres is an array → multikey

No flag needed — if the field holds an array, MongoDB builds the index as multikey automatically.1

One entry per element

A document with genres: ["Drama", "Action"] contributes an index entry for "Drama" and one for "Action" — distinct values only. So a query for { genres: "Drama" } finds it via the index.1

The soft rule of one

Compound indexes can contain at most one multikey field. This matters when you design an index over two arrays: MongoDB won't create a faithful compound multikey over both, because matching two arrays simultaneously can't be represented by simple multikey entries.12

Multikey and covered queries

A multikey index can only cover a query (answer it from the index alone) when the array field is not in the projection and there's no $elemMatch. So a query projecting the array itself will always need a FETCH.1

// covered if: array not projected, no $elemMatch
db.movies.find({ genres: "Drama" }, { _id: 0, title: 1 })
  .sort({ title: 1 }).limit(5)
Key idea Multikey is the mechanism behind tagging, categorizing, and "element in array" queries you'll design constantly. Remember it stores per-element, is limited to one array per compound index, and rarely covers a query that returns the array.
