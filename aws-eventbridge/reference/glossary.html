EventBridge Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

Events & the bus

Event
A JSON record that describes a state change or an action ("an order was placed", "a user was created"). It carries metadata (who, when, where) plus a detail payload. It is a notification of what happened, not a command to a specific service.1
Event bus
The managed pipe that events flow through. Producers PutEvents onto a bus; rules on the bus match events and route them to targets. Every account has a default bus plus any number of custom buses.2
Default event bus
The bus every AWS account gets automatically. Many AWS services emit their events here (e.g. S3, EC2, CodePipeline). Custom applications can also publish to it.
Custom event bus
A bus you create to keep one application's or team's events separate from AWS noise. Cleaner rules, permissions, and auditing.
Partner event bus
Receives events from integrated SaaS providers (Stripe, Datadog, …) via EventBridge Partner Sources, without you running ingestion code.
Cross-account / cross-region
An event bus can route events to targets in another AWS account (via resource policies) or by replicating events to a bus in another region.
Producer
Anything that publishes an event onto a bus — frequently a Lambda convenience endpoint or an AWS service.
Consumer / subscriber
Anything that receives matched events — a Lambda, an SQS queue, a Step Functions workflow, an API destination, another bus.

Producers & how events are shaped

PutEvents
The API a producer calls to send one or more events to a bus. Each entry needs at least a Source, DetailType, and Detail.3
Envelope
The standard outer structure every EventBridge event carries: version, id, detail-type, source, account, time, region, resources, detail.1
Source
Identifies who produced the event, as a dotted namespace, e.g. com.acme.orders. Pairs with detail-type to say WHAT the event is about.
Detail-Type
A free-form string naming the event kind, e.g. Order Placed. The source + detail-type pair is usually the key you route on.
Detail
The JSON payload — the business data. Nested fields here are what content filtering inspects (e.g. $.detail.price >= 100).

Routing

Rule
A named subscription on a bus: an event pattern plus the targets the matched events are sent to. All matching rules fire, so one event fans out to many consumers.4
Event pattern
The JSON filter of a rule. It matches on the fields you specify (usually source, detail-type, and nested detail paths); everything else matches as a wildcard.5
Content filtering
Comparison operators inside a pattern — prefix, suffix, anything-but, numeric ranges, exists, and wildcards — to match on more than exact equality.6
Target
The destination a matched event is delivered to: Lambda, SQS queue, SNS topic, Step Functions, API destination, another event bus, and more.4
Input transformer
Rewrites the event payload right before delivery, so a target sees a trimmed/combined JSON instead of the whole envelope.7
EventBridge Pipes
A separate, point-to-point pattern: source → optional enrichment → target. Where the bus is many-to-many, a Pipe is one source to one target and can preserve ordering from ordered sources.8

Reliability

At-least-once delivery
The guarantee EventBridge makes: an event is delivered to a target at least once, but may be delivered more than once. Consumers must be idempotent.9
Ordering
EventBridge does not guarantee events arrive in the order they were published. When order matters, route into an SQS FIFO queue keyed by a MessageGroupId.9
Retry policy
Per-target delivery retries with exponential backoff and jitter. Default: up to 24 hours and up to 185 attempts. You set the retry attempts and maximum event age.10
Dead-letter queue (DLQ)
A standard SQS queue that receives events EventBridge could not deliver after retries (or immediately, for non-retriable errors). Configured per target. Must be a standard queue — FIFO is not supported for EventBridge DLQs.11
Idempotency
Designing a consumer so processing the same event twice has the same effect as once. Required because at-least-once can deliver duplicates.

Contract & schema

Schema
A formal description of an event's shape — an OpenAPI 3 or JSON Schema Draft4 document. The contract that lets producers and consumers stay in sync.12
Schema Registry
EventBridge's central store of schemas. Built-in registries: aws.events (all AWS service event schemas) and discovered-schemas (from schema discovery), plus custom registries you create.
Schema discovery
A bus setting that infers schemas from the events flowing through, so you don't maintain them by hand. Schemas are versioned as events evolve.
Code bindings
Generated typed classes/interfaces for a schema (Java, TypeScript, etc.) you can download to speed up development against a known event shape.

Related services (for choosing)

Amazon SQS
A queue. Pull-based: a consumer polls messages, which persist (up to 14 days). Great for buffering and fine-grained flow control. FIFO queues add strict ordering.
Amazon SNS
A pub/sub topic. Push-based fan-out of one message to many subscribers. No content routing the way EventBridge rules do; filtering is simpler.
EventBridge vs these
EventBridge is an event bus with routing rules and content-based filtering and many target types. Choose it when you need to route one event to the right consumer(s) by structure. Combine it with SQS when you also need a durable buffer.13
