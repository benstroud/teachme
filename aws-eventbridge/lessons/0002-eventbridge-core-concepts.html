EventBridge: the core concepts

Events, buses, producers, consumers, rules, and targets — the vocabulary you build everything on.

The five pieces

Everything in EventBridge is one of these five things:1

PieceRole
EventA JSON record describing that something happened.
Event busThe pipe events flow through; rules live on it.
ProducerPublishes events onto a bus.
RuleA filter + target list on a bus.
TargetWhere a matched event is delivered.

The flow is always the same: producer → PutEvents → bus → rules match → targets.

Buses

Every account owns a default bus. AWS services (S3, EC2, CodePipeline…) emit their events into it by default, and custom apps may too. You can also create custom buses to isolate one application or domain. Custom buses keep your rules clean and your permissions auditable — if a team owns acme-order-bus, its rules don't compete with unrelated AWS noise.1

Two more kinds matter later: a partner bus receives events from integrated SaaS providers (Stripe, Datadog…) without you writing ingestion code, and a bus can route events cross-account to another account's targets using resource policies.2

Reading the event envelope

The skill for this lesson: look at any event and label its parts. Every EventBridge event carries this standard envelope:3

{
  "version": "0",
  "id": "9149a97f-7f6a-4a4f-9b9a-111111111111",
  "detail-type": "Order Shipped",
  "source": "com.acme.orders",
  "account": "123456789012",
  "time": "2026-09-06T10:30:00Z",
  "region": "us-east-1",
  "resources": [],
  "detail": {
    "orderId": "ord_1001",
    "carrier": "FedEx",
    "tracking": "7923987593"
  }
}

Train yourself to read it the way EventBridge does:
source = who produced it (com.acme.orders)  ·  detail-type = what it is (Order Shipped)  ·  detail = the business payload (the shippable facts). The id is a per-event unique key you can exploit for idempotency later.3

Pattern to remember The pair source + detail-type is almost always what a rule filters on. Think "who + what", then filter the payload for anything narrower.

Check yourself

1. An event arrives with source: "com.acme.orders" and detail-type: "Order Placed". What do the two fields tell you?

2. Where does the business payload live in an EventBridge event?

3. You want a clean home for just the orders domain's events. What should you create?

4. Which label matches the piece that filters events and sends them to targets?
