Lesson 3 of 8AWS EventBridge

Turning a Lambda into a producer

How one service publishes events so many others can react.

The producer's only job

Recall the flow: producer → PutEvents → bus → rules → targets. On the producer side there is exactly one API call that matters: PutEvents.1 It sends one or more event entries to a bus. The producer does not decide who receives the event — it just announces that something happened.

Here is a minimal TypeScript producer using the AWS SDK v3:

import {
  EventBridgeClient, PutEventsCommand
} from "@aws-sdk/client-eventbridge";

const client = new EventBridgeClient({
  region: process.env.AWS_REGION
});

export async function putOrderPlaced(orderId: string, customerId: string, total: number) {
  await client.send(new PutEventsCommand({
    Entries: [{
      Source: "com.acme.orders",
      DetailType: "Order Placed",
      Detail: JSON.stringify({ orderId, customerId, total }),
      EventBusName: process.env.EVENT_BUS_NAME
    }]
  }));
}

The rules of a correct entry

  • Source, DetailType, and Detail are all required. Drop one and that entry fails.2
  • Detail must be a string containing the JSON — not a JavaScript object. That's why the code calls JSON.stringify.2
  • DetailType is a free-form string, capped at 128 characters.2
  • EventBusName is optional; omit it and the event goes to the default bus.
  • One PutEvents call can carry up to 10 entries. The total entry size of a request must stay under 256 KB.1
  • Batch related events into one call for efficiency, but don't exceed the 10-entry / 256 KB caps.
Common bug Newcomers pass Detail: { orderId, ... } as an object and wonder why the event won't publish. The SDK is typed — Detail is a string field. Always stringify.

Missing: idempotency (why it matters already)

You will see this properly in Lesson 6, but hold the thought now: event-driven delivery is at-least-once, so the same event can reach a consumer more than once. That pushes a discipline onto both sides — and it starts here, by giving every event a stable identity you can dedupe on later (a business key like orderId, plus the envelope's id).3 You make this decision at design time, not after an outage.

Check yourself

1. Which three fields are required on every PutEvents entry?

2. In TypeScript, what must Detail be set to on a PutEvents entry?

3. You have 14 unrelated events to publish at once. What is the best approach?

4. Your event carries a shipping update with progress text well under 128 characters. What is a sound source/detail-type pairing?

Hands-on step (attempt one at a time)

Do this with a real AWS account if you have one; otherwise trace it by hand. Try step 1 now, then come back for the next.

  1. Create a custom bus named com.acme.order-bus (console: Amazon EventBridge → Event buses → Create).
  2. Give a Lambda permission to events:PutEvents on that bus (attach a policy, or add an EventBridge resource-based policy).
  3. Publish your first event with the AWS CLI: aws events put-events --entries '[{ "Source":"com.acme.orders","DetailType":"Order Placed","Detail":"{\"orderId\":\"1\"}","EventBusName":"com.acme.order-bus"}]'
Ask the agent Paste the entry you published (or your traced payload) and ask: is the source/detail-type pair clean? Should the event carry more identity for idempotency?
