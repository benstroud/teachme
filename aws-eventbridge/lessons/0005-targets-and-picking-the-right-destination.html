Targets: choosing the right destination

The second half of a rule — deciding what a matched event is handed to.

What a target can be

Once a rule matches an event, EventBridge pushes it to each of the rule's targets. The common ones for application coordination:1

TargetModelTypical job
LambdaPushReact and compute right now on the event.
SQS queuePush → pullBuffer events; consumers work at their own pace.
SNS topicPushFan out to even more subscribers.
Step FunctionsPushStart a long-running workflow from the event.
API destinationPushCall an external HTTP endpoint.
Event bus (cross-account)PushHand the event off to another account's bus.

EventBridge pushes: when an event matches, EventBridge delivers it to the target. It does not wait for the target to come ask.1

Lambda directly vs. an SQS buffer

This is the most consequential target decision for Lambda coordination. Ask two questions:

  • Do consumers need a durable buffer? A direct Lambda target gets the event pushed and that's it — EventBridge does not retain it. An SQS target stores the event (up to 14 days), so a slow or down worker can catch up later.2
  • Does order or flow control matter? EventBridge alone gives no ordering and no backpressure. Routing into an SQS queue gives you visibility-timeout flow control, and a FIFO queue gives ordered processing — the topic of Lesson 6.
Heuristic Direct Lambda = "react now, fire and forget." SQS buffer = "guarantee it eventually gets processed, even at the cost of latency." Use a buffer when the work is heavy, bursty, or must be strictly ordered.

Input transformation: reshape what the target sees

The whole envelope is delivered by default, but a target often wants less. An input transformer lets a rule rewrite the payload before delivery using JSONPath references like $.detail.orderId:3

{
  "InputPathsMap": {
    "oid": "$.detail.orderId",
    "cust": "$.detail.customerId",
    "total": "$.detail.total"
  },
  "InputTemplate": "{\"orderId\": \"<oid>\", \"total\": \"<total>\"}"
}

Now the Lambda receives a slim JSON with just what it uses — less parsing, less coupling to the full event shape, and a smaller invocation payload.
