VS Code Extension Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. Architecture

manifest (package.json) + entry file (activate/deactivate)
run inside the extension host process (isolated from the UI)
  • Extensions cannot impact startup, slow UI, or modify the UI directly.13
  • The vscode module is the API you code against.1

2. Manifest fields

{
  "name": "my-ext", "publisher": "acme",
  "engines": { "vscode": "^1.80.0" },
  "main": "./out/extension.js",
  "activationEvents": [],
  "contributes": { ... }
}
  • ID is .; main is the entry point.1
  • engines.vscode gates which APIs you may use.2

3. Activation

"activationEvents": ["onLanguage:rust", "workspaceContains:**/*.toml"]
onCommand, onLanguage, workspaceContains, onStartupFinished, * (sparingly)
  • Declares WHEN the extension loads; lazy loading protects startup.3
  • Since 1.74, contributed commands auto-activate.1

4. Contribution points (contributes)

commands, menus, keybindings, configuration, views, ...
menu item: { "command": "acme.f", "group": "1_modification@1" }
  • JSON declarations that add to VS Code.4
  • Groups are ordered; @N orders within a group.4

5. Using the API

vscode.commands.registerCommand("acme.run", run);
await vscode.commands.executeCommand("editor.action.format");
vscode.window.showInformationMessage("hi");
context.subscriptions.push(disposable);
  • commands / window / workspace are the main namespaces.5
  • Every registration is a disposable; push to subscriptions.1

6. Views & UI surfaces

"views": { "explorer": [ { "id": "acme.items", "name": "Items" } ] }
vscode.window.registerTreeDataProvider("acme.items", provider);
  • Declare the view, implement a TreeDataProvider for its data.6
  • Status bar items and quick picks are created at runtime.1

7. Webview

panel.webview.html = "
Hi
";
panel.webview.onDidReceiveMessage(m => ...);
panel.webview.postMessage({ type: "refresh" });
  • Sandboxed HTML/CSS/JS; messages are the only bridge.7
  • Use the webview URI helper plus a Content Security Policy.7

8. Language features

declarative: language config, TextMate grammar, snippets
programmatic: providers   rich: a language server (LSP)
  • Start with the cheapest level; graduate to LSP for breadth.8

9. Testing & bundling

tests:  run inside a real extension host
bundle: esbuild/webpack -> one file (needed for VS Code for the Web)
.vscodeignore: exclude node_modules, out, src
  • Integration tests boot VS Code and activate the extension.9
  • Bundling speeds install/activation and enables web support.10

10. Publish & deploy

vsce package            # -> my-ext-0.0.1.vsix
vsce publish            # -> Marketplace
vsce publish --packagePath file.vsix
vsce package --target win32-x64
  • PAT must be Marketplace (Manage) + All accessible organizations.11
  • Max 30 keywords/tags; unpublish/deprecate as needed.11
  • Automate build/test/publish in CI on a tag.12
