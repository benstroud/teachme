Activation

When your extension loads: activation events and lazy activation.

The mental model in one sentence

Activation events declare when your extension loads — and loading lazily (only when relevant) is what keeps VS Code starting fast.1

The ones you will use most

EventFires when…
onCommand:…The command is invoked.1
onLanguage:rustA file of that language is opened.1
workspaceContains:**/*.tomlThe workspace matches a glob.1
onStartupFinishedStartup settles (low priority work).1
*Any VS Code startup — use sparingly.1

Lifecycle

{
  "activationEvents": ["onLanguage:rust", "workspaceContains:**/*.toml"]
}

activate() is invoked once when any listed event fires. deactivate() handles cleanup and must return a Promise if the cleanup is asynchronous.1

Key idea Prefer specific events over *. The host loads extensions lazily so they do not consume CPU and memory until they are actually needed.2
