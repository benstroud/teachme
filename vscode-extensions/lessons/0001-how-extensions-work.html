How Extensions Work

Manifest, entry file, and the isolated extension host that runs your code.

The mental model in one sentence

A VS Code extension is a package described by a manifest and loaded into the extension host — a separate process that keeps misbehaving extensions from slowing or changing your editor.1

The three moving parts

PartWhat it is
Manifestpackage.json: ID, entry point, engine, what it adds.2
Entry fileExports activate() and deactivate().2
Extension hostA separate process that runs your code.1

The API is just a module

import * as vscode from "vscode";

export function activate(context: vscode.ExtensionContext) {
  let d = vscode.commands.registerCommand("x.hello", () => {
    vscode.window.showInformationMessage("Hello!");
  });
  context.subscriptions.push(d);
}

export function deactivate() {}

Everything you do — commands, messages, edits — goes through the vscode module, and every registration returns a disposable you push into context.subscriptions.2

Key idea The extension host is why extensions are trustworthy-ish: VS Code prevents them from impacting startup, slowing UI operations, or modifying the UI directly. You ask the API; the host does the work.1
