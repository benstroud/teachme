Using the API

Commands, window, workspace — and why every registration is a disposable.

The mental model in one sentence

You interact with the editor entirely through the vscode module, organized into namespaces: commands, window, and workspace — and every registration returns a disposable you keep.1

The core calls

// run / register commands (Command Palette + programmatic)
vscode.commands.registerCommand("acme.run", run);
await vscode.commands.executeCommand("editor.action.format");

// talk to the user
vscode.window.showInformationMessage("Done");
const pick = await vscode.window.showQuickPick(["a", "b"]);

// touch documents
const doc = await vscode.workspace.openTextDocument(uri);
await vscode.window.showTextDocument(doc);

Disposables keep you clean

Each registerCommand, provider, listener, and status bar item is a disposable. Push them into context.subscriptions so VS Code disposes them on deactivate — this prevents leaks across reloads.1

Key idea Commands are the universal lever: they show up in the Command Palette, can be bound to keys, added to menus, and called from your own code with executeCommand.2
