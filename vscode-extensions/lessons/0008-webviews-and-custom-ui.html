Webviews & Custom UI

Sandboxed HTML panels and the message bridge to your extension.

The mental model in one sentence

A webview is a sandboxed HTML/CSS/JS panel rendered by your extension; you build the HTML, attach it to a panel, and pass messages between the extension and the page.1

Create a panel and talk to it

const panel = vscode.window.createWebviewPanel(
  "acme.preview", "Preview", vscode.ViewColumn.One,
  { enableScripts: true }
);
panel.webview.html = "<h1>Hello</h1>";

// webview -> extension
panel.webview.onDidReceiveMessage((msg) => {
  vscode.window.showInformationMessage("got " + msg.type);
});

// extension -> webview
panel.webview.postMessage({ type: "refresh" });

Rules of the road

  • Set a Content Security Policy and load assets via the webview URI helper.1
  • Messages are the only supported bridge — no direct DOM access from the extension.1
  • Registrations and the panel are disposables; keep them in context.subscriptions.1
Key idea Reach for a webview only when native UI (tree views, quick picks, editors) cannot express what you need — it is the most powerful and the most expensive surface.1
