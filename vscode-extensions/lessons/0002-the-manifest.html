Lesson 2 of 10VS Code Extensions

The Manifest

package.json: the ID, the entry point, the engine gate, and the contributions.

The mental model in one sentence

The manifest is package.json — it names the extension, points at the entry file, sets the required VS Code version, and declares every contribution the extension makes.1

The fields that matter first

{
  "name": "my-extension",
  "publisher": "acme",
  "engines": { "vscode": "^1.80.0" },
  "categories": ["Other"],
  "activationEvents": [],
  "main": "./out/extension.js",
  "contributes": {
    "commands": [
      { "command": "acme.hello", "title": "Hello" }
    ]
  }
}
FieldMeaning
publisher + nameCombined as the unique ID acme.my-extension.1
mainThe entry file exporting activate/deactivate.1
engines.vscodeThe minimum VS Code API version.1
Key idea Since VS Code 1.74, a command declared in contributes.commands activates the extension automatically — you no longer need a matching onCommand activation event for it.1
