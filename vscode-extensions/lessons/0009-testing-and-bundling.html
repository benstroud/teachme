Testing & Bundling

Test inside a real extension host and bundle for speed and the web.

The mental model in one sentence

Ship-quality extensions have two habits: tests that run inside a real extension host, and a bundle so the package is one fast-loading file.1

Testing in the extension host

// tests run against a launched VS Code instance
const ext = vscode.extensions.getExtension("acme.my-extension");
await ext.activate();
// assert on commands, UI, and behavior

Integration tests boot VS Code, activate your extension, and exercise it end to end — far more trustworthy than mocking the API.1

Bundling for speed and the web

Why bundleEffect
One entry fileRequired for VS Code for the Web (browser).2
Fewer files to loadFaster install and activation.2
Smaller packageExclude node_modules, out, src with .vscodeignore.2
Key idea Bundle with esbuild or webpack, point main at the bundle, and prune with .vscodeignore. Tests are not bundled — compile them separately.2
