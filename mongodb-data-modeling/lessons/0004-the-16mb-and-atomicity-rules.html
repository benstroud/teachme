The 16 MiB & Atomicity Rules

Two constraints shape every model: how big a document may be, and what a single write may promise.

The mental model in one sentence

A document may not exceed 16 MiB, and every write to a single document is atomic — model so the hot path fits one bounded document and mutates it in one operation.12

The 16 MiB wall

Documents in MongoDB must be smaller than 16 MiB.1 The classic violation is an unbounded embedded array: the more you push into it, the bigger the document — until one day it errors. Symptoms:

  • A comments/events array that grows with every write.
  • Accumulating logs or version history embedded forever.
  • Writes that rewrite an ever-larger document each time (the massive unbounded document anti-pattern).

Fix: cap the array (keep the most recent N, archive the rest), or move the unbounded child to its own collection with a reference.1

Atomicity: write to one document

MongoDB writes are atomic at the single-document level — even when you modify multiple fields at once, they all commit together or not at all.2 But updateMany touching many documents is not atomic as a whole: each document is, the operation isn't. Cross-document guarantees need transactions (and the manual's advice is to prefer good modeling over transactions).2

// atomic: one document, several fields, all or nothing
db.orders.updateOne(
  { _id: 10 },
  { $set: { status: "fulfilled", fulfilledAt: new Date() } }
)

Avoiding lost updates

Two concurrent updates to the same document can silently overwrite each other. Protect the value:2

// filter on the expected current value — second update won't match
db.movies.updateOne({ _id: 1, score: 80 }, { $set: { score: 90 } })

// or use $inc so updates compose instead of overwrite
db.movies.updateOne({ _id: 1 }, { $inc: { score: 20 } })

Why these two rules change your model

Embedding is great — until it violates one of these. The bounded, atomic test is your guardrail: if an embedded array can grow without bound, or if a flow needs to change several documents at once, the model is telling you to reference instead.12

Key idea Think of each document as one unit of integrity: small enough to be bounded, and fully updatable in a single atomic write. If either condition breaks, split and reference.
