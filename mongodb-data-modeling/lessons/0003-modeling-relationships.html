Modeling Relationships

One-to-one, one-to-many, many-to-many — the three relationship shapes and the document shapes that serve them.

The mental model in one sentence

Every relationship is one-to-one, one-to-many, or many-to-many, and each can be modeled embedded or referenced — your workload picks the shape.1

One-to-one: embed the "one"

When each document relates to exactly one other and they're read together, embed it.

{ _id: "alice", email: "a@x.dev",
  healthRecord: { height: 170, allergies: ["peanuts"] } }

One-to-many: the interesting one

Two idioms, chosen by how the child is used:2

// (a) EMBED the many — bounded, always shown with the parent
{ _id: "joeb", name: "Joe", addresses: [
    { street: "...", city: "Faketon" },
    { street: "...", city: "Boston" } ] }

// (b) REFERENCE the many — array of ids, or a foreign key on the child
// user: { _id: "joeb", name: "Joe" }
// posts live in their own collection, each carrying the author id
post:    { _id: 9001, author: "joeb", text: "..." }
  • Embed when you always read the children with the parent and they're bounded (addresses, line items on an order).2
  • Reference (often a "reverse" array of ids on the parent, or a foreign key on each child) when the children are many, large, or queried on their own — e.g. a user's posts.3

Many-to-many: reference on both sides

A student has many courses and a course has many students. Model it with references — often arrays of ids on each side (or a join collection):5

student: { _id: 7, name: "Ada", courseIds: [ 101, 102 ] }
course:  { _id: 101, title: "Algorithms", studentIds: [ 7, 8 ] }

This avoids duplicating a course inside every student (and a student inside every course). Resolve with application-side lookups or aggregation.

Turning the crank: which shape wins?

RelationshipDefault shapeWhy
One-to-one, co-readEmbedOne read, atomic.
One-to-many, bounded, co-readEmbed the arrayOne read for the page.
One-to-many, many/large/independentReferenceBounded size, independent queries.
Many-to-manyReference (both sides)No unbounded duplication.
Key idea There is no one "right" shape in the abstract — only the shape that matches the read/write workload of that relationship. Embed by default; move to references the moment cardinality or independence makes embedding costly.
