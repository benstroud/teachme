Schema Validation

MongoDB is schema-flexible by default — lock it down with $jsonSchema where your app needs guarantees.

The mental model in one sentence

MongoDB's default is no enforced schema, but you can attach a validator to a collection so every insert and update must match; by default invalid documents are rejected.1

Attaching a JSON Schema validator

db.createCollection("students", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      title: "Student Object Validation",
      required: [ "name", "year", "major" ],
      properties: {
        name: { bsonType: "string" },
        year: { bsonType: "int", minimum: 2017, maximum: 3017 },
        gpa:  { bsonType: "double" }
      }
    }
  }
})
  • bsonType enforces the type; required lists mandatory fields; properties describes each.2
  • minimum/maximum bound numbers; enum restricts allowed values.

When validation runs

  • Every insert must match, or it is rejected.
  • Updates are also checked — an update that would produce an invalid document is rejected.1
  • Existing documents are only subject to the rules you choose (via the validation level), and you can configure MongoDB to warn instead of reject.1

Beyond types: cross-field rules

Combine $jsonSchema with query-operator rules to assert relationships between fields:

db.createCollection("sales", {
  validator: {
    $and: [
      { $expr: { $lt: [ "$discountedPrice", "$price" ] } },
      { $jsonSchema: { properties: { items: { bsonType: "array" } } } }
    ]
  }
})

This guarantees the discounted price is always below the list price, and items is an array — enforced by the database.2

Why it matters for a senior dev

  • Flexible ≠ shapeless: after your model matures, validation prevents unintended schema drift and type bugs at the data layer instead of in code.1
  • You can start flexible and add validation only where strict control is needed — the flexible model supports iterative schemas.3
Key idea Add validation after the model is stable, targeting the fields that matter — type correctness on critical fields, and cross-field invariants — rather than trying to describe every field.
