Data Modeling Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

The document model

Flexible data model
Documents in a collection are not required to share fields, and a field's type may differ between documents. The schema can evolve with the app.1
Polymorphic data
Storing documents with different fields or types in one collection — a pattern MongoDB endorses for product catalogs, events, and similar.
Denormalized (embedded) model
Related data stored together in one document (often with duplication across collections) so it can be read back in a single operation.2
Normalized (reference) model
Related data split across collections and linked by references, avoiding duplication.3
"Data accessed together is stored together"
The core MongoDB modeling principle: choose the model by how the application reads and writes, not by abstract normal forms.1
BSON
The binary JSON format MongoDB stores documents in; docs must be under 16 MiB.
_id
The required unique identifier of a document; always indexed. It may be a meaningful value you supply rather than an ObjectId.4

Relationships & linking

One-to-one
Each document relates to exactly one other (a patient ↔ their medical record). Usually embedded.5
One-to-many
One document relates to many others (a user → many posts). Embed when the many is shown inside the parent; reference when it is large or independent.5
Many-to-many
Each side relates to many of the other (students ↔ courses). Usually modeled with references or reverse references.5
Embedding
Storing a related sub-document or array inside the parent document, for "contains"/has-a and co-read data.2
Referencing
Storing a link (often the other document's _id) and resolving it with an application join or $lookup.3
Reverse reference / array of ids
The "many" side storing the parent's _id(s), e.g. a student document listing its courseIds.
High cardinality
A child side that has very many or unbounded members — a signal to reference rather than embed.6

Constraints, validation & evolution

16 MiB BSON document limit
The maximum size of any single document. Unbounded embedded arrays will eventually exceed it.2
Atomic single-document write
Writes to one document are atomic even when they change multiple fields; updateMany is not atomic as a whole.7
$jsonSchema
The validator expression for schema validation: bsonType, required, properties, minimum/maximum, enum.8
Schema validation
Rules that runs on insert and update; by default MongoDB rejects invalid documents (or can be set to warn).8
Schema versioning
A schema_version-style field that lets old and new document shapes coexist while an app rolls forward.9
Materialized path / tree patterns
Five ways to model a tree: parent references, child references, ancestors array, materialized paths (path string), nested sets.10
