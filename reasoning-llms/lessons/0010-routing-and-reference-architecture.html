Routing & Reference Architecture

Per-request allocation of the compute budget, from easy to hard, in a real product.

The mental model in one sentence

A production app doesn't pick one model — it routes: cheap, fast standard calls for the easy majority, and reasoning calls (with careful effort) for the hard minority, wrapped in streaming, caching, and cost/latency budgets.1

A reference routing design

request
  -> classify difficulty / intent
  -> easy?   standard model  (low latency, low cost)
  -> hard?   reasoning model  (effort by task)
  -> stream thinking, cache results, cap budget
log: quality, latency, and token cost per route
  • Use a standard model for recall, extraction, and simple transforms.
  • Use a reasoning model for math, code, deep analysis — at the right effort.
  • Stream output so latency feels shorter; cache repeat queries.
Key idea The lever you own is per-request allocation of the compute budget. The reasoning-vs-standard distinction becomes a routing rule, not a religion.1
