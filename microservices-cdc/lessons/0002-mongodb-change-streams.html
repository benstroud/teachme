MongoDB Change Streams

Change streams are the CDC source of truth: watch a collection and get a live feed of inserts, updates, replaces, and deletes.

The mental model in one sentence

MongoDB Change Streams let an application watch a collection, database, or deployment and receive change events for inserts, updates, replaces, and deletes — backed by the oplog and resumable via tokens.1

What you watch and what you get

// watch a collection (driver / mongosh)
const changeCursor = db.orders.watch([
  { $match: { operationType: { $in: ['insert', 'update', 'replace', 'delete'] } } },
]);

// each change event carries:
//   operationType         'insert' | 'update' | 'replace' | 'delete' …
//   documentKey           { _id: … }   the stable identifier
//   fullDocument          the post-change document (with updateLookup)
//   resumeToken | clusterTime
  • Watch scope can be a collection, a database, or the whole deployment.1
  • $match filters the event types you care about (here only CRUD operations).
  • fullDocument: 'updateLookup' returns the document after an update; the document key is your stable event id.1
Key idea Because a change stream reflects actual writes to the database, it captures changes from any writer — not just your service — which is exactly why it is a good CDC source.1

Resume tokens keep you going

If your listener disconnects, a resume token lets you continue from where you stopped rather than re-reading everything — vital for a reliable relay.1
