The Relay Lambda

When the managed Atlas trigger isn't enough, a custom Lambda tails the change stream and publishes events to EventBridge.

The mental model in one sentence

A relay Lambda subscribes to a MongoDB change stream and, for each change, publishes a shaped event to an EventBridge bus — giving you full control over transformation and resilience.1

When to choose it

Choose the native Atlas→EventBridge trigger (lesson 4) first. Reach for a relay Lambda when you need to transform change records into your own event schema, attach fields, or handle delivery more precisely than the managed path allows.

// pseudo — tail the change stream and publish
const stream = db.orders.watch([$match ops], { fullDocument: 'updateLookup' });
for await (const change of stream) {
  await eventbridge.putEvents({
    Entries: [{
      Source: 'orders',
      DetailType: toDetailType(change.operationType), // OrderPlaced / OrderUpdated …
      Detail: JSON.stringify({ v: 1, orderId: change.documentKey._id, change }),
    }],
  });
}
Key idea Because the change stream supports resume tokens, persist where you are so the relay can recover after a restart instead of re-reading everything.1 Prefer the managed trigger unless you specifically need this control.
