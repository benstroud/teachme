The Consumer Lambda

Downstream services receive events as TypeScript Lambdas — idempotent, retry-tolerant, and able to fail into a dead-letter queue.

The mental model in one sentence

A consumer Lambda receives an event from the bus, applies the downstream work, and — because delivery is at-least-once — makes that work idempotent so a redelivered event is harmless.1

export async function handler(event: OrderUpdatedEvent): Promise<void> {
  await dedupe(event.detail.id, () => apply(event));   // idempotent apply
}

At-least-once semantics

EventBridge can deliver an event more than once (e.g. after a retry). So the consumer must tolerate repeats: dedupe on the event's idempotency key, and make the apply step idempotent (e.g. "set status to paid" is safe to repeat).1

Retries and dead letters

  • Retries — if the handler throws, Lambda/EventBridge retries; give the function the timeout and retries it needs.
  • DLQ — after repeated failures, route the event to a dead-letter target so you can inspect and later replay.1
Key idea Design the consumer around at-least-once: assume the same event can arrive twice, and make "apply" repeatable — that single habit removes most CDC class bugs.
