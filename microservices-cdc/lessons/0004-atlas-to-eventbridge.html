Atlas to EventBridge (native)

The managed path: an Atlas database trigger publishes change events straight onto your EventBridge event bus.

The mental model in one sentence

MongoDB Atlas can send database trigger events to AWS EventBridge — you associate the MongoDB partner event source with a bus, configure a trigger with an EventBridge event processor, and change events arrive as events.1

Configuration

In an Atlas trigger, the EventBridge event processor carries the target account_id and region, so the trigger knows which bus to publish to:1

"event_processors": {
  "AWS_EVENTBRIDGE": {
    "config": { "account_id": "012345678901", "region": "us-east-1" }
  }
}

Constraints to design around

  • Associate the MongoDB partner event source with your event bus first.1
  • A single EventBridge trigger event must be under ~1 MB — keep it small.1
  • A project expression can limit which document fields are sent, shrinking payloads.1
  • Configure an error handler so delivery failures go somewhere you can act.
Key idea This is the lowest-friction CDC producer: no custom Lambda to tail a change stream — Atlas does it for you. Reach for it first; drop to a relay Lambda (lesson 6) only when you need control the managed path can't give.
