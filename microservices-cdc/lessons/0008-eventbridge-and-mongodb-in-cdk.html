EventBridge & MongoDB in CDK

Declare the bus, rules, and Lambda consumers as infrastructure — CDK wires them together and grants the permissions for you.

The mental model in one sentence

Use the AWS CDK to define the EventBus, a Rule with an event pattern, and a NodejsFunction consumer as a target — CDK creates the rule-to-Lambda trigger and IAM.

import { EventBus, Rule } from 'aws-cdk-lib/aws-events';
import { LambdaFunction } from 'aws-cdk-lib/aws-events-targets';
import { NodejsFunction } from 'aws-cdk-lib/aws-lambda-nodejs';

const bus = new EventBus(this, 'OrdersBus', { eventBusName: 'orders' });
const inventory = new NodejsFunction(this, 'InventoryConsumer', { entry: 'inventory.ts' });

new Rule(this, 'ForOrderPlaced', {
  eventBus: bus,
  eventPattern: { source: ['orders'], 'detail-type': ['OrderPlaced'] },
  targets: [new LambdaFunction(inventory)],
});
  • EventBus is the router; Rule + eventPattern filter; the Lambda target receives matches.1
  • NodejsFunction bundles your TypeScript Lambda.2
  • CDK grants the rule permission to invoke the Lambda — matching infra grows with the code.
Key idea The insight: after you craft the CDC source (Atlas trigger or relay), the bus/rules/consumers are just declarative infra in the CDK app — one bus, several rules, one consumer per concern.
