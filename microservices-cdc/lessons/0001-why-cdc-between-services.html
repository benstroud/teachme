Why CDC Between Services

Each service owns its database, so when one service's data changes, the others can't read it — they must be told. That's change data capture.

The mental model in one sentence

Because every service owns its data, another service cannot query it directly — so a data change in MongoDB must become an event that downstream services consume (change data capture / CDC).1

The problem: private data

You do not share a database, and you do not call another service's code to notice its writes. When an order is placed in the orders service, inventory wants to know — so the orders data must be propagated as an event instead of being read directly.

How you could propagate a change

ApproachIdea
Share a databaseFast to build; reintroduces coupling between services.
Transactional outboxWriter emits a prepared event in the same transaction as the change.3
Change data capture (CDC)Observe the database log/change stream and emit events for changes made by any writer.
Key idea CDC shines when you cannot change every write path: MongoDB Change Streams watch the actual changes, so even changes made by other systems still produce events.2
