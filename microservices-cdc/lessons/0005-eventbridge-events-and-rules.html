EventBridge Events & Rules

The bus receives events; rules with event patterns decide which of them reach which target — usually a Lambda.

The mental model in one sentence

An event bus is a router that receives events and, via rules with event patterns, delivers each matching event to zero or more targets (often Lambda functions).1

The pieces

  • Event bus — the central router for your CDC integration.
  • Rule — attached to the bus with an event pattern (e.g. match on source and detail-type).
  • Target — where matching events go, e.g. an inventory-consumer Lambda.
// a rule matches an event pattern
{
  "source": ["orders"],
  "detail-type": ["OrderPlaced", "OrderUpdated"]
}

One bus can host many rules, so a single change can fan out to several consumers while each rule filters only what it cares about.1

Key idea Put the fan-out in EventBridge, not in the producer or in a Lambda: the publisher emits once, and rules route to whichever services need the event — that is what keeps services decoupled.
