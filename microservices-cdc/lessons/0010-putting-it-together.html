Putting It All Together

Assemble the full pipeline — MongoDB changes → EventBridge → TypeScript consumers in CDK — and defend the design choices.

The reference architecture

MongoDB orders  →  CDC source  →  EventBridge bus  →  consumer Lambdas
   (source)       (Atlas trigger       (rules):          (inventory, audit,
                   OR relay Lambda)     fan-out)          billing ) in CDK
  1. Capture — MongoDB Change Streams are the source of truth; an Atlas trigger (preferred) or relay Lambda publishes events.1
  2. Shape — events carry source, detail-type, a versioned detail, and an idempotency key.
  3. Route — one bus, several rules; each consumer gets only the events it cares about.2
  4. Consume — idempotent TypeScript Lambdas with retries/DLQ and replay.3
  5. Declare — the whole thing (bus, rules, NodejsFunction consumers) lives in the CDK app.4

Choosing the source, honestly

NeedPick
Low friction, managed setupAtlas trigger → EventBridge
Full control of shaping/retriesrelay Lambda on a change stream
You control the write path & need atomicitytransactional outbox (not CDC)5
Key idea The pipeline is durable because it layers guarantees: CDC captures all writes, rules fan out cleanly, and at-least-once + idempotency + DLQ + replay absorbs the failures that will happen.
