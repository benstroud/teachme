Microservices CDC Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The pattern

MongoDB (orders)
   │ change stream (CDC)
   ▼
Atlas trigger OR relay Lambda  ──publish──▶  EventBridge (bus)
                                               │ rule (event pattern)
                                               ▼
                                   consumer Lambdas (idempotent)
  • Each service owns its data; CDC turns a data change into an event other services react to.1
  • MongoDB Change Streams watch insert/update/replace/delete and expose resume tokens.1

2. Change streams (MongoDB)

// watch a collection (driver / mongosh)
const cursor = orders.watch([
  { $match: { operationType: { $in: ['insert','update','replace','delete'] } } },
]);
// each change: operationType, documentKey, fullDocument, resumeToken/clusterTime
  • operation types: insert / update / replace / delete.1
  • fullDocument: 'updateLookup' returns the post-update document; resume tokens let you resume.1
  • Use documentKey as a stable id for the mutation event.

3. Atlas → EventBridge (native)

// Atlas database trigger config (fragment)
"event_processors": {
  "AWS_EVENTBRIDGE": { "config": { "account_id": "012345678901", "region": "us-east-1" } }
}
  • Associate the MongoDB partner event source with a bus, then the trigger publishes.2
  • Single events must be under ~1 MB; use a project expression to shrink them.2
  • Wire an error handler for failures.

4. EventBridge

// an event
{ "source": "orders", "detail-type": "OrderUpdated",
  "detail": { "orderId": "o1", "status": "paid", "v": 1 } }
// a rule matches on source / detail-type / detail… and targets a Lambda
  • Event buses receive and route events to targets; rules with event patterns filter.3
  • Targets are often Lambda; delivery is effectively at-least-once.

5. Design events (TypeScript)

type OrderUpdated = {
  source: "orders"; "detail-type": "OrderUpdated";
  detail: { v: 1; orderId: string; op: "update"; status: string; at: string };
};
  • Put a v schema version and an id (idempotency key) in every event.3
  • Keep detail-type verb-like and business-meaningful (OrderPlaced, OrderUpdated).

6. Consumers & reliability

// consumer: idempotent + retries/DLQ
if (await seen(event.detail.orderId, eventId)) return;
await apply(event);        // throws → Lambda retries → DLQ
  • Assume at-least-once: dedupe on an event id.4
  • Use Lambda retries and a DLQ for persistent failures.

7. CDK wiring

const bus = new events.EventBus(this, 'Bus', { eventBusName: 'edc' });
const rule = bus.addRule('ForOrderUpdated', {
  eventPattern: { source: ['orders'], 'detail-type': ['OrderUpdated'] },
  targets: [new targets.LambdaDestination(consumer)],
});
  • Define bus + rule + Lambda target in CDK; grants are created for you.5
  • Bundle TypeScript consumer with NodejsFunction.6

8. Checklist

  • Pick the CDC source: native Atlas≥EventBridge trigger vs a relay Lambda on a change stream.2
  • Design events with version + idempotency key; keep them lean.
  • Route with rules by source/detail-type; target one consumer per concern.
  • Make consumers idempotent; add retries + DLQ; plan for replay.4
  • Consider the transactional outbox when you control the write path.7
