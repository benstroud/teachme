Microservices CDC Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

Change capture

CDC (change data capture)
Observing changes in a data source (here MongoDB) and turning them into events so other services can react.1
change stream
A MongoDB feature that lets an application watch a collection, database, or deployment for inserts, updates, replaces, and deletes, delivered as change events.1
$changeStream
The aggregation pipeline stage that powers change streams (used by `watch()`).1
operationType
The kind of change: insert | update | replace | delete (among others).1
resume token
A token that lets a change stream resume from where it left off after a disconnect.1
pre image / post image / fullDocument
The document before (pre) and after (post) a change; fullDocument returns the post-update document.1
documentKey
The _id (and shard key) identifying the changed document — useful as the stable id of a mutation event.

Events & EventBridge

mutation event
A structured message describing a business-data change (e.g. "OrderUpdated"), distinct from the raw change-stream record.
event schema
The agreed shape of an event: source, detail-type, detail, plus versioning.2
source / detail-type / detail
EventBridge event fields: where the event came from, what kind it is, and the payload.2
event bus
A router that receives events and delivers them to matching targets.2
rule / event pattern
A rule attaches a pattern to a bus; matching events are sent to its target(s).2
target
A destination an event bus delivers to, often a Lambda function.2
partner event source
A source (e.g. MongoDB Atlas) you associate with an event bus so its events flow in.3
idempotency key
A stable identifier in the event (e.g. document key + operation) consumers use to deduplicate at-least-once redeliveries.

Pipeline & reliability

relay (producer)
The component that turns captured changes into events on the bus — an Atlas trigger or a relay Lambda.
consumer
A Lambda (or other target) that receives an event and performs the downstream work.
at-least-once
Delivery semantics where an event may be delivered more than once; consumers must be idempotent.2
DLQ (dead-letter queue)
A queue where events that keep failing are parked for inspection.4
replay
Resending past events from the bus to rebuild state or recover after a failure.2
transactional outbox
The authored-event alternative: write the event to an outbox table in the same transaction as the change, then publish reliably.5
project expression
An Atlas trigger setting that limits which fields are included before sending to EventBridge.3
