App, Stack & the Construct Tree

Your whole infrastructure is a tree: an App holding Stacks, each holding Constructs, each holding more Constructs.

The mental model in one sentence

An App is the root container, a Stack is one CloudFormation deployment targeted at an environment, and a Construct is a building block that can nest inside other constructs — together they form a tree.1

The three shapes

ShapeRole
AppThe root; created as new App() in your entrypoint; holds stacks.
StackMaps to one CloudFormation stack; the unit you deploy and destroy, targeted at an account + region.
ConstructAnything inside a stack — from a single S3 bucket to an entire subsystem you design.
1

A minimal app in TypeScript

// bin/app.ts — entrypoint
import { App } from 'aws-cdk-lib';
import { MyStack } from '../lib/my-stack';

const app = new App();
new MyStack(app, 'MyStack', {
  env: { account: '123456789012', region: 'eu-west-1' },
});

// lib/my-stack.ts — stack of constructs
import { Stack, StackProps } from 'aws-cdk-lib';
import { Construct } from 'constructs';
import * as s3 from 'aws-cdk-lib/aws-s3';

export class MyStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);
    new s3.Bucket(this, 'Bucket', { versioned: true });   // a construct
  }
}
  • The env sets the target account and region — the stack's environment.1
  • this (the stack) is the scope for the bucket construct, making the bucket a child in the tree.
Key idea Scope is what links everything: each construct's parent is its scope. This tree is what CDK walks during synthesis to build the templates and to give every construct a stable, unique path.

Multiple stacks, separate lifecycles

You can put different resources in different stacks so they deploy, update, and destroy independently — e.g. one stack for networking, one for the application, one for databases. Each stack synthesizes to its own CloudFormation template.1
