The Deploy Pipeline

init, synth, bootstrap, diff, deploy — the commands that turn your TypeScript into real AWS resources, in order.

The mental model in one sentence

You scaffold with cdk init, turn code into a template with cdk synth, prepare the account with cdk bootstrap, check changes with cdk diff, and provision with cdk deploy.1

The commands

CommandWhat it does
cdk initScaffolds a new CDK project for a language (e.g. app --language typescript) and installs aws-cdk-lib.2
cdk synthRuns the app and emits the CloudFormation templates for its stacks into cdk.out.
cdk bootstrapDeploys the CDKToolkit bootstrap stack (including the asset bucket) into the target environment.1
cdk diffCompares the synthesized stack against the deployed one before you act.
cdk deployDeploys your stacks through CloudFormation to AWS.1
cdk destroyTears down a deployed stack and its resources.

Why bootstrap matters

Deployment that involves assets — local files or container images — needs a place to store them. Bootstrapping deploys the CDKToolkit stack with an S3 bucket for exactly that, once per environment. Most real apps need it before cdk deploy.

Key idea Synth and deploy are separate steps on purpose: synth is safe and local (code → template), deploy is the effectful one. Diff sits between them so you never deploy unseen changes.

Compile before you synth

In TypeScript, your code is compiled with tsc to JavaScript before CDK runs it. Use npm run build to compile manually (and catch type errors) or let CDK's build step do it; npm run watch recompiles on save.2
