Assets & Bootstrap

Your Lambda code and container images are assets CDK packages and uploads — which is exactly why deployment needs a bootstrap bucket.

The mental model in one sentence

An asset is local content (files or a Docker image) that CDK packages and uploads so an AWS service can use it; the upload target is the S3 bucket provisioned by cdk bootstrap.1

Defining an asset

import * as lambda from 'aws-cdk-lib/aws-lambda';

const fn = new lambda.Function(this, 'Fn', {
  runtime: lambda.Runtime.NODEJS_20_X,
  handler: 'index.handler',
  code: lambda.Code.fromAsset('src'),   // package the src/ folder as an asset
});

At deploy time, CDK fingerprints the source, uploads it to the bootstrap bucket, and references it in the template — so the function's code travels with the infrastructure.1

Kinds of assets

  • File assets — a directory or single file (Lambda code, config).
  • Docker image assets — a local image built and pushed to a container registry as part of the deploy.
Key idea Assets are why cdk bootstrap exists. Hand-written templates that inline everything may not need it, but any real app shipping code or images does — run it once per environment you deploy to.1

Lifecycle and fingerprinting

CDK fingerprints each asset's source so a change to a file produces a new asset (and a new template reference). This keeps deployments deterministic and avoids re-uploading unchanged content. Confirm the exact packaging behavior for your asset type against the docs for your version.
