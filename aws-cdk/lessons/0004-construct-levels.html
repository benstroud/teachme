Construct Levels

L1, L2, L3 — a ladder of abstraction from raw CloudFormation resources to pre-built patterns. Pick your rung per resource.

The mental model in one sentence

Constructs come in three levels: L1 (one per CloudFormation resource, no abstraction), L2 (curated, intent-based, with defaults and helpers), and L3 (pre-built patterns) — higher means easier but less control.1

L1: the escape to full control

Every CloudFormation resource has an L1 counterpart, so anything you could express in a CloudFormation template you can express in CDK. Use L1 when you need a property the L2 does not (yet) surface, or when you want the template to look exactly like a resource spec.1

L2: the everyday default

L2 constructs are "usually the most widely used." They encode defaults, security best practices, and helper methods (permissions, event wiring) so a bucket becomes new s3.Bucket(this, 'Bucket', { versioned: true }) instead of a dozen template lines.1

Key idea Start at L2 for standard resources; drop to L1 (or an escape hatch) only when you need a control the L2 doesn't expose. Picking the right level is a judgment, not a rule.

Choosing the level

  • Need the standard resource with sane defaults and safe policies → L2.
  • Need a raw CFN property or exact template fidelity → L1.
  • Want a whole well-trodden topology out of the box → L3 pattern.
