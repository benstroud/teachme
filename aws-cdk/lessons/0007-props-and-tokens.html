Props & Tokens

Constructs are configured with props bundles and connected with Tokens — lazy values that resolve to real CloudFormation expressions at synthesis.

The mental model in one sentence

Every construct takes a props bundle typed by an interface, and outputs values like bucket.bucketName that are Tokens — placeholders resolved to Ref/GetAtt/Join only when the template is synthesized.1

Props: a typed key/value bundle

const bucket = new s3.Bucket(this, 'Bucket', {
  versioned: true,        // BucketProps — typed in TypeScript
  removalPolicy: RemovalPolicy.DESTROY,
});

Props shape is defined by a per-construct interface (e.g. BucketProps), so your IDE tells you the required and optional keys and their types.1

Tokens: lazy references

const bucket = new s3.Bucket(this, 'Bucket', {});
bucket.bucketName;        // a Token — { Ref: 'Bucket...' } at synth time
bucket.bucketArn;         // a Token — { Fn::GetAtt: [...] }

These values do not exist until CloudFormation creates the resource, so CDK carries them as Tokens and emits the right intrinsic function in the template.2

Key idea Never force a Token through raw string concatenation in a way CDK cannot see. Passing a Token value into another construct's props is fine (CDK keeps it lazy); the danger is pre-flattening it into a string that discards the reference.

Composing references

this.fn.addEnvironment('BUCKET', bucket.bucketName);
queue.grantSendMessages(this.fn);      // wires IAM + creates dependencies

Passing one construct's token into another is how you connect resources without hardcoding names or ARNs — and CDK records the dependency between them.2
