Wiring & References

Pass values between constructs, let CDK infer dependencies, grant IAM — and connect resources across stacks.

The mental model in one sentence

You connect resources by passing one construct's values (Tokens) into another's props; CDK records the dependency, and grants handle the IAM policy.1

Implicit dependencies

this.fn.addEnvironment('QUEUE_URL', queue.queueUrl);   // reference ⇒ ordering

Once construct A references a value from construct B, CDK knows B must exist before A is created, and emits the right CloudFormation dependency ordering automatically.1

Grants make IAM declarative

import * as sqs from 'aws-cdk-lib/aws-sqs';
import * as lambda from 'aws-cdk-lib/aws-lambda';

const queue = new sqs.Queue(this, 'Queue');
const fn = new lambda.Function(this, 'Fn', { /* ... */ });

queue.grantSendMessages(fn);        // adds receive permission policy to fn
bucket.grantReadWrite(fn);          // similar for the bucket

Grant methods encapsulate the least-privilege policy so you don't hand-write IAM JSON; they also create the reference that links the two resources.2

Key idea Wire by passing constructs' outputs, not ARNs you copy-paste. That is what lets CloudFormation order resources, and what lets a rename refactor safely through the template.

Across stacks

When resources live in different stacks, passing a value across the App boundary is still possible — CDK emits CloudFormation exports/imports (or parameters) to pass the reference between stacks at deploy time.1
