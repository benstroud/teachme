Why the CDK

Define your cloud infrastructure in a real programming language, and let CDK turn it into CloudFormation that provisions on AWS.

The mental model in one sentence

The AWS Cloud Development Kit (CDK) is an open-source framework for defining cloud infrastructure in code and provisioning it through AWS CloudFormation.1

Two halves: library and toolkit

  • CDK Construct Library — pre-written, modular, reusable pieces of code called constructs for building and integrating AWS services.1
  • CDK Toolkit — the command-line tool (the CDK CLI) and a programmatic library for managing CDK apps, such as synthesis and deployment.1

Infrastructure as code, with the language you already know

CDK supports TypeScript, JavaScript, Python, Java, C#/.NET, and Go. Because you write in a general-purpose language, you get loops, conditionals, interfaces, inheritance, IDE completion, tests, and source control — the whole software-engineering toolkit applied to infrastructure.1

Key idea CDK writes synthesis output: your code compiles to CloudFormation templates, and CloudFormation performs the actual provisioning — predictably, repeatedly, with rollback on error.1

Why not just use CloudFormation directly

CloudFormation is powerful but verbose and template-based. CDK keeps you on CloudFormation's reliable deployment engine while removing the friction: your code is the source of truth, and the template is generated. If you know CloudFormation concepts, they carry over — you just author them in TypeScript.1

The workflow in miniature

cdk init app --language typescript     # scaffold a project
# ...author the app (App → Stack → Constructs)...
cdk synth                              # code → CloudFormation template
cdk deploy                             # CloudFormation → provisioned AWS
