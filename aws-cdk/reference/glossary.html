AWS CDK Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

The architecture

AWS CDK
Open-source framework for defining cloud infrastructure in code and provisioning it through AWS CloudFormation. Two parts: the Construct Library and the Toolkit (CLI).1
App
The root of a CDK application — the container for one or more stacks. Defined as new App() in the entrypoint.2
Stack
The deployment unit CDK maps to a CloudFormation stack (targeted at an environment). Resources are grouped into stacks for independent deploy/destroy.2
Construct
A component representing one or more CloudFormation resources and their configuration — the basic building block of a CDK app.3
Construct tree
The parent/child hierarchy formed by scope; the App is the root, Stacks are children, constructs nest beneath them.3
Environment
The account and region a stack deploys to, set via stack props (e.g. env: { account, region }).2
CloudFormation
AWS's managed IaC service CDK synthesizes to; it performs predictable, repeatable deployments with rollback on error.1

The lifecycle

cdk init
Creates a new CDK project for a language, e.g. cdk init app --language typescript; installs aws-cdk-lib.4
cdk synth
Compiles the app and emits the CloudFormation templates for its stacks (the synthesis output).2
cdk bootstrap
Deploys the CDKToolkit bootstrap stack into an environment, including the S3 bucket used to store assets (Lambda code, Docker images).2
cdk deploy
Deploys the app's stacks through CloudFormation to the target environment.2
cdk diff
Shows the difference between the synthesized stack and the deployed one before you act.2
cdk destroy
Tears down a deployed stack and its resources.2
Asset
Local files or Docker images the app packages and uploads to the bootstrap bucket so services (e.g. Lambda) can use them.2

Construct model

L1 construct (CFN resource)
Lowest level; maps one-to-one to a CloudFormation resource, named Cfn* (e.g. CfnBucket for AWS::S3::Bucket); no abstraction.3
L2 construct
A curated construct (e.g. s3.Bucket) with an intent-based API, sensible defaults, best-practice security, and helper methods.3
L3 construct / pattern
The highest abstraction level: pre-built patterns wiring several resources together.3
scope
The first argument to a construct; its parent in the construct tree.4
id
The second argument; must be unique within its scope and forms (with the path) the construct's logical path.4
props
The third argument: a key/value bundle conforming to an interface (e.g. BucketProps) that configures the construct.4
Token / lazy value
A placeholder value whose real CloudFormation expression (Ref, GetAtt, Join) is only known at synthesis — how CDK defers evaluation until the template is built.2
Aspect
A visitor applied across the whole construct tree to implement cross-cutting concerns (e.g. tagging, security checks).2
