AWS CDK Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. Core mental model

App  →  Stack(s)  →  Constructs  →  synthesize  →  CloudFormation  →  deploy

// bin/app.ts — the entrypoint
import { App } from 'aws-cdk-lib';
import { MyStack } from '../lib/my-stack';
const app = new App();
new MyStack(app, 'MyStack', { env: { account: '123456789012', region: 'eu-west-1' } });

// lib/my-stack.ts — a Stack of constructs
import { Stack, StackProps } from 'aws-cdk-lib';
import * as s3 from 'aws-cdk-lib/aws-s3';
export class MyStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props);
    new s3.Bucket(this, 'Bucket', { versioned: true });   // L2 construct
  }
}

CDK defines infra in code, synthesizes CloudFormation templates, and provisions through CloudFormation.1

2. Lifecycle commands

npm install -g aws-cdk          # or use local: npx aws-cdk
cdk init app --language typescript   # scaffold project (installs aws-cdk-lib)
npm run build                        # compile TS → JS (tsc)
cdk synth                            # emit CloudFormation templates
cdk diff                             # show changes vs deployed stack
cdk bootstrap                        # deploy CDKToolkit + asset bucket (needed for assets)
cdk deploy                           # deploy through CloudFormation
cdk list                             # list stacks in the app
cdk destroy                          # tear down a deployed stack

Workflow: init → synth → (bootstrap once) → diff → deploy.2

3. Construct levels

LevelWhatExample
L1 (CFN resource)One-to-one with a CloudFormation resource; no abstractionCfnBucket → AWS::S3::Bucket
L2 (curated)Intent-based, defaults, best-practice security, helperss3.Bucket
L3 (pattern)Pre-built multi-resource patternsload-balanced Fargate service etc.

Higher level = easier, less control; lower level = more control, less convenience.3

4. Authoring constructs

  • Every construct takes (scope, id, props); props conforms to an interface (e.g. BucketProps).4
  • Extension point: class MyConstruct extends Construct, add L2 children with this as scope.
  • Expose values to consumers with public readonly properties (e.g. readonly topic).

5. Tokens & references

// Tokens defer the real expression to synthesis (Ref / GetAtt / Join)
bucket.bucketName          // Token → { Ref / GetAtt }
bucket.bucketArn
this.fn.addEnvironment('BUCKET', bucket.bucketName);   // wired without hardcoding

Never string-wrap a Token; pass values as objects so CDK keeps the reference lazy.2

6. Assets & bootstrap

import { Code } from 'aws-cdk-lib/aws-lambda';
const fn = new lambda.Function(this, 'Fn', {
  runtime: lambda.Runtime.NODEJS_20_X,
  handler: 'index.handler',
  code: Code.fromAsset('src'),       // packaged as an asset
});

Assets upload local files/Docker images to the bootstrap bucket so services can use them.2

7. Wiring & IAM

queue.grantSendMessages(fn);        // adds the needed IAM policy
bucket.grantReadWrite(fn);
// harness cdk to infer dependencies from references automatically

Passing references creates implicit Cfn depends-on; grants keep least-privilege declarative.

8. Best practices checklist

  • Treat infrastructure as code: review, test, commit it.1
  • Prefer L2 constructs; drop to L1 or the escape hatch only when needed.3
  • Organize into stacks per environment/lifecycle; set env (account + region).2
  • Avoid hardcoding; use props, context, and Tokens.
  • Use Aspects for cross-cutting policy (tagging, security checks).
  • Run cdk diff before cdk deploy; be deliberate about destructive changes.
  • Bootstrap each environment where you deploy assets.
