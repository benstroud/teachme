OpenSearch Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

Engine & cluster

Elasticsearch
A distributed, open-source search and analytics engine built on Lucene; the model OpenSearch inherits.
OpenSearch
The open-source fork of Elasticsearch 7.10 (Apache-2.0) maintained by the OpenSearch Project; the open-source engine under Amazon OpenSearch Service.1
OpenSearch Service / domain
The AWS managed service. A domain is equivalent to an OpenSearch cluster — settings, instance types, and instance counts you specify.1
node
A single server in the cluster; in OpenSearch Service, each EC2 instance you choose is one node.1
shard
A single Lucene index holding a slice of an index's documents; an index is split across shards and replicated as replicas.
replica
A copy of a shard that provides failover and read scaling; a primary and its replicas form a shard group.
cluster health
A status (green/yellow/red) reported by the CAT health API describing whether all primary and replica shards are allocated.
OpenSearch Serverless
The on-demand, auto-scaling AWS configuration: a collection scales compute automatically, with always-encrypted storage and no manual capacity management.6

Data model

document
A JSON object stored and searchable by OpenSearch, identified by an _id within an index.
index
A collection of documents with a shared set of fields and mappings; the unit you search.
mapping
The definition of a document's fields, their types, and their analyzers; can be dynamic or explicit.
text field
A field type that is analyzed: tokenized for full-text matching and relevance scoring on words.4
keyword field
A field type that is not analyzed: stored as one exact value, good for term matching, sorting, and aggregations.4
multi-field
A field with sub-fields, e.g. title plus title.raw (keyword), so one field supports both full-text and exact use.
inverted index
The structure mapping each (normalized) term to the documents containing it — the core of fast full-text lookup.
_source
The original JSON document as indexed, returned in search hits unless disabled in the mapping.

Queries & relevance

match query
Full-text query that analyzes the input and matches on terms; OR operator by default.3
term query
Exact, unanalyzed term match against a field — the query value is taken literally.7
query / filter context
Query context computes relevance scores; filter context matches without scoring (and can be cached), used inside a bool.
bool query
Composes clauses with must (scored, required), should (bonus), filter (required, no score), and must_not.
_score
The relevance number OpenSearch assigns a hit; higher means more relevant.
BM25
The default relevance scoring algorithm: a formula over term frequency, inverse document frequency, and field-length normalization with tunable k1 and b.
analyzer
An ingestion/query-time text processor built from character filters, a tokenizer, and token filters.5
tokenizer / token filter
The stage that splits text into tokens, and the stages that transform them (lowercase, stop, stem, synonyms).5

Searching & analytics

_search
The API endpoint that runs a search and returns hits — the matched documents and their scores.8
aggregation
A computed grouping or metric over matching documents — metric (e.g. avg) or bucket (e.g. terms).9
deep pagination
Getting to results far beyond the first pages, where from/size grows expensive; solved with search_after + point-in-time.
point-in-time (PIT)
An immutable snapshot of an index's state used with search_after for stable deep pagination.10
