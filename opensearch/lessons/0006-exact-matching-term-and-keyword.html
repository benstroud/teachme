Exact Matching: Term & Keyword

When a key, status, or slug must match a stored value byte for byte.

The mental model in one sentence

When you want an exact value — not a word match — use the term query against a keyword field: no analysis happens on either side, so PENDING only matches PENDING.1

term matches the stored value exactly

GET /products/_search
{ "query": { "term": { "status": "PENDING" } } }

Because status is a keyword, this matches documents whose stored value is literally PENDING. Running the same on a text field would compare against the analyzed tokens and almost certainly miss.

match vs term

QueryFieldInput analyzed?Use for
matchtextYesFull-text ranked prose.
termkeywordNoExact ids, statuses, enums, slugs.
termskeywordNo"Any of these values" filters.
rangenumeric / date—Greater/less than boundaries.
Key idea The trap: people run term against a text field and get nothing. If the field is analyzed, your "exact" value no longer exists as-is — that is why we keep the .raw keyword sub-field.1
