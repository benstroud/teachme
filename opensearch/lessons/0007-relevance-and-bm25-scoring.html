Relevance & BM25 Scoring

Why results are ordered as they are, and how to steer ranking with bool.

The mental model in one sentence

Every hit carries a _score computed by BM25 — a formula combining term frequency, how rare the term is across the index, and the field length — which is why a document with your words repeated in a short field ranks first.1

Why one result beats another

BM25 rewards a term that appears often in a document (term frequency) but punishes it when the term is common across all documents (inverse document frequency), and it normalizes the count by how long the field is. The k1 and b parameters tune how much term frequency and length matter; OpenSearch ships sensible defaults, so you rarely touch them.

Combine matches with a bool query

GET /products/_search
{ "query": { "bool": {
    "must":   [ { "match": { "category": "kitchen" } } ],
    "should": [ { "match": { "name": "copper" } } ],
    "filter": [ { "term": { "inStock": true } } ]
  } } }

must is required and scored, should adds a score bonus when it matches, and filter narrows results without touching _score.

Key idea Relevance is a ranking, not a filter — _score tells you the order, and _explain shows exactly how each document's score was built. Use filter for constraints so ranking is never distorted by them.1
