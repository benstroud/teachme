Indexing & the Bulk API

One round trip for thousands of documents: batching writes with NDJSON.

The mental model in one sentence

To load data at scale you stop issuing one request per document and send the _bulk endpoint a batch of NDJSON action lines — each just { "index": {...} } over a document line — so one round trip indexes thousands of records.1

A bulk payload

POST /products/_bulk
{ "index": { "_id": "1" } }
{ "name": "Copper Mug", "price": 12.5, "inStock": true }
{ "index": { "_id": "2" } }
{ "name": "Steel Flask", "price": 9.9, "inStock": false }

Each pair is an action (here index) followed by the document; the response gives a per-item status so you can tell what failed without aborting the rest.

Why bulk is fast

  • One request carries many documents, slashing network round trips.
  • index with an _id is idempotent: re-running replaces the same doc.
  • OpenSearch buffers writes and periodically refreshes to make them searchable (near-real-time), rather than on every single document.
Key idea Bulk is a throughput technique: keep batches a few megabytes, give every document a stable _id when you can, and treat re-sends as safe because indexing is by id.1
