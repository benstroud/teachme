Aggregations for Analytics

Turning a search corpus into averages, counts, and time buckets.

The mental model in one sentence

An aggregation turns matching documents into computed answers — a metric like an average, or buckets you group by — so one search can also return the report.1

Metric aggregations

GET /products/_search
{ "size": 0,
  "aggs": { "avg_price": { "avg": { "field": "price" } } } }

Metrics compute a value over the matching set: avg, sum, min, max, cardinality (unique count).

Bucket aggregations

GET /products/_search
{ "size": 0,
  "aggs": { "by_status": { "terms": { "field": "status" } } } }

Buckets group documents — terms by value, date_histogram by time interval — and each bucket reports its own doc_count.

The keyword-subfield rule

OpenSearch will not aggregate a text field by default; it reunites the tokenized words only at real memory cost. Keep a keyword sub-field (like the fields.raw pattern) and aggregate on that instead.1

Key idea Aggregations are the engine behind facets ("filter by status" counts and "price" averages). They run over however many documents match, so keep size: 0 when you only want the report.1
