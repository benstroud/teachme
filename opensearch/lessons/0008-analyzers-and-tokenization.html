Analyzers & Tokenization

The hidden pipeline that decides what counts as a matching word.

The mental model in one sentence

An analyzer decides exactly what "text" means for a field — splitting on words, lowercasing, and removing noise — so that the same text can match the same terms at index and query time.1

An analyzer is three stages

StageJobExample
Character filtersPreprocess characters before splittingStrip HTML, replace & with "and".
TokenizerSplit text into tokensstandard splits on word boundaries.
Token filtersTransform each tokenlowercase, stop, stem, synonyms.1

See the tokens with _analyze

GET /_analyze
{ "analyzer": "standard", "text": "Let's contribute to OpenSearch!" }

The response lists tokens like let's, contribute, to, opensearch with their offsets. Lowercase and stopword filters would shrink that further.

Defining a custom analyzer

PUT /products
{ "settings": { "analysis": {
    "analyzer": { "my_lower": {
       "tokenizer": "standard",
       "filter": ["lowercase", "stop"] } } } } }
Key idea The same analyzer must run at index time and query time, or terms never line up. Use the _analyze API to confirm the tokens before trusting a field's behavior.1
