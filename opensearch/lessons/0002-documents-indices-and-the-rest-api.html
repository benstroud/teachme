Documents, Indices & the REST API

The JSON document as the unit of storage, and the HTTP CRUD calls that touch it.

The mental model in one sentence

Every document in OpenSearch is addressed by an _id inside an index, and you create, read, update, and delete it through plain REST calls to the _doc endpoint.1

CRUD over HTTP

# index (create or replace) a document with id "1"
PUT /products/_doc/1
{ "name": "Copper Mug", "price": 12.5, "inStock": true }

# read it back
GET /products/_doc/1

# update part of it (script or partial doc)
POST /products/_doc/1/_update
{ "doc": { "price": 11.0 } }

# delete it
DELETE /products/_doc/1

The endpoints at a glance

MethodEndpointAction
PUT / POST/{index}/_doc/{id?}Index a document; omit the id and OpenSearch assigns one.
GET/{index}/_doc/{id}Fetch a document by id.
POST + _update/{index}/_doc/{id}/_updateApply a partial update to a document.
DELETE/{index}/_doc/{id}Remove a document.
Key idea A PUT with an explicit _id is idempotent — re-sending it replaces the same document. A raw POST without an id lets the engine generate one for you.1
