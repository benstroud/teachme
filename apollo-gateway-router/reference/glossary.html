Gateway & Router Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

The graph

graph gateway / graph router
The edge component that sits in front of several GraphQL services and presents one composed schema to clients, planning and executing each request across those services.1
subgraph
A single GraphQL service that contributes part of the federated graph, with its own schema and resolvers. A subgraph can be an Apollo Server, another language implementation, or a connector to a REST API.2
supergraph
The single, composed GraphQL schema produced from all subgraph schemas. It is what clients query and what the gateway routes against.2
API schema
The client-facing schema the gateway exposes to consumers — the supergraph after federation composition has resolved directives and ownership.2
entity
A type with an identity (a @key) that several subgraphs can contribute fields to, matched by that key at runtime.3
@key
A federation directive marking an entity and naming the fields that identify a single instance, e.g. @key(fields: "id").3
__resolveReference
A special resolver (in the owning subgraph) that loads an entity from just its key fields when another subgraph references it.
@shareable / @external / @provides / @requires
Federation directives that spell out which subgraph owns a field, which fields a type contributes, and what a field depends on when resolving across subgraphs.

The Node gateway (@apollo/gateway)

@apollo/gateway
Apollo's Node.js gateway. Runs in-process with Apollo Server and turns Apollo Server into a graph router for a federated supergraph.4
ApolloGateway
The class exported by @apollo/gateway. Construct it with a supergraph source, then pass the instance as the gateway option to new ApolloServer(...).4
supergraphSdl
The option that tells ApolloGateway where the supergraph schema comes from: a string, a hook, or a manager (such as IntrospectAndCompose).4
IntrospectAndCompose
A SupergraphManager that introspects a list of subgraph URLs at startup and composes the supergraph, with optional polling for updates.4
buildService
A function you can give ApolloGateway to customize the data source used to talk to each subgraph (e.g. to attach auth).

The Apollo Router

Apollo Router
The standalone, high-performance graph gateway (a binary) recommended by Apollo for production. It serves the supergraph and routes requests across subgraphs.1
router.yaml
The Router's default configuration file, where runtime features are declared: schema source, listeners, CORS, authentication, caching, telemetry, and more.5
listeners
The Router config section that opens HTTP (and/or shared/unix) sockets the Router listens on.
supergraph source
Where the Router reads the supergraph schema from: local files, graph artifacts, Apollo Uplink, or the Kubernetes Operator.5
Apollo Uplink
Apollo's schema delivery service; the Router reads the supergraph from Apollo when APOLLO_GRAPH_REF is set.
hot reload
The Router feature that reloads a changed local supergraph file at runtime without a restart.5
query plan
The internal execution strategy the gateway produces for a client query: which subgraphs to call, in what order, and how to merge the pieces.6
Rhai
A scripting language the Router runs for customization (e.g. authorization logic) without recompiling the binary.
coprocessor
An out-of-process hook (in any language) for customizing Router behavior at defined points in the request lifecycle.

Security, caching & operations

JWT authentication
A Router security feature that verifies client tokens (against a JWKS/issuer/audience) before a request is planned and executed.7
subgraph authentication
Headers the Router attaches when calling subgraphs, forwarding or adding credentials on the upstream hop.
CORS
Cross-origin request rules the Router enforces on the paths it serves, controlling which browsers may call it.7
APQ (Automatic Persisted Queries)
A protocol optimization where clients send a hash of a query and only send the full query on a miss, reducing payload size.8
response caching
Router-level caching of full responses (often in Redis) so identical operations do not hit subgraphs every time.8
traffic shaping
Per-operation Router policies for timeouts, retries, and batching that tune reliability and performance of upstream calls.8
OpenTelemetry
The observability standard the Router emits traces/metrics to (exporters like OTLP, Datadog, Prometheus).9
Apollo Operator
Apollo's Kubernetes operator for deploying and managing the Router on Kubernetes with schema-aware blue/green updates.
