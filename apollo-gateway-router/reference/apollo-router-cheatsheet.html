Gateway & Router Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The mental model

   Clients (web, mobile)
          │  one GraphQL query to the gateway
      ┌───▼─────────┐
      │  GATEWAY     │  serves the supergraph,
      │  (Router)    │  plans + routes the request
      └──┬────┬────┬─┘
     ┌───▼┐ ┌▼───┐ ┌▼──────┐
     │users│ │prod│ │reviews│   ← subgraphs (GraphQL
     └─────┘ └────┘ └───────┘      services / REST)

A gateway composes subgraphs into a supergraph, serves it to clients, and for each request builds a query plan executed across subgraphs.1

2. Supergraph & entities

# subgraph schema (products)
type Product @key(fields: "id") {
  id: ID!
  name: String!
  price: Int
}
# subgraph schema (reviews) contributes a field, ties on the key
extend type Product @key(fields: "id") {
  id: ID! @external
  reviews: [Review!]!
}
  • Build the supergraph from subgraphs: rover supergraph compose --config ./supergraph.yaml --output ./supergraph.graphql.2
  • Entities use @key; non-owning subgraphs extend and mark the key @external.

3. Node gateway (@apollo/gateway)

npm install @apollo/gateway @apollo/server graphql

import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';
import { ApolloGateway } from '@apollo/gateway';
import { readFileSync } from 'fs';

const supergraphSdl = readFileSync('./supergraph.graphql').toString();
const gateway = new ApolloGateway({ supergraphSdl });
const server = new ApolloServer({ gateway });

const { url } = await startStandaloneServer(server);
console.log('ready at', url);
  • In-process with Apollo Server; docs recommend the Router for production.3
  • Or compose by introspection: new IntrospectAndCompose({ subgraphs: [ { name, url } ] }).

4. Apollo Router — run it

# provide the supergraph and a config file
APOLLO_ROUTER_SUPERGRAPH_PATH=./supergraph.graphql ./router
# or: ./router --supergraph ./supergraph.graphql

# Docker
docker run -p 4000:4000 \
  -v ./supergraph.graphql:/supergraph.graphql \
  -v ./router.yaml:/config/router.yaml \
  -e APOLLO_ROUTER_SUPERGRAPH_PATH=/supergraph.graphql \
  ghcr.io/apollographql/router:v2 \
  --config /config/router.yaml
  • Schema source options: local files (APOLLO_ROUTER_SUPERGRAPH_PATH), Uplink (APOLLO_GRAPH_REF), graph artifacts (APOLLO_GRAPH_ARTIFACT_REFERENCE), or the Kubernetes Operator.4
  • Note — the Docker image/version tag above is illustrative; confirm the current tag and config path for the version you run.

5. router.yaml

supergraph:
  path: ./supergraph.graphql

listeners:
  - port: 4000

cors:
  origins:
    - https://app.example.com

headers:
  all:
    request:
      - propagate:
          named: x-request-id

authentication:
  router:
    jwt:
      issuer: https://auth.example.com
      audiences: [ "my-app" ]
      jwks:
        - url: https://auth.example.com/.well-known/jwks.json
  subgraph:
    all:
      http:
        headers:
          Authorization: "Bearer fixed-token-placeholder"

telemetry:
  exporters:
    metrics:
      otlp:
        endpoint: http://collector:4317
  • router.yaml configures features; the supergraph is wired separately (see §4).4
  • Exact JWT/jwks and caching key names vary by version — confirm against router --docs.

6. Security, caching, operations

  • Auth: verify client JWTs at the router (issuer + audience + JWKS); propagate credentials to subgraphs and lock down paths.5
  • CORS: control which origins may call the router.
  • Caching: response caching (Redis) and automatic persisted queries reduce subgraph load.6
  • Plan-aware: the native query planner decides which subgraphs run what, in order.
  • Customize: Rhai scripts (in-binary) or coprocessors (out-of-process) for authz/logic.
  • Observe: emit OpenTelemetry spans/metrics; export to OTLP/Datadog/Prometheus; use health checks.7
  • Deploy: Docker, Kubernetes via the Apollo Operator, AWS, Azure, or GCP.8

7. Design checklist

  • Route all client traffic through one gateway; subgraphs stay private behind it.
  • Pick the Router for production performance; use @apollo/gateway for deep Node integration.
  • Own fields once per subgraph; use entities + @key to share across them.
  • Authenticate at the edge with JWT; keep secrets out of reproduction snippets.
  • Cache the queries that deserve it; plan for invalidation.
  • Emit telemetry and health checks from day one.
