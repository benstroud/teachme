Lesson 1 of 10Apollo GraphQL Gateway & Router

Why a Graph Gateway

When a domain is split across many GraphQL services, a gateway gives clients one schema — the supergraph — and one place to route.

The mental model in one sentence

A graph gateway (also called a graph router) sits in front of several GraphQL services, presents them as a single composed schema — the supergraph — and, for each client request, plans how to gather the answer across those services.1

The problem it solves

An organization rarely runs one big GraphQL API. Teams own separate services: a users service, a products service, a reviews service — each a subgraph with its own schema. Without a gateway, a client that needs a product and its reviews must:

  • Call several services and stitch the results by hand, and
  • Know every service's URL, schema, and auth model.

That is exactly the fragmentation a gateway removes: one API in front, many services behind it.2

Key idea A gateway composes subgraphs into a supergraph, serves the supergraph to clients, and executes each request across subgraphs — so clients behave as if the domain were one monolith.

What a gateway gives you

PropertyWhat it means
One endpoint, one schemaClients query the supergraph, not N services.
Cross-service joinsOne query can cross the products and reviews boundary.
Query planningThe gateway decides which services run what, and how to merge it.
A security edgeAuthentication, CORS, and rate rules live in one place.
Freedom for teamsEach team evolves its subgraph without coordinating clients.

Two Apollo gateways

Apollo offers two ways to run this edge layer:1

  • @apollo/gateway — a Node.js gateway that runs in-process with Apollo Server.
  • Apollo Router — a standalone, high-performance binary that Apollo recommends for production.

Both serve the same supergraph, so the choice is mostly about deployment and scale — which the next lessons explore.
