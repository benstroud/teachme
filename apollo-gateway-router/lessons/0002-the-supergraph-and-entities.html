The Supergraph & Entities

The gateway reads one composed schema; entities are how multiple subgraphs share a single type across that schema.

The mental model in one sentence

Each subgraph publishes its own schema; those schemas are composed into a supergraph, and an entity is a type that several subgraphs contribute fields to by agreeing on a key.1

Subgraph versus supergraph versus API schema

SchemaWhat it is
Subgraph schemaOne service's schema, e.g. products, with its resolvers and entities.
Supergraph schemaThe composed whole, produced from all subgraphs; includes routing metadata.
API schemaThe client-facing view the gateway serves, after composition resolves ownership.1

Composing the supergraph

Apollo's Rover CLI composes a supergraph from a subgraph list. You feed Rover a small config naming each subgraph's schema location, and it outputs a supergraph file the gateway loads.2

# supergraph.yaml
subgraphs:
  products:
    routing_url: http://products:4000
    schema:
      file: ./products.graphql
  reviews:
    routing_url: http://reviews:4000
    schema:
      file: ./reviews.graphql

# rover supergraph compose --config ./supergraph.yaml --output ./supergraph.graphql

Entities tie subgraphs together

A Product lives in products but the reviews subgraph wants to add review data to it. They agree Product is an entity identified by a @key. Each contributing subgraph declares the same key; the owner resolves the entity by that key.3

# products subgraph — owns the entity
type Product @key(fields: "id") {
  id: ID!
  name: String!
  price: Int
}

# reviews subgraph — contributes a field
extend type Product @key(fields: "id") {
  id: ID! @external
  reviews: [Review!]!
}
  • @key(fields: "id") names the identity the gateway uses to match a product across subgraphs.3
  • The non-owning subgraph extends the type and marks the shared key field @external.
  • The owning subgraph provides a reference resolver that loads the entity from just its key fields when it is reached from another subgraph.
Key idea The supergraph is the contract the gateway routes against. Entities — via @key — are what let one client query across subgraph boundaries in a single request.
