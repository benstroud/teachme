Gateway vs Router: Two Runtimes

One composes inside a Node process; the other is a standalone binary. They serve the same supergraph — the choice is operational.

The mental model in one sentence

@apollo/gateway runs the graph gateway in-process with Apollo Server (Node.js), while the Apollo Router is a separate, standalone binary that Apollo recommends for production.1

The Node gateway: in-process with Apollo Server

With @apollo/gateway, your gateway is code. You construct an ApolloGateway, hand it the supergraph, and pass it to new ApolloServer({ gateway }). Apollo Server then behaves as the graph router. Because it is a Node process, you can customize it with the usual Apollo Server plugins, service hooks, and your own middleware.2

The Apollo Router: a standalone binary

The Apollo Router is Apollo's execution engine for graph-based API orchestration — a binary you run next to your services, configured with a YAML file and a supergraph schema.1 It is written for throughput: query planning and routing happen in a purpose-built runtime, so it scales to high request loads without per-request Node overhead.

Key idea Both runtimes consume the same supergraph and expose the same combined API to clients. You are not locked into different graph models — you are choosing where and how the routing layer executes.

Choosing between them

Consideration@apollo/gateway (Node)Apollo Router
RuntimeIn-process with Apollo ServerStandalone binary
ConfigurationCode + pluginsrouter.yaml + schema source
PerformanceFine for modest loadBuilt for high throughput
Custom auth logicEasy to write in NodeVia JWT config, Rhai, or coprocessors
Production defaultNot recommended by defaultRecommended by Apollo

Apollo's docs are explicit: in the majority of cases they recommend the Router, because it is faster to configure, more performant at high request loads, and rarely requires custom code; the @apollo/gateway API reference notes that all supergraphs should use it.2 The main reason to stay on the Node gateway is when you need deep, code-level integration with Apollo Server's plugin model or a custom subgraph fetcher.
