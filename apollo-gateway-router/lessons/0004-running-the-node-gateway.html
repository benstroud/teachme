Lesson 4 of 10Apollo GraphQL Gateway & Router

Running the Node Gateway

With @apollo/gateway, Apollo Server becomes the graph router — fed by a supergraph schema string or by introspecting subgraphs.

The mental model in one sentence

You construct an ApolloGateway with a supergraph source, pass it as the gateway option to new ApolloServer(...), and start it with the usual Apollo Server startup — the gateway now plans and routes across subgraphs.1

Install and the minimal gateway

npm install @apollo/gateway @apollo/server graphql

import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';
import { ApolloGateway } from '@apollo/gateway';
import { readFileSync } from 'fs';

const supergraphSdl = readFileSync('./supergraph.graphql').toString();

const gateway = new ApolloGateway({
  supergraphSdl,
});

const server = new ApolloServer({ gateway });

const { url } = await startStandaloneServer(server);
console.log('ready at', url);

Here supergraphSdl is a pre-composed supergraph string (the output of rover supergraph compose). On startup the gateway processes it, extracts subgraph routing info, and begins planning queries across the listed subgraphs.1

Composing at startup by introspection

Instead of a pre-built supergraph, you can let the gateway introspect each subgraph at startup with IntrospectAndCompose, naming each service by name and url:2

import { ApolloGateway, IntrospectAndCompose } from '@apollo/gateway';

const gateway = new ApolloGateway({
  supergraphSdl: new IntrospectAndCompose({
    subgraphs: [
      { name: 'products', url: 'http://localhost:4001/graphql' },
      { name: 'reviews',  url: 'http://localhost:4002/graphql' },
    ],
    // pollIntervalInMs: 60000,  // optional polling for updates
  }),
});
const server = new ApolloServer({ gateway });
const { url } = await startStandaloneServer(server);

Customizing how subgraphs are reached

buildService lets you swap in a custom data source per subgraph (for example to add auth headers):2

const gateway = new ApolloGateway({
  supergraphSdl,
  buildService({ name, url }) {
    return new AuthenticatedDataSource({ name, url });
  },
});
Key idea The gateway is just a special Apollo Server configuration. Everything you know about plugins, headers, and context still applies — the difference is that resolving a query now fans out to subgraphs instead of resolvers in the same process.

Keep the trade-off in view

This path is convenient when you want gateway behavior inside Node. Recall the docs' guidance that production workloads are better served by the Apollo Router — so treat this lesson as the "in-process" option, not the default target.1
