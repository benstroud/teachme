Lesson 1 of 9MongoDB Aggregations

Why Aggregations

Stop shipping documents to Node to reduce them by hand. Move the computation into the database.

The mental model in one sentence

An aggregation pipeline is an array of stages; documents stream through them in order, and each stage takes documents in, processes them, and outputs documents — so the shape of the stream can change as it travels.1

Where answering questions actually happens

When a product asks "revenue per region" or "top five sellers", the naive approach is:

// Anti-pattern: move analysis into the app
const all = await db.orders.find({}).toArray();
const byRegion = {};
for (const o of all) {
  byRegion[o.region] = (byRegion[o.region] || 0) + o.total;
}

That downloads every document, piles them in memory in Node, and burns network and RAM — and it gets worse as the collection grows. The aggregation pipeline moves this work into the server: you send an array of stages, and MongoDB returns the answer.

The pipeline replaces the for-loop

The loop above is one idiom of the pipeline: filter, shuffle through the collection (unwind), then group and reduce:

db.orders.aggregate([
  { $match:  { status: "fulfilled" } },          // keep only these
  { $unwind: "$items" },                         // one doc per line item
  { $group:  { _id: "$region",
               totalRevenue: { $sum: { $multiply: [ "$items.price", "$items.qty" ] } } } },
  { $sort:   { totalRevenue: -1 } },             // biggest first
  { $limit:  5 }                                 // top five
])
StageWhat it does
$matchFilters documents (like find).
$unwindDeconstructs an array into one document per element.
$groupCollects documents sharing a key and reduces them with an accumulator.
$sort → $limitOrders and caps the output — "top N".
Key idea A stage's output is a new stream of documents. Master the shape at each stage and every pipeline becomes legible: filter → flatten → group → rank.

Where the pipeline fits (and where it doesn't)

  • Put it in front of questions: totals, averages, counts, distincts, rankings, per-group breakdowns, time buckets.
  • Pairing with single-purpose helpers: estimatedDocumentCount(), count(), and distinct() answer the simplest forms without a full pipeline.2
  • Avoid huge results if a group's output would grow past MongoDB's document-size and memory limits (covered in Lesson 9).
