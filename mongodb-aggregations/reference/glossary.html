Aggregations Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

The pipeline

Aggregation pipeline
An array of stages run against a collection. Documents flow through each stage in order; each stage takes documents in, processes them, and outputs documents, so the shape of the stream can change stage to stage.1
Stage
One operation in the pipeline (e.g. $match, $group). Order matters — a stage operates on the output of the previous stage.
Streaming stage
A stage that can emit documents as they arrive (e.g. $match, $limit), without needing the whole input first.
Blocking stage
A stage that must consume all its input before emitting anything (e.g. $sort, $group). Uses memory; may spill to disk past 100 MB.2
Stage order
The sequence of stages. Put filters/limits early to shrink what later stages see; the order changes the result and the cost.
Field path
How an expression refers to a field, written with a leading $, e.g. "$price" or "$items.price". Distinguish from literal strings and from $$variable references.
Accumulator
An operator used inside $group that folds many values into one ($sum, $avg, $push, …).3
Group key
The _id expression in $group that decides which documents share a bucket. null groups everything into a single document.3

Core stages

$match
Filters documents by a query predicate — the pipeline stage that best uses an index. Put it as early as possible.4
$project
Shapes the output document: include/exclude fields, or compute new field: <expression> fields. 1/0 inclusion and computed new fields in one stage was only valid before 4.4 — computed fields want $addFields or $project with inclusions.5
$addFields / $set
Add or overwrite fields without removing others; $unset removes fields.
$sort
Orders documents by one or more keys (1 asc / -1 desc). Blocking; prefers an index; often placed after $group and before $limit.6
$limit / $skip / $count
$limit caps the number of documents; $skip drops the first N; $count returns a single count document and must be the last stage.
$unwind
Deconstructs an array: an array of N yields N documents, each with the array field replaced by one element. Drops null/missing/empty unless preserveNullAndEmptyArrays.7
$lookup
Performs a left outer join into another collection in the same database, adding an array field of matching documents.8
$facet
Runs multiple independent sub-pipelines on the same input in one pass; each result lands under its own facet key.
$setWindowFields
Adds fields computed across a window (partition) of ordered documents: ranks, running totals, moving averages, shifts.9
$out / $merge
Write the pipeline's output into a collection: $out replaces the target (must be the last stage); $merge merges into an existing collection.

Variables, expressions & memory

$$ROOT
The current input document as a whole. Used to group entire documents: { $push: "$$ROOT" }.10
$$CURRENT / $$REMOVE / $$NOW / $$IDX
$$CURRENT = current document/field; $$REMOVE = drop a field; $$NOW = the command's start date; $$IDX = current array element index (8.3).10
Expression operators
Functions used inside a stage to compute values, e.g. $add, $multiply, $cond, $ifNull, $dateToString, $filter, $map.
16 MiB BSON document limit
The maximum size of any single BSON document. Every aggregation result document must stay under it, or the aggregation errors.11
100 MB per-stage limit
Pipeline stages needing more than ~100 MB of RAM either spill to disk or error, depending on allowDiskUse. $group, $sort, $setWindowFields, $bucket* can spill.11
allowDiskUse
The option (or allowDiskUseByDefault parameter) that lets memory-hungry stages write temporary files to disk instead of erroring past 100 MB.
