Lesson 5: Asynchronous I/O & Error Handling

Mission: Handle non-blocking I/O and asynchronous errors gracefully in Node.js backend services.

Backend performance depends on Asynchronous I/O powered by the Node.js event loop. Combining `async/await` syntax with strong TypeScript promise return typing prevents unhandled rejection crashes.

Typed Async Operations

Consider querying a database asynchronously with typed promises:

interface UserRecord {
  id: string;
  username: string;
}

const fetchUserFromDb = async (id: string): Promise<UserRecord> => {
  // Simulating async I/O delay
  await new Promise((resolve) => setTimeout(resolve, 100));
  
  if (id === "99") {
    throw new Error("Database timeout");
  }
  
  return { id, username: `user_${id}` };
};

// Safe controller wrapper
const handleGetUser = async (id: string): Promise<string> => {
  try {
    const user = await fetchUserFromDb(id);
    return JSON.stringify(user);
  } catch (err) {
    const message = err instanceof Error ? err.message : "Unknown error";
    return JSON.stringify({ error: message });
  }
};
Key Takeaway: In TypeScript, caught errors in catch blocks default to `unknown`, requiring runtime narrowing (`err instanceof Error`) before accessing properties safely. Consult the Node.js Async Context Documentation.
