Lesson 1: Node.js 22 Runtime & Native TypeScript

Mission: Build robust backend services with unified JavaScript and TypeScript on Node 22.

Welcome to your backend engineering journey. As an experienced programmer, you understand control flow, memory, and concurrency. Traditionally, learning TypeScript meant configuring complex build tools like tsc and Webpack separately from JavaScript. In Node.js 22, that friction is eliminated.

Node.js 22 introduces experimental native type stripping. This allows the runtime to execute TypeScript files directly by stripping out type annotations on the fly.

Your First Unified Backend Script

Create a file named server.ts. Notice how we combine JavaScript runtime logic (ESM import and built-in modules) with static TypeScript type annotations in a single cohesive file:

import http from "node:http";

interface ServerConfig {
  port: number;
  host: string;
}

const config: ServerConfig = {
  port: 3000,
  host: "127.0.0.1",
};

const server = http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ status: "healthy", timestamp: Date.now() }));
});

server.listen(config.port, config.host, () => {
  console.log(`Server running at http://${config.host}:${config.port}`);
});

Running without a Build Step

To execute this file directly in Node.js 22 without running a separate compilation step, use the experimental strip-types flag:

node --experimental-strip-types server.ts
Key Takeaway: You no longer need dual mental models for JS runtime execution and TS build pipelines. Node 22 executes standard ESM TypeScript directly. Read more in the Node.js v22 Documentation.
