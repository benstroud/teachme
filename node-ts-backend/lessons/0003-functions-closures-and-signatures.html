Lesson 3: Functions, Closures & Signatures

Mission: Implement type-safe middleware and higher-order functions in backend routing.

Backend services rely heavily on higher-order functions and closures for authentication, logging, and error handling. In TypeScript, function signatures and overload signatures provide robust contracts without sacrificing JavaScript's expressive first-class functions.

Typed Higher-Order Middleware Pattern

Consider an Express-style or native HTTP logging middleware closure:

type HttpHandler = (req: { url: string; method: string }, res: { statusCode: number }) => void;

// Higher-order function wrapping logging behavior via closure
const withRequestLogging = (handler: HttpHandler): HttpHandler => {
  return (req, res) => {
    const start = Date.now();
    console.log(`--> Incoming [${req.method}] ${req.url}`);
    
    handler(req, res);
    
    const duration = Date.now() - start;
    console.log(`<-- Completed [${res.statusCode}] in ${duration}ms`);
  };
};

// Usage
const myHandler: HttpHandler = (req, res) => {
  res.statusCode = 200;
};

const loggedHandler = withRequestLogging(myHandler);
loggedHandler({ url: "/api/health", method: "GET" }, { statusCode: 200 });
Key Takeaway: Closures capture lexical scope while function type annotations ensure middleware contracts are rigorously enforced across complex pipelines. See TypeScript Functions Handbook.
