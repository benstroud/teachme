Gateway → Router Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The job

subgraphs --compose--> supergraph schema
clients -> gateway/router -> subgraphs
  • Clients query only the router; it plans, it does not just forward.1

2. Apollo Gateway (incumbent)

// Node library inside Apollo Server
class DS extends RemoteGraphQLDataSource {}
new ApolloGateway({ supergraphSdl, buildService })
  • A library you configure in code: data sources, context, plugins.2
  • buildService runs once per subgraph.2

3. Apollo Router (successor)

router --supergraph ./supergraph.graphql
APOLLO_GRAPH_REF="my-graph@current" router
  • Standalone binary; bundles the GraphQL and HTTP servers.3
  • Platform: query batching, caching, APQ, @defer, subscriptions.3

4. Gateway vs Router

              Gateway                 Router
runtime       Node library            Rust binary
config        code (data sources)     declarative YAML
customize     Apollo Server plugins   Rhai / coprocessors
  • Response/HTTP status and error codes can differ between them.7
  • Check for a native router option before rewriting a plugin.7

5. Supergraph composition

subgraph schemas --compose--> supergraph schema
(conflict => compose FAILS => keep last valid schema)
  • Composition validates and merges subgraphs.4
  • Both gateway and router run the composed schema.4

6. Query planning & entities

type Product @key(fields: "upc") { upc: String! ... }
Product: { __resolveReference(rep) { return byUpc(rep.upc); } }
  • @key marks a shared entity; the router joins by key.5
  • Reference resolvers must guard against N+1 (batch with loaders).5

7. Configure the router

supergraph: { listen: 0.0.0.0:4000 }
headers: { all: { request: [ { propagate: { named: authorization } } ] } }
telemetry: { metrics: { prometheus: { enabled: true } } }
  • router.yaml drives features, security, observability.6
  • Schema comes from a file, artifact, Uplink, or the Operator.6

8. Customization

Rhai script       -> in-process, Rust-embedded scripting
Coprocessor       -> external service, any language
  • Use these only when no config option covers the need.7

9. Migration checklist

1 compose supergraph   2 run router (--supergraph / artifact / Uplink)
3 context -> header propagation   4 plugins -> config or Rhai/coprocessor
5 re-check error codes   6 canary via proxy, then cut over
  • context maps to header propagation; plugins map to config/customizations.7
  • Run gateway and router together and shift traffic gradually.7

10. Operate

telemetry  -> OpenTelemetry (traces + metrics)
traffic sh:  timeouts, rate limiting
perf:        batching, APQ, Redis response cache
  • Watch traces and error codes to gate the cutover.3
