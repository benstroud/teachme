The Apollo Gateway

The incumbent: a Node.js library inside Apollo Server, configured in code.

The mental model in one sentence

Apollo Gateway is the Node.js gateway: the @apollo/gateway library run inside Apollo Server, which you configure with code — data sources, context, and plugins.1

What it is, precisely

  • A library (@apollo/gateway) you instantiate with your supergraph schema.
  • Wired into Apollo Server, so your HTTP server and plugins are yours to configure.
  • Configurable in code: subclass or extend data sources to customize subgraph requests.

Customizing subgraph requests in code

class MyDataSource extends RemoteGraphQLDataSource {
  willSendRequest({ request }) {
    request.http.headers.set("x-user-id", getUserId());
  }
}

// buildService runs once per subgraph
const gateway = new ApolloGateway({
  supergraphSdl,
  buildService: ({ url }) => new MyDataSource({ url }),
});

This is the gateway's strength and its burden: total control in TypeScript, at the cost of owning a Node server and its scaling.1

Key idea Remember the shape of gateway configuration — imperative code. The migration will ask you to translate each piece of it into the router's declarative world.2
