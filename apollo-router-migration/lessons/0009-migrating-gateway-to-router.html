Migrating Gateway to Router

Translate configuration and customizations, then roll out gradually behind a proxy.

The mental model in one sentence

The migration is a translation: every Apollo Server option and gateway behavior becomes either a router config option or a router customization — then you roll it out gradually behind a proxy.1

Map the two big options

Gateway (Apollo Server)Router equivalent
context (auth info)Header propagation / router config1
pluginsRouter config option first; else Rhai/coprocessor1

A migration checklist

  1. Compose the supergraph schema you already have.2
  2. Run the router against it (--supergraph locally, artifact/Uplink in prod).3
  3. Translate context into header propagation.
  4. Translate each plugin: native option, or Rhai/coprocessor.1
  5. Re-check response/error behavior for HTTP status and GraphQL error codes.1

Roll out gradually

You can run @apollo/gateway and the router side by side and conditionally proxy traffic to the router for a gradual release (an Apollo Solutions strategy; experimental).1

Key idea Do not big-bang it. A proxy in front lets you shift a percentage of traffic to the router and cut back instantly if error codes or behavior diverge.1
