Gateway vs Router

Same job, two models: a Node library you code vs a Rust binary you configure.

The mental model in one sentence

Gateway and Router do the same federated job two very different ways: gateway = a Node library you code, router = a Rust binary you configure.1

The comparison that matters

AxisApollo GatewayApollo Router
RuntimeNode.js library in Apollo Server2Standalone Rust binary3
ConfigurationImperative code (data sources, plugins)Declarative YAML3
CustomizationApollo Server pluginsRhai scripts & coprocessors1
ServerYour HTTP server + Apollo ServerGraphQL + HTTP bundled1

Two gotchas the migration guide calls out

  • Reply/response behavior can differ: because the router bundles its server, HTTP status codes and GraphQL error extension codes may change.1
  • Plugins do not carry over: before rewriting a plugin, check whether the router already has the feature (e.g. header propagation, OpenTelemetry).1
Key idea The migration is not a rename — it is a change of programming model. Everything you expressed in code must be re-expressed as configuration or a router customization.1
