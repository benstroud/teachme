One Graph, Many Services

Federation fundamentals: subgraphs, the supergraph, and the gateway/router role.

The mental model in one sentence

Apollo Federation lets many GraphQL services (subgraphs) compose into one supergraph; clients talk to a single endpoint, and the gateway/router plans how to fetch each query from the right subgraphs.1

Subgraphs and the supergraph

subgraph: users    subgraph: products    subgraph: reviews
        \___________  compose  ___________/
                     |
                     v
              supergraph schema
                     |
        clients  -->  gateway / router  -->  subgraphs

Clients should only query the router, and only the router should query the subgraphs. It does not just forward requests — it intelligently calls the APIs it needs to satisfy them.1

Entities are the glue

A type that several subgraphs contribute fields to is an entity, marked with @key. The router uses those keys to stitch a single result object together across subgraphs.2

Key idea Everything in this course sits on one job: given a query and a supergraph, decide which subgraphs to call and how to assemble the answer. Gateway and Router are two implementations of that job.1
