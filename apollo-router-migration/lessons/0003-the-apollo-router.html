The Apollo Router

The successor: a standalone execution engine, configured in YAML.

The mental model in one sentence

The Apollo Router is a standalone binary — "the execution engine for graph-based API orchestration" — that sits in front of your APIs, plans an efficient way to fetch each query, and bundles the GraphQL and HTTP servers together.1

What you get

AspectRouter
FormA single binary you run next to your APIs1
ConfigDeclarative YAML (router.yaml)2
ServerGraphQL + HTTP server bundled in3
Built-in featuresQuery batching, caching, APQ, @defer, subscriptions1

How the router gets its supergraph schema

# local schema file (dev / CI-managed)
router --supergraph ./supergraph.graphql

# versioned artifact (immutable deploys)
router --graph-artifact-reference="artifact...@sha256:..."

# Apollo-managed, auto-updating
APOLLO_GRAPH_REF="my-graph@current" router

Local files can use hot reload for zero-downtime schema updates; Uplink pushes updates without a redeploy.2

Key idea The router trades the gateway's "write TypeScript for everything" model for "run a binary and declare configuration". Most of the migration is translating imperative gateway code into that declarative form.3
