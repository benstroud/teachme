Configuring the Router

One declarative file for features, security, telemetry, and traffic shaping.

The mental model in one sentence

Almost everything the router does is configured declaratively in one file — router.yaml — from header propagation to CORS, telemetry, and traffic shaping.1

A router.yaml sketch

supergraph:
  listen: 0.0.0.0:4000

headers:
  all:
    request:
      - propagate:
          named: authorization

cors:
  origins: ["https://app.example.com"]

traffic_shaping:
  router:
    timeout: 30s

telemetry:
  metrics:
    prometheus:
      enabled: true

Where the config lives vs the schema

  • Config = router.yaml (features, security, observability).1
  • Schema = a separate supergraph source (file, artifact, Uplink, Operator).2
  • Local schema files can hot-reload for zero-downtime updates.2
Key idea In the gateway, this was scattered across Apollo Server options and plugins. In the router it is one reviewable YAML file — which is exactly why the migration asks you to translate rather than port.2
