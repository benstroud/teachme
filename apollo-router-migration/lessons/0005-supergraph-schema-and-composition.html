The Supergraph Schema & Composition

The compiled artifact both runtimes run — and why a bad compose is safe.

The mental model in one sentence

Composition validates and merges your subgraph schemas into one supergraph schema — and both the gateway and the router consume that same artifact.1

Composition is a compiler

users.graphql + products.graphql + reviews.graphql
        \____ compose ____/
               |
               v
        supergraph-schema.graphql   <-- what the router runs

If a subgraph change conflicts with another, composition fails and no new supergraph is produced — so the router keeps running the last valid schema. It is like a compiler error that stops invalid code from shipping.1

Who consumes the supergraph

RuntimeHow it gets the supergraph
Apollo GatewayPassed as supergraphSdl in code2
Apollo RouterLocal file, graph artifact, Uplink, or the Operator3
Key idea The supergraph schema is the hand-off point in the migration: if you already compose one for the gateway, the router can run the same schema. The work is in how each runtime receives and reloads it.3
