Mission context

The white rectangle becomes a bird rider. This lesson covers the full texture pipeline — create or load, draw scaled to any size, and flip horizontally using the player_facing variable that has been waiting since Lesson 08.

Image vs Texture2D

Raylib distinguishes two types that represent pixel data in different places:

TypeWhere it livesUse for
Image struct CPU memory (RAM) Loading, editing pixels, generating programmatically
Texture2D struct GPU memory (VRAM) Drawing — only GPU-resident data can be rendered

The typical pipeline: create or load an Image on the CPU → upload it to the GPU with LoadTextureFromImage → the Image is no longer needed, free it with UnloadImage → draw the Texture2D every frame → free it with UnloadTexture when done.

If you already have a PNG on disk, skip straight to LoadTexture("path/to/file.png") which does the whole pipeline in one call.

Building a placeholder sprite in code

Until you have pixel art, raylib's image-drawing functions produce a recognizable stand-in. This is worth knowing regardless — procedural textures are useful for debug shapes, UI elements, and generated content.

odinmake_rider_sprite :: proc() -> rl.Texture2D {
    img := rl.GenImageColor(40, 60, rl.BLANK)   // 40×60, transparent background
    rl.ImageDrawRectangle(&img,  6, 28, 28, 22, rl.ORANGE)     // bird body
    rl.ImageDrawRectangle(&img, 12, 18, 16, 14, rl.ORANGE)     // bird neck
    rl.ImageDrawRectangle(&img, 10,  8, 20, 14, rl.DARKBROWN)  // rider body
    rl.ImageDrawRectangle(&img, 14,  2, 12, 10, rl.BROWN)      // rider head
    rl.ImageDrawRectangle(&img, 30, 13, 10,  3, rl.LIGHTGRAY)  // lance (right-facing)
    t := rl.LoadTextureFromImage(img)
    rl.UnloadImage(img)    // CPU copy no longer needed once on GPU
    return t
}

This procedure returns a Texture2D — the GPU-side handle you will draw every frame. The CPU-side Image is freed immediately after upload. Call the procedure once, before the game loop.

Swapping in real art Replace the entire make_rider_sprite procedure with rl.LoadTexture("assets/rider.png") when you have actual pixel art. The rest of the draw code stays identical. Pixel art for a 40×60 Joust rider is small enough to draw in a free tool like Aseprite or Libresprite.

DrawTexturePro — all six parameters

DrawTexturePro is the most powerful draw call in raylib. It handles scaling, positioning, rotation, and flipping in one call:

odinrl.DrawTexturePro(texture, source, dest, origin, rotation, tint)
ParameterTypeWhat it doesWhat we pass
texture Texture2D The GPU texture to sample from rider
source Rectangle Which region of the texture to use — and how to orient it computed from player_facing
dest Rectangle Where on screen, and the drawn size (can differ from source size) {player_x, player_y, PLAYER_W, PLAYER_H}
origin Vector2 Pivot point for rotation, relative to the dest rectangle {0, 0} — top-left, no rotation used
rotation f32 Clockwise rotation in degrees 0
tint Color Multiplied into each pixel (WHITE = no tint) rl.WHITE

The source and dest rectangles being independent is what makes this function so flexible: the source selects a region of the texture at its original resolution; the dest places it on screen at whatever size you want, scaling automatically.

Horizontal flip via negative source width

Raylib has no separate "flip" function. Instead, it samples the source rectangle from right to left when source.width is negative. To make this work correctly, source.x must also shift to the right edge:

Normal (facing right): source = { 0, 0, +40, 60} samples x=0 → x=40 (left to right) Flipped (facing left): source = {40, 0, -40, 60} samples x=40 → x=0 (right to left = mirror)

player_facing is already 1 or -1, so both values fall out of simple arithmetic:

odin// source.x: 0 when facing right, texture width when facing left
src_x := f32(0) if player_facing > 0 else f32(rider.width)

// source.width: positive (normal) or negative (flipped)
src_w := f32(rider.width) * player_facing

src := rl.Rectangle{src_x, 0, src_w, f32(rider.height)}
dst := rl.Rectangle{player_x, player_y, PLAYER_W, PLAYER_H}
rl.DrawTexturePro(rider, src, dst, {0, 0}, 0, rl.WHITE)

rider.width and rider.height are c.int in the binding, so the explicit f32() casts are required. Odin will not silently convert them.

Freeing GPU resources with defer

Textures live on the GPU. Unlike stack variables, they are not automatically freed when the function exits — you must call UnloadTexture explicitly. defer is the right pattern:

odinrider := make_rider_sprite()
defer rl.UnloadTexture(rider)    // runs when main() exits
// ...
rl.InitWindow(...)
defer rl.CloseWindow()          // also deferred — cleanup in LIFO order
Load textures after InitWindow make_rider_sprite() uploads data to the GPU — a graphics context must exist first. Always call InitWindow before loading any texture. The code below puts this in the right order.

Complete main.odin

odinpackage main

import rl "vendor:raylib"

SCREEN_W   :: 800
SCREEN_H   :: 600
GRAVITY    :: f32(800)
FLAP_FORCE :: f32(420)
MAX_FALL   :: f32(600)
MOVE_SPEED :: f32(200)
PLAYER_W   :: f32(40)
PLAYER_H   :: f32(60)

PLATFORMS :: [?]rl.Rectangle{
    {  0, 554, 280, 46},
    {520, 554, 280, 46},
    { 48, 426, 176, 18},
    {576, 426, 176, 18},
    {288, 316, 224, 18},
    {336, 186, 128, 18},
}

LAVA :: rl.Rectangle{280, 574, 240, 26}

make_rider_sprite :: proc() -> rl.Texture2D {
    img := rl.GenImageColor(40, 60, rl.BLANK)
    rl.ImageDrawRectangle(&img,  6, 28, 28, 22, rl.ORANGE)
    rl.ImageDrawRectangle(&img, 12, 18, 16, 14, rl.ORANGE)
    rl.ImageDrawRectangle(&img, 10,  8, 20, 14, rl.DARKBROWN)
    rl.ImageDrawRectangle(&img, 14,  2, 12, 10, rl.BROWN)
    rl.ImageDrawRectangle(&img, 30, 13, 10,  3, rl.LIGHTGRAY)
    t := rl.LoadTextureFromImage(img)
    rl.UnloadImage(img)
    return t
}

main :: proc() {
    rl.InitWindow(SCREEN_W, SCREEN_H, "Joust")
    defer rl.CloseWindow()
    rl.SetTargetFPS(60)

    rider := make_rider_sprite()         // after InitWindow!
    defer rl.UnloadTexture(rider)

    player_x:      f32 = 380
    player_y:      f32 = 256
    player_vx:     f32 = 0
    player_vy:     f32 = 0
    player_facing: f32 = 1

    for !rl.WindowShouldClose() {
        dt := rl.GetFrameTime()

        if rl.IsKeyDown(.Left) {
            player_vx     = -MOVE_SPEED
            player_facing = -1
        } else if rl.IsKeyDown(.Right) {
            player_vx     = MOVE_SPEED
            player_facing = 1
        } else {
            player_vx = 0
        }

        player_vy += GRAVITY * dt
        player_vy  = min(player_vy, MAX_FALL)
        if rl.IsKeyPressed(.Space) {
            player_vy -= FLAP_FORCE
        }

        player_x += player_vx * dt
        player_y += player_vy * dt

        player_rect := rl.Rectangle{player_x, player_y, PLAYER_W, PLAYER_H}
        for plat in PLATFORMS {
            if rl.CheckCollisionRecs(player_rect, plat) && player_vy > 0 {
                player_y  = plat.y - PLAYER_H
                player_vy = 0
            }
        }

        if player_x > f32(SCREEN_W) { player_x = -PLAYER_W          }
        if player_x < -PLAYER_W    { player_x = f32(SCREEN_W)        }
        if player_y > f32(SCREEN_H) { player_y = -PLAYER_H           }
        if player_y < -PLAYER_H    { player_y = f32(SCREEN_H)        }

        rl.BeginDrawing()

            rl.ClearBackground(rl.BLACK)

            rl.DrawRectangleGradientV(
                i32(LAVA.x), i32(LAVA.y),
                i32(LAVA.width), i32(LAVA.height),
                rl.RED, rl.ORANGE,
            )

            for plat in PLATFORMS {
                rl.DrawRectangleRec(plat, rl.DARKGRAY)
            }

            // draw rider sprite, flipped when facing left
            src_x := f32(0) if player_facing > 0 else f32(rider.width)
            src_w := f32(rider.width) * player_facing
            src   := rl.Rectangle{src_x, 0, src_w, f32(rider.height)}
            dst   := rl.Rectangle{player_x, player_y, PLAYER_W, PLAYER_H}
            rl.DrawTexturePro(rider, src, dst, {0, 0}, 0, rl.WHITE)

            rl.DrawText("JOUST", 10, 10, 20, rl.YELLOW)

        rl.EndDrawing()
    }
}

Run it, move left and right — the lance should point in the direction you are facing. The sprite is blocky but directional. That is the whole mechanism. Real pixel art drops in without any other code change.

Check your understanding

1. After the game loop ends, to free a GPU texture, call:

UnloadTexture — raylib consistently uses Unload* for cleanup: UnloadTexture, UnloadImage, UnloadSound, UnloadModel. The Delete* and Remove* patterns are from other APIs (OpenGL, standard library). If you ever forget a name, search for Unload in the package docs.

2. In DrawTexturePro(..., origin, rotation, tint), the origin for a top-left anchor with no rotation is:

{0, 0} — origin is the pivot point for rotation, expressed in pixels relative to the dest rectangle's top-left corner. At {0, 0}, rotation pivots around the top-left. Since we pass rotation = 0, origin has no visible effect here. It matters when you add rotation — a bird that spins around its center would use {PLAYER_W/2, PLAYER_H/2}.

3. The source rectangle width for a horizontally flipped sprite is computed as:

tex_w * facing — facing is ±1, so multiplication produces ±tex_w. Negative width triggers raylib's right-to-left sampling. Subtraction (tex_w - 1) or addition (tex_w + 1) would give a slightly wrong size with no flip. Division by ±1 would technically work but is non-idiomatic; division by 0 (if facing were zero) would also crash, making multiplication the safer and clearer choice.

4. After LoadTextureFromImage(img) uploads to the GPU, the source img should be:

Unloaded immediately — once the texture is on the GPU, the CPU copy serves no drawing purpose. Keeping it wastes RAM proportional to the image size. UnloadImage is the correct call (not FreeImage). The returned Texture2D is what you keep. Images are also not directly drawable — only textures are rendered by the GPU.
