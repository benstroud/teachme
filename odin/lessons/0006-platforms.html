Mission context

Joust is played on platforms. Before anything moves, the arena must exist. This lesson draws all six platforms, the lava gap, and positions the player rectangle on a ledge. After this, the stage is set — Lesson 07 makes it fall.

rl.Rectangle — the workhorse type

Nearly everything in raylib that describes a 2D region uses this struct:

odin// from vendor:raylib — all fields are f32
Rectangle :: struct {
    x:      f32,
    y:      f32,
    width:  f32,
    height: f32,
}

Because all fields are f32, you can pass your game-world coordinates directly. No i32 cast. The four exact field names — x, y, width, height — matter: you will use them by name when reading and writing collision logic starting in Lesson 09.

FunctionWhen to use
DrawRectangleRec(rec, color) Draw a filled rectangle from an rl.Rectangle. Takes f32 coords — the standard choice for game objects.
DrawRectangle(x, y, w, h, color) Takes separate i32 arguments. From Lesson 05. Only reach for this when you don't already have a Rectangle.
DrawRectangleLinesEx(rec, thick, color) Outline only — no fill. Useful for debug overlays (drawing hitboxes).
DrawRectangleGradientV(x, y, w, h, c1, c2) Filled rectangle with a vertical gradient from c1 (top) to c2 (bottom). Uses i32 coords. Good for lava.

Platform data — fixed arrays and [?]

Platforms never move. They are a perfect fit for a compile-time constant array. Odin's [?] syntax infers the length from the literal so you do not need to count manually:

odinPLATFORMS :: [?]rl.Rectangle{
    // ground sections — thick, span the sides
    {  0, 554, 280, 46},   // left ground
    {520, 554, 280, 46},   // right ground
    // lower platforms
    { 48, 426, 176, 18},   // lower left
    {576, 426, 176, 18},   // lower right
    // upper platforms
    {288, 316, 224, 18},   // centre middle
    {336, 186, 128, 18},   // top centre
}

LAVA :: rl.Rectangle{280, 574, 240, 26}  // the gap between the ground sections

The initialiser syntax {x, y, width, height} is positional — field names in order. You could also write {x=0, y=554, width=280, height=46} for clarity, but positional is standard for data tables like this.

Screen coordinates Y increases downward — (0,0) is top-left. A platform near the bottom of a 600-pixel screen has a large Y value (554). This is standard 2D screen space and what raylib uses throughout.

Draw order — back to front

Raylib draws calls in the exact order you make them. Each call paints over everything drawn before it. The rule: draw the background first, then things on top of it, then things on top of those.

For the Joust arena the order is:

odinrl.BeginDrawing()

    rl.ClearBackground(rl.BLACK)         // 1. erase everything

    rl.DrawRectangleGradientV(            // 2. lava — drawn first, behind platforms
        i32(LAVA.x), i32(LAVA.y),
        i32(LAVA.width), i32(LAVA.height),
        rl.RED, rl.ORANGE,
    )

    for plat in PLATFORMS {              // 3. platforms — on top of lava
        rl.DrawRectangleRec(plat, rl.DARKGRAY)
    }

    rl.DrawRectangle(                    // 4. player — on top of everything
        i32(player_x), i32(player_y), 40, 60, rl.WHITE,
    )

    rl.DrawText("JOUST", 10, 10, 20, rl.YELLOW)  // 5. HUD — always on top

rl.EndDrawing()

Notice for plat in PLATFORMS — this range loop gives you a copy of each rectangle, which is all you need for drawing. (To mutate elements you would write for &plat in platforms with a mutable slice, but that is not needed here.)

The complete main.odin

Replace your main.odin from Lesson 05 with this. The player is positioned on the centre-middle platform — player_y = 316 - 60 = 256, sitting on its top edge:

odinpackage main

import rl "vendor:raylib"

SCREEN_W :: 800
SCREEN_H :: 600

PLATFORMS :: [?]rl.Rectangle{
    {  0, 554, 280, 46},
    {520, 554, 280, 46},
    { 48, 426, 176, 18},
    {576, 426, 176, 18},
    {288, 316, 224, 18},
    {336, 186, 128, 18},
}

LAVA :: rl.Rectangle{280, 574, 240, 26}

main :: proc() {
    rl.InitWindow(SCREEN_W, SCREEN_H, "Joust")
    defer rl.CloseWindow()
    rl.SetTargetFPS(60)

    player_x: f32 = 380
    player_y: f32 = 256   // resting on centre platform (316 - 60)

    for !rl.WindowShouldClose() {
        rl.BeginDrawing()

            rl.ClearBackground(rl.BLACK)

            rl.DrawRectangleGradientV(
                i32(LAVA.x), i32(LAVA.y),
                i32(LAVA.width), i32(LAVA.height),
                rl.RED, rl.ORANGE,
            )

            for plat in PLATFORMS {
                rl.DrawRectangleRec(plat, rl.DARKGRAY)
            }

            rl.DrawRectangle(
                i32(player_x), i32(player_y), 40, 60, rl.WHITE,
            )

            rl.DrawText("JOUST", 10, 10, 20, rl.YELLOW)

        rl.EndDrawing()
    }
}

Check your understanding

1. The four field types in rl.Rectangle (x, y, width, height) are all:

All f32 — which is why DrawRectangleRec requires no casting. You can pass your f32 game positions directly. This is the key advantage over DrawRectangle, which takes separate i32 arguments.

2. In raylib, each draw call paints:

Each call paints above (on top of) everything drawn before it. This is why ClearBackground goes first, then background elements (lava), then midground (platforms), then foreground (player), then HUD. Reverse the order and you erase things you just drew.

3. In a for plat in PLATFORMS range loop, plat is a:

A copy — Odin's range loop gives you a value copy of each element, which is fine for read-only use like drawing. If you needed to mutate elements (e.g. animate a platform), you would write for &plat in platforms on a mutable slice to get a pointer instead.

4. Which function draws a filled rectangle directly from an rl.Rectangle (no i32 cast)?

DrawRectangleRec — takes an rl.Rectangle directly, all f32. DrawRectangle takes four separate i32 args. DrawRectangleV takes two Vector2 values (position + size). DrawRectanglePro adds rotation and a custom origin point — useful later for spinning enemies.
