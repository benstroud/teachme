Lesson 09 · Joust — Physics

Platform Collision

AABB overlap detection, top-only landing, and snap resolution

← Lesson 08: Movement & Wrap

Mission context

After this lesson the arena is structurally complete: the player lands on platforms, can fly up through them from below, and falls into the lava gap. Everything from this point — enemies, combat, eggs — layers on top of a working physics foundation.

AABB: axis-aligned bounding box

Every game object is wrapped in a rectangle aligned to the X/Y axes (not rotated). Two AABB rectangles overlap when they overlap on both axes simultaneously:

┌──────────────┐ │ rect A │ │ ┌──────┼────────────┐ └───────┼──────┘ │ │ OVERLAP rect B │ └────────────────────┘ overlap on X? a.x < b.x+b.w AND a.x+a.w > b.x ✓ overlap on Y? a.y < b.y+b.h AND a.y+a.h > b.y ✓ collision? both axes overlap ✓

You do not need to write this check yourself. Raylib provides rl.CheckCollisionRecs(rec1, rec2: Rectangle) -> bool which does exactly this — returns true if the two rectangles overlap.

Building the player rectangle

The player's state is stored as loose variables — player_x, player_y for position. To use CheckCollisionRecs, build a Rectangle from them each frame:

odinplayer_rect := rl.Rectangle{player_x, player_y, PLAYER_W, PLAYER_H}

This is a fresh value each frame — it costs nothing to construct. No heap allocation, no pointer, just four f32 fields on the stack. You will use the same pattern for enemies in Lesson 11.

Top-only landing

Joust platforms are one-way: you can fly up through them from below, but you land on them when falling. Full AABB resolution (blocking from all four sides) is both harder to implement and wrong for this game.

The solution is a single extra condition on the velocity:

odinfor plat in PLATFORMS {
    if rl.CheckCollisionRecs(player_rect, plat) && player_vy > 0 {
        player_y  = plat.y - PLAYER_H   // snap bottom to platform top
        player_vy = 0                   // stop falling
    }
}

player_vy > 0 means the player is moving downward (positive Y is down). When the player flies upward into a platform from below, vy is negative — the condition is false and the collision is ignored. The bird passes through. Exactly what Joust does.

The snap explained

before (overlap detected)
┌──────┐ player_y │player│ └──────┘ player_y + PLAYER_H ───────── plat.y ← inside platform ████████ platform
after (snapped)
┌──────┐ player_y = plat.y − PLAYER_H │player│ └──────┘ player_y + PLAYER_H = plat.y ✓ ───────── plat.y ████████ platform

Snapping to plat.y - PLAYER_H places the player's bottom edge exactly on the platform's top edge — no overlap, no gap. player_vy = 0 stops the fall so gravity does not immediately push the player back inside next frame.

Where collision fits in the update order

Order matters. Collision must happen after position is integrated (so the new position can be tested) and before screen wrap (so a landing near the bottom edge does not trigger a vertical wrap):

1Horizontal input → set player_vx
2Vertical physics: gravity, terminal velocity cap, flap
3Integrate: player_x += vx * dt, player_y += vy * dt
4Platform collision: detect overlap, snap, zero velocity
5Screen wrap: all four edges
6Draw
Tunneling is not a concern here Tunneling is when an object moves so fast in one frame that it skips past a thin surface entirely. At MAX_FALL = 600 px/s and 60 fps, the maximum fall per frame is 10 px. The narrowest platform is 18 px tall — so the player can never skip through. If you later raise MAX_FALL significantly, revisit this.

Complete main.odin

odinpackage main

import rl "vendor:raylib"

SCREEN_W   :: 800
SCREEN_H   :: 600
GRAVITY    :: f32(800)
FLAP_FORCE :: f32(420)
MAX_FALL   :: f32(600)
MOVE_SPEED :: f32(200)
PLAYER_W   :: f32(40)
PLAYER_H   :: f32(60)

PLATFORMS :: [?]rl.Rectangle{
    {  0, 554, 280, 46},
    {520, 554, 280, 46},
    { 48, 426, 176, 18},
    {576, 426, 176, 18},
    {288, 316, 224, 18},
    {336, 186, 128, 18},
}

LAVA :: rl.Rectangle{280, 574, 240, 26}

main :: proc() {
    rl.InitWindow(SCREEN_W, SCREEN_H, "Joust")
    defer rl.CloseWindow()
    rl.SetTargetFPS(60)

    player_x:      f32 = 380
    player_y:      f32 = 256
    player_vx:     f32 = 0
    player_vy:     f32 = 0
    player_facing: f32 = 1

    for !rl.WindowShouldClose() {
        dt := rl.GetFrameTime()

        // horizontal input
        if rl.IsKeyDown(.Left) {
            player_vx     = -MOVE_SPEED
            player_facing = -1
        } else if rl.IsKeyDown(.Right) {
            player_vx     = MOVE_SPEED
            player_facing = 1
        } else {
            player_vx = 0
        }

        // vertical physics
        player_vy += GRAVITY * dt
        player_vy  = min(player_vy, MAX_FALL)
        if rl.IsKeyPressed(.Space) {
            player_vy -= FLAP_FORCE
        }

        // integrate
        player_x += player_vx * dt
        player_y += player_vy * dt

        // platform collision (top-only)
        player_rect := rl.Rectangle{player_x, player_y, PLAYER_W, PLAYER_H}
        for plat in PLATFORMS {
            if rl.CheckCollisionRecs(player_rect, plat) && player_vy > 0 {
                player_y  = plat.y - PLAYER_H
                player_vy = 0
            }
        }

        // screen wrap
        if player_x > f32(SCREEN_W) { player_x = -PLAYER_W          }
        if player_x < -PLAYER_W    { player_x = f32(SCREEN_W)        }
        if player_y > f32(SCREEN_H) { player_y = -PLAYER_H           }
        if player_y < -PLAYER_H    { player_y = f32(SCREEN_H)        }

        // draw
        rl.BeginDrawing()

            rl.ClearBackground(rl.BLACK)

            rl.DrawRectangleGradientV(
                i32(LAVA.x), i32(LAVA.y),
                i32(LAVA.width), i32(LAVA.height),
                rl.RED, rl.ORANGE,
            )

            for plat in PLATFORMS {
                rl.DrawRectangleRec(plat, rl.DARKGRAY)
            }

            rl.DrawRectangle(
                i32(player_x), i32(player_y),
                i32(PLAYER_W), i32(PLAYER_H), rl.WHITE,
            )

            rl.DrawText("JOUST", 10, 10, 20, rl.YELLOW)
            rl.DrawText("SPACE flap  \xE2\x86\x90\xE2\x86\x92 move", 10, 34, 14, rl.GRAY)

        rl.EndDrawing()
    }
}

Run it. Stand on every platform. Fly up into them from below — you pass through. Walk off an edge — you fall. Walk into the lava gap — you fall through and wrap to the top. The arena now behaves correctly.

Check your understanding

1. The raylib function that checks whether two rectangles overlap is:

CheckCollisionRecs — the others are not raylib functions. This is exactly the kind of question where fluency matters: all four names convey the same concept, but only one is in the API. When reading docs, look for the exact name; when typing from memory, look it up rather than guess.

2. The guard player_vy > 0 enables top-only landing because it means the player is:

Player is falling down — positive vy means moving toward larger Y, which is downward in screen space. When the player rises (vy < 0), the guard is false and the collision is skipped — the player flies through the platform. This is the entire mechanism for one-way platforms in under one line of code.

3. To snap the player's bottom edge flush with the platform's top, set player_y to:

plat.y - PLAYER_H — player_y is the player's top edge. The player's bottom edge is player_y + PLAYER_H. Setting that equal to plat.y gives player_y = plat.y - PLAYER_H. Adding PLAYER_H instead would push the player below the platform. Using PLAYER_W (width) is the wrong dimension entirely.

4. After snapping position, you must also:

player_vy = 0 — without this, gravity keeps adding to vy every frame. On the next frame the player would have a positive vy again, immediately re-trigger the collision, and jitter in place. Zeroing vy on landing is what makes the player stay put. Horizontal velocity (vx) is controlled by input and should not be cleared by landing.
