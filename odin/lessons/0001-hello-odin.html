Lesson 01 · Odin Foundations

Hello, Odin

Packages, imports, and the :: operator — the anatomy of a first program

Mission context

Before you write a single raylib call, you need to read Odin fluently. This lesson establishes the baseline: how an Odin source file is structured, what the :: operator means, and how to get a program compiling. Every lesson that follows builds on exactly this.

Your first Odin program

Create a new directory, save the following as main.odin, and run odin run . from inside it.

odinpackage main

import "core:fmt"

main :: proc() {
    fmt.println("Hello, Odin!")
}
LineWhat it means
package main Every .odin file in a directory must share the same package name. The name main marks this as an executable package — not a library.
import "core:fmt" Imports the fmt package from the core collection — Odin's standard library. The colon separates the collection from the package name.
main :: proc() {…} Declares the entry-point procedure. The :: is Odin's constant declaration operator — more on this in a moment.
fmt.println(…) Calls println from the imported fmt package. Appends a newline automatically. The package name is always the qualifier.

The :: operator — constant declarations

This is the most important syntax shift if you are coming from C, Go, or TypeScript. In Odin, :: means "bind this name to a compile-time constant value." Procedures, named types, and numeric constants all use exactly the same syntax:

odinPI          :: 3.14159                   // numeric constant
MAX_ENEMIES :: 128                       // integer constant
main        :: proc() { }                // procedure (a constant procedure value)
Vec2        :: struct { x, y: f32 }      // named type

The counterpart is :=, which declares a mutable variable at runtime with type inference:

odinscore  := 0          // mutable int, initialised to 0
speed  := 2.5        // mutable f64
name   := "player"   // mutable string

Rule of thumb: if it never changes after the program is compiled, use ::. If it changes while the program runs, use :=.

The core: collection — and what comes next

Odin organises its packages into collections. The core: collection is the standard library. You will use it constantly. The vendor: collection holds third-party bindings — including raylib, which is where graphics lives.

odinimport "core:fmt"       // formatted I/O (today)
import "core:os"        // operating system interface
import "core:math"      // math functions and constants
import "vendor:raylib"  // ← graphics, input, audio — coming soon

You do not install packages separately. Both collections ship with the Odin compiler; everything above works out of the box once Odin is installed.

Running your program

Odin compiles a directory (package), not a single file. The standard workflow:

shell">mkdir hello_odin
cd hello_odin
# create main.odin — paste the hello world above
odin run .       # compile the current directory and run it

You should see Hello, Odin! printed. Keep this directory — you'll use it to try things out as lessons progress.

Two other commands worth knowing now:

CommandWhat it does
odin run . Compile the current package and immediately run it. Use during development.
odin build . Compile to a binary without running it. Use when you want the executable.

Check your understanding

1. Which symbol declares a constant (including procedures) in Odin?

:: is Odin's constant declaration operator. It binds a name to a compile-time value — a procedure, a named type, or a literal constant. The := operator declares a mutable variable whose value can change at runtime.

2. To import Odin's standard formatting package, you write:

The standard library collection is called core. The import path format is "collection:package", so "core:fmt" means the fmt package from the core collection. There is no odin:, base:, or main: collection.

3. An Odin program's entry-point procedure is named:

Like C and Go, the entry point is a procedure named main inside the main package. Odin also supports _start for bare-metal targets, but you will not need that for games.

4. To compile and immediately run a project in the current directory:

odin run . compiles the package in the current directory and immediately executes the result. Use odin build . when you want the binary without running it — useful once you are producing executables to distribute.
