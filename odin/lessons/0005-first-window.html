Mission context

This is where Joust stops being abstract. By the end of this lesson there is a black window open, a "JOUST" title in the corner, and a white rectangle where the player will eventually live. Gravity and input come in the next two lessons — but first, something on screen.

Step 1 — Install Odin

Raylib ships inside Odin's vendor/ directory, so there is nothing extra to install for graphics. You only need the compiler.

macOS (build from source — the official path):

1

Install Xcode command-line tools if you haven't already:

shellxcode-select --install
2

Install LLVM via Homebrew (versions 17–21 all work):

shellbrew install llvm
3

Clone the Odin repository and build it:

shellgit clone https://github.com/odin-lang/Odin
cd Odin
make release-native
4

Add the Odin/ directory to your shell's PATH — add this to ~/.zshrc:

shellexport PATH="/path/to/Odin:$PATH"
5

Verify the install:

shellodin version
# → odin version dev-2025-xx:...
macOS quarantine If macOS refuses to run the odin binary with "cannot be verified", clear the quarantine flag: xattr -d com.apple.quarantine /path/to/Odin/odin

Full instructions and troubleshooting: odin-lang.org/docs/getting_started/

Step 2 — Create the project

shellmkdir joust
cd joust
# create main.odin — paste the program below

Save this as joust/main.odin:

odinpackage main

import rl "vendor:raylib"

SCREEN_W :: 800
SCREEN_H :: 600

main :: proc() {
    rl.InitWindow(SCREEN_W, SCREEN_H, "Joust")
    defer rl.CloseWindow()

    rl.SetTargetFPS(60)

    player_x: f32 = 380
    player_y: f32 = 270

    for !rl.WindowShouldClose() {
        rl.BeginDrawing()
            rl.ClearBackground(rl.BLACK)
            rl.DrawText("JOUST", 10, 10, 30, rl.YELLOW)
            rl.DrawRectangle(i32(player_x), i32(player_y), 40, 60, rl.WHITE)
        rl.EndDrawing()
    }
}

Run it:

shellodin run .

You should see this:

800 × 600
Joust
JOUST

A black window, a gold title, and a white rectangle near the centre. That rectangle is the player — currently frozen, soon to fall.

Anatomy of the frame loop

CallWhat it does
InitWindow(w, h, title) Opens the OS window at the given size. Must be called before any other raylib call. Title is a cstring — string literals are auto-coerced.
defer CloseWindow() Paired teardown. Guaranteed to run when main returns — even if the program errors during startup.
SetTargetFPS(60) Tells raylib to sleep at the end of each frame so you hit 60 fps. Remove this if you want uncapped.
WindowShouldClose() Returns true when the user clicks ✕ or presses Escape. This is the loop's exit condition.
BeginDrawing() / EndDrawing() All drawing calls must live between these two. EndDrawing flips the back buffer to the screen and waits out any remaining frame time.
ClearBackground(color) Paints every pixel to color. Call this first inside Begin/End or previous frames bleed through.
DrawText(text, x, y, size, color) Renders text using the built-in font. Size is in pixels. Coordinates are i32.
DrawRectangle(x, y, w, h, color) Draws a filled rectangle. All coordinates and dimensions are i32 — not f32. You must cast your float positions.

The i32 cast for drawing

Your game positions will be f32 (smooth sub-pixel movement requires it). But raylib's integer-coordinate drawing calls expect i32. You will cast on every draw call — get used to it:

odinplayer_x: f32 = 380.5   // stored as f32 for physics

rl.DrawRectangle(i32(player_x), i32(player_y), 40, 60, rl.WHITE)
//               ^^^^^^^^^^^^  cast truncates — 380.5 becomes 380

Alternatively, DrawRectangleV takes a raylib Vector2 and accepts f32 directly — useful once we define our position structs. But for now, the cast is fine.

Where GetFrameTime() lives

We do not use it yet — nothing moves. But this is where it will go when we add physics in Lesson 07:

odinfor !rl.WindowShouldClose() {
    dt := rl.GetFrameTime()   // seconds since last frame, ~0.016 at 60fps

    // update phase — physics, input, AI (uses dt)
    // draw phase  — BeginDrawing ... EndDrawing
}

GetFrameTime() returns an f32. You will multiply velocities by dt so the game runs at the same speed regardless of frame rate.

Check your understanding

1. The raylib function that returns time elapsed since the last frame (as f32, in seconds) is:

GetFrameTime() — returns the time in seconds since the last frame completed. At a stable 60 fps this is approximately 0.0167. You will store it as dt and multiply all velocity values by it so the game runs at the same speed on any machine.

2. DrawRectangle(x, y, w, h, color) — the coordinate and size arguments are typed as:

i32 — raylib's integer drawing calls use 32-bit signed integers. Because your game logic stores positions as f32, you must explicitly cast: i32(player_x). The cast truncates — 380.7 becomes 380. For f32 coordinates use DrawRectangleV instead.

3. The raylib color constant for a classic arcade-black background is:

rl.BLACK is solid black (R:0 G:0 B:0 A:255). rl.BLANK also exists but it is fully transparent (A:0) — useful for clearing a render texture, not the main screen. rl.RAYWHITE (an off-white) is raylib's default background; for Joust's arcade feel you want BLACK.

4. The Odin keyword that guarantees CloseWindow() runs even if the game errors during startup is:

defer — schedules a statement to run at the end of the enclosing scope, unconditionally. scope is a Go concept, guard is Swift, after is not an Odin keyword. In the raylib pattern, defer rl.CloseWindow() immediately after InitWindow is the standard idiom.
