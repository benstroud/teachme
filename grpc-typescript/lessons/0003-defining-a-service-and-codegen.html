Define a Service & Codegen

Turn messages into RPCs, then turn the whole thing into TypeScript stubs you can type against.

The mental model in one sentence

A service block groups rpc methods; the server implements them and the client gets a generated stub with matching methods — one contract, two sides, both typesafe.1

Declaring the service

syntax = "proto3";

package orders.v1;

message GetOrderRequest  { string id = 1; }
message GetOrderResponse { Order order = 1; }

service OrderService {
  rpc GetOrder(GetOrderRequest) returns (GetOrderResponse);
}
  • The package becomes the namespace for generated types: orders.v1.OrderService.
  • Each rpc names a method, an input message, and an output message.
  • Adding stream before a type changes the call kind — you will meet all four in Lesson 7.

The four RPC kinds (preview)

ShapeSyntaxWhen (domain layer)
Unaryrpc Get(Req) returns (Res)Default for reads/writes.
Server-streamingrpc List(Req) returns (stream Res)Bulk query, page streaming.
Client-streamingrpc Send(stream Req) returns (Res)Bulk ingest/upload.
Bidirectionalrpc Sync(stream Req) returns (stream Res)Live sync; use rarely.

Turning the proto into TypeScript

Two ways to load a proto in Node:2

  • Dynamic (@grpc/proto-loader + grpc.loadPackageDefinition): the proto is parsed at runtime. Least setup, weakest types.
  • Static (grpc-tools/buf): protoc emits JS + .d.ts at build time. Most type safety — recommended for a real project.
