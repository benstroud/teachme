Metadata, Context & Auth

The side channel that carries request identity, tenant, tracing, and credentials across the BFF → domain hop.

The mental model in one sentence

Metadata is a key/value bag attached to a call, shipped as HTTP/2 headers (before the first message) and trailers (when the server closes it). It is the natural home for context — tokens, request ids, tenant, trace context — that isn't part of your message data.1

Metadata rules

  • Keys are ASCII strings, case-insensitive, and must not start with grpc- (reserved for gRPC itself).1
  • Values are strings (or base64 binary for binary headers).
  • Servers may limit request-header size (~8 KiB default suggestion) — metadata is for small context, not payloads.

What to carry on every BFF → domain call

const metadata = new grpc.Metadata();
metadata.set("authorization", "Bearer " + token);  // from the inbound request
metadata.set("x-request-id", requestId);           // for correlation
metadata.set("x-tenant", tenantId);                // multi-tenant context
metadata.set("traceparent", traceContext);         // W3C trace propagation
// pass via call options:
client.getOrder(req, { metadata }, handler);

The domain service reads the same keys from call.metadata in its handler and can re-propagate them to any downstream service it calls — that is how a request id and trace survive the whole fan-out.

Interceptors: apply behavior to every call

Interceptors are middleware attached to a channel or server that runs for every RPC — ideal for logging, metrics, fault injection, and (server-side) auth.2 They split into client vs server interceptors, and order matters: an interceptor closer to the network sees raw traffic, one closer to the app sees app behavior.

Auth: channel creds + call creds

Authentication has two layers:3

  • Channel credentials — transport-level TLS (createSsl) so traffic inside the VPC is encrypted; with mTLS, both ends present certs.
  • Call credentials — per-RPC identity, typically a token. The idiomatic way is a metadata generator, not an interceptor:
const callCreds = grpc.credentials.createFromMetadataGenerator((_params, cb) => {
  const m = new grpc.Metadata();
  m.set("authorization", "Bearer " + token);
  cb(null, m);                       // re-run before retries so tokens refresh
});

const client = new OrderServiceClient(
  "orders:50051",
  grpc.credentials.createSsl(rootCert),
  undefined, callCreds);

On the server, a verification interceptor validates the token (e.g. a JWT against a JWKS endpoint) and rejects with UNAUTHENTICATED/PERMISSION_DENIED before the handler runs.
