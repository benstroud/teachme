gRPC Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

The contract

IDL (Interface Definition Language)
A language for describing an interface in a tool-readable way. gRPC uses Protocol Buffers (.proto) as both its IDL and its message wire format. The same file is compiled to clients and servers in many languages.1
proto / proto3
The Protocol Buffers schema syntax. proto3 is the version recommended with gRPC: simplified syntax, first-class multiplatform support.1
message
A structured record in a .proto, made of typed, numbered fields. Compiled into data-access classes. e.g. message Person { string name = 1; }.2
field number
The integer identifying a field on the wire. Write-once: never reuse a number (older readers corrupt data) and never rename the meaning of one. This is the backbone of forward/backward compatibility.3
scalar type
A primitive field type: int32, int64, uint32, uint64, sint32, sint64, fixed32, fixed64, float, double, bool, string, bytes.3
enum
A named set of integer constants allowed in a field; the first value must be 0 in proto3.
repeated
Marker making a field a list (an array of that type). The protobuf equivalent of a typed collection.
service
The interface being exposed, containing rpc methods. The server implements it; the client gets a generated stub with the same methods.1
rpc method / call type
A single remote method. Four kinds: unary, server-streaming, client-streaming, and bidirectional streaming — determined by stream appearing on the request and/or response.4
protoc
The Protocol Buffers compiler. With a gRPC plugin it also emits client/server stubs for each language.1

Transport & runtime

HTTP/2
The transport gRPC runs on: multiplexed streams, binary framing, header compression, flow control. This is what makes true streaming and low-overhead multiplexed calls feasible.1
channel
A client-side connection to a server (with its connection pooling, name resolution, and load-balancing config). A client stub is bound to a channel.5
stub (client)
The generated client object exposing the service's methods locally; each call is serialized and sent over the channel. Also called “the client”.1
deadline
The point in time past which a client is unwilling to wait; the local gRPC library fails the call with DEADLINE_EXCEEDED. There is no default — set one or you may wait forever.6
metadata
Key/value side channel attached to a call, carried as HTTP/2 headers (sent before the first message) and trailers (sent by the server when it closes the call). Keys must not start with grpc-. Used for auth tokens, request IDs, trace context, tenant headers.7
status code
The integer outcome of every RPC (0 = OK … 16 = UNAUTHENTICATED). The gRPC library and your app both choose codes; some codes are generated only by user code.8
interceptor
Middleware applied to every RPC on a channel or server: logging, metadata injection, auth, metrics, fault injection. Split into client and server interceptors.9
call credentials
Per-RPC credentials (e.g. a token) attached via a metadata generator, combined with channel credentials. The idiomatic way to do client-side auth — better than an interceptor.10
channel credentials
Transport-level credentials: createInsecure() or createSsl(rootCert) for TLS.10
toolchain: @grpc/grpc-js
The maintained pure-JS gRPC implementation for Node. Client, server, and channel API.
loaders & codegen
@grpc/proto-loader loads a .proto at runtime (dynamic). grpc-tools / buf compile a .proto to static TypeScript stubs ahead of time (static) — better type safety.11

Resilience & context

transparent retry
Retry done by the gRPC client even with no policy: unlimited while the RPC never left the client; a single retry if it reached the server but not the app logic. Safe because gRPC is certain the work wasn't processed.12
retryPolicy
Service-config settings (maxAttempts, initialBackoff, maxBackoff, backoffMultiplier, retryableStatusCodes) enabling per-method retries; jitter ±20% is applied. No default policy is configured.12
idempotency
The property that a handler produces the same observable result whether a request is executed once or repeatedly. Required to retry safely, since retries can duplicate side effects.
cancellation
When a client cancels (deadline expiry, user cancel), the server is told to abandon work; the app must stop its own sub-work. The server sees the call as cancelled.
trace context
Identifying metadata propagated across calls so a single logical request can be assembled from many service spans (e.g. W3C traceparent / gRPC grpc-trace-bin).13
BFF (Backend-for-Frontend)
A client-facing service (here a GraphQL and/or REST layer) that sits at the edge and fans out to domain services behind it.
