## Facts verified during authoring (2026-09)

- gRPC = RPC framework + protobuf as IDL/message format. Client calls a method on
  a remote server "as if it were a local object." Client uses a generated stub;
  server implements the same `service` interface. gRPC clients and servers can be
  written in different languages. (grpc.io introduction)
- protobuf `message` = small record of name-value `fields`; each field has a type
  and a field `number`. `protoc` compiles `.proto` into data-access classes; a
  gRPC plugin additionally generates client/server code. (grpc.io introduction)
- proto3 recommended for gRPC; proto2 is the "current default" only in a legacy
  sense and can cause compatibility issues crossing proto2/proto3. (grpc.io)
- One gRPC RPC can be: unary, server-streaming, client-streaming, or
  bidirectional streaming. On the wire all are carried via HTTP/2 streams.
- Node: two ways to link a proto — dynamic codegen (`@grpc/proto-loader` +
  `grpc.loadPackageDefinition`) and static codegen (`grpc-tools` protoc plugins
  emitting `.d.ts` + JS). `@grpc/grpc-js` is the maintained pure-JS implementation.
- Client: `new proto.Greeter('localhost:50051', grpc.credentials.createInsecure())`
  (or `createSsl`). Server: `new grpc.Server(); server.addService(Svc.service, impl);
  server.bindAsync(addr, creds, cb); server.start()`. (grpc.io Node basics)
- Status codes: OK 0, CANCELLED 1, UNKNOWN 2, INVALID_ARGUMENT 3,
  DEADLINE_EXCEEDED 4, NOT_FOUND 5, ALREADY_EXISTS 6, PERMISSION_DENIED 7,
  RESOURCE_EXHAUSTED 8, FAILED_PRECONDITION 9, ABORTED 10, OUT_OF_RANGE 11,
  UNIMPLEMENTED 12, INTERNAL 13, UNAVAILABLE 14, DATA_LOSS 15, UNAUTHENTICATED 16.
  Codes never generated by the library (user code only): INVALID_ARGUMENT,
  NOT_FOUND, ALREADY_EXISTS, FAILED_PRECONDITION, ABORTED, OUT_OF_RANGE, DATA_LOSS.
  Retry decision guidance: UNAVAILABLE → retry the failing call; ABORTED → retry at
  a higher level; FAILED_PRECONDITION → retry only after state is fixed. (grpc.io)
- Default client has NO deadline (# wait forever). Server auto-cancels a call
  (CANCELLED) once the client's deadline passes; server app must stop its own work.
  Propagation converts a deadline into a remaining-timeout to dodge clock skew.
  (grpc.io deadlines)
- Metadata = key/value side channel via HTTP/2 headers + trailers. Keys ASCII,
  case-insensitive, must NOT start with `grpc-` (reserved). Values ASCII or base64
  binary. Headers sent before first message; trailers sent by server when it closes
  the call. Default header size limit ~8 KiB. Used for auth, tracing, custom
  headers. (grpc.io metadata)
- Retries: enabled by default but NO default policy; without a policy gRPC only
  does "transparent retry" (unlimited if the RPC never left the client; a single
  retry if it reached the server library but not app logic). Config is per-method
  via service config: `retryPolicy` maxAttempts / initialBackoff / maxBackoff /
  backoffMultiplier / retryableStatusCodes; jitter ±20% is applied. Throttling via
  `retryThrottling` maxTokens & tokenRatio. Once a response header is received the
  RPC is "committed." (grpc.io retry)
- Interceptors = middleware applying to every RPC on a channel or server; split
  into client interceptors and server interceptors; order matters (some closer to
  network, some closer to app). Use for metadata, logging, fault injection,
  caching, metrics, server-side auth. Client auth is better done via call
  credentials than an interceptor. (grpc.io interceptors + auth)
- proto3 essentials: `message` fields are typed + numbered; scalars incl. int32,
  int64, uint32, uint64, sint32, sint64, fixed32/64, float, double, bool, string,
  bytes; `repeated` for lists; `enum`; nested types; imports; nullable via
  message-field presence; field numbers are write-once — never reused (causes
  data corruption for older readers); never rename a field.
  (protobuf.dev proto3)
- Protobuf wire: a message is sequence of `tag` = (field<<3) bit-or wire_type,
  encoded as varint. VARINT for int/bool/enum, LEN for string/bytes/submessage.
  Unknown fields are preserved, making compatible evolution possible. Fields are
  written by number but receivers read by tag. (protobuf.dev encoding)
- gRPC-web lets browsers call gRPC over HTTP/1.1 via a proxy (e.g. Envoy
  grpc_web filter); commonjs + grpcwebtext modes; the page's EchoService uses a
  proxy on :8080 forwarding to the backend on :9090. Used to decide the BFF
  boundary (keep gRPC server-side and let BFFs call it). (grpc.io web basics)
- Server-streaming client: `client.listFeatures(req)` returns a Readable
  (`data`/`end`/`error`); client-streaming passes a callback for the single response
  and uses `call.write(...)` / `call.end()`; bidi returns a Duplex. Messages
  arrive in write order on each side but the two streams are independent.
  (grpc.io Node basics)
