The API Gateway

Clients shouldn't navigate the service mesh — a gateway is the single entry that routes and composes calls for them.

The mental model in one sentence

An API gateway is a single entry point for clients that routes requests to the right services and, when needed, composes several services' responses into one — so clients never talk to each service directly.1

Why a gateway

  • One endpoint for clients — a web/mobile client issues one request instead of fanning out to many services.
  • Routing — the gateway dispatches by path/operation to the owning service.1
  • Composition / aggregation — it combines responses for a screen (the API-composition read path).1
  • Cross-cutting edge — auth, rate limiting, and CORS can live here.
Key idea The gateway is a pragmatic counterpart to "dumb pipes": it exists because clients genuinely need a point of aggregation. A backend-for-frontend is the same idea scoped per client type, so each platform gets the shape it needs.2

Watch the trade-offs

A gateway is also a single point that must not become a bottleneck or a monolith-in-disguise. Keep it thin (routing and light composition), and push heavy or long-running work into the services or async flows.1
