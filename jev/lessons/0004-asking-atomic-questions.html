Asking Atomic Questions

Each question should be one well-scoped judgment; decompose the complex ones and combine the answers in code.

The mental model in one sentence

System One models work best when each question asks one specific, well-scoped thing — the kind of gut-check a knowledgeable person could make in seconds given the right context.1

What "atomic" means

An atomic question is a single determination: is this ticket urgent?, which team owns this?, how severe is this defect?. The less a question asks, the more reliable the evaluation tends to be.1

Key idea If a question would require extended reasoning or weigh several independent factors, it is not atomic — decompose it. Ask each factor as its own question, then combine the results with logic in your code.1

Decompose, then combine in code

Instead of one compound question, "rate this startup pitch," ask separately about market size, technical feasibility, and differentiation. Then combine the scores with your own formula:

const pitch = await jev.ask({
  questions: [
    { id: "market",      type: "score", prompt: "How large is this market?",   levels: [1,2,3,4,5] },
    { id: "feasibility", type: "score", prompt: "How feasible technically?",   levels: [1,2,3,4,5] },
    { id: "edge",        type: "score", prompt: "How differentiated is it?",   levels: [1,2,3,4,5] },
  ],
});
const score = 0.4*pitch.market + 0.4*pitch.feasibility + 0.2*pitch.edge;

When priorities shift you change a coefficient in code rather than rewriting a prompt — keeping policy explicit and testable.1

Why this matters for reliability

A narrow, single-factor question has a clear answer boundary and yields cleaner probabilities; a compound request muddies what any reported probability refers to. Decomposition preserves the ability to weight dimensions and to debug exactly which factor drove a result.14
