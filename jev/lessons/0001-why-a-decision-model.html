Why a Decision Model

When code must act on a judgment, coercing generated text into structure is a mismatch — System One models exist to fix it.

The mental model in one sentence

LLMs produce text for humans; when you need a judgment your code will consume, a System One model takes state and typed questions and returns structure your code can branch on directly — no text, no parsing.1

The mismatch

To make an LLM help software decide, teams add three steps: describe an output format in a prompt, parse the JSON or natural-language reply, then validate and convert it. That is flexible but fragile: formatting errors, extra parsing, and no honest signal about when the model is unsure.4

Key idea The hard part in real products is usually not a paragraph — it is a stream of small, consistent judgments: which team gets this ticket, does this need approval, is this urgent, which model runs next.4

What System One models are

System One models are a new class built to make fast, structured decisions that software can use directly. Named after Kahneman's fast, intuitive System 1 versus slow, considered System 2, they optimize for speed and calibrated, typed output rather than prose.23

Where it fits

A decision model is a decision layer, not a chatbot and not a substitute for every LLM: it classifies, routes, verifies, ranks, and checks inside bounded answer spaces, while a generative model handles open-ended text and reasoning.34
