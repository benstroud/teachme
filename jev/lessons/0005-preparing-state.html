Preparing State

State is the context you send; Jev evaluates every question against it — so the quality of your state sets the ceiling on the decision.

The mental model in one sentence

You send state (the application context) plus typed questions, and Jev judges each question against that same state — so state is the raw material every decision is made from.13

What to send

Think of state as structured program state: the ticket, the order, the user's request, the current values your code holds. TypeSafe's model emphasizes structured program state with text fields, and lets questions reference nested fields within that state.23

{
  "ticket": {
    "subject": "Refund not received after 5 days",
    "customerTier": "pro",
    "amountUsd": 129.0,
    "thread": ["I never got my refund…", "Please escalate"]
  }
}
// questions then reference these fields to decide team and urgency

Rules of thumb for good state

  • Send what the decision needs, not your whole database. More context is not always better; it costs tokens and can blur the judgment.
  • Keep questions narrow and anchored in fields you actually send — an answer is only as grounded as the state behind it.4
  • Preprocess non-text inputs (images, audio) into a textual summary or structured fields before shipping them as state.4
Key idea Watch the context window. On OpenRouter, Jev's window is 32,000 tokens for the state you send plus the questions.3 Budget your state so big decisions still fit on a single request.

State is not a prompt

You are not asking Jev to narrate; you are giving it facts to judge. Curate the fields, avoid redundant prose, and keep the state in the language your questions assume so probabilities stay meaningful.2
