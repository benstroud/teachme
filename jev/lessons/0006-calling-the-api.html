Calling the API

Reach Jev with a model identifier and an HTTP surface — the Decisions API for plain HTTP, or the System One API for the TypeSafe SDK.

The mental model in one sentence

You call Jev with an API key and a model identifier, sending state plus questions to one of two OpenRouter endpoints, and get a typed answer back — no chat loop required.3

The model identifier and endpoints

  • Model id: typesafe/jev-1.13 (or the floating alias ~typesafe/jev-latest).3
  • Decisions API: POST https://openrouter.ai/api/alpha/decisions — for calling Jev from any language with plain HTTP, or via the OpenRouter SDKs.3
  • System One API: POST https://openrouter.ai/api/v1/systemone — for pointing the official TypeSafe JS/Python SDK at OpenRouter with a base-URL change.3
curl -X POST https://openrouter.ai/api/v1/systemone \
  -H 'Authorization: Bearer $OPENROUTER_API_KEY' \
  -H 'content-type: application/json' \
  -d '{
    "model": "typesafe/jev-1.13",
    "state": { "ticket": { "subject": "Refund not received" } },
    "questions": [
      { "id": "team", "type": "choice", "options": ["billing","support","sales"] }
    ]
  }'

Reach it from code

From TypeScript or Python you can call the Decisions/System One endpoints directly or use the OpenRouter SDK; if you already use the TypeSafe SDK, point it at OpenRouter by changing its base URL to the System One endpoint.3

Key idea No separate TypeSafe account is needed for the OpenRouter path — an OpenRouter API key authenticates both the Decisions API and the TypeSafe SDK pointed at OpenRouter.3

Billed per input token

Jev charges for input tokens (the state and questions you send); output tokens are free because answers are tiny typed values. Each response includes a usage.cost field in USD. Confirm the live per-token price on the Jev model page.3
