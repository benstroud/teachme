Confidence & Thresholds

Every answer carries a confidence signal — the discipline is choosing the bar at which your code acts, routes, or asks a human.

The mental model in one sentence

Jev reports its confidence with each decision, and your job is to set thresholds so the system decides when to act automatically versus escalate — calibrated confidence is the unit that makes that reliable.12

Confidence is not accuracy

Confidence and probability are signals that help your application choose its level of automation — they are not a guarantee that the decision is correct in your business. A model can be right 95% of the time while being confidently wrong in the 5%, so the signal only helps if you act on the uncertainty, not just the answer.42

Key idea Robust automation is built on knowing when the model thinks it is on shaky ground. Treat a low-confidence answer as first-class data: its job is to route you to a human or a stronger step.

Pick thresholds per decision

  • Set a bar per decision and per risk level, not one global number.
  • High-confidence decisions run automatically; a band below that pauses or routes to review; the tail escalates to a human.4
  • Because only the ambiguous calls require human review, you can afford to be strict on riskier actions.

Evaluate on your own data

Calibration is not universal — measure it on your data, language, domain, and risk profile, and keep a human-review path for high-impact actions. The confidence you observed in a demo is not the confidence you will get in production at your concurrency and mix.4

// a deliberate threshold policy
const d = await jev.ask({ questions: [ /* ... */ ] });
if (d.risk.confidence > 0.9)            return autoDecision(d);
if (d.risk.confidence > 0.6)            return reviewQueue(d);
return humanApproval(d);
