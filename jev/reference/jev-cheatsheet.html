Jev & System One Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The mental model

     app state + typed questions
                 │
                 ▼
      ┌─────────────────────┐
      │     Jev (System One) │  fast, structured decisions
      └──────────┬──────────┘
                 ▼
    typed answer: choice / score / noul
    + probabilities + confidence     ──►  code branches/routes

Jev is a decision model, not an LLM: state and typed questions in, structured answers out — no text, no parsing, "no hallucination."1

2. The three primitives

PrimitiveQuestionReturns
ChoiceWhich of these options?chosen option + probability per option + confidence
ScoreWhere on an ordered rubric?probability-weighted position + probability per level + confidence
NoulDoes this condition hold?0–1 probability

Mix all three in one call; each is evaluated in parallel against the same state.1

3. Writing atomic questions

  • One well-scoped judgment per question ("gut-check the expert can answer in seconds").1
  • Decompose: instead of "rate this pitch", ask market size, feasibility, differentiation separately.
  • Combine results with your own weights in code; change a coefficient, not a prompt.

4. Calling Jev (OpenRouter)

# model id
typesafe/jev-1.13        (~typesafe/jev-latest alias)

# Decisions API  POST https://openrouter.ai/api/alpha/decisions
# System One API POST https://openrouter.ai/api/v1/systemone

curl -X POST https://openrouter.ai/api/alpha/decisions \
  -H 'Authorization: Bearer $OPENROUTER_API_KEY' \
  -H 'content-type: application/json' \
  -d '{
    "model": "typesafe/jev-1.13",
    "state": { "ticket": { "subject": "Refund not received", "priority": "high" } },
    "questions": [
      { "id": "team",   "type": "choice", "options": ["billing","support","sales"] },
      { "id": "urgent", "type": "noul",    "statement": "This ticket is urgent" }
    ]
  }'
  • Context window 32,000 tokens; input tokens billed, output tokens free.3
  • Every response includes usage.cost (USD).
  • No TypeSafe account for the OpenRouter path — an OpenRouter key is enough.3
  • Example request shape is illustrative; confirm field names in the current Decisions API reference.

5. Confidence & thresholds

  • Every output carries calibrated confidence/probabilities; use them to decide whether to act.12
  • Confidence is NOT accuracy. Measure on your own data; keep a human-review path for high-risk actions.4
  • Pick thresholds per decision; escalate low-confidence cases to a human.

6. Decision patterns in code

  • Gate: check a risky action against the user's request; run safe calls, refuse unsupported, pause ambiguous for a human.3
  • Cascade: draft with a cheap model, verify with Jev, escalate to a stronger model only on failure.3
  • Route: classify tickets/requests to the right team or model.
  • Queue / escalate: set priority and pull humans in on low confidence.

7. Limits to respect

  • Not a chatbot and not a standalone substitute for a generative LLM.4
  • Does not return reasoning/explanations — pair with an LLM or a human for justification.
  • Keep questions narrow; preprocess non-text inputs; validate latency in your own environment.4
  • Speed/pricing are moving snapshots — confirm against the live source.24
