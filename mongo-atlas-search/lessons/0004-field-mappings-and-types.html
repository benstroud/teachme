Field Mappings & Types

Explicit mappings let you say exactly what each field is indexed as — string, number, date, geo, or a stored token — so each query type works.

The mental model in one sentence

Instead of indexing every field, an explicit fields mapping names each field and assigns a search type, which is what allows text, range, geo, and exact-match behavior.1

Explicit mapping

db.movies.createSearchIndex({
  name: "explicit",
  mappings: {
    dynamic: false,
    fields: {
      title:  { type: "string" },
      body:   { type: "string", analyzer: "standard" },
      price:  { type: "number" },
      releasedAt: { type: "date" },
      location:   { type: "geo" }
    }
  }
})
  • dynamic: false disables inference; only the listed fields are indexed.1
  • String fields get full-text behavior; number/date enable range; geo enables distance.
Key idea The field's search type is what unlocks an operator: you cannot run a range on a string mapping, or geo without a geo field. Map the type to the queries you need.1

The search token type & stored source

A field can be indexed as a token (with a normalizer, so an exact-match/sorted/filter field), and you can store selected fields on the search service (storedSource) to serve results faster without hitting the database. Confirm the field-type details for your server version.2

Dynamic vs explicit — the trade

  • Dynamic: quick, indexes everything, less control over analyzers.
  • Explicit: precise, curates the index, chooses analyzers per field — better for production.
