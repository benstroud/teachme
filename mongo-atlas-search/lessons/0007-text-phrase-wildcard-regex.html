text, phrase, wildcard & regex

The core string operators: analyzed term matches, exact sequences, wildcard patterns, and regular expressions.

The mental model in one sentence

Choose the operator by how strict the match must be: text for analyzed terms, phrase for an exact sequence, wildcard for * and ? patterns, regex for regular expressions.1

The operators

OperatorUse for
textTokenized term matches across one or more string fields (run against the analyzer).1
phraseAn exact sequence of words in order.
wildcardPatterns with * (any chars) and ? (one char), e.g. prefix search.
regexFull regular-expression matching on an indexed field.

Text vs phrase

{ "text":   { "query": "senior engineer", "path": "profile" } }
{ "phrase": { "query": "senior engineer", "path": "profile" } }

text matches documents containing each term (analyzed, so "engineers" can match "engineer"); phrase requires the terms to appear together in that order.1

Key idea text is the workhorse for relevance; phrase is what you reach for when order matters ("serverless framework" must stay together), and wildcard/regex cover prefix and ad hoc patterns — at the cost of the analyzer's language-aware matching.

Wildcard and regex

{ "wildcard": { "query": "k8s*", "path": "name" } }
{ "regex":    { "query": "^te[a-z]+er$", "path": "profile", "allowAnalyzedField": true } }

Wildcards give prefix/substring-style matching; regex expression matching gives full control for exact patterns (e.g. SKUs). Watch analyzer behavior — some operators can search non-analyzed fields only; confirm against your version.1
