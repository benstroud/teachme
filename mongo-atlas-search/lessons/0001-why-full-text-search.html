Lesson 1 of 10MongoDB Atlas Search

Why Full-Text Search

A normal find cannot rank results, understand language, or do fast prefix search — that is the gap a search index fills.

The mental model in one sentence

MongoDB Search (Atlas Search) is full-text search that runs inside MongoDB: you index fields, then query them with an aggregation stage that returns ranked results — unlike a plain find.1

What a plain find cannot do

  • Relevance. A find returns matches in no meaningful order; a search returns documents highest to lowest relevance.2
  • Language awareness. No tokenizing, case-folding, or stemming — "Running", "ran", "run" are unrelated strings to a substring match.
  • Fast prefix/autocomplete. Regex scans fall back to collection scans; a search index is built to answer prefix queries quickly.
  • Ranking knobs. No notion of boosting or normalizing to tune what surfaces first.
Key idea The difference is structural: a search index is a data structure optimized to retrieve documents that meet search criteria, and that is what makes relevance and speed possible at all.1

Search queries are aggregation pipelines

A MongoDB Search query is an aggregation pipeline that begins with $search (return the matching documents) or $searchMeta (return metadata about the search). Inside those stages you use operators to express what to match.1

When to reach for it

Blog/article search, e-commerce product search with filters and facets, typeahead/autocomplete, and any "find the best match" experience. If you only need exact equality or range lookups, an ordinary index is the right tool; search buys you ranking and tokenization when matching text matters.3
