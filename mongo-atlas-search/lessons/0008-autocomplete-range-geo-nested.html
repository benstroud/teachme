autocomplete, range, geo & nested

Beyond plain text: suggest-by-prefix, filter numeric/date ranges, search by location, and reach into embedded documents.

The mental model in one sentence

Each of these operators targets a mapped field type or indexing strategy: autocomplete for prefix suggestions, range for number/date bounds, geo for coordinates, and nested for embedded documents.1

Autocomplete

{ "autocomplete": { "query": "micro", "path": "title" } }

Autocomplete returns documents whose indexed field starts with (or contains) the query — the basis of typeahead suggestions. It pairs with a field indexed with an analyzer suited to prefix matching (often an edge-gram custom analyzer) so partial terms can match.1

Range

{ "range": { "path": "price", "gte": 100, "lte": 250 } }

range matches an indexed number or date field between bounds (gt/gte/lt/lte), and can boost the range clauses.

Geo

{ "geo": { "path": "location", "circle": { "center": { "type": "Point",
        "coordinates": [ -73.98, 40.75 ] }, "radius": 5000 } } }

geo runs against a geo-mapped field and supports shape-based distance queries (a circle around a point), useful for "near me" search.

Key idea These operators depend on the index mapping — autocomplete needs a prefix-ready analyzer, range/geo need number/date/geo mappings. Keep the index and the operator in sync or the query cannot use the search index.

Nested

nested applies search inside the documents embedded in an array field, so you can match on fields of sub-documents (e.g. "a review by a VIP user contains 'fast'"). Use it when your matches must be scoped to the embedded object rather than the document as a whole.2
