Defining a Search Index

Before any query, create a search index on the collection — choosing the name, the fields, and how they map.

The mental model in one sentence

You create a search index for a collection and give it a definition — a mappings block that decides which fields are indexed and how — and only then can you query those fields.1

Where you create it

  • In the Atlas UI under the collection's Search Indexes tab.
  • Or programmatically via db.collection.createSearchIndex(...) in mongosh / a driver.

The Quick Start walks creating one against sample data; that is the fastest way to see one in action.1

A minimal definition

db.movies.createSearchIndex({
  name: "default",
  mappings: { dynamic: true },    // index every eligible field
})

dynamic: true indexes all eligible fields with inferred types — a great starting point. For control, use explicit field mappings instead (next lesson).2

Key idea The index definition determines what your queries can do: which fields are searchable, whether sorting/faceting/autocomplete work, and how strings are tokenized. Design it for the search experience you intend to ship.1

Names and iteration

Give the index a meaningful name (queries target an index by name or use the default). You can iterate: add or change field mappings and re-deploy the index as your search needs evolve.2
