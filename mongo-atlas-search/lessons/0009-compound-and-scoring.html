Compound & Scoring

Combine many criteria with must/should/mustNot/filter, then tune which results rank first with boosts and score normalization.

The mental model in one sentence

The compound operator wraps clauses: must (all required), should (optional, raise score), mustNot and filter (exclude), so you can filter and rank in one query — and scoring makes some results surface first.12

A compound query

{ "$search": { "compound": {
    "must":   [ { "text": { "query": "ace", "path": "brand" } } ],
    "should": [ { "text": { "query": "refurbished", "path": "condition",
                            "boost": { "value": 2 } } } ],
    "mustNot":[ { "text": { "query": "used", "path": "condition" } } ],
    "filter": [ { "range": { "path": "price", "gte": 100 } } ]
}}}
  • must — every clause must match (like AND).
  • should — optional; each match adds to the relevance score.1
  • mustNot / filter — exclude or filter without contributing score.1
Key idea Use filter (not mustNot) for anything that shouldn't affect ranking, and lean on should + boost to make "nice to have" criteria lift the most relevant results.

Reading and tuning the score

Project it with $project: { score: { $meta: "searchScore" } }, or inspect the breakdown with searchScoreDetails. Scores reflect term position and frequency and the operator/analyzer used.2 You can then boost a clause or term (amplify its effect) or normalize the scores.3

Deterministic order

If scores tie, ordering is non-deterministic — include a sort (by score or a unique field) when you need a stable order.2
