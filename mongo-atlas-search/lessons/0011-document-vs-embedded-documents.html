Document vs Embedded Documents

Two field types decide whether a subdocument is searched as one unit or as many per-array elements — and an operator matches inside a single element.

The mental model in one sentence

The document field type indexes an object as a single unit, while embeddedDocuments indexes each element of an array independently — and the embeddedDocument operator queries inside one of those array elements, like $elemMatch for search.12

The two field types

Field typeWhat it indexesTypical use
documentFields of an object/subdocument as one unit (dynamic or static sub-mappings).Highlighting, matching nested fields, faceting counted per root doc.1
embeddedDocumentsEach element of an array of documents as its own indexed unit, independent of the parent.Scoping a match to a single array element and scoring within it.2
Key idea You cannot use one field type to do the other's job: document cannot index fields inside array elements (use embeddedDocuments), and embeddedDocuments only applies to elements of an array.12

Indexing them

db.schools.createSearchIndex({
  name: "default",
  mappings: {
    dynamic: false,
    fields: {
      "teachers":        { "type": "document" },
      "teachers.classes":{ "type": "document" },
      "clubs.sports":    { "type": "embeddedDocuments", "dynamic": true }
    }
  }
})

Note in the docs' example, the same teachers path is indexed as document (to support highlighting) while array paths meant for element-scoped queries are indexed as embeddedDocuments.3

Querying inside embedded documents

To make several predicates hold on a single array element, use the embeddedDocument operator on an embeddedDocuments field:2

{ "$search": { "embeddedDocument": {
    "path": "items",
    "operator": { "compound": { "must": [
      { "range": { "path": "items.quantity", "gt": 2 } },
      { "text":  { "path": "items.tags", "query": "school" } }
    ]}}
}}}
  • path must be an indexed embeddedDocuments field and a parent of every field in operator.2
  • Scoring: each array element is evaluated and scored independently, the matches are combined (summed by default or via the embedded score option), and joined back to the parent document.2
Key idea This is the search answer to "$elemMatch": it guarantees the constraint is met by one element (e.g. a teacher with a grade-5 class), not by different elements scattered across the array.2

The false-positive trap

The subtle trap is what happens when you index an array of objects as the document type and search a nested field with dot notation (e.g. teachers.classes.grade). That search is not scoped to a single array element — every element is searched as part of the parent. With one condition that is harmless, but with several conditions (say a compound that must match grade=5 and subject=math) the matches can come from different array elements.

teachers: [
  { name: "Ann", classes: [ { grade: 5, subject: "history" } ] },   // has 5, not math
  { name: "Bo",  classes: [
      { grade: 5, subject: "history" },                             // grade 5 here
      { grade: 6, subject: "math" }                                 // math here
  ] },
]
# dot-notation 'document' search: grade=5 AND subject=math  → matches Bo  (FALSE POSITIVE:
#   the grade-5 class is one element, the math class is a different one)

Because each condition is satisfied by a different element, the document matches even though no single class is a grade-5 math class. Indexing the array as embeddedDocuments and querying with the embeddedDocument operator eliminates this class of false positive, because every predicate must be satisfied by the same element.2

Key idea Rule of thumb: if a match must hold within a single element of an array, use embeddedDocuments + embeddedDocument; if you only need "any element contains X", indexing the array as document and using dot notation is fine.

Considerations

  • Highlighting is not supported inside embeddedDocument.2
  • embeddedDocuments supports at most 5 levels of nesting.2
  • To return only matching array elements, pair storedSource with the returnScope.path query option.3
  • Faceting on fields in arrays is counted per matching element with embeddedDocuments; index as document to count per matching root document.3
