Running a Search Query

A search is an aggregation pipeline: pick the stage, write an operator, project the score, and limit the results.

The mental model in one sentence

A MongoDB Search query is an aggregation pipeline that begins with $search (documents) or $searchMeta (metadata), inside which an operator expresses the match — then you shape the output with the usual pipeline stages.1

A first search

db.articles.aggregate([
  { "$search": {
      "index": "default",
      "text": { "query": "deployment", "path": ["title", "body"] }
  }},
  { "$project": { "title": 1, "score": { "$meta": "searchScore" } } },
  { "$limit": 10 }
])

$search returns the matching documents (ranked); $project pulls in the relevance score; $limit pages the top results.1

Key idea Only fields in the search index can be searched, and the index name in the query must match the one you built. Design the index for the experience, then write operators that fit its mappings.1

The other stages

  • $searchMeta — return metadata/analytics (e.g. facet counts) rather than documents.1
  • $count — count matching documents.
  • )$project with $meta: "searchScore" — surface each doc's score (or searchScoreDetails).2
  • $sort — deterministic ordering when equal scores make rank ambiguous.2
