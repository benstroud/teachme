Index, Query, Score

Three pieces make search work: an index on your fields, a $search query against it, and a relevance score that orders the results.

The mental model in one sentence

You define a search index over a collection's fields (and how to tokenize them), run a $search query against it, and every returning document gets a score used to order them best-first.12

1. The index

A search index is a per-collection data structure optimized to retrieve documents that meet search criteria. Its definition says which fields to index and how to tokenize them — so the same field can be set up for full-text, sorting, facets, or autocomplete depending on how you map it.1

2. The query

A search query is an aggregation pipeline beginning with $search (to return documents) or $searchMeta (for metadata). Inside, operators express what to match — plain terms, a phrase, a range, a geo point, and so on.1

db.articles.aggregate([
  { "$search": { "text": { "query": "deployment", "path": ["title", "body"] } } },
  { "$project": { "title": 1, "score": { "$meta": "searchScore" } } }
])

3. The score

Every returned document receives a relevance score. Results are ordered from highest to lowest; you surface the number with a $project using { "$meta": "searchScore" } (or searchScoreDetails for a breakdown).2

Key idea The index shape decides what the query can do; the score decides what the user sees first. Design the index for the experience, then tune the query and score together.1
