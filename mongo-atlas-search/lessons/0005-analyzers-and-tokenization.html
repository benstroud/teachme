Analyzers & Tokenization

An analyzer decides how a string is split into searchable tokens — the lever that controls how "running" matches "run".

The mental model in one sentence

An analyzer determines how MongoDB Search tokenizes a string field into search terms, and therefore what queries can match it — from broad, language-aware full text to exact-match keywords.1

Built-in analyzers

AnalyzerBehavior
Standard (default)Splits on word boundaries, lowercases — the general-purpose default.1
SimpleSplits wherever a non-letter appears, lowercases.
WhitespaceSplits on whitespace only.
KeywordIndexes the whole string as a single term — only exact matches return.1
LanguageUses per-language rules (stemming etc.) for a specific language.
Key idea If you don't specify an analyzer, MongoDB uses the default standard analyzer. The choice is the difference between matching "running" when the user types "run" (language/stemming) and treating it as an exact string (keyword).1

Query-time and index-time analyzers

An analyzer can be set at index time (how the stored field is tokenized) and at query time (how the query terms are tokenized). They should be compatible so tokens line up. You can also index one field with alternate analyzers using the multi object, letting you search a title both as full text and as an exact/autocomplete field.2

Custom analyzers & n-grams

For prefix and autocomplete behavior, a custom analyzer with n-gram tokenization is the common tool: it indexes chunks of a word so a partial term can match. Normalizers (e.g. lowercase) produce a single token and apply to the search token type for exact-match fields.13
