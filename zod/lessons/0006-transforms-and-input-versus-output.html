Transforms and Input vs Output

A transform checks the input and then converts it: a string becomes a Date, a padded name becomes a trimmed one. Once a schema transforms, its input and output types differ, and Zod gives you both.

Transform after the check

.transform(fn) runs after the schema has accepted the value. The function receives the checked value and returns the value the rest of the program will use.1

const DateFromString = z.string().transform((s) => new Date(s));
const Trimmed = z.string().transform((s) => s.trim());

DateFromString.parse("2026-01-02");  // a Date object
Trimmed.parse("  hi  ");             // "hi"

Input and output are different types

Once a schema transforms, the value that goes in and the value that comes out may have different types. Zod exposes both: z.input for the type that goes in, and z.output for the type that comes out. z.infer is the output type.1

const Payment = z.object({
  amount: z.string().transform((s) => Number(s)),
  paidOn: DateFromString,
});

type PaymentInput  = z.input<typeof Payment>;   // amount: string, paidOn: string
type PaymentOutput = z.output<typeof Payment>;  // amount: number, paidOn: Date
Name the boundary Keep the input type for what the outside world sends, and the output type for what your code uses. Mixing them up is the usual cause of "this is a string, not a number" bugs far from the boundary.

Check yourself

When does .transform run, relative to the check?

A transform runs after the schema has accepted the value, so the function receives a checked value.1

For DateFromString, what does z.input give?

The input type is what the outside world sends: a string. The output type is Date.1

Why keep the input type and output type separate?

Transforms change the shape of the data. Naming the input and output types tells you which side of the boundary a value is on.
