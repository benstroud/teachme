Objects, Optional, and Defaults

Most real data is an object with some keys missing, some null, and some extra keys nobody asked for. Zod has a choice for each case, and the default choice may not be the one you want.

Unknown keys

By default, z.object strips keys the schema does not list. The parsed result has only the declared fields. This is safe for most input, but it can hide a typo in a field name, since the extra key simply disappears.1

SchemaUnknown key
z.objectStripped from the result
z.strictObjectRejected with an error
z.looseObjectKept in the result unchanged
const Plain = z.object({ id: z.string(), name: z.string() });
Plain.parse({ id: "1", name: "a", extra: true });       // { id: "1", name: "a" }

const StrictUser = z.strictObject({ id: z.string() });
StrictUser.safeParse({ id: "1", extra: true }).success; // false

const LooseUser = z.looseObject({ id: z.string() });
LooseUser.parse({ id: "1", extra: true });              // { id: "1", extra: true }

Optional, nullable, and default

These three words answer different questions. .optional() allows the value to be undefined. .nullable() allows null. .default(x) fills in x when the input is undefined.1

const Profile = z.object({
  role: z.string().default("viewer"),
  nickname: z.string().nullable(),
  bio: z.string().optional(),
});

Profile.parse({ nickname: null });
// { role: "viewer", nickname: null }   bio is absent, not undefined-valued
Nullable is not optional nickname must be present, even if its value is null. Only bio may be left out. Check which fields your data source really omits.

Check yourself

A client sends an extra key that the schema does not declare, to an ordinary z.object. What happens?

The default for z.object is to strip unknown keys from the result.1

What does .default("viewer") do?

A default applies when the input is undefined. It does not allow null, and it does not change which strings are valid.

Which schema accepts a key that is present with the value null, but rejects the key being absent?

A nullable schema accepts null. It does not accept an absent key, since the key is still required. Optional and nullish both allow an absent key.
