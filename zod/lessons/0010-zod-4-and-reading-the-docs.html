Zod 4 and Reading the Docs

Much of the Zod you will find online was written for version 3. Version 4 moved several common forms to new names, and some older forms are now deprecated. Learn the changes, and check every example against the version you install.

Which version this set uses

The lab installs zod@^4. When this set was written, npm listed 4.6.7 as the latest release, and the Zod docs describe Zod 4 as the stable line.12 Check the version in your own package.json, because the examples here depend on it.

Changes a learner meets first

Zod 3 styleZod 4 styleWhy it matters
z.string().email()z.email()The method form is deprecated; the top-level function is the current form
z.object(...).strict()z.strictObject(...)Unknown keys are rejected by the named function
z.object(...).passthrough()z.looseObject(...)Unknown keys are kept by the named function
message: or invalid_type_error:error:One parameter now covers custom errors
error.format() and error.flatten()z.treeifyError and z.flattenErrorThe top-level helpers are the current forms

The Zod migration guide lists these changes and others, including the deprecation of z.nativeEnum in favour of z.enum, and a removal of .deepPartial().3 The lessons in this set use the Zod 4 forms, and each deprecated form in the migration guide is noted as such.

Check the version before you copy A snippet from a blog post may be the Zod 3 form. The error message and the object-strictness behaviour both differ between versions. Compare the import and the function names against the docs for the version you install.

How to read the docs on a new feature

  1. Find the version the page documents, and the install line it shows.
  2. Check whether the function is top-level (z.email()) or a method (.email()), and whether the method is marked deprecated.
  3. Run the example in the lab's test file before you rely on it. A passing test is the cheapest proof that the docs and the code agree.

Check yourself

Which form is the current Zod 4 way to validate an email address?

The top-level z.email() is the current form. The method form still works, but the docs mark it as deprecated.3

What is the Zod 4 way to reject unknown keys?

The named function z.strictObject rejects unknown keys. z.looseObject keeps them.3

Why should a learner run an example before trusting it?

Running the example against the installed version is the cheapest check that the docs match the code you have.
