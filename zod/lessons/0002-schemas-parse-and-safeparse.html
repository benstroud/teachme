Schemas, parse, and safeParse

A schema is a value you build from Zod's functions. Two methods use it: parse throws on bad input, and safeParse returns a result you can branch on.

Build a schema

Zod builds schemas from functions such as z.string(), z.number(), and z.object(...). Each schema is an ordinary value, so you can store it, pass it around, and combine it with others.1

import { z } from "zod";

export const UserSchema = z.object({
  name: z.string().min(1),
  age: z.number().int().nonnegative(),
  email: z.email(),
});

export type User = z.infer<typeof UserSchema>;

z.email() is a top-level function in Zod 4. Lesson 10 covers the older method form.

parse: the value, or an exception

parse returns the checked value when the input is valid. When it is not, it throws a ZodError. Use it where bad input should stop the work, such as during start-up when a config file is wrong.1

safeParse: a result you branch on

safeParse never throws for invalid input. It returns an object with success. On success, data holds the value. On failure, error holds the ZodError. Use it at boundaries where you want to respond with an error rather than crash.1

const result = UserSchema.safeParse(body);
if (!result.success) {
  return { status: 400, issues: result.error.issues };
}
return { status: 201, user: result.data };
Parse returns a new value Zod returns a checked copy of the input. The result is the thing you should use from then on, not the original object.

Check yourself

What does safeParse return for invalid input?

On failure, safeParse returns a result with success: false and an error. It does not throw.1

Which type should the code use for a value that came from UserSchema.parse?

The inferred type comes from the same schema that checks the data, so the two stay in step.

A web handler should respond with a 400 for a bad body and not crash. Which method fits best?

safeParse returns the result, so the handler can branch without an exception and return a 400.
