Errors, Paths, and Messages

A failed check produces a list of issues, each with a code, a path to the bad value, and a message. Learn to read that list, to shape it for a form or an API, and to write messages a person can act on.

The issues list

A ZodError holds an issues array. Each issue carries a code, a path to the bad value, and a message. The path is an array: object keys are strings, and array indices are numbers.12

const SignupForm = z.object({
  username: z.string().min(3, "Username needs at least 3 characters"),
  favoriteNumbers: z.array(z.number()),
});

const r = SignupForm.safeParse({ username: "ab", favoriteNumbers: [1, "x"] });
// issues: path ["username"], and path ["favoriteNumbers", 1]

Three shapes for the same errors

A flat list is rarely what a form needs. Zod gives you helpers that reshape the error for different consumers.2

HelperShapeUse it for
z.treeifyErrorNested to match the schema, with properties and itemsPer-field errors in deep forms
z.flattenErrorformErrors and fieldErrors, one level deepFlat forms with top-level fields
z.prettifyErrorA readable string with the pathLogs and command-line output

The docs mark z.formatError as deprecated in favour of z.treeifyError.2

Messages a person can use

Pass a message as the second argument to a check, such as .min(3, "…"), or set one on a schema with the error parameter. A message written for a developer ("expected string, received number") helps no one using the form. Write the message for the person who sees it.3

const Age = z.number({ error: "Age must be a number" });
Messages are not the contract Code should branch on the issue's code and path, not on the message text. Messages change with wording; codes and paths are the stable part you can test against.

Your task (one attempt)

  1. Open errors.ts. Run the form with username: "ab" and favoriteNumbers: [1, "x"]. Predict the path of each issue before you check it in the tests.
  2. Decide which helper a sign-up form with one level of fields should use, and which a deep settings page should use. Give one reason each.
  3. Rewrite one message in your own code so it tells the user what to do next, not what the validator expected.

Check yourself

In an issue for the value "x" at favoriteNumbers[1], what is the path?

The path is an array. Object keys are strings and array indices are numbers, so the path is ["favoriteNumbers", 1].2

Which helper keeps errors nested to match a deep schema?

treeifyError mirrors the schema, so object keys sit under properties and array entries under items. formatError is deprecated in its favour.2

What should code branch on, to stay correct when wording changes?

Messages are wording and may change. The code and path are the stable parts you can test against.
