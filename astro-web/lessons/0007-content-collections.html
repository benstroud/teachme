Content Collections

Turning a folder of Markdown into a validated, typed content API.

The mental model in one sentence

A content collection is a typed folder of Markdown/MDX (or data) entries: you define a schema for the frontmatter, and Astro validates every entry, then you query it with getCollection.1

Define a collection and schema

// src/content.config.ts
import { defineCollection, z } from "astro:content";
const blog = defineCollection({
  type: "content",
  schema: z.object({
    title: z.string(),
    date: z.date(),
    tags: z.array(z.string()).default([]),
  }),
});
export const collections = { blog };

Frontmatter that violates the schema fails the build, so your templates can trust the field types.1

Query and render

---
import { getCollection } from "astro:content";
const posts = await getCollection("blog");
---
{posts.map((p) => <a href={"/blog/" + p.slug}>{p.data.title}</a>)}

Each entry has typed data (the frontmatter) and a body; render() / <Content /> turns the Markdown into markup.1

Key idea Collections turn a folder of loose files into a validated, typed content API — the backbone of a blog, docs site, or catalog.1
