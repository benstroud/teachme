On-Demand Rendering & Adapters

Choosing per-request rendering, reading the request, and picking a host adapter.

The mental model in one sentence

By default Astro pre-renders pages to static HTML at build time; when a page must run per request you opt it into on-demand rendering and add an adapter for your host.1

Static vs on-demand

ModeWhen HTML is producedGood for
Static (default)At build timeContent, marketing, docs.
On-demandAt request timePersonalized or fresh data.1

Opting a page in

---
// src/pages/account.astro
export const prerender = false;   // render this page on demand
const cookie = Astro.request.headers.get("cookie");
---

With on-demand rendering you get the request (Astro.request) and can set the response status and headers (Astro.response), or return a Response directly.1

The adapter

// astro.config.mjs
import node from "@astrojs/node";
export default { output: "server", adapter: node() };

The adapter (Node, Netlify, Vercel, Cloudflare, …) is what lets the built site run on demand on that platform.1

Key idea Keep the static default for anything you can pre-render, and reserve on-demand rendering for the pages that genuinely need per-request behavior — that keeps both performance and cost in your favor.1
