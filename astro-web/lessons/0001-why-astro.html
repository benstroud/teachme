Why Astro

The server-first, content-focused framework that ships no JavaScript by default.

The mental model in one sentence

Astro is a server-first, content-focused web framework: it renders your pages to plain HTML and, by default, ships zero JavaScript to the browser — you opt a component into interactivity only when it truly needs it.1

The problem Astro targets

A typical single-page app sends a large JavaScript bundle and then hydrates the whole page in the browser before it becomes interactive. For a mostly-static site (a blog, docs, marketing, a storefront), that is a lot of cost for little benefit. Astro flips the default: produce finished HTML on the server, and add client JS only where you ask.1

What "content-focused" buys

DefaultConsequence
Zero JS shippedFast first paint, less to download and parse.1
HTML superset syntaxIf you can write HTML, you can write Astro components.1
Opt-in complexityAdd features and interactivity incrementally as needed.1
Key idea Astro renders on the server, so there is no reactivity in the browser unless you add an island. That removes hooks, stale closures, refs, and observables from the default path.1
