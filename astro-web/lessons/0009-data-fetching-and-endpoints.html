Data Fetching & Endpoints

Fetching at build or request time, and writing API routes that return a Response.

The mental model in one sentence

Astro pages can fetch data during render — at build time for static pages, or at request time for on-demand pages — and a .js/.ts file under src/pages/ can export an endpoint that returns a Response.1

Fetching in a page

---
const res = await fetch("https://api.example.com/posts");
const posts = await res.json();
---
<ul>{posts.map((p) => <li>{p.title}</li>)}</ul>

For a static page this runs once at build; for an on-demand page it runs per request. Same code, different timing.1

An API endpoint

// src/pages/api/counter.ts
export async function POST({ request }) {
  const body = await request.json();
  return new Response(JSON.stringify({ ok: true, got: body }), {
    headers: { "Content-Type": "application/json" },
  });
}

Endpoints can read the request, do server-only work (secrets, database), and return a status, headers, and body — ideal for form submissions and small APIs.2

Key idea The same fetch call meets two timings. If the data only changes occasionally, fetch at build and ship static HTML; if it must be live, make the page (or endpoint) on-demand.1
