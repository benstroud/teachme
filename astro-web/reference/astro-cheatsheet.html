ReferenceAstro.js

Astro Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. The model

server-first, content-focused
render HTML on the server (build or request)
zero client JS by default  ->  opt a component in when needed
  • Astro ships no client JavaScript unless you add a directive.1
  • The .astro language is a superset of HTML.1

2. Components (.astro)

---
// frontmatter: server/build only, never shipped
const { title } = Astro.props;
---
<h1>{title}</h1>
<slot />
  • Frontmatter runs on the server; the template is HTML.3
  • Read props from Astro.props; braces evaluate expressions.3

3. Routing

src/pages/index.astro        ->  /
src/pages/blog.astro         ->  /blog
src/pages/blog/[slug].astro  ->  /blog/:slug   (getStaticPaths)
  • File path defines the URL; brackets make it dynamic.5
  • getStaticPaths enumerates values to pre-render.5

4. Layouts & slots

<html>
  <head><slot name="head" /></head>
  <body><slot /></body>
</html>
  • A layout is a component that wraps pages via a slot.4
  • Named slots + fallback content support composition.3

5. Islands & directives

<Counter client:load />     immediately
<Counter client:idle />     when idle
<Counter client:visible />  when in view
<Counter client:only />     browser only
  • Only marked components hydrate; the rest stays HTML.2
  • Islands load and hydrate in parallel, in isolation.2

6. Styles & assets

<style> ... </style>            scoped to the component
<style is:global> ... </style> site-wide
public/         served as-is
src/assets/     optimized + hashed (import them)
  • Component styles are scoped by default.6
  • Use is:global or a global import for site-wide rules.6

7. Content collections

defineCollection({ type:'content', schema: z.object({...}) })
const posts = await getCollection('blog');
post.data.title   // typed frontmatter
await render(post) // -> <Content />
  • Schemas validate every entry's frontmatter at build.9
  • getCollection / getEntry query, render() renders the body.9

8. Rendering modes & adapters

static (default):  HTML at build time
export const prerender = false;   // on demand
import node from '@astrojs/node';
export default { output: 'server', adapter: node() };
  • Static for content; on-demand for per-request pages.12
  • An adapter wires server output to a host (Node/Netlify/Vercel/Cloudflare).12

9. Data & endpoints

--- const res = await fetch(url); const d = await res.json(); ---
// src/pages/api/x.ts
export async function POST({ request }) {
  return new Response(JSON.stringify({ ok: true }));
}
  • fetch runs at build (static) or request time (on demand).10
  • Endpoints return a Response for forms and small APIs.11

10. Checklist

  • Keep pages static unless they truly need per-request rendering.
  • Make interactivity an explicit, per-component choice (client directives).
  • Use scoped styles; import assets you want optimized.
  • Define content schemas so templates can trust field types.
  • Add prefetch + view transitions, a sitemap, then deploy to a matching host.
