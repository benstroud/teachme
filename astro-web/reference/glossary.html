Astro Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

Rendering model

Astro
A content-focused, server-first web framework that renders pages to HTML on the server and ships zero client JavaScript by default.1
server-first
Markup is produced on the server (build or request time) rather than in the browser.1
zero JS by default
Astro emits plain HTML/CSS unless you explicitly make a component interactive.1
hydration
Attaching client-side JavaScript to server-rendered HTML to make it interactive — the cost Astro avoids by default.2

Islands & interactivity

island
An interactive component on an otherwise static page, hydrated independently.2
client directive
An attribute like client:load that opts a component into client hydration.2
client:load / idle / visible
Hydrate immediately / when the browser is idle / when scrolled into view.2
client:only
Skip server rendering and run the component only in the browser.2
server island
A component marked server:defer that renders its own server content separately, in parallel.2

Components & pages

.astro component
A component file: a frontmatter script fence, then an HTML-superset template.3
frontmatter fence
The --- block at the top; it runs at build/server time and never ships to the browser.3
layout
A component (often with <slot />) that wraps page content in a shared shell.4
slot
A placeholder where child content is injected; named slots and fallback content are supported.3
file-based routing
Files under src/pages/ become routes.5
dynamic route
A route with a parameter, e.g. [slug].astro, driven by getStaticPaths (static) or at request time.5

Content & data

content collection
A typed group of Markdown/MDX/data entries with a frontmatter schema.9
schema (zod)
A zod definition validating each entry's frontmatter fields and types.9
getCollection / getEntry
APIs to query entries from a collection at build/request time.9
endpoint (API route)
A .js/.ts file under src/pages/ exporting a function that returns a Response.11

Rendering modes & deploy

static output
Pages are pre-rendered to HTML at build time (the default for content sites).12
on-demand rendering
Rendering at request time; enabled per page via export const prerender = false.12
adapter
The integration (Node, Netlify, Vercel, Cloudflare) that lets an Astro project run on demand on a host.12
View Transitions
Opt-in animated client-side navigation between pages.13
prefetch
Preloading linked pages on hover/visibility so navigation feels instant.13
