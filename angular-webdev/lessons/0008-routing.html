Routing

Change the view client-side as the URL changes — Routes, Outlets, and Links.

The mental model in one sentence

Angular's Router maps URLs to components, renders the active component in a <router-outlet>, and navigates without a full page reload.1

Define routes

import { provideRouter, Routes } from '@angular/router';
import { HomeComponent } from './home.component';

export const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'users', component: UsersComponent },
  { path: 'users/:id', component: UserDetailComponent },   // route param
];
// app config: providers: [provideRouter(routes)]

The Routes array maps path patterns to components. Params are written with a colon (:id).1

Outlets and links

// where the active route renders (usually in AppComponent)
<router-outlet />

// client-side links — no full page reload
<a routerLink="/users">Users</a>
<a [routerLink]="['/users', user.id]">{{ user.name }}</a>
PartRole
RoutesMap URL → component.
OutletPlaceholder that renders the active component.
LinksNavigate without a page reload.1

Programmatic navigation & lazy loading

// in a component
private router = inject(Router);
go() { this.router.navigate(['/users']); }

// lazy-load a feature's routes
{ path: 'users', loadChildren: () => import('./users.routes').then(m => m.routes) }
  • router.navigate([...]) navigates in code.
  • loadChildren lazy-loads a routes file — code-splitting the app by feature.1
Key idea Routing is what turns a component tree into a navigable app. Keep one <router-outlet> at the top, define routes per feature, and lazy-load each feature's routes for performance.
