Why Angular & the CLI

A batteries-included, structured SPA framework — and the command that starts a whole project.

The mental model in one sentence

Angular is an opinionated, structure-first framework: one component tree, a CLI to scaffold it, and built-in DI, routing, forms, and HTTP — so the architecture is consistent across every app.

What Angular gives you out of the box

  • A component model — the UI is a tree of self-contained components.1
  • The Angular CLI — ng new scaffolds a whole buildable project; ng serve runs a dev server.2
  • Built-in features — dependency injection, routing, forms, and an HTTP client are part of the framework, not add-ons.
  • TypeScript-first — the whole framework is typed; templates are type-checked.

For an experienced TypeScript developer, the appeal is "structure without decisions": the framework chooses the architecture so teams stay consistent.

Your first project

npm i -g @angular/cli        # one-time; or use npx @angular/cli
ng new my-app                # creates a standalone, runnable app
cd my-app
ng serve                    # dev server at http://localhost:4200

ng new generates a project with an src/ folder, a root AppComponent, and everything wired to build and run. Modern Angular projects are standalone by default (no NgModules).2

What you'll build toward

The rest of this course assembles that project: components and templates (2–3), signals (4), services & DI (5), forms (6), HTTP (7), routing (8), and a full app (9).

Key idea Angular rewards consistency: learn the one idiomatic way (standalone components, signals, inject-able services) and it scales from a hello world to a large team app without a rewrite.
