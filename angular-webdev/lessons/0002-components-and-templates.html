Components & Templates

The unit of UI: a class, a template, and a selector composed into a component tree.

The mental model in one sentence

Every Angular component pairs a TypeScript class (behavior) with an HTML template (what renders) and a CSS selector (how it's used).1

A component

import { Component } from '@angular/core';

@Component({
  selector: 'profile-photo',
  template: `<img src="photo.jpg" alt="Your photo" />`,
  styles: [`img { border-radius: 50%; }`],   // scoped to this component
})
export class ProfilePhoto {}
  • Metadata lives in the @Component decorator: selector, template, styles.1
  • Use templateUrl/styleUrl to point at separate files.
  • Styles are scoped to the component by default.

Using a component (standalone + imports)

import { Component } from '@angular/core';
import { ProfilePhoto } from './profile-photo';

@Component({
  selector: 'user-profile',
  imports: [ProfilePhoto],            // make the child usable here
  template: `<profile-photo />`,
})
export class UserProfile {}

Components are standalone by default; to use another component, directive, or pipe in a template, list it in imports.1

The component tree

Each component's rendered template is its view, shown inside its host element. Parent components render children, growing into an app-wide component tree — the mental model behind DI and queries.1

Template basics

Templates are HTML plus Angular syntax. Two quick rules:

  • @ introduces control flow; [] and () have special binding meaning.2
  • <script> is not allowed in templates (security).
Key idea Think of a component as a reusable, self-contained "widget": inputs come in, it renders a view, events go out. Compose widgets, not pages.
