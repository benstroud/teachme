Binding & Control Flow

Data in, events out: interpolation, bindings, and the modern template control flow.

The mental model in one sentence

Angular keeps the DOM in sync with your data: templates use interpolation, property/event bindings, two-way binding, and @if/@for control flow blocks.1

The four binding forms

<p>Hello, {{ user.name }}!</p>              <!-- interpolation -->
<img [src]="picUrl" />                       <!-- property binding -->
<button (click)="save($event)">Save</button>   <!-- event binding -->
<input [(ngModel)]="name" />                 <!-- two-way binding -->
  • [prop] sends a value into the element/component; (event) listens.1
  • [(ngModel)] is the "banana in a box" — bind and update together (needs the FormsModule).1

Passing data with @Input / @Output

import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({ selector: 'counter', template: `...` })
export class Counter {
  @Input() start = 0;                          // data in from parent
  @Output() changed = new EventEmitter<number>();   // event out to parent
  bump() { this.changed.emit(this.start + 1); }
}
// parent:  <counter [start]="3" (changed)="onChanged($event)" />

@Input lets a parent feed data in; @Output raises events the parent listens to — this is how components communicate down-and-up.

Control flow blocks

@if (user.tier > 5) { <b>VIP</b> } @else { <i>regular</i> }

@for (item of items; track item.id) {
  <li>{{ item.name }}</li>
} @empty { <p>Nothing here</p> }

@switch (status) {
  @case ('on') { <p>Running</p> }
  @default { <p>Off</p> }
}
  • @if/@else are real blocks (not hidden elements).1
  • @for needs a track key; @empty handles the no-items case.
Key idea Learn the shape once and it explains how Angular stays in sync: bindings express "when this data changes, update that part of the DOM," and control flow expresses the structure conditionally and repeatedly.
