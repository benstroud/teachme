Signals for State

A signal wraps a value and notifies Angular when it changes — the framework's reactive state model.

The mental model in one sentence

A signal is a wrapper around a value that notifies interested consumers when it changes; reading it lets Angular track and re-render automatically.1

Writable signals

import { signal } from '@angular/core';

const count = signal(0);          // initial value
console.log(count());             // read by calling the getter
count.set(3);                     // set a new value directly
count.update(v => v + 1);         // derive from the previous value

In a template, read it the same way — {{ count() }} — and Angular re-renders whenever it changes.1

computed: derived, read-only

import { signal, computed } from '@angular/core';

const count = signal(0);
const double = computed(() => count() * 2);  // depends on count

// double is read-only; when count changes, Angular updates double lazily
console.log(double());

computed() derives a read-only signal from others; it's lazy and cached until a dependency changes.1

effect: reactions outside the template

import { signal, effect } from '@angular/core';

const cart = signal<string[]>([]);
effect(() => console.log('cart has', cart().length));  // runs on change

effect() schedules a side effect that re-runs when the signals it reads change — useful for logging, syncing, and non-template reactions.1

Exposing state safely

@Service()
export class CartState {
  private readonly _count = signal(0);
  readonly count = this._count.asReadonly();   // consumers can't set it
  add() { this._count.update(v => v + 1); }
}

asReadonly() exposes a read-only view so consumers can read but not mutate.1

Key idea Signals make state explicit and reactive: components read signals in templates, Angular tracks them, and the DOM stays correct with no manual bookkeeping. Model app state as signals, derive views with computed.
