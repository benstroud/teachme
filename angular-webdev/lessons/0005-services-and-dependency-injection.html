Services & Dependency Injection

Share data and logic app-wide by providing services and injecting them where needed.

The mental model in one sentence

Dependency injection supplies a class with the objects it needs from the outside, instead of the class creating them — and Angular wires it up automatically.1

A service

import { Service, signal } from '@angular/core';

@Service()                       // shorthand for @Injectable({providedIn:'root'})
export class CartService {
  items = signal<string[]>([]);  // shared reactive state
  add(item: string) {
    this.items.update(list => [...list, item]);
  }
}

@Service makes the class an app-wide-singleton injectable service.1

Injecting with inject()

import { Component, inject } from '@angular/core';

@Component({ selector: 'navbar', template: '...' })
export class Navbar {
  private cart = inject(CartService);   // get the singleton
}
// or in the constructor: this.cart = inject(CartService);

inject() runs in an injection context — component/directive/service construction, route guards, etc.1

The injector hierarchy

Angular has a tree of injectors aligned with the component tree. A service provided at the root is a singleton across the app; you can also provide one at a component/route level to give that subtree its own instance.

Why DI matters for real apps

  • Shared state — one CartService instance shared by every component that injects it.
  • Testability — tests can provide a fake implementation in place of the real one.1
  • Separation — components stay "dumb"; data + HTTP live in services (Lesson 7).
Key idea Put app-wide state and logic in @Service classes and inject them with inject(). Components render; services own data and behavior — the backbone of Angular architecture.
