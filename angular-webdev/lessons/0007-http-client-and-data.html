HTTP Client & Data

Talk to a backend with typed requests — from an injectable service.

The mental model in one sentence

Angular's HttpClient (@angular/common/http) makes typed HTTP requests, and lives in services so components stay clean.1

Set it up once

import { provideHttpClient } from '@angular/common/http';

// in the app config providers:
export const appConfig = {
  providers: [provideHttpClient()],
};

provideHttpClient() enables the HTTP client for the app.1

Request typed data in a service

import { Service, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';

interface User { id: number; name: string; }

@Service()
export class UserService {
  private http = inject(HttpClient);

  users = this.http.get<User[]>('/api/users');   // Observable<User[]>

  create(user: User) {
    return this.http.post<User>('/api/users', user);
  }
}
  • Type the response with generics (get<User[]>).1
  • Inject HttpClient exactly like any other dependency.
  • Requests return Observables; for signal-friendly async data, httpResource bridges HTTP responses into a signal.1

Where the HTTP lives

Keep HTTP in a service (injectable), and let components read from the service. This keeps components testable and separates data access from rendering — the DI/architecture pattern from Lesson 5.

Key idea Data access is a service concern: inject HttpClient in a service, type your responses, and expose them to components. Components render; services fetch.
