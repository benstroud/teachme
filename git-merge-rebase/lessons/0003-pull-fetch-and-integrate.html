Pull, Fetch & Integrate

git pull is really two steps — download (fetch) then bring it in (merge or rebase). Separate them and nothing surprises you.

The mental model in one sentence

git pull runs git fetch to download the remote branch into a local remote-tracking ref (like origin/main), then integrates it into your current branch — by default a merge.1

Fetch only downloads

git fetch origin            # update origin/*, touch nothing local

Fetching is safe: it updates remote-tracking refs but does not modify your working tree or current branch. That makes fetch a good habit before you decide how to integrate.1

Pull = fetch + integrate

The manual equivalent of a default git pull on main against origin/main is:1

git fetch origin
git merge origin/main        # integrate the remote-tracking ref

Which branch pull integrates is set by your branch's upstream — how the branch was created/clone set branch.<name>.remote and branch.<name>.merge.1

Key idea The merge that default pull does is a normal git merge: it may fast-forward or create a merge commit — or stop on a conflict. "Pull" does not choose merge versus rebase for you; the next lessons cover those modes.

Choosing the integration mode

  • Default git pull — merges the upstream into your branch (produces merge commits when diverged).
  • git pull --rebase — replays your local commits on top of the upstream (covered in a later lesson).
  • git pull --ff-only — only bring in upstream if it can fast-forward cleanly (no merge commit, no rebase).
