The Commit Graph

Merging and rebasing are operations on history — so first you have to see history as a graph of commits, not a stack of saves.

The mental model in one sentence

A commit is a snapshot wired to its parent(s), forming a directed graph; a branch is just a pointer to a commit that moves forward as you commit, and HEAD points at the branch you are on.1

Commit, graph, branch, HEAD

  • Commit — a snapshot plus its parent(s); special commits (merges) have two parents.
  • Branch — a movable pointer to one commit; new commits move it forward.1
  • HEAD — the pointer Git uses for "where am I"; normally the current branch.1
  • Reachability — a commit is an ancestor of another if you can walk parent links to it.

See the graph

git log --oneline --graph --all        # visualise the whole history
git log --graph --oneline              # just the current branch

Divergence: the idea behind it all

Branching means creating a new pointer from some point and committing on it. When both your branch and another branch gain commits after their common ancestor, they have diverged — there is no single tip that contains both lines, and something must integrate them.1

o---o---o---o          main
            \
             o---o     feature   (merge base = the 3rd o)
Key idea Everything in this course — fast-forward, merge, rebase — is Git answering "what happened after the merge base, and how do I bring two lines together?" Start from the graph and the commands stop being magic.
