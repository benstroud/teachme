Merge Conflicts

When both sides change the same lines, Git can't choose — it marks the spot, and you resolve the intent by hand.

The mental model in one sentence

A conflict happens when two branches changed the same lines in different ways; Git leaves conflict markers in the file and asks you to pick the intended result, stage it, and commit.1

The markers

<<<<<<< HEAD
<div id="footer">contact: email.support@github.com</div>
=======
<div id="footer">please contact us at support@github.com</div>
>>>>>>> iss53

The top block is HEAD (what you had checked out), the bottom is the other branch; ======= separates them. To resolve, produce the correct content and delete all three marker lines.1

Resolve, stage, finish

# edit the conflicted files, removing the markers, then:
git add path/to/file      # staging marks it resolved
git status                # verify nothing is still unmerged
git commit                # finalize the merge
# (for a rebase that hits conflicts, use git rebase --continue)

Staging a file tells Git you have resolved it.1

Key idea A conflict is not an error — it is Git stopping to ask you about intent. Resolve at the level of the change you actually want, not "keep my side". Then continue or abort cleanly.

Abort and tooling

  • git merge --abort — cancel the merge and restore your pre-merge state.
  • git merge --continue — finish once conflicts are staged.
  • git mergetool — open a visual merge tool to walk through conflicts.1

Check yourself

1. In a conflict marker, the section above the equals line is…

2. To mark a conflicting file resolved you…

3. To back out of an in-progress merge entirely you…

Primary source (read this next)

Read the conflict-resolution walkthrough in Pro Git — Basic Branching and Merging and the conflicts sections of the git-merge man page.

Ask the agent Make two branches edit the same line differently, merge, and resolve the marker by hand. Then practice git merge --abort on a second conflict to confirm it restores your branch.
