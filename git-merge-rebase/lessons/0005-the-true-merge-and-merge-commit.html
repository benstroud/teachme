The True Merge & the Merge Commit

When histories diverge, a merge combines two lines of work into one commit with two parents.

The mental model in one sentence

A true merge of diverged history combines the two latest snapshots and their merge base, then records the result in a merge commit that has two parents.1

What Git combines

      o---o         main (HEAD)
     /
o---o
     \   o---o       feature
git merge feature    # combine main tip, feature tip, and the merge base

The three-way merge takes the two tips plus the common ancestor so it knows what each side actually changed, then applies both sets of changes to the working tree. You finalize with a git commit (or it auto-commits), producing a commit with two parents.1

The merge commit's meaning

  • It has two parents: the previous tip of main and the tip of feature.
  • History stays branched: no commit is rewritten; the graph records that the two lines met here.1
  • This is why merging is "safe" for shared branches — it never changes existing commits.1
Key idea Merge preserves what happened (two lines came together). Rebase, by contrast, rewrites one line to appear straight — which is why the merge-vs-rebase choice is about what you want history to say.

Controlling it

  • git merge --no-ff — force a merge commit even when a fast-forward would work, to mark "a branch was merged here".
  • git merge --no-commit — merge into the working tree without committing, so you can adjust first.
