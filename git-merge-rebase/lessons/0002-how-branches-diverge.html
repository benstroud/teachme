How Branches Diverge

Every integration debate is really about the merge base and whether the two tips have split since then. Read it once and the options become obvious.

The mental model in one sentence

The merge base of two branches is their most recent common ancestor; whether the tips are ancestors of each other decides if integration can fast-forward or must merge/rebase.1

Find the merge base

git merge-base main feature     # prints the common ancestor sha

Everything Git integrates is relative to this commit: the changes "since the time the histories diverged" are what a merge incorporates from each side.2

The two shapes

ShapeMeaningIntegration
One tip is a descendant of the otherNo real divergence; feature is just ahead of mainFast-forward or a no-ff commit
Both tips have commits since the merge baseTruly divergedTrue merge, or a rebase
# descended (fast-forwardable)
  main: o---o---A
  feat:            B---C      (feature is descended from A)

# diverged (needs merge or rebase)
  main: o---o---A---D
  feat:      \     B---C
Key idea The question "can I just fast-forward?" is answered by reachability: is the thing I'm merging already in my ancestry? If yes, move the pointer; if no, both sides changed since the base and you need a real integration.1
