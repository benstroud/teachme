Git Merge & Rebase Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. Mental model

master:  o---o---o---o
                    \
feature:             o---o      (diverged: merge base = 3rd o)

# merge base of master..feature
git merge-base master feature
git log --oneline --graph --all        # see the shape
  • A branch is a pointer to a commit; committing moves it forward.1
  • Merge base = the common ancestor from which two branches diverged.3
  • If one branch is a descendant of the other, a merge can fast-forward.

2. Merge: fast-forward vs true merge

git switch master
git merge feature            # fast-forward if feature is ahead; else merge commit

# when you want to control it
git merge --ff-only feature          # error if a fast-forward is impossible
git merge --no-ff feature            # always make a merge commit
git merge --abort                    # cancel an in-progress merge
git merge --continue                 # finish after resolving conflicts

Fast-forward = just move the pointer (no commit); a true merge of diverged history = a merge commit with two parents.2

3. Remotes: fetch, pull, pull --rebase

git fetch origin            # download refs; touch nothing local
git merge origin/main       # integrate the fetched remote-tracking ref
# the two above are what `git pull` does by default

git pull                    # fetch + merge (default)
git pull --rebase           # fetch + rebase your local commits onto origin
git config --global pull.rebase true    # make --rebase the default

pull = fetch + integrate; remote-tracking refs like origin/main update on fetch.5

4. Rebase and rebase --onto

# replace a merge with a linear replay of your commits onto the target
git switch feature
git rebase main                # replay feature's unique commits onto main

# move a RANGE of commits onto a different base
git rebase --onto newbase upstream [branch]
#   replays the commits unique to upstream..branch onto newbase
#   e.g. drop a middle commit: --onto A B (branch's own B'..tip)

git rebase -i ...              # interactive: reorder/edit/squash/drop

Rebase writes new commits (new hashes) on the new base.4

5. Conflict resolution

# file content during conflict
<<<<<<< HEAD
...your side...
=======
...their side...
>>>>>>> feature

# resolve → stage → continue
# (edit the file, remove markers)
git add path/file
git commit                # for a merge
git rebase --continue     # for a rebase

Staging a file marks the conflict resolved.1

6. Merge vs rebase — when

  • Merge preserves "what happened" and adds a merge commit; safe on shared branches.1
  • Rebase tells a cleaner linear "story"; rewrites local commits only.1
  • Golden rule: never rebase commits others may have based work on.1
  • Common flow: rebase local work onto latest main, then merge published work into main.
