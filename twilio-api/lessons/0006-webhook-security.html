Webhook Security

Verify X-Twilio-Signature before you let a webhook control a call.

The mental model in one sentence

Twilio signs every webhook request with an X-Twilio-Signature header, and your handler should verify it before trusting the request — otherwise anyone who finds /twiml can drive your calls.1

Validating form-encoded webhooks

const twilio = require("twilio");

function verify(req, res) {
  const ok = twilio.validateRequest(
    process.env.TWILIO_AUTH_TOKEN,
    req.headers["x-twilio-signature"],
    "https://app.example.com/twiml",   // the EXACT URL Twilio called
    req.body                            // parsed form params
  );
  if (!ok) return res.status(403).send("invalid signature");
  // ...trusted request
}

Rules that trip people up

RuleWhy
Use the exact URLDecoding or re-encoding breaks the signature.1
Pass the form paramsTwilio sorts them and appends them to the URL.1
JSON bodiesUse validateRequestWithBody with the raw body and bodySHA256.1
Key idea The current handler does not validate the signature — that is a real gap. Adding validateRequest (or the Express middleware tutorial) is the single highest-value security fix in this integration.1
