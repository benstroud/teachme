TwiML & <Dial>

The XML your /twiml route returns, and the caller-ID rules that gate it.

The mental model in one sentence

Your /twiml route returns XML: an <Dial> verb connects the caller to a destination, and callerId sets what the callee sees — which must be a number you own.1

Building the TwiML

const { VoiceResponse } = require("twilio").twiml;

function twimlHandler(req, res) {
  const response = new VoiceResponse();
  response.dial(
    { callerId: process.env.TWILIO_FROM_NUMBER },  // an owned number
    req.body.To                                     // destination
  );
  res.type("text/xml").send(response.toString());
}

Caller ID rules

RuleConsequence
Use an owned Twilio numberAllowed as callerId.1
Use a verified numberAllowed once verified on the account.1
Use an arbitrary numberRejected or fails — Twilio blocks it.1
Key idea The browser never decides the final route — it sends To, and your server owns the policy: which caller ID, whether to record, and whether the call is allowed at all.2
