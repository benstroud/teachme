Accounts & Subaccounts

One main account, many customer buckets — billing rolls up, resources stay separate.

The mental model in one sentence

Twilio accounts form a tree: a main account owns subaccounts, and each subaccount is a clean bucket for one customer's numbers, calls, and usage — with billing rolling up to the parent.1

Why subaccounts, not one big account

PropertyEffect
Segmented resourcesEach org's numbers and calls are isolated.1
Single billAll subaccount usage bills to the main balance.1
Default limitUp to 1,000 subaccounts per main account.1

Creating one and using it

const twilio = require("twilio");
const client = twilio(process.env.TWILIO_ACCOUNT_SID, process.env.TWILIO_AUTH_TOKEN);

// create a subaccount for a new organization
const sub = await client.api.accounts.create({ friendlyName: "Acme Org" });
// sub.sid is the new AccountSid (AC...)

// act as the subaccount by constructing a client with its SID
const orgClient = twilio(sub.sid, sub.authToken);
Key idea Closing a subaccount is destructive: by default Twilio deletes it 30 days after closure, and closing releases its phone numbers. Transfer numbers to the main account first if you want to keep them.1
