Production Hardening

Verified, idempotent, rate-aware, and observable — the last mile.

The mental model in one sentence

Production voice is mostly about the edges: verify every webhook, tolerate retries idempotently, respect CPS, manage the subaccount lifecycle, and keep an eye on CallSid end to end.1

Hardening checklist

ConcernPractice
Webhook trustValidate X-Twilio-Signature on every request.1
RetriesAssume duplicate callbacks; dedupe on CallSid.
Rate limitsQueue/serialize outbound calls; back off above ~1 CPS.4
TenancyOne subaccount per org; transfer numbers before closing.2
UpgradesBump the library deliberately; v6 needs Node 20.3

A reference shape

POST /token    -> mint Access Token (identity + VoiceGrant)
POST /twiml    -> validate signature -> TwiML <Dial>
POST /status   -> verify + dedupe on CallSid -> update call state
GET  /numbers  -> search/buy, bind voiceApplicationSid
     logs      -> CallSid, AccountSid, errors, latency
Key idea The happy path is the easy 10%. The senior move is making the failure path boring: verified, idempotent, rate-aware, and observable.1
