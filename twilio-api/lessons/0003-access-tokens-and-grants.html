Access Tokens & Grants

Short-lived JWTs, identity, and the VoiceGrant that points at your TwiML app.

The mental model in one sentence

An Access Token is a short-lived JWT your server mints to authorize a client-side Twilio SDK — it carries the user's identity plus a grant (for voice, a VoiceGrant) that names the TwiML app to use.1

Minting a voice token

const AccessToken = require("twilio").jwt.AccessToken;
const VoiceGrant = AccessToken.VoiceGrant;

const grant = new VoiceGrant({
  outgoingApplicationSid: process.env.TWILIO_TWIML_APP_SID,
});

const token = new AccessToken(
  process.env.TWILIO_ACCOUNT_SID,
  process.env.TWILIO_API_KEY,
  process.env.TWILIO_API_SECRET,
  { identity: userId }          // who this token belongs to
);
token.addGrant(grant);

const jwt = token.toJwt();       // send this string to the browser

What matters about the token

PropertyGuidance
LifetimeConfigurable up to 24h; use the shortest feasible.1
Created whereOn your server, never in the browser.1
RevocationDelete the API key that signed it.1
Key idea outgoingApplicationSid is the linchpin: without it, the Voice SDK has no TwiML app to ask what to do with an outbound call.2
