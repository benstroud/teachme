The Browser Voice SDK

Token in, connect out — and why Twilio then calls your TwiML URL.

The mental model in one sentence

The browser Voice SDK connects to Twilio using the Access Token; then, for an outbound call, Twilio requests the TwiML app URL (your /twiml route) to learn what to do.1

The flow, end to end

browser --(Access Token)--> Twilio
browser --(connect: To=+1555...)--> Twilio
Twilio --(HTTP POST /twiml)--> your server
your server --(TwiML <Dial>)--> Twilio --> callee

The client side

// current Voice SDK (v2.x); check the docs for the latest version
const device = new Twilio.Device(token, { codec: "opus" });

device.on("ready", () => console.log("ready"));
device.connect({ params: { To: "+15551234567" } });

The token authenticates the device; the To value is what your TwiML handler will dial. Older quickstarts often pin an outdated SDK (e.g. 1.14) — prefer the current v2 docs.1

Key idea The SDK is a transport, not the logic. Routing decisions live on your server in TwiML, which is why the same browser code can dial, conference, or record by changing only the handler.1
