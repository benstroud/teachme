Tokens & Tokenization

Models read and write tokens, not characters — so tokenization shapes cost, vocabulary coverage, and context length.

The mental model in one sentence

A tokenizer turns text into the model's input units (tokens) through a pipeline of normalization, pre-tokenization, and a subword model — and every token you send or generate counts toward the context and the cost.1

The tokenization pipeline

  • Normalization — clean up text (case, Unicode, accents).
  • Pre-tokenization — split into rough pieces (e.g. on whitespace/punctuation).
  • Model (BPE / WordPiece / Unigram) — build and apply a subword vocabulary.1
  • Post-processing — add special tokens (end-of-sequence, padding, instruction markers).1

Why subwords

A fixed word vocabulary cannot cover every word a user will type, and a character vocabulary is inefficient. Subword tokenizers balance both: common words become single tokens, rare or unknown words are split into known pieces — so anything can still be represented.1

"unbelievable"  →  ["un", "believ", "able"]     # subword split
"tokenization"  →  ["token", "ization"]
Key idea Tokens are the actual currency: a prompt "cost" is measured in tokens, and the context window is a token budget. Different tokenizers give different token counts for the same text — worth checking before you assume a length.
