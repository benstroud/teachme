Evaluation & Limitations

A model is a sampler over language, not an oracle. Hallucination is real, and responsible use means testing, grounding, and guarding.

The mental model in one sentence

Because an LLM generates plausible-sounding text from probabilities, it can confidently hallucinate — so you evaluate outputs, ground high-stakes ones, and design for graceful failure.1

Hallucination

Hallucination is fluent text that is not faithful to facts or to the provided context. It follows from the fundamentals: the model only has its weights and the prompt, so facts outside both are simply predicted, not looked up. It is a key reason grounding (RAG) and verification matter.1

How to evaluate

  • Task-level tests: run a fixed set of realistic prompts and judge or score outputs (correctness, format, safety).
  • Ground and check: for factual answers, have the model cite the retrieved chunks, or verify against sources.
  • Decode for consistency: lower temperature for factual tasks; test across seeds because sampling is non-deterministic.
  • Benchmarks: published benchmarks give a rough sense but do not guarantee your domain — evaluate on your own data.
Key idea Build for the failure case: assume uncertain/out-of-context answers can be wrong, add guardrails, cite sources, and route high-stakes output through a check or a human before it acts.

The practical checklist

  • Fit everything the model needs into the context window; retrieve the rest.
  • Choose decoding to match the task (deterministic vs creative).
  • Write clear instructions and examples; set a system prompt.
  • Ground and verify before the model's output controls anything important.
  • Test on real inputs; never assume a claimed capability.
