Grounding with RAG

A model only knows what is in its weights — retrieval plus generation lets it answer from documents you supply, and hallucinate far less.

The mental model in one sentence

Retrieval-augmented generation (RAG) combines a generator (an LLM) with a retriever over a document index: for each prompt, retrieve relevant text and let the model generate conditioned on it.1

The pieces

  • Index — your documents made searchable (e.g. split into chunks and embedded as vectors).
  • Retriever — given a question, fetch the top-k most relevant chunks.
  • Generator — the LLM, prompted with the retrieved chunks as context.
query ──retrieve──▶ top-k chunks ──prompt(instruction + chunks + query)──▶ answer

Why it helps

  • Grounding: the model answers from supplied text instead of only its weights, so it can handle private or up-to-date knowledge it never saw in training.1
  • Less hallucination: when the answer must be consistent with the retrieved context, the model is less free to invent.1
  • Fits the window: you inject a relevant slice rather than an entire knowledge base.
Key idea RAG trades a bigger model for better-engineered context. It does not make the model omnipotent — retrieve well, and the model stays on script; retrieve poorly, and grounding fails.
