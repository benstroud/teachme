LLM Glossary

Every term in this course, in one place. Return here when a lesson uses a word you do not fully own.

The model

LLM (large language model)
A neural network trained on massive text to predict the next token — an autoregressive language model whose size ("large") has grown ~10x/year.1
parameter
A learned weight of the network; model "size" (e.g. 7B) is its parameter count.
autoregressive
Generating text by repeatedly predicting the next token given all tokens so far; the sequence probability is a product of next-token probabilities.2
next-token prediction
The core training/generation operation: from a context, choose the probability distribution over the next token.
checkpoint vs architecture
An architecture is the definition of a model's layers; a checkpoint is the specific set of weights loaded into it.3

Tokens & the context

token / tokenizer
A token is the model's input unit; a tokenizer turns text into tokens via a pipeline (normalization, pre-tokenization, then a subword model).4
subword / BPE / WordPiece / Unigram
Tokenization that builds a vocabulary of words and word-pieces so rare/unknown words still tokenize. BPE (byte pair), WordPiece, Unigram are common subword algorithms.4
special tokens
Reserved tokens added by the tokenizer, e.g. end-of-sequence, padding, or conversation/instruction markers.4
context window
The finite number of tokens a model can attend to at once — the sum of prompt and generated tokens it can see.
embedding
The vector a token/token sequence is mapped to inside the model (and, in retrieval, the vector representation of text).

Architecture & training

Transformer
The dominant architecture, based solely on attention, dispensing with recurrence and convolutions — more parallelizable and faster to train.5
attention / self-attention
The mechanism by which each position weighs other positions to gather context; self-attention attends within the same sequence.5
multi-head attention
Several attention computations in parallel, letting the model attend to different relationships at once.5
encoder / decoder / attention mask
Encoder reads the whole input (undirected); decoder generates sequentially and is masked so it cannot see future tokens.3
pretraining / fine-tuning / transfer learning
Pretraining trains on raw text for general capability; fine-tuning adapts a pretrained checkpoint to a task (transfer learning).31
RLHF (reinforcement learning from human feedback)
Aligning an LM to human preferences in three steps: pretrain (and SFT), train a reward model from human feedback, then fine-tune with RL.6
reward model
A model trained on human preference pairs to score how good a response is, used as the signal in RLHF.6
KL penalty
In RLHF, a term that keeps the fine-tuned model close to its original distribution so it does not drift too far.6

Using the model

greedy / beam / sampling
Decoding methods: greedy picks the top next token (argmax); beam searches several candidates; sampling draws from the distribution.2
temperature / top-k / top-p
Sampling knobs: temperature softens/sharps the probabilities; top-k limits to the k most likely; top-p (nucleus) keeps the smallest set exceeding a probability mass.2
prompt / few-shot / system prompt
The input that conditions output; few-shot includes example input/output pairs; a system prompt sets top-level behavior/instructions.3
RAG (retrieval-augmented generation)
Combining a generator with a retriever over a document index; the model conditions on retrieved text to ground and reduce hallucination.7
hallucination
Confidently generated text that is not based on facts/context — a key failure mode, mitigated by grounding (e.g. RAG) and evaluation.
quantization
Storing model weights in fewer bits (e.g. 8-bit) to shrink memory and speed inference.1
