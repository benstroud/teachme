LLM Cheat Sheet

The compressed essence of the course. Skim before a lesson, study it fully before an interview.

1. Core definition

  • An LLM is an autoregressive next-token predictor trained on massive text.1
  • Generation = repeatedly predict the next token given all tokens so far: P(w) = ∏ P(w_t | w_<t).2
  • "Large" = parameter count growing ~10x/year; transfer learning makes them practical.1

2. Tokens & context

  • Text → tokens via a tokenizer pipeline (normalize → pre-tokenize → subword model → post-process/special tokens).3
  • Subword families: BPE, WordPiece, Unigram; rare/unknown words still tokenize.3
  • Tokens add up: prompt + output must fit the context window.

3. Architecture & attention

  • Transformer = attention only, no recurrence/convolution; parallelizable, faster to train.4
  • Attention lets each position weigh others; multi-head runs several attentions.4
  • Encoder reads the whole input; decoder is masked (no future tokens) and generates.5

4. Training & scale

  • Pretrain on raw text (next-token loss), then fine-tune — transfer learning.5
  • Architecture = layers; checkpoint = the loaded weights; "model" can mean either.5
  • RLHF (3 steps): pretrain/SFT → reward model from human preferences → RL (PPO) with a KL penalty.6

5. Decoding

6. Prompting & grounding

  • Prompt/instruction/few-shot examples condition the output; a system prompt sets top-level behavior.5
  • RAG: retriever pulls top-k from a document index → generator conditions on them → grounded, less hallucination.7
  • Always evaluate: hallucination is real; ground on retrieved context and check outputs.

7. Decision checklist

  • Confirm the context window and count your tokens (prompt + output).
  • Pick decoding: low temperature for factual, higher for creative.
  • Give the model enough context and clear instructions; add examples when needed.
  • Ground high-stakes output in retrieved sources (RAG) and verify.
  • Treat the model as a sampler over language, not an oracle — evaluate.
