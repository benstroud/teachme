Running & Choosing Kafka

How a Kafka cluster runs today, how to run it on AWS, and the decisions that decide when to use it.

The mental model in one sentence

A Kafka cluster runs on brokers coordinated by the modern KRaft controller (ZooKeeper replaced), is available fully-managed on AWS as MSK, and is worth choosing whenever you need replayable, ordered, multi-consumer event history.1

Running today: KRaft

  • Brokers form the cluster; a KRaft controller (a small number of nodes) manages cluster metadata, replacing the old ZooKeeper dependency.1
  • Deployment is usually orchestrated (Docker/K8s) or fully managed.

A managed option on AWS: MSK

Amazon MSK (Managed Streaming for Apache Kafka) runs Kafka for you and connects to the AWS ecosystem (IAM auth, VPC, S3/Glue integration) — the same way you'd avoid running SQS/es yourself.2 For a team on AWS, MSK is the "just give me Kafka" lever.

Choosing: Kafka vs a queue (SQS)

You need…Choose
One consumer processes each job onceQueue (SQS)
Replayable event historyKafka
Strict per-entity ordering at scaleKafka (partition key)
Many consumer groups read the same eventsKafka
Serverless, zero-infra, simpleQueue / event bus

A queue removes a message consumed once; Kafka keeps an ordered log many consumers read — that distinction drives the choice (Lesson 1).

A realistic design

App --produces--> topic "orders" (replicated, compact-as-needed)
                 |-- consumer group: warehouse (process once-ish, idempotent)
                 |-- consumer group: analytics (replayable, lag-managed)
                 `-- Kafka Streams: compute totals -> topic "metrics"
Sink Connect --> warehouse DB       Schema Registry pins the event shape

Design right: pick a partition key for ordering, set acks=all + a replication factor for durability, commit offsets after idempotent processing, and set retention/compaction per topic's purpose.

Key idea Kafka earns its place when events are a first-class, durable asset — history to replay and a stream to process. When it's just "get this job done once," a queue is simpler. Know which side you're on.
