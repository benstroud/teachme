The Ecosystem

Streams, Connect, and Schema Registry — the tools built on top of the producer/consumer core.

The mental model in one sentence

On top of the producer and consumer APIs, Kafka's compute layer adds Kafka Streams (stateful processing), Kafka Connect (external-system integration), and a Schema Registry (schema governance).1

Kafka Streams: process in Java

Kafka Streams is a Java API for stream processing — filtering, grouping, aggregating, joining — that keeps its state locally and in Kafka internal topics, and reassigns state when stream-processing nodes are added or removed.2 It's often embedded in a service that also exposes a REST API.

Kafka Connect: integrate systems

Kafka Connect moves data between Kafka and external systems. Source connectors read from an external system and produce to topics; sink connectors read topics and write to external systems.1

Schema Registry: govern schemas

Because events carry structured data (JSON/Avro/Protobuf), the Schema Registry enforces schemas and compatibility on topics — so a producer can't break consumers with a silent shape change. It's the contract layer Kafka producers/consumers agree on.2

Putting it together

External system --> [Source Connect] --> topic --> [Kafka Streams] --> topic
                                            |        (state, join, agg)
                                            v          |
topic --> [Sink Connect] --> External system   Schema Registry governs shapes

Producers and consumers are the primitives; Streams and Connect are how real systems ingest, transform, and export at scale.

Key idea The core is small (produce, consume); the ecosystem turns that log into a platform — process it (Streams), connect it out (Connect), and keep it consistent (Schema Registry).
