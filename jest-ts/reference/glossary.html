Jest + TypeScript — Glossary & Cheat-Sheet

The compressed essence of Lessons 01–07. Print this; revisit when a concept gets fuzzy.

Transformers — the one decision

TransformerType-checks?SpeedConfig
ts-jestYes (tsc)Slowest createDefaultPreset() (modern) or preset: 'ts-jest' (legacy)
babel-jestNoFast Jest's default; add @babel/preset-typescript
@swc/jestNoFastest transform: { '^.+\\.(t|j)sx?$': '@swc/jest' }

Decision: if CI runs tsc --noEmit, pick by speed (babel-jest or @swc/jest). If not, ts-jest type-checks in the test run. Hybrid: ts-jest with isolatedModules: true for transpile-only speed without switching transformers.

Matchers — the families

toBe — identity
Uses Object.is. Reference identity for objects, value equality for primitives. expect(NaN).toBe(NaN) passes.
toEqual — deep equality
Recursive deep equality. Ignores undefined properties and sparseness.
toStrictEqual — strict deep equality
Like toEqual but rejects extra keys, undefined properties, and sparseness. Use when exact shape matters.
Truthiness — toBeTruthy, toBeFalsy
"Something is there" / "nothing there." Not the same as toBe(true).
Numbers — toBeGreaterThan, toBeLessThan, toBeCloseTo
Comparisons. toBeCloseTo for floats (avoids 0.1+0.2 precision traps).
Strings — toMatch (regex), toContain
Pattern or substring.
Arrays — toContain, toContainEqual, toHaveLength
toContainEqual for deep membership.
Exceptions — toThrow, toThrowError
Pass a function, not its result: expect(() => fn()).toThrow().
Negation — .not
Prefix any matcher: expect(x).not.toBe(y).
Async — .resolves, .rejects
Must await: await expect(p).resolves.toBe(x). Without await, silent pass.

The type-level trap

expect(actual: any) — the matcher chain is loosely typed. The code under test is type-checked (ts-jest), but the expected side isn't guarded by Jest. A typo in the expected object is a runtime failure, not a compile error. Mitigate: type the actual explicitly — const r: ReturnType<typeof fn> = fn(); expect(r).toEqual(...).

Mocks — the typed-mock toolkit

jest.fn<typeof realFn>()
Type-safe mock matching the real function's signature. The senior default — a signature change in realFn fails the mock at compile time.
jest.fn<() => Promise<T>>()
Async return shorthands: mockResolvedValue, mockRejectedValue. The generic is the whole signature.
jest.Mocked<T>
Type that wraps T with mock definitions. Variants: jest.MockedFunction, jest.MockedClass, jest.MockedObject.
jest.mocked(source, { shallow? })
Runtime helper — wraps the source with mock types. Preferred over casting. Deep-wraps by default; { shallow: true } for top level only.
jest.mock<typeof import('m')>('m', factory)
Module mock with typed factory. Factory must include __esModule: true for default exports. Partial mock: spread jest.requireActual('m').
jest.Spied<T>
Return type of jest.spyOn. Variants: jest.SpiedFunction, jest.SpiedClass, jest.SpiedGetter, jest.SpiedSetter.

Contract vs implementation

Mock the contract (inject a jest.fn typed against an interface) when you own the boundary — the test survives refactors. Mock the implementation (jest.mock('path')) for boundaries you don't control (external packages, fs, fetch).

Async — the four patterns

1. Return the promise
return fn().then(x => expect(x).toBe(y)). The return is the fix; without it, silent pass.
2. .resolves / .rejects
await expect(fn()).resolves.toMatchObject(...). The await is required — not optional.
3. async/await — the senior default
const x = await fn(); expect(x).toBe(y). Cleanest: implicit return, Jest waits, rejections fail the test.
4. Callbacks with done — legacy
test('...', done => { fn(cb => { expect(...); done(); }); }). For APIs that don't return promises. expect before done().

The silent-pass trap

A test that calls promise.then(...) without returning the promise passes — Jest sees the function complete, runs zero assertions, reports green. The .then runs after the test finishes. Fix: return the promise, or use async/await.

Config — the cheat-sheet

Modern ts-jest (preset-creator functions)

<code>import type { Config } from 'jest';
import { createDefaultPreset } from 'ts-jest';

const config: Config = {
  ...createDefaultPreset({ tsconfig: 'tsconfig.test.json' }),
  testEnvironment: 'node',
};</code>

Path aliases (tsconfig → Jest)

<code>import { pathsToModuleNameMapper } from 'ts-jest';
import { compilerOptions } from './tsconfig.json';

moduleNameMapper: pathsToModuleNameMapper(compilerOptions.paths,
  { prefix: '<rootDir>/' }),</code>

ESM mode

<code># run with the flag
node --experimental-vm-modules node_modules/.bin/jest

# config: use createDefaultEsmPreset() or:
#   useESM: true in transform, extensionsToTreatAsEsm: ['.ts']
# tsconfig: module = ES2022/ESNext or Node16/NodeNext
# hybrid Node16/Next requires isolatedModules: true

# ESM mocking (jest.mock does NOT work):
jest.unstable_mockModule('./db', () => ({ saveUser: async () => true }));
const { saveUser } = await import('./db');  // after mock</code>

Two configs, one goal

tsconfig.json — how TS compiles (module, paths, strict, esModuleInterop). Read by tsc, editor, ts-jest.
jest.config.ts — how tests run (transform, preset, moduleNameMapper, testEnvironment). Read by Jest.
The overlap is the transformer: ts-jest reads tsconfig to know how to compile. esModuleInterop is a tsconfig setting that ts-jest respects — not a Jest config.

Senior testing principles

Arrange-Act-Assert
One Act line, one behavior per test. Long Arrange = too many dependencies. Three Act calls = testing a flow, not a unit.
Test behavior, not implementation
Assert results, not calls. expect(spy).toHaveBeenCalled() on your own internals is the smell. Spy on boundaries (network, DB), not internal functions.
One behavior per test
Not one assertion — one behavior. A behavior may need several assertions (reject + right error + logged). Avoid two behaviors in one test — when it fails, you don't know which broke.
What not to test
Getters/setters with no logic. Framework internals. Third-party libraries. Constants. Private methods. Test behavior and contracts.
Refactor-resilience
The quality bar: can you refactor the code without rewriting the tests? Coupling (breaks on internal change), signal (failure tells you what/where), speed (slow suites get skipped).
Name tests for what they verify
"rejects expired tokens with 401" not "works". The name is the failure message.

Glossary

Transformer
Jest's hook for compiling non-JS. A regex maps file patterns to a transformer (ts-jest, babel-jest, @swc/jest). Configured via transform or a preset.
Preset
A base Jest config from an npm module. ts-jest's modern form: createDefaultPreset() returns the transform object directly. Legacy: preset: 'ts-jest'.
moduleNameMapper
Jest's regex-to-path map for resolving module specifiers. Use pathsToModuleNameMapper to sync with tsconfig paths.
esModuleInterop
TS compiler option (not Jest). Controls how import x from 'cjs' works under strict mode. ts-jest inherits it.
Distribution (conditional types)
(From the type-level track.) Not a Jest concept — but jest.Mocked<T> uses conditional types internally to wrap nested members.
Silent pass
A test that reports green because no assertion ever ran. The async trap: forgetting to return/await a promise.
Contract vs implementation mock
Contract: mock an interface (inject jest.fn typed against it). Implementation: mock a module (jest.mock('path')). Seniors prefer contracts for code they own.
isolatedModules
ts-jest option: transpile per-file without project-wide type-checking. ts-jest's "transpile-only" mode — same speed as babel-jest without switching transformers.
--experimental-vm-modules
Node flag required for Jest ESM. Jest's ESM support is experimental (still labeled so in Jest 30.4). ESM mocking uses jest.unstable_mockModule, not jest.mock.
